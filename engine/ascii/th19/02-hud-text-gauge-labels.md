# 02 — TH19 气槽 HUD 的**文字**（一手：格式串 / 颜色 / 分档 / 逐字画法）

> **版本**：TH19 v1.10c（`th19.exe`，imagebase `0x400000`，19,937,28 B）。★ 不是 TH18 ✗。
> 本文裸地址默认属该版本。**方法**：Ghidra 反编译 + 逐字节核常量 + `thanm -l 8` 读 anm，
> 全部 2026-10-24 一次做完（脚本见文末「复现」）。
> **可信度**：格式串 / 颜色 / 分支判据 / anm 字形格 = ✅ **一手**；
> 「气槽本体在屏幕上的 y」= 🟡 **未测**（只拿到文字的两个 y，没拿到条本身的 y）；
> 「哪个 font id 对应 16×16 那档字形」= 🟡 **推**（见 §5）。

## 0. 一句话

TH19 气槽 HUD 上的文字是**引擎字符串系统**画的：卡侧只设置「**颜色 + 位置 + 格式串**」，
字形由 `ascii1280.anm` 的 sprite 表给。**三档提示 + 两条常驻等级**，各自有**独立的一手颜色**：

| 状态（`g` = 槽值 0..2500） | 文本 | 颜色 | y（640×480）|
| --- | --- | --- | --- |
| `t2 ≤ g < t3` | `Skill` | `0xff80d0ff` 浅蓝 | 448 |
| `t3 ≤ g < t4` | `Ex.Attack Lv%d` | `0xffffff80` 半透明白（A=0x80）| 448 |
| `g ≥ t4` | `Boss Lv%d` | `0xffff8080` 浅红 | 448 |
| `g < t4`（常驻）| `Lv%d`（C4/ Boss 的等级）| `0xffc0c0c0` 浅灰 | 460 |
| `g < t3`（常驻）| `Lv%d`（C3/ Ex 的等级）| `0xffc0c0c0` 浅灰 | 460 |

⇒ 「**到点提示**」与「**常驻等级**」是**两行**（448 / 460，差 12），不是同一行换字。

## 2. 一手：分档与颜色（`FUN_004e8a20` 原文等价代码）

```c
g  = *(int*)(self + 0x94);              /* 槽值，0..2500 */
L  = *(int**)(*(int*)(self + 0xcc) + 0x2c);   /* 阈值/等级表 */
t1 = L[0x28/4]; t2 = L[0x2c/4]; t3 = L[0x30/4]; t4 = L[0x34/4];   /* 4 个标位，各 clamp 到 0..0x9c4 */
lvl_ex   = clamp(L[0x38/4], 0, 7);      /* Ex.Attack 等级 */
lvl_boss = clamp(L[0x3c/4], 0, 7);      /* Boss 等级 */
cy  = *(int*)(self + 0xc8) ? 328.0f : 16.0f;   /* 左/右那侧 */

if (g < t4) {
    if (g >= t3) { ctx->col=0xffffff80; queue(x(t3), 448, "Ex.Attack Lv%d", lvl_ex+1); }
    else if (g >= t2) { ctx->col=0xff80d0ff; queue(x(current), 448, "Skill"); }
} else { ctx->col=0xffff8080; queue(x(t4), 448, "Boss Lv%d", lvl_boss+1); }

if (g < t4) { ctx->col=0xffc0c0c0; queue(x(t4), 460, "Lv%d", lvl_boss+1); }  /* 常驻（C4 标下）*/
if (g < t3) { ctx->col=0xffc0c0c0; queue(x(t3), 460, "Lv%d", lvl_ex+1);   }  /* 常驻（C3 标下）*/
ctx->col = 0xffffffff;      /* 画完一律重置成白 */
```

要点：

* **等级一律 `+1`**（表里是 0..7，显示 1..8）。
  ⚠ **本卡不照抄这条**：本卡的 `s_c3_lv_n` / `s_c4_lv_n` **本身就是显示等级**
  （初值 C3 = 1 ⇒ `Lv1`、C4 = 3 ⇒ `Lv3`；Lunatic ⇒ 5 / 5），与一手表里的 0 基下标**差一档**
  （owner 2026-10-24：「开局一手应当是 lv1，C4 应当是 lv3」「lunatic 开局 C3 lv5、C4 lv5」）✓
* `Skill` 的 x 用**当前槽值**（`FUN_0040b720()`），另两条用**各自标位**——所以 `Skill` 会跟着充能滑。
* 到点提示与常驻等级**互斥于同一档**：越到第 3/4 档之后，那两条常驻 `Lv%d` 就**不画**了
  （信息已由 448 那行的 `Ex.Attack Lv%d` / `Boss Lv%d` 承担）。
* 位置换算：`x(v) = (cy + 148) + (v * 224 / 2500 - 112)`，
  其中 `DAT_005aa404 = 296.0`（`/2 = 148`）、`DAT_005aa3ec = 224.0`（条宽，`/2 = 112`）、
  `DAT_005aa48c = 2500.0`、`DAT_005aa418 = 328.0` / `DAT_005aa30c = 16.0`（按 side 取一）。
  ⇒ **`x` 就是「标位在条上的位置」**（`v = 0` 时 = 条左端）。
* 样式字段（写进全局绘制上下文 `DAT_005d1a34`，每个入队记录**整块复制**一份）：

| 字段 | 值 | 含义（本文只到「观测到的值」）|
| --- | --- | --- |
| `+0x1977c` | 见上表 | **颜色**（`0xAARRGGBB`）|
| `+0x197a4` | 到点提示/常驻 = `0`，画完重置 = `1` | 渲染器里 `==0` ⇒ 左对齐（不位移）；`==2` ⇒ 按串宽左移（右对齐/居中那套）|
| `+0x197a8` | `1` | 渲染器里 `0` = 半行高居中、`2` = 整行高，其它 = 用默认 |

## 3. 一手：一条字符串怎么变成像素（调用链 + 上下文布局）

| 环节 | 函数 | 一手要点 |
| --- | --- | --- |
| 入队（有参数）| `FUN_004e75a0`（105 B）| `vsprintf(buf, fmt, ...)` → `FUN_004e6c30` |
| 入队（本体）| `FUN_004e6c30`（289 B）| 记录 = `ctx + 0xc78 + n*0x13c`，**上限 0x140 = 320 条**；位置**乘** `DAT_0062eeb0`（分辨率倍率）；把 `ctx+0x1977c..0x197ac` 整块抄进记录 |
| 老化 | `FUN_004e5750`（174 B）| 每条一个生存计数（`+0xd08` 族），到 0 收掉 |
| 按组画 | `FUN_004e6b60`（201 B）| 遍历记录，`rec+0x12c == group` 的交给下一层 |
| **逐字画** | `FUN_004e5850`（4699 B）| ★ 核心：`switch(rec+0x124)` = **字体档** → 算字形号 → 用**内嵌 VM** 逐字设 sprite/pos/color 再画 |

上下文构造器 `FUN_004e6fa0`（558 B）：`ctx` = `0x197d4` B、`0x140` 条 × `0x13c`；
默认样式 = 颜色 `0xffffffff` / 描边色 `0xff000000` / 缩放 `1.0, 1.0` / `0x197a4 = 0x197a8 = 1`。

**字形号**（`switch(rec+0x124)`，一手）：

| 字体档 | 字形号 | 备注 |
| --- | --- | --- |
| `0` | `ch - 0x20` | 96 格，落在 sprite `0..94` = `ascii_1280.png` 顶部 **28×28 衬线体** |
| `6` | `ch + 0x120` | |
| `7` | `ch + 0x1e4` | |
| `8` | `ch + 0x182` | |
| `9` | `ch + 0x246` | |
| `0xc` | `ch + 0x2a8`（`ch < 0x20` ⇒ `0x349 - ch`）| |
| `0xd` | `ch + 0x30c`（`ch < 0x20` ⇒ `0x3ad - ch`）| |

## 4. 一手：字形贴图与那 96 格

`data/ascii1280.anm` 的 entry0 = `ascii/ascii_1280.png`（512×512，**915 个 sprite**）。`thanm -l 8` 一手：

```
sprite98:  { x: 0,   y: 176, w: 16, h: 16 }   ← 空格（全透明）
sprite99:  { x: 16,  y: 176, w: 16, h: 16 }   ← '!'
…
sprite129: { x: 496, y: 176, w: 16, h: 16 }   ← '?'
sprite130: { x: 0,   y: 192, w: 16, h: 16 }   ← '@'      （y=192 整行 32 格）
sprite162: { x: 0,   y: 208, w: 16, h: 16 }   ← ' '      （y=208 整行：空格 + a..z + { | } ~ + 空格）
… sprite193: { x: 496, y: 208, w: 16, h: 16 }
```

⇒ **★ sprite `98..193` = 三行细体 16×16（32 格/行）**，正是 owner 指认「从上往下第二个字体区域」那一档，
`sprite98 + i` ↔ 本仓 `POFV109_ASC_C(i)`（`i` = 行*32+列）**逐格同一条**。
（⚠ 旧记录曾断言「这三行在原版里没有 sprite」——**错** ✗：`ascii1280.anm` 的 sprite 表确实**只覆盖顶部
`y=0..168` 那 98 个 28×28**，但**同一张表后面还有** y=176/192/208 这三行 16×16 的 96 格；
当时只看了前 98 个就下了结论。已在 `mods/th18.v1.00a/card-expand/AUDIT.md` §BE-109-20261024a 订正。）

## 5. ✅ 定案（2026-10-24 补测）：**字体档 1 = 就是这三行**，`sprite = ch + 0x42`

`FUN_004e5850` 的**字形号 switch** 有 `case 1`（我上一轮漏看了它，只记了 0/6/7/8/9/0xc/0xd）：

```c
case 1:  iVar5 = ch + 0x42;      /* ★ 0x20(' ') + 0x42 = 0x62 = 98 ✓ ；0x21('!') + 0x42 = 99 ✓ */
```

⇒ **字体档 1 的字形 = sprite `98..193`**，逐格对应 `ch = 0x20..0x7e`（空格 → 98 … `~` → 193），
**正好就是我们切的那 96 格** ✓✓（本仓 `POFV109_ASC_C(i)` ↔ `i = ch − 0x20`）。

三份 ascii anm 的表**同构、只差缩放**（`thanm -l 8` 一手，sprite 98/99/129/130/193 逐个核）：

| anm | 格子 | 第 0 行 y | 每行格数 | 三行 |
| --- | --- | --- | --- | --- |
| `ascii.anm`（基准 1×）| 8×8 | 88 | 32 | 88 / 96 / 104 |
| `ascii_960.anm`（1.5×）| 12×12 | 132 | 32 | 132 / 144 / 156 |
| `ascii1280.anm`（2×）| 16×16 | 176 | 32 | 176 / 192 / 208 |
| （下一块）| — | 112 / 168 / **224** | — | `sprite194` 起是别的字体（粗数字）|

⇒ 本卡按 1280 那一档 **1:1 不缩放**切（16 px），与一手同尺寸 ✓。

🟡 **仍未定（不影响本卡）**：`FUN_004e8a20` 自己**不设** `ctx+0x19798`，所以那一帧气槽文字到底用档 1
（细体）还是档 0（28×28 衬线体）取决于**它之前谁设过** —— 要钉死需要跑起来看那一帧的上下文值。
本卡**按 owner 2026-10-24 的裁决**用**档 1 的字形**（= `ascii_1280.png` 的第二个字体区域）✓。
