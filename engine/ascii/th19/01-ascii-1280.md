## 7. ★★★ 2026-10-23 定案：**墨 = `alpha < 128`**（不是 0、不是 >40）

★ 这张 png 是 ★ **白底 + 半透明字形**✗：
- ★ `alpha = 0` = **背景**（透明）✗
- ★ `alpha = 255` = **白板**✗
- ★ ★ **字形 = `alpha < 128` 的"半透明洞"**✗ ✓ ← ★ 就是它 ✓

★ 用 `alpha < 128` dump `ascii_1280.png` 的 **`y = 0..25`**（x 30..200），可以**直接读出字形**：

```

```

★ ⇒ ★ 这就是 ★ **ASCII 32..126 的连续排布**✗ ✓ —— ★ 字形**确实在 `ascii_1280.png` 里** ✓，
　★ 只是 ★ **不是"每格一块"**✗，★ 而是 ★ **整行连续排**✗（★ 所以段数会合并 ✓）。

★ ★ 下一步（判据 ① 收尾）✗：
1. 用 `alpha < 128` 重做**行分段**与**列分段** ⇒ 得到**真正的字符格**；

## 9. ★ 段内切格：**必须用固定网格，不能用空隙分段**（2026-10-23 实测）

★ 用"列空隙"分段会得到 ★ **46 / 45 / 59 段**✗ —— ★ 因为 ★ **一个字形内部也有空隙**✗
　（★ 例：`"` 是两根独立的竖条 ✓、`i` 上下分离 ✓）⇒ ★ 空隙数 ≠ 字符数 ✓。

★ ★ 所以正确做法 ✗：★ **每段内按 32 等分**✗：

| 段 | y | x 范围 | 宽 | 每格 |
| ---: | --- | --- | ---: | ---: |
| 0 | 0..25 | 38..496 | 458 | ★ ≈ 14.3 |
| 1 | 30..54 | 5..499 | 494 | ★ ≈ 15.4 |
| 2 | 59..79 | 2..500 | 498 | ★ ≈ 15.6 |

★ 注意：★ **段 0 从 x=38 起**✗ ⇒ ★ 左边 38 px 是**空格**（★ 无墨 ✓）⇒
　★ `ord(c)−32` 的 **第 0 格（空格）** 在段 0 里可能**不占格**，★ 需要按"★ 最左有墨的字形"反推偏移 ✓。

★ ★ 结论 ✗：★ 切 95 格之前，**先用一个已知串验证**✗ ——
　★ 建议拿 ★ `Ex Attack lv3`✗ 或 ★ `skill`✗ 的实际渲染（★ 你那张图 ✓）来**定偏移** 🟡。

## 10. ★★★★ 定案（2026-10-23 最终）：墨 = **`alpha > 0 且 R < 128`**（黑字 / 白板）

★ 直接 dump **四个通道**（段 1，`y=30..44`，`x=82..97`）看到真相：

```
R 通道: 0000000000 6F FF B9   ← 字身 R = 0x00（黑），字边 R 递增
A 通道: 0000000003 DF FF D9   ← 字身 A ≈ 0x30~0x5F（半透明），白板 A = 0xFF
```

★ 结论：
- ★ **白板** = `RGB = (255,255,255)`、`alpha = 255` ✗
- ★ **字身** = `RGB = (0,0,0)`、`alpha ≈ 0x30..0x5F` ✗（★ **半透明黑** ✓）
- ★ **背景** = `alpha = 0`（★ `RGB` 也是 0 ✓ ⇒ ★ 必须**先用 alpha>0 排除** ✓）

★ ★ 所以正确谓词 ✗：

```
墨(y,x) = alpha[y,x] > 0  &&  R[y,x] < 128
```

★ ★ 前面所有失败都因为 ★ **只看 alpha**✗（★ 而 alpha 在"背景(0) / 字身(~0x40) / 白板(0xFF)"三档上不可分 ✓）。

★ 下一步：用这个谓词切 95 格（★ 格宽由段宽/32 得 ✓），逐格 rect 落库 ✓。
