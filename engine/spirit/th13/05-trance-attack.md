## 0. 一句话结论（地址链）

```
灵界标志 GAME_FLAGS 0x4be830 bit 0x100（TranceManager::begin 0x405a60 置位）
        │
        ▼  每帧、开火时
FUN_00446000(player, timer)  ← 本帧的 shooterset ticker（由 Player::on_tick 0x443bff 调 FUN_004460d0 再调进来）
        │  0x446006  test dword [0x4be830], 0x100
        │  0x446011  jne 0x446036
        │  0x446036  mov eax, 0xa          ★ 灵界 ⇒ 组号**硬编码 10**
        │  0x446041  mov esi, [ecx + eax*4 + 0xc8]   ← pl0Xa.sht 的组指针数组
        ▼
同一个循环按 row[i] 发射：(timer % row->rate == row->delay) → FUN_00445c40(player, row, timer, &player->pos)
        ▼
FUN_00445c40 尾部 0x445e0c  movsx ecx, word [row+0x22] / 0x445e10 add ecx, 0xa
        → AnmLoaded::copy_vm(vm, player+0x10, script = row->anm + 10)   ← 【0x403800】
```

**一句话**：灵界不改任何一发子弹的伤害或速度公式，它**把主炮的 shooter 组从「火力档/聚焦算出来的 0..9」换成 pl0Xa.sht 里那一组固定编号 10 的组**。
四个角色各有一组，组内容本身就是全部差异（条数 / 角度 / 速度 / 增伤 / 贴图 / 是否有诱导）。

## 1. 证据前提：TH13 的 `.sht` 布局（本文首次逐字节钉死）

TH13 的四个自机文件是 `pl00a.sht` / `pl01a.sht` / `pl02a.sht` / `pl03a.sht`（`thdat -x 13` 解出，3200/2752/4040/2640 B）。

### 1.1 载入/解析器 = `FUN_00443e40` ✅

`0x443e45 call 0x4724c0`（load file）→ `0x443e4a mov [esi+0x660], eax`（**`player+0x660` = sht 影像**）。随后：

```c
n = *(u16*)(buf + 2);                          // 0x443e5c cmp cx,[eax+2]
for (i = 0; i < n; i++) {                      // ecx 从 0xc8 起、每次 +4
    *(int*)(buf + 0xc8 + i*4) += buf + 0xf4;   // ★ 0x443e7c add [ecx+eax],edi ; edi = buf+0xf4
    for (row = *(char**)(buf + 0xc8 + i*4); *(i8*)row >= 0; row += 0x38) {   // 0x443ec4 add eax,0x38
        row[0x28] = table_0x4bb8d0[row[0x28]];  // SHT_ON_INIT_FUNCS
        row[0x2c] = table_0x4bb4d4[row[0x2c]];  // SHT_ON_TICK_FUNCS
        row[0x30] = table_0x4dc66c[row[0x30]];  // SHT_ON_DRAW_FUNCS
        row[0x34] = table_0x4bb8e8[row[0x34]];  // SHT_ON_HIT_FUNCS
    }
}
```

| 项 | TH13 值 | 一手 |
| --- | --- | --- |
| 头部 `+0x00` u16 | `3`（四文件同值，含义未定 ❓）| 逐字节 |
| 头部 `+0x02` u16 | **`11` = 组指针数组长度** | `0x443e5c` 读它当循环上界 |
| 数组位置 / 重定位基址 | `+0xc8` / **`+0xf4`**（= 0xc8+11×4）| `0x443e76 lea edi,[eax+0xf4]`、`0x443e7c` |
| 组内 row 步长 | **`0x38`**（TH18 是 `0x5c`，别套用）| `0x443ec4`、`0x4460b2` |
| 组终止符 | 4 字节 `ff ff ff ff`（`rate < 0`）| 逐字节 |
| 组内 row 字段 | 见 §1.2（偏移逐项）| 一手：与 TH18 同名前缀一致 |

> **组号 ↔ row 数**（一手逐字节，用于下文对照）：灵梦 `2/3/4/5/6 // 2/4/6/8/10 // 灵梦灵界 2`；
> 魔理沙 `2/3/4/5/6 // 2/3/4/5/6 // 4`；早苗 `2/5/7/9/12 // 2/4/6/8/10 // 2`；妖梦 `2/3/4/5/6 // 2/3/4/5/6 // 2`。
> 前 5 组 = 非聚焦火力档 0..4，后 5 组 = 聚焦火力档 0..4（组号公式见 §1.3），**第 11 组（号 10）= 灵界专用**。

### 1.3 `FUN_00446000` = 每帧 shooterset ticker ✅（0xc1 字节，`ret 4`）

```c
void FUN_00446000(Player* p /*edi*/, int timer /*[ebp+8]*/) {
    int set;
    if (GAME_FLAGS & 0x100) set = 10;                         // 0x446006 test / 0x446011 jne / 0x446036 mov eax,0xa
    else {
        set = GLOBALS.power_4be7e8 / GLOBALS.power_per_lvl_4be7f0;   // 0x446013–0x446019
        if (p->focus_14840 != 0) set += p->sht_660->pwr_lvl_cnt_20 + 1;  // 0x44601f–0x446030
    }
    for (row = ((char**)p->sht_660)[0xc8/4 + set]; row->rate >= 0; row += 0x38) {   // 0x44603b–0x4460b7
        if (timer % row->rate != row->delay) continue;        // 0x446050–0x44605f
        if (row->mode == 2 && p[0x146d8 + row->slot*4] != 0) continue;  // 0x446061–0x446072（子机 mode2 去重表）
        node = p->+0xa2a4;  if (!node) continue;              // 0x446074–0x44607c（自机弹池空闲链）
        unlink(node);  FUN_00445c40(node /*EAX*/, row, timer, &p->pos_5b8);   // 0x44607e–0x4460aa
    }
}
```

- **`set = 10` 是硬编码常量**，不吃火力档、不吃聚焦 ⇒ **灵界里聚焦与非聚焦打的是同一套弹**（这是「灵界没有低速/高速之分」的来源）。
- `pwr_lvl_cnt_20` 四文件都是 `4` ⇒ 聚焦组 = 非聚焦组 + 5。
- `FUN_00445c40` 的 EAX 传入（ZUN 的 usercall 风格）是池节点；其函数头 `0x445c50 mov [edi+0x70],1` 写状态、`0x445c57 mov [edi+0x94],ebx`(row) 、`0x445c93 movsx eax,word [ebx+2]; mov [edi+0x84],eax`（**伤害 = row->dmg，没有任何倍率**）、`0x445d41 fstp [edi+0x44]`（速度）、`0x445e0c`–`0x445e47`（anm = `row->anm + 10`）。

### 1.4 谁调它 / 谁提供 timer ✅

`Player::on_tick` `0x443240` 在 `0x443bff` 调 `FUN_004460d0(player)`。调用门卫（`0x443bcc`–`0x443bfb`）：
`GUI_PTR->+0x198 == 0`（无对话）、`ENEMY_MANAGER_PTR != 0` 且 `+0xb8 != 0`（场上有敌）、
`GAME_THREAD_PTR->+0x60 & 0x4000 == 0`、`player+0x690 >= 0x14`；
`FUN_004460d0` 自己再要 `player+0x65c == 1`（`0x4460e0`）。它里面有三处 `call 0x446000`：

| 调用点 | timer 实参 | 适用 |
| --- | --- | --- |
| `0x4462d2` | `player+0x146a4`（蓄力计时）+ 0x28 | 妖梦「聚焦 + 蓄力负相位」 |
| `0x4463ea` | 同上（临时把 `+0x14840` 强行置 1 = 聚焦组）| 妖梦「非聚焦时的斩击」 |
| `0x44645b` | `player+0x146cc`（主炮计时）| **所有人**的常规开火路径 |

⇒ 灵界改的是 `FUN_00446000` 的**组号**，改不到别的。

## 3. 妖梦的蓄力：计时器在哪、灵界怎么绕过 ✅

**计时器**：`player+0x146a0` 是一个 **`zTimer`**（`+0x0` prev / `+0x4` **current** / `+0x8` current_f / `+0xc` game_speed / `+0x10` control）：

| 动作 | 指令 |
| --- | --- |
| 初始化（`Player__on_tick` `0x443c7c`–`0x443c96`）| `current=0`、`prev=-999999`（`0xfff0bdc1`）、`game_speed=0x4c0a28` |
| tick | `0x446169 lea esi,[ebx+0x146a0]` + `call 0x401400`（= `zTimer::tick`，内部 add game_speed→ftol）|
| 归零 / 设值 | `0x4016c0`（= `zTimer::set`：`prev = v-1`、`current = v`）|

**状态机**（全在 `FUN_004460d0`，且**外面套了 `cmp [0x4be7b8],3` ⇒ 只有妖梦走这套**，`0x4460ec`–`0x4460f3`）：

| 相位 | 触发 | 指令 | 行为 |
| --- | --- | --- | --- |
| 起蓄 | 聚焦 + 射击键 + `charge == 0` | `0x446106`–`0x446163` | 播音效 0x1d、在自机处起 anm **script 0x12** 的蓄力 VM，句柄存 `player+0x146b4` |
| 蓄力 | 同上 + `charge > 0` | `0x446169`–`0x4461ff` | 每帧 `zTimer::tick`；**这一相位完全不调 `0x446000` ⇒ 不发弹**；`charge == 0x3c`(60) 时播音效 0x1e/0x37 并给 VM 发 interrupt |
| 释放 | 松开射击键 / 松开聚焦 | `0x446208`–`0x4462a3` | 拆 VM；`charge >= 60` ⇒ `zTimer::set(-40)` 并存下自机坐标 `+0x146b8/0x146bc/0x146c0`；否则 `set(0)`（空放）|
| 斩击 | `charge < 0` | `0x446290`–`0x446310` | 把自机坐标**换成释放瞬间记下的坐标**，调 `FUN_00446000(p, charge+40)`（timer 0→39 正好把 set9 的 delay 0/8/16/24/32/39 六段各命中一次），再换回坐标 |
| 非聚焦斩 | 非聚焦 + `charge < 0` | `0x446399`–`0x4463fe` | 与上同，但**临时把 `+0x14840` 置 1**（借用聚焦组）后再还原 |

⇒ 「蓄满 60 帧 → 松手 → 40 帧内 6 段斩」是**同一条 `charge` 负相位**驱动的 ✅。

**灵界怎么做到「无需蓄力、按住就连发」**：灵界**不改** `FUN_004460d0`（那里一处都没读 `0x4be830`）。
它改的是 `set=10`，而**非聚焦路径**（`0x44641b` 起的常规循环）根本不进蓄力分支 ⇒
**非聚焦按住射击键时，`FUN_00446000` 每帧被调、每帧取 set10、`rate=30` 到点就出刀**。
⚠ 反过来说：**若在灵界里按住 Shift（聚焦），蓄力状态机照旧生效**（那一条路与灵界正交）。
用户口径「无需蓄力」在**非聚焦**下 ✅ 成立，在**聚焦**下 ❓ 需实跑确认（静态看仍要蓄）。

## 4. 魔理沙的灵界移速 ×3/2 ✅

`Player::move` `0x442960`，`0x442bcb`–`0x442bf8`：

```asm
0x442bcb  cmp dword ptr [0x4be7b8], 1        ; CHARACTER == 1（魔理沙）
0x442bd2  mov ebx, dword ptr [0x4be830]
0x442bd8  mov dword ptr [ebp-4], ecx
0x442bdb  jne 0x442bfb                        ; 不是魔理沙 → 跳过
0x442bdd  test ebx, 0x100                     ; 不在灵界 → 跳过
0x442be3  je   0x442bfb
0x442be5  lea eax, [eax+eax*2]                ; eax = 水平速度 ×3
0x442be8  cdq / 0x442be9 sub eax,edx / 0x442beb sar eax,1   ; ÷2（向零取整）
0x442bed  mov [ebp-8], eax
0x442bf0  lea eax, [ecx+ecx*2] … 同款          ; 垂直速度同样 ×3/2
0x442bf8  mov [ebp-4], eax
```

- 两个分量都乘 **3/2**（`(3v - sign) >> 1`，即向零取整）⇒ **移速 = 1.5×** ✅。
- 同一函数里 `0x442c1f test ebx,0x100 / jne 0x442cb2` 是**第二处灵界分支**：四个朝向/运动相位分别取
  `AnmLoaded::copy_vm(player+0x14, player+0x10, id)`（`0x403800`）——**非灵界 `1/2/3/4` ↔ 灵界 `6/7/8/9`**，即整套走路动画 +5。
  一手：`0x442c61`(3)/`0x442c7f`(2)/`0x442cab`(4)/`0x442c3f`(1) 对 `0x442cc6`(6)/`0x442d03`(7)/`0x442ce8`(8)/`0x442d27`(9)。

### 6.2 `FUN_00446f20`（灵界里被跳过的那条）🟡

`SHT_ON_TICK_FUNCS[2]`（`0x4bb4d4[2]`）。它做两件事：① 把弹的位置/角度绑到它所属**子机**的位置上（读 `[player+0xa230 + slot*0xe4]`）；
② 当「子机槽号 − 1 < `player+0x146c4`」且「`player+0x146cc >= 0`」且「`player+0x146d8[slot] == 火力档`」且「非聚焦」且 **不在灵界** 且没有对话 时，
把弹状态 `+0x70` 由 1 改成 2、给弹 VM 发 interrupt 1（`0x46fc30`）、清 `player+0x146d8[slot]`、播音效 0x14。
⇒ 语义上像「子机弹到位/变成可命中」，**灵界里这一步被跳过** ⇒ 灵界中这类弹停在状态 1。**用户口径没有提到这个现象**，标 🟡 待实跑。
