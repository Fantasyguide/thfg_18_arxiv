> **版本**：TH08 v1.00d（`th08.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用 TH18 须写成 `th18:0x…`。

> §3 的字段图 🟡（少数列语义未坐实，逐条标）；§4 的映射 ✅ 算术。

## 0. 一句话结论

- TH08 的 `plyNNas.sht`（**妖侧**，`a` = 人侧 / `as` = 妖侧）里，**偏移数组的每一项 = 一个火力档**，
  档的阈值存在槽的 `+0x4`：实测三份文件都是 **`8 / 24 / 48 / 80 / 128 / 999`**。
- ⇒ 第一版卡 108 只搬了**一格**（`ply03as.sht` 的 slot 4 = **妖夢＆幽々子的妖侧、4.00 火力档**），
  四个机体共用 ⇒ 这正是 owner 说的「都是同一个弹幕、火力大概 4P」（**读数完全正确**）。
- 两作 P 的显示单位都是 x.xx、上限 4.00（TH08 `P/32`、TH18 `P/100`）
  ⇒ **TH18 档 `k` ↔ TH08 slot `k`**（§4 给了算术）⇒ 每角色每档都能照抄。

## 1. 发现：档位循环（生成器 `FUN_00450f60` `0x450f60`）

唯一生成器，`Player::UpdateChargeShotTimer` `0x451595` 每帧调。一手逐指令：

```
450f6c  mov eax,[ebp-0x18]              ; = Player*
450f6f  movzx ecx,BYTE PTR [eax+0x3]    ; ★ player+0x3 = isYoukaiMode
450f75  jne 0x450f88
450f7a  mov eax,[edx+0xe2a74]           ; 人侧：g_PlayerShtFile  （= plyNNa.sht）
450f80  add eax,0x38                    ; 跳过 0x38 的头 ⇒ 落在**槽数组**首项
        …
450f8b  mov edx,[ecx+0xe2a78]           ; 妖侧：g_PlayerShtFile2（= plyNNas.sht）★
450f91  add edx,0x38
450f97  mov [ebp-0x8],eax               ; ptr = 槽数组首项
450fa0 … 死亡炸弹那两支（shotActive + unk4）：ptr += 6 或 7 个槽（另一套表，本文不涉及）
451005  mov ecx,0x160f508               ; g_GameManager
45100a  call 0x422480                   ; ★ GameManager::get_current_power
451012  cmp eax,DWORD PTR [ecx+0x4]     ; ★ 与**槽的第二个 dword** 比 = 该档的阈值
451015  jl  0x451022                    ; 未达阈值 ⇒ 停在这一档
45101a  add edx,0x8                     ; 达阈值 ⇒ 下一个槽（槽 = 8 字节）
451020  jmp 0x451005
451022  mov eax,[ebp-0x8]               ; ★ 选中的槽
451025  mov ecx,DWORD PTR [eax]         ; 槽[0] = 该档**第一条行的文件内偏移**（加载时已重定位成指针）
451027  mov [ebp-0x14],ecx              ; row = 组的第一行
```

- **槽 = 8 字节**：`[0]` = 该档第一条行的指针（加载器 `Player::LoadShtFile` `0x44dd70` 把文件内偏移
  `add ecx,[base]` 重定位）；`[1]` = **火力阈值**（i32，与 `get_current_power()` 无符号/有符号按 `jl`
  即**有符号**比较）。
- **行指针从槽选中之后**按行的终止符（`row[0] < 0`）逐行走（`0x451071`–`0x45108b`）。

⇒ **档位不是数据里的"组号"，而是"离头部第几个槽"** ⇒ 三个 TH08 角色的 `plyNNas.sht` 各自一张表。

## 4. 映射到 TH18 的火力档（算术，逐条可复核）

1. **两作的 P 显示单位相同**：TH08 `P/32`（上限 128 = `4.00`）、TH18 `CURRENT_POWER/100`（上限 400 = `4.00`）。
2. TH18 档 `k` 的 P = `100k`；折算成 TH08 的 P：`P08 = 100k × 128/400 = 32k`。
3. 用 §1 的循环判据（`P08 >= 阈值`）取最后一个满足的槽：

| TH18 档 k | P18 | P08 = 32k | 命中的 TH08 slot（阈值）|
| ---: | ---: | ---: | --- |
| 0 | 0 | 0 | **0**（`0 < 8` ⇒ 停在首项）|
| 1 | 100 | 32 | **1**（`32 >= 24`，`32 < 48`）|
| 2 | 200 | 64 | **2**（`64 >= 48`，`64 < 80`）|
| 3 | 300 | 96 | **3**（`96 >= 80`，`96 < 128`）|
| 4 | 400 | 128 | **4**（`128 >= 128`）|

⇒ **`TH18 档 k ↔ TH08 slot k`，一一对应**（这就是「卡 108 取哪一格」的判据，不是自定）。
⚠ 范围限于 `k = 0..4`；TH08 的 slot 5（阈值 999）本作够不到，本卡不用。

## 5bis 早苗那一侧（✅ 2026-09-26 补齐）：TH16 `pl03sub.sht` = **秋（射命丸文）**

- **一手**：TH16 的**副 .sht**（`plNNsub.sht`）= 「副季节子机打的弹」，五副季节各一份
  （春 `pl00sub` / 夏 `pl02sub` / **秋 `pl03sub`** / 冬 `pl01sub` / 土用 `pl04sub`），
  逐档数值表见 [`../../season/th16/01-season-data-and-tables.md`](../../season/th16/01-season-data-and-tables.md) §5.5；
  而早苗的搭档是**文（秋）** ⇒ **她的妖侧弹 = `pl03sub` 的秋弹**。
- **档位映射**（这一层是我们的决定）：TH16 的季节档 `k` = 子机数（set k ⇒ k 台），
  而本卡早苗的妖侧子机数 = `floor(P/100)`（TH18 档 0..4）⇒ **两边天然对齐：TH18 档 k ⇒ TH16 sub set k**
  （k = 1..4 有行；k = 0 = 空组，她那时也不出妖侧弹）。`0x16`（TH08 妖夢那一组）只当最后一层兜底。
- **两处偏离**（照实登记）：① 发射节奏取行里的 `+0x26 fr2`（8 / 12 帧）当作 TH18 的 `fire_rate`
  （TH16 那一支走 120 帧备用计时器，本作不用那一路）；② 加速度 TH16 `tick5` = **+0.5/帧**，
  TH18 同族的是 `tick3` = **+0.3/帧**（[`../th18/03-func-tables-timers-and-dead-fields.md`](../th18/03-func-tables-timers-and-dead-fields.md) §6）
  ⇒ 取同族最接近的一支。弹贴图沿用本文件原生主炮那一支（文自己的弹贴图没切进 `ability.anm`，同 §3 的缺口）。
