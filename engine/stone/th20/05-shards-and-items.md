## §0 一句话结论

TH20 的「异变石碎片」**就是道具类型 `0xd`（=13）那一族**：它由 **擦弹**（`0x4f91d0` 返回 2 →
`0x4f8b90`）、**持续命中造成的伤害**（命中管线 `0x4c0480`）、**击破敌人**（`0x47d3d0` /
ECL 掉落表）与**击破裂变敌**（`0x512fb0`）四条通道产出；道具被吃下时经 `0x533780` 往
**`FUN_00464080(0)` 对象的 `+0x4c`** 累加碎片数（上限 500），累到该对象的 **`+0x50`**
阈值（每块石不同：130/130/150/150/180/130/130/150）即触发 `0x534d00`（升格特效 + SE）。
**Wiki 三条口径逐条为真**（§3），但「这个 `+0x4c` 槽就是玩家侧那条 280.0 的异变攻击槽」
目前只有间接证据 → 🟡（§2.4）。

## §2 碎片道具

### 2.1 碎片 = type `0xd`（=13），不是 9..12

- 四条掉落通道**全部请求 `0xd`**（§3），只有 ECL 掉落表能点名 9..12 ✅。
- `0xd` 出生走 **state 5**（`+0xc24 = 5`）、`+0xc34` = 错帧延时，延时归零后
  `0x4c4420` 把它翻成 **state 2** 并**随机定色**：`rand() % 8 < 5` 时
  `+0xc28 = FUN_004641d0(mgr, rand()%4) / 2 + 9`，否则 `+0xc28 = rand()%4 + 9` → 落在 **9..12** ✅。
- 因此吃下的那一刻 `+0xc28` 已是 9..12，`0x4c25a0` 的 `switch(类型-1)` 里 `case 0xc`（type 13）
  实际不可达（它与 `case 8` 共用同一段代码，都指向 `0x4a9ec0` = 色 0）。

### 2.2 加在哪：`FUN_00464080(0)` 对象的 `+0x4c`

| 字段 | clamp | 作用 | 读 / 写址 |
| --- | --- | --- | --- |
| `+0x4c` | `[0,500]` | **碎片蓄积量** | 读 `0x51b8a0`、加 `0x533920`、置 `0x4be940` ✅ |
| `+0x50` | `[100,500]` | **升格所需碎片数** | 读 `0x51b920`、置 `0x4bea00` ✅ |
| `+0x54` | `[1,100]` | 与 `+0xa8` 一起算异变攻击时长（`0x534260`） | 读 `0x51b8e0`、置 `0x4be9b0` ✅ |
| `+0x98` | 0..3 | 刚满格的颜色下标（`0x4a9d80/9e60/9ec0/9f20` 写） | ✅ |
| `+0x64/0x68/0x6c/0x70` | wrap `1000`（`0x4aafa0`） | 四色的异变石计数（每个石头道具 `+10`） | ✅ |
| `+0x60` | `[0,5000]` | 另一条槽（见 §2.4），难度上限在 `0x5333b0` 里置 | 读 `0x513e60`、加 `0x513c70`、置 `0x4be710` ✅ |
| `+0x5c` | `[0,10000]` | 上一条槽的「显示/跟随」值 | 读 `0x499520`、置 `0x4be620` ✅ |

**加碎片的唯一函数** = `0x533780(target, n)`（在语料里只有 4 个调用点，全是道具拾取 switch）✅：

```
0x533780(target, n):
  if (paused || target+0x54 != 0) return;                 // 暂停/演出中不结算
  step = 10（或 15，取决于 FUN_00464400(mgr) 的慢速模式）
  if (0x534390(mgr)) {                                    // mgr+0xa4 字节开关
      if (0x51b8a0(mgr) % step == step-1) { n++; 0x4865b0(target+0x34, 1); }   // 每 step 个多送 1
  }
  if (0x51b8a0(mgr) < 0x51b920(mgr)) {                    // 未满
      0x533920(mgr, n);                                   // +0x4c += n（clamp 500）
      if (0x51b920(mgr) <= 0x51b8a0(mgr)) { 0x4be940(mgr, 0x51b920(mgr)); 0x534d00(); }
  } else { 0x4be940(mgr, 0x51b920(mgr)); 0x534d00(); }     // 已满：钉住并重复升格演出
```

> 这里 `mgr` = `FUN_00464080(0)`、`target` = `FUN_00464230(0)`（两者是同一条槽记录里的两个成员，
> 见 §2.3）；满格演出 `0x534d00` 会播 SE `0x1c`、在自机位置放 **effect 脚本 `0x1d`**、
> 并把 `target+0x54` 置 1 ✅。

### 2.3 阈值 = 每块石一张表（`0x5333b0`）

`0x5333b0`（stone weapon 复位）里按 `idx = *(mgr+0xc)`（当前装备的异变石 0..7）取两张表：

| 目标字段 | 数组（`local_a8[8..0xf]` / `local_a8[0x10..0x17]`） | 写入函数 |
| --- | --- | --- |
| `+0x50` 碎片阈值 | **130, 130, 150, 150, 180, 130, 130, 150** | `0x4bea00` ✅ |
| `+0x54` 时长参数 | 30, 30, 40, 65, 100, 60, 70, 20 | `0x4be9b0` ✅ |
| `+0x60` 上限（按难度 `*DAT_005c6110`） | —, 1100, 1200, 1300, 1400 | `0x4be710` ✅ |

⇒ **8 块石 = 灵梦/魔理沙 × R/B/Y/G**（`weaponred.cpp` / `weaponblue.cpp` / `weaponyellow.cpp` /
`weapongreen.cpp` 各有 `_m` 变体），每块石有**自己的碎片阈值**；这就是「异变攻击槽」的档位量纲。

### 2.4 它是不是「异变攻击槽」—— 🟡

- **支持**：`+0x50` 是每块石各自的「蓄积目标」、满了 `0x534d00` 出升格演出，
  且 HUD（`stonemenu.c` 的 `case 6` 段）用 `0x51b8a0(mgr) / 0x51b920(mgr)` 当**条状仪表的填充比** ✅。
- **不支持 / 未解**：玩家侧那条 float `*(player+0x5c8) + 0x60`（上限 `280.0` = `0x575d58`）
  在语料里**只找到减法**（`0x5316c0` 的 `-280/时长`、`0x531d30` 的 `+0x90 -= 280/时长`），
  **没有任何写入 280 的代码** ⇒ 充能路径没反到（§5）。
- 同一对象上还有第二条槽 `+0x60`（clamp 5000，难度上限 1100..1400），
  击破裂变敌时 `+150`（`0x511f00` → `0x513c70(mgr, 0x96)`），HUD 用 `/5000` 画它。
  **`+0x4c/+0x50` 与 `+0x60/+0x5c` 谁是「异变攻击槽」尚不能从一手区分 → ❓**。

## §3 掉落通道

统一入口是**累加器生成器** `0x4a9f80(dropMgr, pos, amount, type)` → `0x533720(dropMgr+0x38, …)` ✅：

```
0x533720(this, pos, amount, type):
  this[0] += amount;                                   // 累加
  while (this[4] < this[0]) {                          // this[4] = 阈值
      0x4c45b0(FUN_00498fd0(0), pos, 1, type);         // 生成 1 个 type 号道具
      this[0] -= this[4];
  }
```

⇒ **「投入量 ÷ 阈值」= 实际掉几个**。阈值在 `dropMgr+0x3c`，**设值点未反到 → ❓**（§5）。

| # | 通道 | 证据 | 投入量 / 类型 | 可信度 |
| --- | --- | --- | --- | --- |
| 1 | **擦弹** | 命中测试 `0x4f91d0` 返回 **2 = 擦弹** → `0x4f8b90(player, pos, u)` | 投入 **1000**（慢速模式 `0x5dc`=1500），type `0xd` | ✅ |
| 2 | **持续命中（伤害）** | `0x4c0480`（hit.cpp 命中管线）内 `FUN_004a9f80(dropMgr, pos, damage, 0xd)` | 投入 = **本次伤害**（某标志位置位时 **×10**），type `0xd` | ✅ |
| 3 | **击破普通敌人** | `0x47d3d0(this, pos, kind)`：`kind==1` → 1 个；`kind==4` → 每 5 个一次给大件 | type `0xd`（也生成 type `2`） | ✅ |
| 4 | **击破裂变敌（StoneEnemy）** | `0x512fb0`（`stoneenemy.cpp:76 StoneEnemyInf` 的 Start） | 投入 **2000**，type = `rand%5 + 9`（即 9..13，含碎片） | ✅ |
| 5 | **ECL 掉落表** | `0x4a5df0` 里的 15 计数循环（`type = i+1`，i=0..14） | 逐类型计数，含 15（伪类型） | ✅ |
| 6 | ECL 两槽掉落 | `0x48bf10(this, pos, flag)`：按 `this+4` / `this+8` 选类型 | 任意 type | ✅ |
| 7 | 消弹/炸弹 | 自机炸弹代码（`bomb_reimua.cpp` 段）7 连发 | type `1` ×7 | ✅ |
| 8 | 石武器释放 | `0x5312d0` 释放时生成 1 个 | type `6` | ✅ |

### 3.1 擦弹通道逐条（`0x4f8b90`）✅

```
0x4f8b90(player, pos, u):
  0x4fe8d0(player, 1);                    // player+0xe4 += 1，clamp [0,99999999] = 擦弹计数
  0x49dc60(effectMgr, rand%4, 4, &pos, 0);// 随机色特效
  n = paused ? 1000 : 1500;
  0x4a9f80(FUN_00464230(0), pos, n, 0xd); // ★ 碎片
  0x4a9fb0(FUN_00464080(0), u ? 50 : 10);// +0x44 += 10（或 50）= 最大得点累加
  0x426eb0(&DAT_005ba830, 0x2a, pos.x);// SE 0x2a = se_boon01.wav
```

- 五个调用点全在 `0x4f91d0(...) == 2` 之后：`0x4d2750`（`game_b.c:5425`）、
  `0x4a5df0`（`game_b.c:26552`，用自机自身坐标）、`0x4d2a20`、`0x4d2dd0`（`game_c.c`）✅。
- `0x4f91d0` 的三态 ✅（一手反编译）：小半径不重叠 → `0`；大半径不重叠 → `2`（擦弹）；
  两圈都重叠且未无敌 → 调 `0x4f86f0()`（死亡）后返回 `1`（被弹）。
- ⚠️ **`se_graze.wav`（SE 表 22 号）在 TH20 全语料里 0 个播放入口** —— 擦弹播的是
  `se_boon01`（`0x2a`）。这条是**否定结论**（不是没反到）：`DAT_005ba830` 的所有调用点里没有 22。

### 3.2 击破裂变敌（Wiki 的「大量掉落」）✅

`0x512fb0`：按 `rand()%5` 选色，`0x4a9f80(FUN_00464230(0), 敌坐标, 2000, rand%5+9)` +
`0x4a9fb0(mgr, local_2c)`（最大得点）+ 按色 `0x4a9de0(mgr, color, local_2c)`（色计数）。
另外 `0x511f00`（与该类绑定的回调）在击破时 `0x513c70(mgr, 0x96)` = **`+0x60 += 150`** ✅。
⇒「击破裂变敌大量掉道具」为真，且**除了碎片还直接灌色计数**。

> 「对象成员 + 每石单阈值」；② 碎片走的是**通用累加器生成器**（投入量÷阈值），
> 不是 TH16 的「按累计伤害一对一出」；③ TH20 的碎片同时喂**色计数**（`+0x64..+0x70`）。
