## 0. 一句话结论

**是「中弹时查询异变攻击 → 取消 Miss」**，而且判据**不是** 06 §5 说的石头槽 26，
而是管理器上的状态字：玩家受击处理 `FUN_004f86f0` 读 **`WeaponStoneInf+0x54`**
（经 `FUN_004ff6d0` = `*(x+0x54)`），`== 1`（异变攻击进行中）时**根本不进死亡分支** ——
只把攻击状态置 2（`FUN_004ffec0(wsInf,2)`）并给 4 帧受击无敌（`player+0x2050 = 4`）；
`!= 1` 时才写 `player+0x10 = 4`（死亡态）并开 **8 帧**决死窗口。**可信度 ✅ 高**（一手 + 分支互斥 + 读写点闭合）。

⚠ **对 brief 前提的两条订正（✅ 字节级）**：
1. `DAT_005ba828` **不是玩家对象**，是 `FUN_004bec70` 里 `FUN_004b9b10()` `operator_new(0x110)`
   出来的 **`GameInf`**（`FUN_004b9df0` 写 `GameInf::vftable`）。它只被用到 `+0xe8` / `+0x38` /
   `+0x108`（直读）与 `+8`（只经 `FUN_00464350`）、`+0x10c`（只经 `FUN_00511590`/`FUN_004bd980`）。
   ⇒ 「玩家 `+0xe8` 位场」与「玩家 `+0x10c`」实为 **GameInf** 的字段，**与本链无关**（§2/§3）。
2. 玩家（`PlayerInf`，`FUN_00460830(0)`）**没有** `+0xe8` 标志位：`FUN_004f46a0`（含串
   `"initialize PlayerInf"`）的初始化列表从 `+0x28`（一个子对象 `FUN_00448b40`）直接跳到
   `+0x60c`，**从不初始化 `+0xe8`**；全语料也没有任何函数把 `+0xe8` 位运算施加到玩家指针上。
   玩家的「无敌 / 死亡 / 被弹」状态在**别的偏移**（§2.2）。

⚠ **对 06 §2 阶段①的订正（🟡→✅）**：`FUN_00534300(DAT_005ba828) = (GameInf+0xe8 >> 6) & 1`
是 **GameInf** 的 bit6，其**唯一置位者** `FUN_00511590` 的**唯一调用点**是 `FUN_00510b60`
（`StageClearInf::Calc`，结算段）。⇒ 06 §2 阶段①那次「取消攻击」是**关卡结算时的收尾**，
与中弹无关。中弹走的是 §0 那条**完全不同的**路径。

## 3. 「攻击进行中」查询接口的**全部**调用点判定

## 4. 与决死 Bomb 的相对位置

```c
// FUN_004f7430（玩家每帧）case 4 = 玩家态 4（死亡/决死窗口）
local_a0 = (void *)((int)player + 0x644);
bVar2 = FUN_004235c0(local_a0, *(int *)((int)player + 0x2204));   // 0x644 计时 >= 0x2204 ?
if (!bVar2) {                       // ← 还没到 8 帧：窗口开
  iVar4 = FUN_00424010(*(int *)((int)player + 0x14858));          // 槽记录 +0x18 = 输入对象
  if (iVar4 != 0) {
    local_54 = FUN_004b58e0(local_a4, 4);    // ★ (输入对象+0x2a8) & 4 = 炸弹键
    if (local_54 != 0 && FUN_004780a0(iVar4) != 0) {   // 且还有炸弹
      FUN_00477e30(iVar4);
      FUN_004f86c0(local_24);                // ★ 决死 Bomb 成立
    }
  }
  break;                            // 继续等
}
FUN_004f8420(local_24);             // ★ 满 8 帧 → 提交死亡
```

| 项 | 值 / 地址 | 可信度 |
| --- | --- | :-: |
| 窗口长度常量 | **8 帧**（`player+0x2204`；`FUN_004ffd00(player,8)` 与 `FUN_004fb450` 两处都写 8） | ✅ |
| 窗口计时器 | `player+0x644`（Miss 时清 0，每帧 `FUN_00423540` 递增，递增点在 `FUN_004f7430` 尾部 5582） | ✅ |
| 窗口判定 | `FUN_004235c0(player+0x644, player+0x2204)` = `长度 <= 计时`（到点即关窗） | ✅ |
| 炸弹键读取 | `FUN_004b58e0(x,4) = *(x+0x2a8) & 4`，`x = FUN_00424010(槽记录)` = `*(槽记录+0x18)` | 🟡 |
| 「还有炸弹吗」 | `FUN_004780a0(root_0)`：`FUN_00477ff0(FUN_0041caf0(*(x+0x38))) > 0`，`FUN_00477ff0` = 把 `+0xcc` clamp 到 `[0,10]` | 🟡 |
| 决死 Bomb 生效 | `FUN_004f86c0(player)`：`player+0x644 = 0x3c`、`player+0x10 = 1` | ✅ |
| 提交死亡 | `FUN_004f8420(player)`：`player+0x10 = 2`、`player+0x2050 = 0xb4`（180 帧无敌）、effect `0x15` | ✅ |

### 4.1 两条保命路的相对位置（**互斥，不是串联**）

| 情形 | 谁处理 | 结果 |
| --- | --- | --- |
| 被打时 **`wsInf+0x54 != 1`** | `FUN_004f86f0` 的 **else** | 进 `player+0x10 = 4` ⇒ **开 8 帧决死窗口**，可按炸弹 |
| 被打时 **`wsInf+0x54 == 1`** | `FUN_004f86f0` 的 **if** | **不写 `player+0x10`** ⇒ 不进死亡态 ⇒ **连决死窗口都不开**（只剩 `player+0x2050 = 4` 帧无敌） |

- **结论（✅）**：异变攻击抵消发生在**决死窗口之前**（`FUN_004f86f0` 是窗口的开启者），
  二者由同一个 `if/else` 二选一 ⇒ 「攻击进行中被打」时**不可能**再触发决死 Bomb
  （因为 `player+0x10` 不是 4，`FUN_004f7430` 走 case 1 而不是 case 4）。
- ❓ 需要实跑/存档验证的部分：4 帧无敌是否够、抵消时攻击是否真的「接着发动而不是白给」、
  以及抵消是否消耗残机（按代码**不消耗**：`FUN_004f8420` 里的 `FUN_004e1250(x,-1)` 才在 else 路）。
- 旁证（🟡）：`FUN_004780a0`（「能否扔炸弹」）的形状在 bomb.c 47-48 的 bomb 输入路径里
  被一模一样地复用（`0 < iVar2 && !FUN_00478130(param_1) && DAT_005c06a4 != 0 && …`）
  ⇒ 它是全局的「炸弹可用」谓词，不是本链专属。
