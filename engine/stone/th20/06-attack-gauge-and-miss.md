# stone 逆向 06：异变攻击的发动 / 时长 / 收尾状态机

> **版本**：TH20 v1.00a（`th20.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th18:0x…`。

> 方法：一手反编译（`local/th20.v1.00a/decomp/*.c`）+ RTTI 复原的虚表槽位（`local/th20.v1.00a/th20-rtti.json`）
> + `.rdata` 常量直读（`tooling/pe_read.py`）。日期 2026-09-28。分级 ✅高 / 🟡中 / ❓未解。
> 「抵消 Miss」那一条链**不在本文**，单独在 [`07-miss-cancel-chain.md`](07-miss-cancel-chain.md)。

## 0. 一句话结论

异变攻击是一个**三态状态机**，状态存在异变石管理器 `WeaponStoneInf+0x54`
（0 空闲 / 1 进行中 / 2 **被 Miss 抵消后的收尾态**），
**每帧由 `FUN_00532b20` 驱动**；发动走**主石对象的虚表槽 20**，收尾走**槽 22**（`FUN_00532f20` 把
`stone+0x34` 清 0），外部想知道「攻击是否进行中」问**槽 26**（`FUN_00530500` 读 `stone+0x34`）。
**时长**由 `FUN_00534260()` 现算（`base × (1 + a/100)`，`base` 上限 `0x4b0`=1200 帧），
发动时写进石头自己的计时器 `stone+0x14`；槽位下方那根线效果按 `280.0 / 时长` 每帧往下走
（`DAT_00575d58` = `0x438c0000` = **280.0f**，见 §4）。
★ **「抵消 Miss」在引擎里是真的**：中弹处理 `FUN_004f86f0` 读 `WeaponStoneInf+0x54`，
== 1 就不死、把状态推到 2（见 §5.1，链在 [`07`](07-miss-cancel-chain.md)）。

## 1. 状态机

`WeaponStoneInf+0x54`（int）：

| 值 | 含义 | 证据 |
| :-: | --- | --- |
| 0 | 空闲 / 无攻击 | `FUN_00532b20` 三处写 0 |
| 1 | **进行中** | 中弹处理读它做「抵消 Miss」判定（`FUN_004f86f0`）|
| 2 | **被 Miss 抵消后的收尾态** | 唯一置位者 = 中弹处理 `FUN_004ffec0(wsInf, 2)` |

- **发现**：`FUN_00532b20` 里 `*(int *)(this + 0x54)` 只用这三个值；
  `FUN_004ffec0`（写 `+0x54`）**全语料只有 1 个调用点** —— `FUN_004f86f0`（中弹处理）。
- **结论（✅）**：状态 2 = 「这一发被中弹打断、进入收尾」；`+0x54 != 0` 即「有攻击存在」。
- ❓ **0 → 1 的置位点**不在 `FUN_00532b20` 里（它只写 0 与 1→…，其中写 1 的那处是从状态 2 回到 1），
  尚未定位；可能与发动（§3）在同一处，由**主石槽 20 的调用者**完成。
- 证据：`FUN_00532b20`（`0x532b20`，1013 字节）；`FUN_004ff6d0` / `FUN_004ffec0`（读/写 `+0x54`）；
  `FUN_004f86f0`（唯一调用点）。

## 2. `FUN_00532b20` 的三个阶段（每帧）

| 阶段 | 做什么 | 关键调用 |
| --- | --- | --- |
| ① 收尾 | 若 `GameInf+0xe8` bit6 = 1（**关卡结算**）**且**状态 ≠ 0 ⇒ 清状态 + 结束攻击 | `FUN_00534300`、主石 slot22 |
| ② 状态 2 | 问主石 slot22：非 0 ⇒ 状态回到 1（攻击继续）；为 0 ⇒ 记掉落价值、起 60 帧计时器 | 主石 slot22 |
| ② 状态 1 | 轮询主石 slot21，非 0 就收尾（清状态 + `FUN_00534ab0()`）| 主石 slot21 |
| ③ 四槽 tick | 依次调 `+0x28`/`+0x2c`/`+0x30`/`+0x34` 的槽 15/16/17/18 | 四个石头对象 |

- 阶段①的 `FUN_00534300(x) = (x->+0xe8 >> 6) & 1` 里 `x` = **`GameInf`（`DAT_005ba828`）**，
  唯一置位者 `FUN_00511590` 的唯一调用点 = `FUN_00510b60`（`StageClearInf` 的结算回调）
  ⇒ **这一支是关卡结算时的收尾，不是中弹抵消**（✅，订正本文初稿的猜测）。
- 阶段②里 `DAT_0056cd98` / `DAT_0056f7b4` 两个常量被写进管理器 `+0x74`
  （`+0x74` 随后被用作**掉落道具的价值**，见阶段②尾部的 `FUN_00478e80`/`FUN_004caad0` 两处 spawn），
  ⇒ 🟡 **异变攻击期间会掉道具**（时长计时器 `this+0x64` 到点时掉一次）。❓ 待与
  [`05-shards-and-items.md`](05-shards-and-items.md) 的道具表对上。
- 证据：`FUN_00532b20` 全文；`FUN_00534300`；`FUN_00511590`；`FUN_00510b60`。

## 3. 发动：`FUN_00531460`（G 组两类的槽 20）

```
iVar1 = FUN_00534260();                       // 时长（帧）
FUN_00423520(this+0x14, iVar1);               // 石头自己的计时器 = 时长
*(undefined1 *)(this+0x34) = 1;               // ★ 攻击进行中标志
FUN_0044fcd0(this+0x38);                      // 初始化攻击实体
... 取位置、spawn 实体
*(int *)(entity + 0x5c8) = this;              // 实体回指石头
FUN_00438a50(entity, FUN_00531050);           // 注册每帧回调
```

- **结论（✅）**：`stone+0x34` = 攻击进行中标志，**由发动置 1、由槽 22 清 0、由槽 26 读出**。
  这是全作「异变攻击在不在」的**唯一权威标志**。
- 每帧回调 `FUN_00531050` 顺着实体 `+0x5c8` 回到石头，做 §4 的槽线推进。
- 证据：`FUN_00531460`（`0x531460`）；`FUN_00530500`（槽 26）；`FUN_00532f20`（槽 22）。

## 4. 时长与那根线

| 项 | 值 / 公式 | 证据 |
| --- | --- | --- |
| 时长 | `FUN_00534260()` = `base × (1 + a / 100)` | `FUN_00534260` |
| `base` | `FUN_0051b8e0(game) × 0x4b0 / 100`，`Fun_0051b8e0` 读 `+0x54` 并 clamp `[1,100]` | 同上 + `FUN_0051b8e0` |
| `a`（百分比加成） | `FUN_005342b0(game)`，读**石头对象 `+0xa8`**，clamp `[0,100]` | `FUN_005342b0` |
| ⇒ 时长范围 | `12`–`1200` 帧（按 `a` 最多 ×2 ⇒ 上限 2400 帧＝40 秒） | 由上两式推出 |
| 槽线每帧位移 | `280.0 / 时长`（`DAT_00575d58` = `0x438c0000`） | `FUN_005316c0` / `FUN_00531d30` |

- **发现**：两个同构的每帧函数 `FUN_005316c0` 与 `FUN_00531d30` 都在做
  「读一条曲线（`FUN_0042a110`）→ 写实体位置（`FUN_0045dd60`）→ 把同一个量喂给 anm（`FUN_00470e50`）」，
  并把 `+0x60` / `+0x90` 按 `280.0/时长` 递减。
- **结论（🟡）**：`+0x5c..+0x64` 是攻击实体的**坐标**（`FUN_0045dd60` 用它设置位置），
  `280.0` 是那根槽/线的**总长度**（像素级，世界坐标 —— 世界层已有 ×2 的缩放在本仓其他卡上验证过）。
  ⇒ 这条 280 是**表现层**的一条线，**不是充能槽本身**。
- ★ **订正（2026-09-28，来自 [`05`](05-shards-and-items.md)）**：「槽长度随石不同」这条 wiki 口径
  在代码里是**真的**，但位置不在这条线上：**每块石有自己的满槽阈值**
  （`0x5333b0` 按装备石编号 0..7 写 `阈值 = {130,130,150,150,180,130,130,150}`），
  充能计数在 `game+0x4c`（clamp `[0,500]`）。详见 05 §2。
- 证据：`FUN_00534260`；`FUN_005342b0`；`FUN_0051b8e0`；`FUN_005316c0`；`FUN_00531d30`；
  `pe_read.py … 0x575d58 --dwords 2`（= `0x438c0000`）；`FUN_005333b0`（阈值表，见 05）。

## 5. 谁读「攻击是否进行中」

| 查询器 | 返回 | 消费方 |

- 证据：`FUN_004f86f0`；`FUN_004ff6d0`；`FUN_004ffec0`；`FUN_004618c0`；`FUN_00464270`；

### 7.1 三张初始化表（**主控一手复核过**，`FUN_005333b0`）

`FUN_005333b0`（`0x5333b0`，834 字节）每次开局把三张表按「石头 / 难度」写进游戏对象，
三张表的落点由 setter 本体确认（`FUN_004bea00` → `+0x50` clamp `[100,500]`；
`FUN_004be9b0` → `+0x54` clamp `[1,100]`；`FUN_004be710` → `+0x60` clamp `[0,5000]`）：

| 表（`FUN_005333b0` 里的局部数组） | 索引 | 值 | 落到 | 含义（结论） |
| --- | --- | --- | --- | --- |
| `local_a8[8..0xf]` | **装备石 0..7** | `130,130,150,150,180,130,130,150` | `game+0x50` | **异变攻击满槽阈值**（✅ wiki「槽长随石不同」）|
| `local_a8[0x10..0x17]` | **装备石 0..7** | `30,30,40,65,100,60,70,20` | `game+0x54` | **攻击时长基准百分比**（✅ wiki「持续时间随石不同」，见 §4）|
| `local_a8[0..7]` | 难度 `*DAT_005c6110` | `0,1100,1200,1300,1400,1400,1400,1400` | `game+0x60` | **异变敌人出现槽的阈值**（1100/1200/1300/1400，索引 1..4）🟡 → 见 [`04`](04-incident-value.md) §1.1/§2.3（那边把所有写入点列全了）|

- **发现**：三处都用 `FUN_0041cab0(game)`（= **装备的主石编号 0..7**）或 `*DAT_005c6110`（难度）当下标。
- **结论（✅）**：`+0x4c`（充能）/`+0x50`（阈值）/`+0x54`（时长%）三者是一组、**随石变**；
  `+0x60` 是另一根槽、**随难度变**。
- 证据：`FUN_005333b0` 全文（三张表 + 三个 setter 调用）；`FUN_004bea00` / `FUN_004be9b0` / `FUN_004be710`
  各自写入的偏移与 clamp；`FUN_004be940`（`+0x4c` clamp `[0,500]`）。
