## 0. 一句话结论

wiki 口径的「异变值」在一手里**没有同名标识符**（全 exe 字符串表里只有「異変石」与「◯の異変レベル」），
按逐条对证 + **owner 2026-09-28 实机口径**（两条槽 = 异变敌召唤 / 异变攻击储存），
它就是**全局单例 `FUN_00464080(0)+0x44`** ✅：这是「得分道具」得分算式里**唯一的乘数因子**
（`FUN_004c4960`），并且被**原生 HUD 画在画面右侧**（`0x570af0`=608.0, `0x570ae4`=204.0，见 §4）。
另有一条**同在右侧但走 anm 脚本**的竖直槽 `+0x5c`（阈值 `+0x60`）= **异变敌召唤槽**，它**不进**得分算式（§1.2 判定 c）。
四色的「異変レベル」是**另外四个字段** `+0x84/+0x88/+0x8c/+0x90`（✅ ZUN 自己的字符串），
不要与 `+0x44` 混为一谈。**「发动异变攻击 → 异变值提升」找不到直接写入点**（❓ 见 §2.4）。

## 2. 提升通道（写入点全部列全 —— 语料零缺失，故为穷举）

### 2.1 `+0x44`（=∑ 异变值）：只增不减，复位点两处

| 事件 | 增量 | 函数 / 调用点 |

| 击破**任意**敌机 | `敌机 +0x300 × 表[类型] / 100` | `FUN_004a5640` 内 `FUN_004a9fb0(game, x)`（game_b.c 25979） |

- **`FUN_00511f00` 就是「击破异变敌人」的回调（✅）**：它由 `StoneEnemyInf::Start` 里注册的 `lambda_2`

### 2.4 「发动异变攻击 → 提升」

- **发现**：`+0x44`、`+0x84..+0x90`、`+0x5c`、`+0x60` 的**全部**写入点（§2.1–2.3 / 2.5）里，
  **没有**任何一处挂在异变攻击的发动/进行上；发动侧（`FUN_005332b0` → `FUN_005333b0`）反而把 `+0x5c` **下调**。
- **推测**：wiki 这句是**间接观察** —— 异变攻击期间/之后大量敌机被击破（`+0x44` 各加 `分值×%`）、
  且异变攻击会掉碎片（见 [`06`](06-attack-gauge-and-miss.md) §2），拾取再 `+1`。
- **结论（❓）**：一手里**没有**「发动即提升」的直接证据；也找不到扣除/衰减 ⇒ 若 wiki 说法为真，
  其机制在**未被语料覆盖的形式**（例如纯 script 驱动）或**就是这条间接链**。
- 附近唯一"大额一次性"入口：`FUN_004f8b90`（碎片雨，`+0x44 += 50` 或 `+10`，同时放出约 1000/1500 价值的
  `0xd` 型碎片道具），5 个调用点：game_b.c 5425/26552、game_c.c 5424/5535/5626。

## 3. 倍率公式

### 3.1 得分道具的得分（✅ 一手公式）

- **发现**：道具类型 `item+0xc28` 为 **2 或 15** 时进 `FUN_004c4960`（`0x4c4960`，453 字节）——
  这是全语料里**唯一**带乘数的得分算式。分派点：`FUN_004c25a0`（`0x4c25a0`）的
  `switch (*(int*)(item+0xc28) - 1)`，`case 1` 与 `case 0xe` 都指向它。
- 公式（原文照抄，`game` = `FUN_00464080(0)`）：

  ```c
  point = FUN_004c4b30(game);              // +0x40 clamp [10000,1000000]  最大得点
  M     = FUN_004b82c0(game);              // +0x44 clamp [0,1000000]      ★异变值
  D     = FUN_004b8300(game);              // +0x48 clamp [5000,10000]
  score = point / 2 + (M * point) / D;     // == point * (0.5 + M/D)
  score = score - score % 10;
  // 若拾取点低于 POC 线：score = (score*9)/10 - ((score*9)/10 * 距离) / 0x1c2   (0x1c2 = 450)
  ```

- **结论（✅）**：**得分道具倍率 = 1/2 + (+0x44)/(+0x48)**；wiki「异变值影响得分道具获得时的得分倍率」
  在这条链上是**逐字成立**的（把倍率写成 `0.5 + M/D`，`D` 初值 5000）。
- **❓**：道具类型 2/15 的**贴图/名字**未定（要读 anm/ECL 侧），故只说「走 `FUN_004c4960` 的那类得分道具」。
- 证据：`FUN_004c4960`；`FUN_004c25a0`；`FUN_004c4b30`；`FUN_004b82c0`；`FUN_004b8300`。

### 3.2 通关结算里的同项（另一条，别混）

- **发现**：`FUN_00510b60`（`0x510b60`，763 字节，`StageClearInf` 的 anm 回调 0x2d）里：

  ```c
  local_8[10]  = FUN_00474d60(&DAT_005ba568) * 100000;      // 首项，量纲❓
  local_8[10] += FUN_004b82c0(game) * ( +0x84 + +0x88 + +0x8c + +0x90 );  // ★异变值 × Σ異変レベル
  local_8[10] += ( +0x74 + +0x78 + +0x7c + +0x80 ) * 100000;              // Σ攻击级别
  local_8[10] -= local_8[10] % 10;
  FUN_00488550(&DAT_005ba568, local_8[10]);                 // 加进分数（内部 /10）
  ```

- `FUN_00510e80`（回调 0x56）把它画成 `"クリアボーナス　　　%s"`（`0x573fc4`），
  并在同屏画出 `"赤/青/黄/緑の異変レベル"`（`0x573f64`/`0x573f7c`/`0x573f94`/`0x573fac`）。
- **结论（🟡）**：这条是**通关奖励**，不是「得分道具获得时」的倍率；但它证明 `+0x44` 与 `+0x84..+0x90`
  是**两个不同的概念**（一个是「值」，四个是「等级」）。
- 证据：`FUN_00510b60`、`FUN_00510e80`、`FUN_005115c0`（`stageclear.cpp:89 StageClearInf`）。

### 3.3 与 TH16 季节倍率的对照（只作结构对照，不搬结论）

- TH16 的倍率挂在**季节道具**上、由 `engine/season/` 已实现的那套消费；
  TH20 这里**没有季节/信仰类的中间对象**：倍率直接由单例的 `+0x44/+0x48` 现算（§3.1），
  因此复刻卡 120 时**不能**照抄 TH16 的季节管线，只能借「一个全局标量 × 道具基础值」的形状。
- ❓ 未做：TH16 侧算式的一手复核不在本文范围（本文不改 `engine/season/`）。
