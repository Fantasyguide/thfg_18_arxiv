# 异变攻击 / 异变石 —— 资产侧（ECL 弹幕脚本 · ANM 精灵 · SHT 自机射击）

> **版本**：TH20 v1.00a（`th20.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th18:0x…`。
> **方法**：一手 —— ① `thecl -d 20`（含 `-r` 原始模式）反汇编 `default.ecl`，自写只读解析器 `SCPT` 头部读 **sub 名字表 → sub id**；
> ② `thanm -l 20` 解 5 个 `.anm` 的 entry/script/sprite；③ 自写只读 SHT 解析器逐字节读 `pl00.sht` / `pl01.sht`；
> ④ PE 直读常量表 + `objdump -d -M intel` 按指令边界复核三条表引用；⑤ 只读既有反编译语料 `local/th20.v1.00a/decomp/`（`stoneenemy.c` / `game_b.c` / `tail.c`）。
> **可信度**：ECL 表与 sub id ✅（原始字节 + 名字表双向核对）；三条表引用指令 ✅（`objdump` 指令边界）；
> `enemy.anm` script 号 ✅（ECL `anmSetMain` 参数 vs anm entry 归属，两侧独立）；SHT 布局 ✅（逐字节），SHT **行的语义** 🟡/❓；
> opcode **名字**一律 🟡（TH20 无 eclmap，名字借 `local/vendor/eclmap/eclmap/th18.eclm`，但 **opcode 号本身是 TH20 文件的属性**）。
>
> ★ **owner 指定的复刻口径（必读，本文只调研不实现）**：
> 「**异变攻击 ≈ th17 暴走咆哮**（本仓 117 卡）」；「**复制粘贴骨架，贴图什么的改一下，具体 anm、ECL 脚本肯定改一下**」

## 0. 一句话结论

1. **异变攻击的弹幕在 `default.ecl`**：20 个 `StoneAttackLevel_{R,B,Y,G}{1..5}` = **4 色 × 5 级**，
   sub id **24–47**（`default.ecl` 共 55 个 sub）；每级是「按难度推参数 → 调 `*_func`」，真正的循环在 4 个 `*_func` 里。
2. **「按名字查 sub」确实存在，而且是二分查找**：TH20 的 `SCPT` 文件**自带 sub 名字表**（`0x5b09e8` 那张表存的就是这些名字的指针）；
   运行时 `0x540340` 用 `_strcmp` 做二分，名字 → sub id。
3. **`0x573ff0` 是 (颜色 × 等级) 的 20 个 dword、四行相同**（`0xc80,0xd48,0xe74,0xf3c,0xfa0`），
   只被 `FUN_005120d0` 读一次；**它的量纲未定**（见 §6）。
4. **异变石 HUD/菜单的贴图全在 `stone.anm`**（22 entry / 41 script），包括 **`front/stonegauge.png`（异变攻击槽）**——
   路径前缀是 `front/`，**文件却打包在 `stone.anm` 里**。
5. **异变敌人（不是异变攻击）走 `enemy.anm` 的 `enemy/enemy_stone.png`**：ECL `Stone{R,B,Y,G}`（sub 50/48/51/49）
   各自 `anmSetMain(0, 272 / 283 / 294 / 305)`，步长 11。

### 1.2 两级结构（发现 → 结论 ✅）

**① 20 个级别 sub 的形状**（以 `StoneAttackLevel_B1` 为例，原始字节）：

```
stackAlloc(0)
!Easy:    pushf 2.0f        !Normal/Hard/Lunatic: pushf 2.5f     ← 栈参 #2
!Easy:    pushi 4           !Normal/Hard/Lunatic: pushi 8       ← 栈参 #1（最后压入 ⇒ s0）
!*(全难度) call StoneAttackLevel_B_func(s0, 1, s1, 2.5f, 160)
delete
```

**② 4 个 `_func` 的公共循环**（`StoneAttackLevel_{R,B,G,Y}_func(var A,var B,var C,var D,var E)`，
`stackAlloc(20)` = 恰好 5 个参数；`$A`=slot0、`$B`=slot4、`%C`=slot8、`%D`=slot12、`$E`=slot16）：

```
flagSet(35); op343(1); wait(60)
loop:
  etNew(0)                          # 600
  etAim(0, <常量>)                  # 607
  etSprite(0, <常量 type>, <常量 color>)   # 602
  etCount(0, $A, $B)                # 606  路数, 层数
  etAngle(0, <常量 ang1>, <常量 ang2>)     # 604
  etSpeed(0, %C, %D)                # 605  第一层速度, 最后一层速度
  etEx(0, 0, 1, 1, -9999994, -9999994.0f, -9999994.0f)   # 611（末三参 = 哨兵，未用）
  etOffset(0, RANDF2 * 32.0f, 0.0f) # 603  随机横向偏移
  unless (gvar[-9875] == 0) goto skip;  etOn(0)   # 601（条件 = 某闸门，见 §6）
skip:
  wait($E)                          # 23
  goto loop
```

- **易/普/难/狂 4 档**由 `!E67` / `!N67` / `!H67` / `!L67` 的 rank 位标在**压栈那两条**上；
  调用本身是 `!*`（全难度）。⇒ 同一级 sub 在 4 档难度下只有 2 个量在变。
- `R_func` 的两条压栈在循环外（`goto` 在 `etEx` 之后），`B/G/Y_func` 的循环体在 `etNew` 之前多一条 `goto`；
  这是 ZUN 编译器对「循环里等一次」的两种排法，**语义相同**。
- **`Y_func` 每轮发 2 波**（第二个 `etNew…etOn` 用 `$A - 1`），所以它的 `$E` 是**两波之间的间隔**。

### 1.3 `X_func` 的五个实参是什么（发现 → 推测 → 结论）

量纲的**一手依据**只有两点，其余为 🟡：

| 参 | 用在哪 | 量纲 | 可信度 |
| --- | --- | --- | --- |
| `$A` | `etCount(0, $A, $B)` 第一参 | 路数（ways） | 🟡 借 `engine/ecl/th16/ECL-info.md` §「etCount(id, 路数, 层数)」|
| `$B` | `etCount` 第二参 | 层数（layers） | 🟡 同上 |
| `%C` | `etSpeed(0, %C, %D)` 第一参 | 第一层速度 | 🟡 同上 §「etSpeed(id, 第一层速度, 最后一层速度)」|
| `%D` | `etSpeed` 第二参 | 最后一层速度 | 🟡 同上 |
| `$E` | `wait($E)` | **帧数**（60 fps） | ✅ `23 wait` 的参就是帧数；`_func` 开头固定 `wait(60)` |

> 我**没有**在 TH20 侧找到 `etCount` / `etSpeed` 参数含义的一手证明（那要读 exe 的 handler）。
> 上表除 `$E` 外一律按 🟡 记；**不要把它们当结论用**（见 §6 待补地址）。

## 2. `StoneAttackLevel_*` 这些名字是怎么被调用的

### 2.1 `default.ecl` 里**有**一张名字表（✅ 一手）

THTK `thecl10.c` 的 `th10_open()` 从 `SCPT` 头读：`ANIM` 列表 → `ECLI` 列表 → `sub_offsets[sub_count]` → **紧跟着就是 NUL 分隔的 sub 名字表**。
⇒ **名字存在 ECL 文件自己的字节里**，`ins_11`(call) 的参数只是 **sub id（表下标）**，THTK 输出时用名字表反查。
本仓 `default.ecl` 实测 `ANIM=0`、`ECLI=0`、`sub_count=55`。

> 复算方法（只读，不影响工程锁）：读 `0x00` 头 → `include_offset` 处的 `ANIM`/`ECLI` → 对齐 4 → `u32[55]` 偏移 → 名字表。
> 我用它拿到 §1.1 的 id↔名字对应。

### 2.2 运行时：名字 → sub id 是**二分查找**（✅ 指令级）

```
FUN_004a8920(mgr, name, pos, ctx)      # 0x4a8920  创建「按名字跑 ECL sub」的对象
  └─ FUN_004a73f0(this, ...)           # 0x4a73f0
       └─ FUN_00540280(obj, this, name)# 0x540280
            ├─ FUN_00540550(obj, name) # 0x540550  → iVar = FUN_00540340(*(obj+0x58), name); *(*(obj+0xc)+4) = iVar
            └─ FUN_00540340(tbl, name) # 0x540340  ← ★ 名字 → 下标 的**二分查找**
```

`FUN_00540340` 的反编译：`lo=0; hi=*(this+8)-1;` 循环 `mid=(hi-lo)/2+lo` → `FUN_0053b590(this+0x20c, mid)` 取项 →
`_strcmp(name, *item)`，`<0` 收 hi、`>0` 抬 lo，命中返回 `mid`。⇒ **名字表必须按字典序排**，
这与 `default.ecl` 名字表实测有序（`BossDead2 … StoneAttackLevel_B1 … test2`）**互为佐证**。

### 2.3 `0x5b09e8` 那张 20 项名字表的作用（✅）

- `0x5b09e8` = 20 个 `char*`，依次指向 `StoneAttackLevel_{R,B,Y,G}{1..5}`（字典序 R1..R5,B1..B5,Y1..Y5,G1..G5）。
- ⚠ **工单里写「它被 `FUN_005120d0` 引用」，实测不是**：`0x5b09e8` 的引用点唯一，且落在 `FUN_00512fb0`（`FUN_005120d0` 引用的是另两张表，见 §2.4）。
- 全文件里该地址**只出现 1 次**（`grep` 4 字节小端），是一条真指令：

```
0x51327e:  mov ecx, DWORD PTR [ecx + eax*4 + 0x5b09e8]     # 位于 FUN_00512fb0
0x51327b:  mov eax, DWORD PTR [edx + 0x30]                 # eax = 石对象 +0x30 = 该色的等级
```
（`ecx` 在此之前 = `0x5b09e8 + 颜色*5*4`。）⇒ **名字 = 表[颜色*5 + 等级]**，
随后 `FUN_004a8920(..., 名字, ...)` 把它变成一次 sub 调用 ⇒ **异变攻击 = 生成一个敌人脚本线程跑 `StoneAttackLevel_XN`**。

### 2.4 另两张表（✅ 指令级；语义一半 ❓）

| 表 | 内容 | 引用点（指令边界已核） | 读者 |
| --- | --- | --- | --- |
| `0x5b09d8` | 4 个 `char*`：`StoneR` / `StoneB` / `StoneY` / `StoneG` | `0x5124c3: mov edx,[ecx*4+0x5b09d8]` | `FUN_005120d0`（HUD 更新）|
| `0x573ff0` | 20 × u32，4 行相同：`0xc80,0xd48,0xe74,0xf3c,0xfa0` | `0x51249c: mov edx,[eax+ecx*4+0x573ff0]` | 同上，索引 `[等级 + 颜色*5]` |

- `0x5b09d8` 的作用**已定**：`FUN_005120d0` 拿它当名字，`FUN_004a8920(..., "StoneR", pos, 0)` 生成**该色的异变敌人**；
  同一函数里 `local_134[4] = {0xffff0000, 0xff0000ff, 0xffffff00, 0xff00ff00}`（ARGB 红/蓝/黄/绿）按同一 `颜色` 下标取用，
  与 `Stone{R,B,Y,G}` 的 ECL 里 `spec1(0/1/2/3)` **双侧对上 ⇒ 颜色序 = R,B,Y,G ✅**。
- `0x573ff0` 的量纲**未定 ❓**：读到后存进**栈上那个对象**的 dword 槽（`objdump` 里是 `[ebp-0x60]`，即反编译的 `local_64`；
  同一函数的对象基址是 `local_7c`=`[ebp-0x7c]`，两者相差 **+0x1c**，所以很可能是「对象 `+0x1c` 字段」——但**反编译里此后没人读它**，🟡）。
  值 3200/3400/3700/3900/4000 随等级**单调增**、**四色相同**。候选（并列，均未证）：异变敌人耐久 /
  异变攻击槽长 / 升级阈值 / 得分。**不许写成结论**（见 §6）。

### 2.5 ★ `Stone{R,B,Y,G}` 不是异变攻击，是**异变敌人**（✅）

`default.ecl` 的 `StoneB`(48) / `StoneG`(49) / `StoneR`(50) / `StoneY`(51) 四个 sub 形状一律是：

```
flagSet(3); anmSelect(2); anmSetMain(0, 272/283/294/305); anmScale(...); anmScaleTime(0,60,3,1,1);
playSound(53); wait(1); spec1(0/1/2/3); setHurtbox(48,48); setHitbox(32,32); wait(60); flagClear(3);
moveLimit(0.0,128.0,300.0,100.0); … 循环 moveRand / getAngle / moveVel / moveSpeedTime …
```

- `anmSetMain` 的 4 个脚本号 **272 / 283 / 294 / 305**（步长 11）全部落在
  **`enemy.anm` entry7 = `enemy/enemy_stone.png`**（该 entry 的全局 script 区间 = 272–325）⇒ **异变敌人的贴图与脚本 ✅**。
- `spec1(0/1/2/3)` 与 `0x5b09d8` 的色序一致。
- `Stone{R,B,Y,G}` 这 4 个 sub **在 `default.ecl` 内部没有任何 `call`**（全文件只有 20 处 `call *_func`），
  所以它们同样是被 exe 按**名字**拉起来的（同 §2.2 那条链）。

### 4.1 TH20 与 TH18 的布局差异（✅）

| 项 | TH18 | TH20 | 证据 |
| --- | --- | --- | --- |
| `+0x00` u16 | 5 | **7** | `pl00/pl01` 同值 |
| `+0x02` u16 | 40 = 偏移数组长度 | **160** | 与实测 `0xFFFFFFFF` 分隔符数 **160 个**吻合 |
| `+0x04/+0x08/+0x0c` f32 | — | 2.3 / 6.0(pl01 12.0) / 28.0(pl01 32.0) | 逐字节 |
| `+0x10` f32×4 | 移动速度 | 4.5 / 2.0 / 3.182 / 1.414 | 含义 👈 借 TH18 的「四速」记法 🟡 |
| `+0x20` i32 | 4 (`pwr_lvl_cnt`) | 4 | |
| `+0x24` 起 i32 数组 | `+0x24` = 每档火力（40→装载时改写 100）| **`+0x24` = 20**，其后 24 个整数（多为 100；pl00 有 200@`+0x3c`、160@`+0x48`；pl01 有 140@`+0x54`、120@`+0x70`,`+0x74`）| 逐字节 |
| `+0x88` i32×16 | — | pl00 `37,37,39,39,41,41,43,43,38,38,40,40,42,42,44,44`；pl01 `32,32,34,34,36,36,38,38,33,33,35,35,37,37,39,39` | **按角色不同** ✅ |

| 偏移数组 | `+0xe0`，**相对** + 基点 `0x180` | **`0x5d4`**，160 × u32、值是**绝对文件偏移** | 逐字节 |

**stride 的推导（可复算）**：分隔符间距 = `0xf4, 0xf4, 0xf4, 0xf4, 0x7c, 0x16c, 0x2d4, 0x43c, 0x5a4, 0x7c, …`，
全部满足 `k*0x78 + 4`（即 k 行 + 4 字节终止符），k = 2/2/2/2/2/1/3/6/9/12/1… ⇒ stride = `0x78`。

2. **贴图来源**：异变攻击本体用 `stone.anm` entry0–7（256px 大石）/ `_80`（80px 小石）；HUD 槽用 `stone.anm` **entry20**（sprite25–27）；
   小图标 `stone.anm` entry21（sprite28–39，4 行 = 4 色）；异变敌人用 `enemy.anm` entry7（sprite346–365）。
3. **异变攻击槽动画**：`stone.anm` `script31` 是入口（并联 `script35/36/33`），底槽/亮条 = `sprite26`/`sprite27`，端帽 = `sprite25`。
4. **不要**照抄 `EffectLineStone*`（它依赖不存在的 `fronttr.anm`）。
