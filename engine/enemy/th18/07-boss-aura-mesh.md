# 07 — TH18 的 boss 光环（`m_bossRMesh`）与「扭曲背景」：★ **光环在 TH18 是残迹**

> **版本**：TH18 v1.00a（`local/th18.v1.00a/th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；
> 引用其他版本须写成 `th16:0x…`。
> **方法**：一手 —— PE 直读（字符串/指针/跳表扫描）＋ 线性与定位反汇编 ＋ `FUN_00430d30` 两级分派表
> 反查 opcode；用既有文档已知的 **523 / 542** 校验过反查公式。
> **可信度**：opcode 629 的定位与两级表公式 ✅（逐条对账）；「TH18 不画这个 mesh」🟡（**负结论**，
> 靠 disp32 全扫 + 唯一引用点；未实跑）。2026-10-01。
> 起因：owner 2026-10-01「boss 的光环算是一个**通用 plot 机制**……可能从 **th12** 就开始这样了」
> ＋「建议你进 **th18** 挖，这部分代码**公用**……万一有个什么**跨代问题**呢」。
> ⇒ 本轮的答案是：**有跨代问题，而且正好就在这条机制上**。

## 0. 三句话结论

1. **TH18 里有一个 `m_bossRMesh` 成员、也有一条 ECL 指令会建它 —— 但没有任何代码画它。**
   ⇒ 它在 TH18 是**运行时残迹**（建完就放着，只在重建时删）。
2. 建它的入口 = **ECL opcode 629**（`FUN_00430d30` 的 case `0x435fe0`）：参数 = **一个 float 半径** ＋
   一个 int，写进 `enemy+0x5594` / `+0x559c`，然后建一个 **17 段的带贴图 mesh** 存 `enemy+0x558c`。
3. TH18 真正在用的「符卡背景（含演出）」是 **`et_ex` 效果名 `BossCard6_et` / `BossCard6_et2`**，
   由 `0x4391a0` 那个更新器遍历符卡管理器生成 —— **不是 mesh**。

## 1. 怎么定位到的（方法与坑）

| 步 | 做法 | 一手 |
| --- | --- | --- |
| ① | 串扫描 TH18：`m_bossRMesh` / `MBossDead` / `BossCard6_et*` / `boss_*` | 命中块在 `0x4b64a4` 一带 |
| ② | ⚠ **坑**：`re.finditer` 给的是**文件偏移**，不是 RVA。直接当 VA 用会**全查不到引用**（第 1 次就踩了） | 换算：`.rdata` raw `0xabc00` ↔ RVA `0xad000` |
| ③ | 反查唯一引用点 | 每条串**恰好 1 个** `push imm32` |
| ④ | ECL 分派器 `FUN_00430d30` 的**两级表**（见 §2） | 用 `01-boss-interrupts-and-spellcard.md` 已知的 **523 / 542** 校验通过 ✅ |

**ECL 分派器的两级表（一手，`FUN_00430d30`）**：

```
index = (int16)opcode - 300                  ; 0x430db8  add eax, 0xfffffed4
if (index > 0x2bd) return;                   ; 0x430dbd  合法 opcode = 300..1001
group = *(uint8_t *)(index + 0x4366f4);      ; 0x430dc8  ① 字节表：opcode -> 组号
jmp  *(__int32 *)(group*4 + 0x436438);       ; 0x430dd4  ② 跳转表：组号 -> case
```

自检：`opcode 523 -> case 0x434fec`、`opcode 542 -> case 0x435067`（与既有文档**逐条对上**）。

## 2. ★★ ECL **opcode 629** = 建立 boss 光环（一手，case `0x435fe0`，组 142 / 表项 `0x436670`）

```c
/* FUN_00430d30 的 case 0x435fe0 */
if (enemy[0x558c]) { FUN_0041be50(enemy[0x558c], 1); enemy[0x558c] = 0; }   /* 先删旧的 */
enemy[0x5594] = ecl_get_float_arg(enemy, 0);   /* 0x438ad0 → xmm0 → +0x5594 = 半径 */
enemy[0x5598] = 16.0f;                         /* 0x436010  mov [edi+0x5598], 0x41800000 */
enemy[0x559c] = ecl_get_int_arg(enemy, 1);     /* 0x438aa0 → +0x559c */
FUN_00404d70(&enemy[0x55a0], 0.0f);            /* 0x43602e */
FUN_00404d70(&enemy[0x55a4], 0.0f);            /* 0x43603c */
if (enemy[0x5594] > 0.0f) {                    /* 0x43604c comiss/jbe  ⇒ 半径 <= 0 就不建 */
    obj = operator_new(0x1c);                  /* 0x48dc71(0x1c) */
    FUN_0042b1f0(obj, 0x11, 0x11, 0);          /* mesh ctor：17 段 */
    enemy[0x558c] = obj;
    FUN_00404f50(*(void **)0x4cf290, obj, 0x1c, "D:\\…\\enemy.cpp:3702 m_bossRMesh");
}
```

⚠ `FUN_00404f50`（`0x404f50`）整个函数体是 **`mov eax,[ebp+8]; ret 0xc`** ⇒
**它在 release 构建里是空函数** —— 那条「按名字注册」是**调试期**的东西，`[0x4cf290]` 也是个
`malloc(4)` 的哑对象（只有启动建、退出删两处）。**这就是为什么那条串查不到任何真消费者。**

## 3. mesh 本体是什么（一手，`FUN_0042b1f0`）

`FUN_0042b1f0(this, n = 0x11, n = 0x11, 0)`：

| 字段 | 内容 | 一手 |
| --- | --- | --- |
| `[+0]` / `[+4]` | **段数 = 0x11（17）** / 同一个值 | `0x42b22d` / `0x42b233` |
| `[+0xc]` | `malloc(0x43)`（67 字节） | `0x42b241` |
| `[+0x10]` | `malloc(0x43)` | `0x42b24b` |
| `[+0x14]` | `malloc(0x1dc × 17)` = **每顶点 476 字节的顶点区** | `0x42b24e`/`0x42b255` |
| `[+0x18]` | `malloc(0xcc × 17)` | `0x42b260`/`0x42b267` |
| `[+8]` | **贴图句柄**：`FUN_00455d80(&local, 2)` → `[eax]`；`&0x7fff` 后去 `[0x51f65c]+0x6f0/0x6f8` 两张表里找 | `0x42b275`–`0x42b2d2` |

⇒ **一个 17 段的、带贴图的环**（顶点区很大 ⇒ 每段带完整的位置/UV/颜色）。
这形状与「环绕在 boss 四周、会扭背景的特效」对得上——**但见下**。

## 4. ★★★ 跨代问题：**在 TH18 里这东西是残迹（建了不画）**

| 证据 | 一手 |
| --- | --- |
| `.text` 全扫 **disp32 = `0x558c`**，能解成真指令的只有 **3 处**：`0x435fe0`（读，判空）、`0x436011`（写）、`0x43608e`（写）—— **全在 opcode 629 的 case 里** | 字节扫 + 逐点回解 |
| `enemy+0x5594`（半径）/`+0x5598`/`+0x559c`/`+0x55a0`/`+0x55a4` 同理，**只有 opcode 629 碰** | 同上 |
| `[0x4cf290]`（那个管理器）只有 **3 处**：`0x471311` 启动 `malloc(4)`、`0x472215` 退出 `free`、`0x436087` 传进**空函数** | 同上 |
| `0x41be50`（mesh 释放）的 `call` 点只有 4 处，其中和光环有关的只有 `0x435fec`（= 629 开头那一下） | `E8 rel32` 全扫 |

⇒ **没有任何绘制路径读 `enemy+0x558c`** ⇒ **TH18 不会把这个 mesh 画出来**。
★ **教训（这正是 owner 担心的那类问题）**：照 TH12 的 `m_bossRMesh` 去「复刻 TH18 的 boss 光环」，
会复刻出一个 **TH18 自己根本不画**的东西。

## 5. TH18 真正在用的是 `et_ex` 的 `BossCard6_et` / `BossCard6_et2`

串块 `0x4b64a4` 一带的构成本身就是线索：

```
0x4b64a4  MBossDead            ┐
0x4b64b0  BossDead             │ **成员名池**（`M` 前缀 = member）
0x4b64bc  BossEscape           │ （`m_bossRMesh` 那条 `enemy.cpp:3702` 也在这一池里）
0x4b64c8  MBossBDead           ┘
0x4b651c  BossCard6_et         ┐ **et_ex 效果名**
0x4b652c  BossCard6_et2        ┘
0x4b6490  error et_ex ID over     ← 紧跟其后的**效果系统报错串**（et_ex = エフェクトEX）
```

- 两条效果名的**唯一引用点** = `0x439154` / `0x4392d4`，都在**函数 `0x4391a0`** 里。
- `0x4391a0` 的骨架（一手）：`edi = [0x4cf3f4]`（**符卡管理器**）→ `esi = [edi+0x14]`（链表头）→
  逐项算位置（`0x404080` / `0x43a2b0` 做投影）→ `mov ecx, [0x4cf2d0]`（**效果管理器**）＋ `push <效果名>`
  → **生成效果**。
- ⇒ **符卡背景/演出走的是 `et_ex` 效果名这条路，不是 mesh。**
