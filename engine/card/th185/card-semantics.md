## 1. `NITORI`（id 0）—— 資本主義のジレンマ

- 表：类别 5 / 购买上限 1；卡图 `ability/NITORI_max.png` + `NITORI_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x34` `+0x50` `+0x54`。
- 方法体：
  - `+0x00`/`+0x04` = 转发壳 → `+0x2c`；`+0x34` = `ret 0`；`+0x50` = `or [card+0x54], 2`（置启用位）。
  - `+0x2c`（`th185:0x40a600`）：未启用直接返回；否则 `[th185:0x4d108c] += 50` → 夹到 `[0, 999]`
    → **若尾数为 99 则再 +1** → 写回 → **清自己的启用位**（`card+0x54 &= ~2`）。
- ⇒ **语义**：**一次性**卡；生效时把自己的状态量 +50（夹 0..999、避开尾数 99），然后自动禁用。
- 交叉验证：说明文 =「河城にとり：黑市的价格随机变化」⇒ 与"改市场/价格相关量 + 只改一次"吻合。
- ⚠ `th185:0x4d108c` **全镜像无静态读者**（§32.1）⇒ 移植时按说明文改商店定价链，别复刻这个写操作。

## 2. `SPEEDQUEEN`（id 3）—— 疾風の下駄

- 表：类别 3 / 购买上限 5；卡图 `ability/SPEEDQUEEN_max.png` + `_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x50` `+0x54`。
- 方法体：
  - `+0x00`/`+0x04` = 转发壳 → `+0x2c`；`+0x50` = `or [card+0x54], 2`；`+0x54` = 析构。
  - `+0x2c`（`th185:0x4136a0`）：`test [card+0x54],2 / je 出口` → **`mov dword [th185:0x4d10b0], 2`**
    → `and [card+0x54], ~2`（自禁用）。
- ⇒ **语义**：**一次性**卡；把状态量 `th185:0x4d10b0` 置成 **2** 后自禁用（"疾風の下駄"= 速度提升，
  2 应为档位/时长，🟡）。与 `NITORI` 同形（一次性 + 写自己的状态格 + 自禁用）——**这是 th185 卡的一种主流形状**。
- ⚠ 同样是"状态格无静态读者"（`th185:0x4d10b0` 全镜像只在 `th185:0x4136a8` 被碰）。

## 3. `SANAE_OP2`（id 12）—— 早苗的子机（陰陽玉系）

- 表：类别 5 / 购买上限 1；卡图 `ability/SANAE_OP2_max.png` + `_min.png`。
- 覆盖槽：`+0x08` `+0x0c` `+0x2c` `+0x34` `+0x50` `+0x54`。
- 方法体（一手）：
  - `+0x08`（`th185:0x410b50`）：**先判自己空闲**（`[card+0x58]==0 && [card+0x38]<=0`），
    然后 **`eax = [th185:0x4d7c3c]`（玩家）→ `movq xmm0, [eax+0x620]`**（读玩家 float3 位置），
    再往下建东西 ⇒ **本卡的效果在"玩家的位置"上产生**；
  - `+0x0c`（`th185:0x410b30`）：`mov [card+0x58],0` → `push [card+0x1c]` → `call th185:0x48a650`
    （归还 anm VM）→ `mov [card+0x1c],0` ⇒ **`card+0x1c` = 本卡的 anm VM/效果句柄**；
  - `+0x2c`（`th185:0x410880`）：`switch ([card+0x58])` 的**状态机**（0 / 1 / …），每帧按状态推进；
  - `+0x34` 与 `+0x50`（`th185:0x4107a0` / `th185:0x4107f0`）：**两段代码完全相同** ——
    `and [card+0x54], ~2`（清启用位）+ 复位 `[card+0x24]` `[card+0x28]` `[card+0x20] = -1` `[card+0x58] = 0`。
- ⇒ **语义**：装备型子机卡 —— 启用后在**玩家位置**生成效果/VM（句柄存 `card+0x1c` 与 `card+0x58`），
  每帧按 `card+0x58` 的状态机推进；移除时归还 VM 并复位。
- ★ 这张卡顺带**验证了两件事**：① 玩家对象确实是 `th185:0x4d7c3c` 且位置在 `+0x620`（§28 的判据）；
  ② `card+0x1c` = anm VM 句柄（与 th18 `zCardBaseClass +0x1c anm_id_for_ingame_effect` 同格）。
- ⚠ 对 §25 的修正：`+0x50` 并非"总是置启用位"——本卡在 `+0x50` 做的是**完整复位**（与 `+0x34` 同码）。
  正确的说法是：**`+0x50` = "设置本卡状态（多数卡＝置/清启用位，部分卡＝复位）"**。

## 4. `DANGO`（id 2）—— 鈴瑚印の団子

- 表：类别 0 / 购买上限 999（视为不限）；卡图 `ability/DANGO_max.png` + `_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x34` `+0x50` `+0x54`。
- 方法体（一手）：
  - `+0x00`/`+0x04` = 转发壳 → `+0x2c`；`+0x34` = 转发壳 → `+0x50`；`+0x54` = 析构；
  - `+0x50`（`th185:0x414e10`）：`or [card+0x54], 2`（置启用位）**且 `[card+0x58] = 0`**（复位自己的计数）；
  - `+0x2c`（`th185:0x414e40`）两段：
    ```asm
    test byte [ecx+0x54], 2 / je 第二段
    add  dword [th185:0x4d1088], 0x64      ; ★ 共享计数器 +100
    and  dword [ecx+0x54], 0xfffffffd      ; 自禁用（一次性）
    第二段（与启用位无关，每帧都跑）:
    cmp  dword [th185:0x4d7af8], 0x14 (20) ; 若"某个计数" ≥ 20
    jl   出口
    cmp  dword [ecx+0x58], 0x64 (100)      ; 且自己回吐的次数 < 100
    jge  出口
    dec  dword [th185:0x4d1088]            ; ★ 共享计数器 −1（回吐）
    inc  dword [ecx+0x58]                  ; 自己的回吐计数 ++
    mov  dword [th185:0x4d7af8], 0         ; 把那个计数清零（相当于消费掉 20）
    ```
- ⇒ **语义**：**先给后扣**的一次性卡 —— 生效瞬间给共享计数器 **+100**，
  之后**每积累 20 点（`th185:0x4d7af8`）就回吐 1 点**，最多回吐 **100** 次。
- 交叉验证：说明文 =「**メインショットの本数が増える**（主射击弹数增加）」
  ⇒ 共享计数器 `th185:0x4d1088` 就是**主射击/弹数**那一档资源，"给 100 再慢慢扣 100"正是
  "吃团子变强、随后逐口消耗"的玩法 ✅（🟡 计数器命名待再证）。

## 5. `NARUMI`（id 4）—— 肉体強化地蔵

- 表：类别 1 / 购买上限 9；卡图 `ability/NARUMI_max.png` + `_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x0c` `+0x2c` `+0x50` `+0x54`。
- 方法体（一手）：
  - `+0x50` = `or [card+0x54], 2`（置启用位）；
  - **`+0x0c`（`th185:0x414d00`，带 1 个栈参数 `ret 4`）**：
    ```asm
    eax = [th185:0x4d1078]     ; 火力
    ecx = [th185:0x4d107c]     ; 火力上限
    if (eax < ecx) { eax += 0x64 (100 = 1.00)；if (eax > ecx) eax = ecx；[0x4d1078] = eax }
    ```
    ⇒ **给火力 +1.00（不超上限）**；
  - `+0x2c`（`th185:0x414d50`）：操作 `th185:0x4d10bc`/`0x4d10c0`/`0x4d10c4`/`0x4d10c8` 那组
    4 格共享状态（`0x4d10c8 = 7`、环形推进、`0x4d10c4` 自增、到 7 归零）⇒ 像是**冷却/轮转的序号**（🟡）。
- ⇒ **语义**：**提升射击攻击力**（= 火力 +1.00/次），另有若干共享状态的轮转管理。
- 交叉验证：说明文 =「**ショットの攻撃力を上げる**（提升射击攻击力）」 ✅ **完全吻合**。

## 6. `ROKUMON`（id 30）—— 地獄の沙汰も金次第

- 表：类别 11 / 购买上限 1；卡图 `ability/ROKUMON_max.png` + `_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x50` `+0x54`（**没有任何死亡相关槽**）。
- 方法体：`+0x50` = 置启用位；`+0x2c` = **与 `NARUMI` 的 `+0x0c` 完全同形的"火力 +1.00"** 然后自禁用。
- ⚠ **与说明文不符**：说明文 =「**弾貨（钱）を消費して死を無効化**；弾貨 ≥ **300** なら弾に当たっても
  弾貨を全部使って生き返る」—— 而卡类方法里**只有"一次性 +1.00 火力"**，且它**不覆盖任何死亡槽**。
- ⇒ 结论（重要的工作方式结论）：**有些卡的效果实现"在引擎侧按 id 判定"，不在卡类方法里**
  —— th18 侧有先例（空白卡的效果实现在 `AbilityShop` 而不是卡类里，见
  [`../th18/05-shop-and-money.md §7`](../th18/05-shop-and-money.md)）。
  `ROKUMON` 的"钱 ≥300 复活"逻辑应在**死亡路径按卡 id 判定**处（待查），
  而卡类里的 `+0x2c` 只是它的**一次性加成**部分。
  ⇒ 逐卡阅读时**不能只看卡类**：**同名/说明文与代码不符时，去引擎侧找 id 判定**（这是本轮的新工作纪律）。

## 7. ★ 四张"持续被动卡"揭示了 `+0x18`/`+0x1c` 的真身：**效果对象的"建 / 驱动"对**

`ITEM_CATCH`(20)、`MONEY`(29)、`AUTOBOMB`(52)、`DEAD_SPELL`(73) 覆盖的槽**完全一样**：
`+0x18` `+0x1c` `+0x34` `+0x50` `+0x54`（都**不覆盖** `+0x2c` 每帧）。逐槽读出来是同一套模板：

| 槽 | 模板代码 | 语义 |
| --- | --- | --- |
| `+0x50` | `and dword [card+0x54], ~2` / `ret` | 清启用位（四张卡都这样） |
| `+0x34` | `call [eax+0x50]`（转发）+ `[card+0x58] = 0` | **拆除效果**（先停用再清句柄） |
| `+0x18` | `push kind / push w / push offx / push h / push offy` → `call th185:0x40b1f0` → `[card+0x58] = eax` | **建效果对象**；句柄存 `card+0x58` |
| `+0x1c` | `push kind2 / push arg2 / push arg1 / push [card+0x58]` → `call th185:0x40b430`（`ret 8`） | **驱动效果**（带两个坐标类参数） |

**四张卡的参数（一手，可直接照抄的"效果号 + 尺寸/偏移"）**：

| 卡 | `+0x18` 建效果 参数 `(kind, w, x, h, y)` | `+0x1c` 驱动 kind | 额外动作 |
| --- | --- | --- | --- |
| `ITEM_CATCH`(20) | `(0x10, 0x1c, 0, 0x1c, 0)` = 号 16、28×28 | — | **设回调**：`[effect+0xf8] = th185:0x40c480`；`or [effect+0xe8], 2` |
| `MONEY`(29) | `(0xe, 0x1c, 0, 0x1c, 0)` = 号 14、28×28 | `0xe`(14) | — |
| `AUTOBOMB`(52) | `(6, 0x20, 0, 0x20, 0)` = 号 6、32×32 | `0x13`(19) | — |
| `DEAD_SPELL`(73) | `(0xe, -0x14, 0, -0x14, 0)` = 号 14、偏移 −20 | `0x15`(21) | — |

⇒ **结构结论（🟢）**：`+0x18`/`+0x1c` 不是"每帧钩子"，而是**"为这张卡建一个表现/判定对象，然后驱动它"** 的一对；
每张卡用 **kind（效果号）** 区分自己的表现，`th185:0x40b1f0` / `th185:0x40b430` 是这两个操作的公共执行器。
**效果对象**的字段也露出来了：`+0xe8` 位域（bit1 被 `ITEM_CATCH` 置上）、`+0xf4` 链表指针、
**`+0xf8` = 回调函数指针**（`ITEM_CATCH` 用 `th185:0x40c480` 接管自己的逻辑）。

### 7.1 与说明文的对照（这批**恰好**说明了 §33 的模型）

| 卡 | 说明文（一手） | 卡类里看到的 |
| --- | --- | --- |
| `ITEM_CATCH` | 「**アイテムの回収範囲が広がる**（道具回收范围变大）」 | 只建了个号 16 的表现对象 + 装了个回调 |
| `MONEY` | 「敵が**追加でお金を出す**（敌人额外掉钱）」 | 号 14 的表现对象 |
| `AUTOBOMB` | 「**ライフが１つ増え、被弾時爆発する**」 | 号 6 / 19 的表现对象（爆炸演出） |
| `DEAD_SPELL` | 「弾貨の**出現量が増える**（弹货出现量增加）」 | 号 14 的表现对象 |

⇒ **"数值语义"（范围/掉率/生命）都不在卡类方法里**，卡类只负责**表现与句柄**；
这与 §33 的模型完全一致：**卡发布状态、引擎侧消费**。
⇒ 读这些卡时**不要指望在方法体里找到"+1 命""范围 ×2"**——要去引擎侧找"读该卡的发布量 / 按卡 id 判定"的地方。

### 7.2 未解（下一轮的探针）

**本批得到的两条"形状"结论**（对后面批量阅读有用）：

1. **`or [card+0x54], 0x20` 是"活动/发射中"标志**：`SAKUYA_OP`、`SANAE_OP`、`OKINA_OP` 的 `+0x2c` 都在置/清它，
   而 §26 已认过 `[card+0x54]` 的低位 = 启用/复位 —— 于是 `card+0x54` 至少有两个位：
   **bit1 = 启用/复位（`+0x50` 管）**、**bit5(0x20) = 活动/发射中**。
2. **`[card+0x58]` 是"卡内状态机"**：`SANAE_OP`(初值 2)、`OKINA_OP`(2→3)、`SANAE_OP2`(switch 它) 都用它，
   而"建/驱动效果"的卡把它当**效果句柄**（§45 批 3）⇒ 同一位移两用，**读卡时必须先看它是不是句柄**
   （判据：有没有 `mov [card+0x58], eax` 紧跟 `call th185:0x40b1f0`）。
