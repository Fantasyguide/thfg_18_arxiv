## 1. `NITORI`（id 0）—— 資本主義のジレンマ

- 表：类别 5 / 购买上限 1；卡图 `ability/NITORI_max.png` + `NITORI_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x34` `+0x50` `+0x54`。
- 方法体：
  - `+0x00`/`+0x04` = 转发壳 → `+0x2c`；`+0x34` = `ret 0`；`+0x50` = `or [card+0x54], 2`（置启用位）。
  - `+0x2c`（`th185:0x40a600`）：未启用直接返回；否则 `[th185:0x4d108c] += 50` → 夹到 `[0, 999]`
    → **若尾数为 99 则再 +1** → 写回 → **清自己的启用位**（`card+0x54 &= ~2`）。
- ⇒ **语义**：**一次性**卡；生效时把自己的状态量 +50（夹 0..999、避开尾数 99），然后自动禁用。
- 交叉验证：说明文 =「河城にとり：黑市的价格随机变化」⇒ 与"改市场/价格相关量 + 只改一次"吻合。
- ⚠ `th185:0x4d108c` **全镜像无静态读者**（§32.1）⇒ 移植时按说明文改商店定价链，别复刻这个写操作。

## 2. `SPEEDQUEEN`（id 3）—— 疾風の下駄

- 表：类别 3 / 购买上限 5；卡图 `ability/SPEEDQUEEN_max.png` + `_min.png`。
- 覆盖槽：`+0x00` `+0x04` `+0x2c` `+0x50` `+0x54`。
- 方法体：
  - `+0x00`/`+0x04` = 转发壳 → `+0x2c`；`+0x50` = `or [card+0x54], 2`；`+0x54` = 析构。
  - `+0x2c`（`th185:0x4136a0`）：`test [card+0x54],2 / je 出口` → **`mov dword [th185:0x4d10b0], 2`**
    → `and [card+0x54], ~2`（自禁用）。
- ⇒ **语义**：**一次性**卡；把状态量 `th185:0x4d10b0` 置成 **2** 后自禁用（"疾風の下駄"= 速度提升，
  2 应为档位/时长，🟡）。与 `NITORI` 同形（一次性 + 写自己的状态格 + 自禁用）——**这是 th185 卡的一种主流形状**。
- ⚠ 同样是"状态格无静态读者"（`th185:0x4d10b0` 全镜像只在 `th185:0x4136a8` 被碰）。

## 3. `SANAE_OP2`（id 12）—— 早苗的子机（陰陽玉系）

- 表：类别 5 / 购买上限 1；卡图 `ability/SANAE_OP2_max.png` + `_min.png`。
- 覆盖槽：`+0x08` `+0x0c` `+0x2c` `+0x34` `+0x50` `+0x54`。
- 方法体（一手）：
  - `+0x08`（`th185:0x410b50`）：**先判自己空闲**（`[card+0x58]==0 && [card+0x38]<=0`），
    然后 **`eax = [th185:0x4d7c3c]`（玩家）→ `movq xmm0, [eax+0x620]`**（读玩家 float3 位置），
    再往下建东西 ⇒ **本卡的效果在"玩家的位置"上产生**；
  - `+0x0c`（`th185:0x410b30`）：`mov [card+0x58],0` → `push [card+0x1c]` → `call th185:0x48a650`
    （归还 anm VM）→ `mov [card+0x1c],0` ⇒ **`card+0x1c` = 本卡的 anm VM/效果句柄**；
  - `+0x2c`（`th185:0x410880`）：`switch ([card+0x58])` 的**状态机**（0 / 1 / …），每帧按状态推进；
  - `+0x34` 与 `+0x50`（`th185:0x4107a0` / `th185:0x4107f0`）：**两段代码完全相同** ——
    `and [card+0x54], ~2`（清启用位）+ 复位 `[card+0x24]` `[card+0x28]` `[card+0x20] = -1` `[card+0x58] = 0`。
- ⇒ **语义**：装备型子机卡 —— 启用后在**玩家位置**生成效果/VM（句柄存 `card+0x1c` 与 `card+0x58`），
  每帧按 `card+0x58` 的状态机推进；移除时归还 VM 并复位。
- ★ 这张卡顺带**验证了两件事**：① 玩家对象确实是 `th185:0x4d7c3c` 且位置在 `+0x620`（§28 的判据）；
  ② `card+0x1c` = anm VM 句柄（与 th18 `zCardBaseClass +0x1c anm_id_for_ingame_effect` 同格）。
- ⚠ 对 §25 的修正：`+0x50` 并非"总是置启用位"——本卡在 `+0x50` 做的是**完整复位**（与 `+0x34` 同码）。
  正确的说法是：**`+0x50` = "设置本卡状态（多数卡＝置/清启用位，部分卡＝复位）"**。
