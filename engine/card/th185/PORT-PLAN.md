| **状态格·全 / ·简** | 11 + 8 | `+0x2c` 一次性写自己的全局状态格（夹 0..999、避尾 99 等），写完自禁用 | 一律改成 **mod 自己的每卡状态数组**（`s_*[id]`）；"一次性 + 自禁用"用 mod 已有的即时卡模式（ctor 返回非 0 自毁）实现；**消费点**按 §33 的模型在 mod 的玩家事件钩子上配对 |

## 3. 货币系统（弹货）移植

| 要素 | 原作（一手） | TH18 侧怎么做 |
| --- | --- | --- |
| 钱 | `th185:0x4d1074`，收/支/清零三点（§7） | **另开一个 mod 字段**，**不要复用** `th18:0x4ccd34`（它是计分乘数，会被污染） |
| 渐进定价 | `price = T(n+1)·(base − w·k) + w·k`（§9），`n` = 已购计数 | 照抄公式；`n` 存 mod 的每卡计数数组；`base` 需先取到数值（见 §5 未解） |
| 类别权重 | `th185:0x4b59c0`（1–9→5、10–14→10，§9） | 硬编码进 mod（th185 的类别号已在主表"类"列） |
| 货架与上架三闸 | `shop+0xa44` 指针数组 / `shop+0xe44` 价格 / 已购<上限、解锁字节、出现组（§9/§11） | 用 mod 自己的商店数据结构重写这三条判定；**不要**改 th18 原生商店表 |
| 卡图版面 | `cardpos.txt`（x, y, 倾角，5 个一组） | 商店 UI 摆位直接读这份数据（§12.4） |
| 商店的硬编码分支 | 5 张卡在市场上被按 id 特判（§42：`NITORI`/`DANGO`/`KOISHI`/`JYUNKA`/`SHION`） | 这几张的市场行为要在 mod 侧单独实现（原作是硬编码，不是数据） |

## 5. 建议的实施顺序（每步都能独立验证）

1. **4.1（已做） + 4.2（已兜住） + 4.3**（卡图容量是**现在唯一**还没拆的墙）—— 跑 `sitecheck --all`，并用 mod 里那张 id=200 的测试卡实跑一次（`../th18/10-extensibility-limits.md` §8.12）。
2. **搬数据不搬行为**：先把 85 张按主表登记进 `th18/cards.js`（id/名/类别/价格/贴图索引），确认图鉴/编成/商店能正常显示与购买。
3. **按族搬行为**，顺序：状态格族（19 张，最简单）→ 效果对族（21 张，搬脚本+池）→ 每帧/子机族（11 张，模板）→ 小族（27 张）→ **spec-only 9 张**（自己设计）。
4. **货币系统**（§3）在行为搬完之后做，因为它要动商店。
5. 每步都跑 `make check` / `check-docs.py` / 一次实跑。
