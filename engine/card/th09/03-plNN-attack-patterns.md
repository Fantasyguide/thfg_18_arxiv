# 03 — TH09 三个角色的**符卡骨架**（`pl00`/`pl01`/`pl02` 的 `plNN.ecl`）

> **版本**：TH09 v1.50a（`local/th09.v1.50a/`）。**方法**：一手 —— `thdat -x9` 抽 `plNN.ecl`，
> `thecl -d9 -m local/vendor/eclmap/eclmap/th09.eclm` 反编译（eclmap 由
> `tooling/eclmap/gen_eclmap.py` 从 ExpHP 的 `labels.json` 的 `ecl` 键生成）。
> **可信度**：结构 / 发弹调用 / 参数 ✅（逐行）；**弹 id ↔ 画面样子** 🟡（未查贴图）。
> 承 [`02-per-character-ecl.md`](02-per-character-ecl.md)。2026-10-01。

角色号（🟡 owner 供给 + `th09:0x4a0330` 结构佐证）：`pl00` = 博麗霊夢 / `pl01` = 霧雨魔理沙 / `pl02` = 十六夜咲夜。

## 0. 一句话

三份**同构**（都是 `Sub0..SubN` 的 boss 循环：到位 → 定时 → 分阶段发弹），但**发弹的参数完全不同**：
**灵梦 = 两种弹（`514`/`642`）左右对称铺**；**魔理沙 = 一种弹（`512`）沿 ±45° 斜扇面 ＋ 瞄准射击**；
**咲夜 = 大 id 弹（`18946`）＋ `shoot_offset` ＋ 生成子敌人**。

## 1. 灵梦（`pl00`）

```
Sub0:  anm_set_main(0); enemy_flags_set(8); enemy_set_hitbox(24.0f, 24.0f);
       … 移动到 [10016.0f] ±80.0f（上下位）→ move_position(…, 128.0f) …
+40:   …
       ins_99 (2,  2, [10000], 1, [10017.0f], 0.5f, [10016.0f], 0.0f, **514**);
       ins_101(2, 15, [10000], 1, [10017.0f], 0.5f, [10016.0f], 0.0f, **642**);
       ins_101(0,  2, [10000], 1, [10017.0f], 0.5f, [10016.0f], 0.0f, **514**);
       ins_99 (0, 15, [10000], 1, [10017.0f], 0.5f, [10016.0f], 0.0f, **642**);
Sub1:  bullet_effects(0, 128, 0, 60, 1, 0.0f, 3.0f);
       bullet_effects(1, 16384, 0, 11, 15, -1.0f, -1.0f);
       bullet_effects(2, 128, 0, 90, 1, 0.0f, 2.0f);
       ins_99 (11, 2, …, **514**);  ins_101(11, 15, …, **17026**);
Sub4:  bullet_effects(0, 128, 1, 90, 1, 0.0f, 2.0f);
```

- **两种弹**：`514` 与 `642`（`Sub1` 里还出现 `17026`）。
- **对称结构**：同一对参数写两遍，前两个实参从 `(2, …)` 换到 `(0, …)`（= 左右/上下两侧），
  颗数在 `2` 与 `15` 之间换 ⇒ **一侧少一侧多**，是「两边不对称的铺弹」那种观感。
- 速度实参 `0.5f`（慢）。

## 2. 魔理沙（`pl01`）

```
Sub0:  ins_99(12,  6, 1, 8, [10020.0f], 0.5f, [10018.0f],      0.0f, **512**);
       ins_99(13,  6, 1, 8, [10020.0f], 0.5f, [10018.0f],      0.0f, **512**);
       ins_99( 0,  6, 1, 8,         2.0f, 0.5f, [10018.0f],      0.0f, **512**);
Sub1:  ins_99(12,  6, 1, 8, [10020.0f], 0.5f, **2.3561945f**, 0.0f, **512**);   // 3π/4 = 135°
       ins_99(13,  6, 1, 8, [10020.0f], 0.5f, **2.3561945f**, 0.0f, **512**);
       ins_99(12, 10, 1, 8, [10020.0f], 0.5f, **0.7853982f**, 0.0f, **512**);   // π/4 = 45°
       ins_99(13, 10, 1, 8, [10020.0f], 0.5f, **0.7853982f**, 0.0f, **512**);
Sub3:  shoot_disable(); … shoot_enable(); shoot_interval([10037]); shoot_interval(0);
Sub4:  bullet_effects(0, 32, 1, 120, -1, [10016.0f], [10017.0f]);
       ins_99(12, 13, 1, 1, [10018.0f], **1.3f**, [10082.0f], 0.0f, **546**);
```

- **只用一种弹 `512`**（另有一处 `546`），速度也是 `0.5f`。
- ★ **明确的角度实参**：`2.3561945f`（= **3π/4**）与 `0.7853982f`（= **π/4**）⇒ **±45° 的斜向扇面**。
- ★ **`Sub3` 里有 `shoot_disable/shoot_enable/shoot_interval`** ⇒ 这是**敌人自己的常规射击**（boss 那种
  瞄准射击）在开关，不是一次性铺弹。

## 3. 咲夜（`pl02`）

```
Sub0:  bullet_effects(0, 16, 0, 40, -1, [10020.0f], -999.0f);
Sub3:  bullet_effects(0, 2048, 0, 1, -1, -999.0f, 0.0f);
       bullet_effects(1, 16384, 0, 20, 3, -1.0f, -1.0f);
       shoot_offset([10094.0f], [10095.0f]);
       ins_99(20, 2, 7, 1, [10016.0f], **2.0f**, [10082.0f], 0.0f, **18946**);
       shoot_offset(0.0f, 0.0f);
Sub6:  enemy_create_abs("Sub8", [10042.0f], [10043.0f], 0.0f, 10, -2, 10);
Sub8:  shoot_offset([10094.0f], [10095.0f]); …
```

- **弹 id 很大**：`18946`（另一个数量级 ⇒ 大概是「带参数的组合弹」，不是单纯一个 anm 脚本号）。
- ★ 用了 **`shoot_offset`**（先把膛口挪开、发完挪回）⇒ **不是从本体正中发**。
- ★ 会 **`enemy_create_abs`** 出一个**子敌人**（`Sub8`）—— 三份里只有咲夜这么做。

## 4. 三者的差异（给 109 用）

| | 灵梦 | 魔理沙 | 咲夜 |
| --- | --- | --- | --- |
| 弹种 | **两种** `514` / `642`（+`17026`）| **一种** `512`（+`546`）| **大 id** `18946` |
| 形状 | 左右**不对称**地两边铺（颗数 `2` vs `15`）| **±45° 斜扇面**（3π/4 与 π/4）| **偏移膛口** 发，另有**子敌人** |
| 常规射击 | 未见 `shoot_*` | ★ **`Sub3` 全程开关瞄准射击** | 未见 |
| 速度实参 | `0.5f` | `0.5f`（一处 `1.3f`）| `2.0f`（更快）|

## 4.5 ★★ 破解：`ins_99` / `ins_101` 是**环弹**（`etRing` / `etRingAway`）

ExpHP 的 th09 `labels.json` **没给 97–104 这些 opcode 命名**（`nums` 里 98–102 **一条都没有**），
但我生成的 `th09.eclm` 一比对仓库那份**手工维护的** `th08.eclm`（同代 ECL）就出来了：

| opcode | th08 的名字 | th09（ExpHP）|
| :-: | --- | --- |
| 96 | `etFanAimed` | `multiple` |
| 97 | `etFan` | **（缺）** |
| 98 | `etRingAimed` | **（缺）** |
| **99** | ★ **`etRing`** | **（缺）** |
| 100 | `etRingAimedAway` | **（缺）** |
| **101** | ★ **`etRingAway`** | **（缺）** |
| 102 / 103 / 104 | `etRandAng` / `etRandSpd` / `etRand` | **（缺）** |

（`awk '$1==99{print $2}' local/vendor/eclmap/eclmap/th08.eclm` 直接可核。
⚠ 跨代借名要留个心眼：**同代同族**才成立；本条只用来**读懂**，不当「一手定论」。）

⇒ **三角色的符卡一律是「环」**，形态差异在**环的颗数/角度/速度/发几组**上：

| 角色 | 反编译（套上名字后）| 读法 |
| --- | --- | --- |
| **灵梦** | `etRing(2, 2, …)` ／ `etRingAway(2, 15, …)` ／ `etRingAway(0, 2, …)` ／ `etRing(0, 15, …)` | **两种环各两组**（颗数 `2` 与 `15`），`0/2` 那一维像是**两侧** ⇒ **左右不对称地铺两圈** |
| **魔理沙** | `etRing(12, 6, 1, 8, …, 0.5f, 2.3561945f, …)` ／ 同 `0.7853982f` | **环的基准角 = 3π/4 与 π/4** ⇒ **斜向的环**（不是正上正下）|
| **咲夜** | `etRing(20, 2, 7, 1, …, 2.0f, …, 18946)` | 速度实参 `2.0f`（比另外两位的 `0.5f` **快 4 倍**）＋ `shoot_offset` ＋ 子敌人 |

⚠ 仍然**不宣称**已解开每个实参的确切含义（`etRing` 的参数序在 th08 那边的 eclmap 里只有名字、
没有签名）—— 但**「是环」**这件事现在是稳的，足以据此重做 109 的弹幕形状。

## 5. 🟡 没做完的

  `etama.anm`/`bullet.anm` 回查）—— 这一步同时能把**角色号直证**（阴阳玉/飞刀一眼可辨）。
  ★ **已确认前提**（2026-10-01）：`thdat -l9 th09.dat` 里有 **`etama.anm`（612632 B）**、
  `enemy.anm`、`pl0X.anm`/`pl0Xb.anm` ⇒ 抽图这条路是通的（th09 只是没进
  `tooling/thtk/unpack.py` 的 `GAMES` 表，`thanm` 要自己给版本号与 anmmap）。
  ★ **anmmap 也有办法了**（2026-10-01 落地）：`tooling/eclmap/gen_eclmap.py` 加了 **`--kind anm`**，
  用 ExpHP `labels.json` 的 `anm` 键生成 `thanm -m` 要的名表：

  ```bash
  python3 tooling/eclmap/gen_eclmap.py th09.v1.50a --kind anm   # → local/vendor/eclmap/eclmap/th09.anmm（90 条）
  ```

  （格式与 eclmap 同形：`!anmmap` ＋ 空行/注释 ＋ `!ins_names` ＋ `NN name`，
  照 `local/vendor/thpages/static/mapfile/v8.anmm`。`--list` 现在同时报 ecl/anm 条数。）

  ★★ **端到端已验证**（2026-10-01）：

  ```bash

      etama.anm pl00.anm pl01.anm pl02.anm -C local/th09.v1.50a/dat
  local/vendor/thtk/build/thanm/thanm -l9 local/th09.v1.50a/dat/etama.anm \
      -m local/vendor/eclmap/eclmap/th09.anmm
  ```

  ⇒ `etama.anm` **612628 B** 已抽到 `local/th09.v1.50a/dat/`，`thanm -l9` 能列出
  `entry entry0 { version: 3, name: "data/etama/etama.png", format: 5, width: 256, height: 256, … }`。
  ⇒ ✅ **链通了**，但 ⚠ **负结果（2026-10-01 实测）**：那串数字**不是 anm 脚本号** ——

  | anm 文件 | script 数 | `512`/`514`/`546`/`642` 在不在 |
  | --- | :-: | --- |
  | `etama.anm` | **108** | ❌ 没有 |
  | `enemy.anm` | **31** | ❌ 没有 |

  ⇒ `ins_99` / `ins_101` **最后一个实参不是 anm 脚本号**。剩下的候选（下一轮从这里挑一个证）：
  1. **打包值**（`文件号 << 8 | 脚本号`）：`512 = 0x200`（文件 2、脚本 0）、`514 = 0x202`、
     `642 = 0x282`、`546 = 0x222`、`18946 = 0x4A02`（后两个的 `0x82`/`0x22` 落在 0..0xff 里，
     但 `0x4A` 那一半对不上小文件号 ⇒ 打包说的**证据不足**）；
  2. **TH09 自己的 bullet spec 表下标**（像 TH18 的 `specNNN`）；TH09 的 `thanm`/`thecl`
     都不认识它 ⇒ 要找的是**引擎里的弹表**（`local/th09.v1.50a/decomp/all.c` 里发弹那一段）；
  3. `ins_99`/`ins_101` 的**前两个实参**（0/2/11/12/13/20）可能才是「弹种/组」，
     尾参是**组内的参数**。

  ⇒ ✅ **已经绕过这条了**：见 **§4.5** —— `ins_99`/`ins_101` 的名字在**同代的 th08 eclmap** 里
  （`etRing` / `etRingAway`），一比对就出来了。⇒ 剩下的只有**参数序**，那条要读 handler 才准。
