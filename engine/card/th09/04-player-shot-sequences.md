## 0. 一句话结论

**TH09 的 Z 射击不是"按住就连发"，而是"每次按下 = 播放一段有限长度的射击序列"** ✓：
按下的**上升沿**把**射击 playhead**（`player+0x303a4`）从"停"（< 0）拨到 **0**，之后**每帧**用 playhead 的当前值
去 shot 表取一列弹发出去，playhead 涨到 **15** 就**自己停掉**（置 −1）⇒ **一次按键 = 约 15 帧的一小串** ✓；
**连打**时（playhead 还在跑）按下会把 playhead **回退 10（≥10 时）或 5（≥5 时）** ⇒ **序列被续命** ⇒ 才成流 ✓。

## 1. 状态机在哪、被什么驱动（一手 ✅）

| 件 | 位置 | 说明 |
| --- | --- | --- |
| 入口 | `th09:0x41f810`（`Player::on_tick` 在 `0x41eabd` 调）| 一个函数**同时**管「Z 射击序列」与「蓄力→CA」✓ |
| 每侧输入记录 | `&DAT_004ace18 + side*0x8e` | `side = [player+8]`（`0x41f819`）|
| **上升沿** | `0x41f82a push 1; call 0x415cd0` | `0x415cd0` = `[input+0x32] & arg` ⇒ **本帧刚按下** ✓ |
| **电平** | `0x415cb0` | `[input+0x2c] & arg` ⇒ **按住** ✓（掩码 1 = Z、4 = 第四键）|
| 每侧模式字节 | `player + 0xb4 + [0x4a7e78]` | 值 `0`/`1` 走**不同支**（`0x41f838`/`0x41f91d`）|
| 蓄力量 | `player+0x30384` | 每帧 `+= 帧倍率 × [shot_data+0x24]`（`0x41fa75` 附近）|
| 蓄力上限（気槽）| `player+0x30388` | 上限常量 `0x48e3c4` = **400.0** ✓ |
| **shot 表** | `player+0x30338` → 表基址 | 发弹器用它取列（见 §3）|
| 序列标志 | `player+0x1b80` **bit 2**（`0x4`）| = 「CA 序列正在播」✓（`0x41f942 or 4` / 播完 `& ~4`）|

## 2. ★ 两个 playhead（都是 `Timer`，一手 ✅）

`Timer` 布局（`0x42f490` 逐条）：`+0` = previous、`+4` = **float 累加器**、`+8` = **int 当前值**。
* `0x401510` = `Timer::sub_401510` = **推进**（`previous := current`，再把 `+4` 加上帧倍率，`current = int(+4)`）✓；
* `0x401520` = `Timer::is_ge(t, n)` = `current >= n`；`0x401540(t, n)` = `current < n` ✓；
* `0x401500` = `set_current_without_previous(t, v)`（**直接设**，同时把 previous 也设成 v）✓；
* `0x406620(t, n)` → `0x406600(t, -n)` → `0x42f490(t, -n)` = **把 playhead 回退 n** ✓（`0x406670` = 回退 1）✓。

| playhead | 对象 | 谁起 | 用途（一手 ✅）|
| --- | --- | --- | --- |
| **普通射击** | `player+0x303a4` | **每次 Z 上升沿**（`0x41f8af`–`0x41f8e8`）| 每帧发一列（选择子 **0**）|
| **蓄力攻击（CA）** | `player+0x30398` | `flags_1b80` 得 bit2 时（`0x41f94b`，即 `LAB_0041f92b` 蓄力达标）| 每帧发一列（选择子 **1**），播 `[shot_data+0x28]` 帧后清 bit2 |

### 2.0 ⚠ 先纠一处（2026-10-12 复核，**取代本文初版的措辞**）

初版写成"**每帧用 playhead 当 index 发一列**" ✗ —— 逐条重读 `0x41f4c0` 的**调用处**才看清：
```asm
41fc30: push 0x1          ; ★ 留在栈上 = 传给 0x41f4c0 的参数（选择子）
41fc32: mov ecx,edi ; call 0x435f00   ; 0x435f00 = `mov eax,[ecx+8]; ret`（**不弹栈** ✓）
41fc39: mov edx,eax       ; edx = playhead（`[timer+8]`）
41fc3d: mov ecx,esi ; call 0x41f4c0   ; → 0x41f4c0(player, 选择子, playhead)
```
而 `0x41f4c0` 里：`ecx = [ebp+8]`（= **那个 push 的选择子** ✓）→ `edi = [shot_data + 选择子*8 + 0x42c]` ✓
⇒ ⇒ **`+0x42c` 数组的索引是"选择子"，不是 playhead** ✓（playhead 反而作为**第二参**传给每行的回调 ✓）。
★ 一手旁证：`thdat` 抽出的 `plNN.sht` 里 **`+0x02` = 2**（装载器 `0x41bbe0` 的循环上限 ✓）—— 见 §3.1 ✓。

### 2.1 普通射击：**一次按下 ≈ 15 帧的一小串** ✅

按下那一帧（`0x41f892` 块，仅 `mode != 1` 或按住第四键时进入 ✓）：
```asm
41f8af: call 0x401540(&t_303a4, 0)   ; t_303a4 < 0 ?（= 序列已停）
41f8b8: je 0x41f8c3
41f8ba: push 0 ; call 0x401500       ; ★ 停着 ⇒ **从头起播**（playhead = 0）
41f8c3: push 0xa ; call 0x401520     ; 否则：playhead ≥ 10 ?
41f8d0: push 0xa ; call 0x41f300     ;   ⇒ ★ **回退 10**（续命）
41f8d4: push 5  ; call 0x401520      ; 否则：playhead ≥ 5 ?
41f8df: push 5  ; call 0x41f300      ;   ⇒ ★ **回退 5**
41f8e8: push 3 ; call 0x401500(&t_303b0) ; 另一个计时器 = 3
41f8f1: push 1 ; call 0x401500(&t_303bc) ; 蓄力"按住"计时器 = 1（§2.2）
```
播放在 `LAB_0041fc72`（每帧）：
```c
if (Timer__is_ge(&t_303a4, 0)) {                 // 只在跑的时候
    if (FUN_0040f810(&t_303a4))                  // = current != previous（= 本帧推进过）
        FUN_0041f4c0(player, Timer__get_current(&t_303a4), 0);   // ★ 发射：index = playhead
    Timer__sub_401510(&t_303a4);                 // 推进
    if (Timer__is_ge(&t_303a4, 0xf))             // ★★ playhead ≥ 15
        Timer__set_current_without_previous(&t_303a4, -1);       // ⇒ 停（下次按下才重来）
}
```
⇒ ⇒ **结论**：一次 Z 按下 ⇒ playhead 0→15（**15 帧**）的射击序列 ⇒ 每帧一列 ⇒ 出"**一小串**"后自动停 ✓；
**想持续**只能**再按**（连打）—— 按下时若序列还在 5 帧内/10 帧内，就被**回退 5 / 10** 续上 ✓。
（`mode == 1` 时这条不跑：`0x41f925 jne 0x41fc16` 之类把流程带去别处 ⇒ 那个模式下不发普通序列 ✓。）

### 2.2 蓄力与 CA（与 §2.1 同一函数）✅

按住 Z 的帧走 `0x41fa08` 起的支：
```asm
41fa17: push 0xa ; call 0x401520(&t_303bc)   ; 「按住」计时器 ≥ 10 ?
41fa22: je 0x41fc16                          ; ★ 不足 10 帧 ⇒ 只走射击支（不蓄力）
41fa28: ... 蓄力支：charge += 帧倍率 × [shot_data+0x24]，钳到 +0x30388（= 400）...
41fa4a: ... 每跨 100 单位"叮"一声 ...
```
⇒ **按住 ≥10 帧才开始蓄力** ✓（先前 `01-pofv-charge-and-cancel-fields.md` §2.1 记的"10 帧闸"就是这里 ✓）；
蓄力达标（`LAB_0041f92b`）时按量选档：`0x403c30 / 0x403c90 / 0x403cf0` = **CA L1/L2/L3**（消弹圈 192/256/448 ✓），
同时 `flags_1b80 |= 4` 并把 **CA playhead `+0x30398` 归 0** ⇒ 之后每帧发一列（选择子 1），
播到 `[shot_data+0x28]` 帧就清 bit2 ✓。

## 3. 发弹器：`FUN_0041f4c0(player, **选择子**, playhead)` ✅

一手（`0x41f4c0` 起 190 字节 + 两处调用点 + 装载器 `0x41bbe0`）：
* `edi = [ [player+0x30338] + 选择子*8 + 0x42c ]` ⇒ **选择子 0 = 普通射击列、选择子 1 = CA 列** ✓
  （`push 0` / `push 1` 两处调用点逐条对上 ✓；playhead 走 `edx` ⇒ 存 `[ebp-4]` ⇒ 传给每行回调 ✓）；
* 遍历该列：每行 **0x38** 字节，取 `[row+0x28]` 当回调（为 0 则用内建 `0x41f490`），并把 `edx`(= playhead)
  与 `[row+0x2c]/[row+0x30]/[row+0x34]` 一起给出去；行终止 = `[row]`（i16，sprite id）**< 0** ✓；
* 弹对象池 = `player+0xc11c`，**0x80** 个槽、每个 **0x484** 字节 ✓。
⇒ ⇒ **"发几次/什么节奏"不是代码写死的** ✓ —— 它由**那一列里每行的回调**按 playhead 值决定 ✓
（内建 `0x41f490` 与装载器查表得到的那些函数指针 ✓，见 §3.1）⇒ **owner 说的"15 帧 3 次"就落在这一层** ✓。

## 7. ★ 「`+5` / `+10` 是退一次还是两次」—— owner 问过，这里给结论 ✅

前提 = **一手表现 ✓**（owner：「**一次按下 15 帧 3 次**」）⇒ **一次间隔 = 5 帧** ✓。

| 立即数 | 拨回 | 按"一次 = 5 帧"算 | 证据 |
| --- | :-: | --- | :-: |
| `0x41f8d4 push 5`（低档）| **−5** | **退一次** ✓ | 代码 |
| `0x41f8c3 push 0xa`（高档）| **−10** | **退两次** ✓ | 代码 |
| 「一次按下 15 帧 3 次」= 上面那个"一次"的分母 | — | — | **表现** |

★ 但**级联**（先判 `≥10`、否则判 `≥5`）使两支**落到同一个窗**：
`playhead ∈ 5..9` ⇒ −5 ⇒ `0..4`；`playhead ∈ 10..14` ⇒ −10 ⇒ `0..4`；`playhead ∈ 0..4` ⇒ 不动
⇒ ⇒ 合起来 = **"把 playhead 拨回它所在那个 5 帧格子的起点"**（= `playhead % 5`）✓
⇒ 所以**从"还能再打几发"看，两支等价** ✓；原版写成两个立即数只是**省掉取模** ✓（不是两个不同强度的效果 ✓）。
