# TH09 花映塚 —— 蓄力 / 拦 Z 的闸、气槽、以及「消弹圈 = 锚定场」

> **版本**：TH09 v1.50a（`th09.exe`，685,056 B，md5 `cf634df46e05552e104fa97a971aaac0`，imagebase `0x400000`）。
> 本文裸地址默认属该版本；引用其他版本一律带前缀（如 `th18:0x45ebfb`）。

> `thanm -l 9 -m v2.anmm` 反编译 + `local/vendor/th-re-data/data/th09.v1.50a/` 的 ExpHP 命名交叉。
> **可信度**：✅ 一手（§1 的节点结构 / 推进 / 消费 / 实例表；§2 的闸与门槛；§3 的气进账）；
> 🟡 单源推断（§4 的「敌死 ⇒ 暴风」那一条 —— **节点系统里没有敌人侧的消费者**，见 §5 #1）。
> **用途**：mod 卡 109（`POFV_BLAST`）的一手依据；改卡前先读本文。**订正对象**：

## 0. 一句话结论

- **TH09 的消弹圈不是「一次性命中」，而是「锚定在世界上、按帧长半径、活有限帧的场」** ——
  一个节点 = `(圆心, r₀, dr, 寿命, kind)`：建 `0x41cf30` 族，推进 `0x41c8e0`（**每帧 `r += dr`、寿命 `--`**），
  消费 `0x41dff0`（**点是否落在圈内** ⇒ 弹被消：`bullet+0xdbe = 5`，`0x414a7b`）。
  ⇒ 「连锁暴风相对世界几乎静止」（owner 2026-09-18 原话）是**字面意思**：圈不动，是妖精/弹幕飞进来。
- **拦 Z（按住射击不发弹）的闸是时间 = 10 帧**（`0x41fa17` push `0xa` → `0x41fa1b Timer::is_ge`；
  没到就 `0x41fa22 je 0x41fc16` 走**原生射击**支）—— 与气槽、与蓄力等级**无关**。
- **气槽 = 4 格 × 100 单位，上限 400**；蓄力量每帧 `+= 0x4b36b8 × shot_data[+0x24]`，**被气槽钳上界**；
  松手时按 **200 / 300 / 400** 三个门槛发 C1/C2/C3（消弹圈终点半径 **192 / 256 / 448**），
  **≥400 且场上没有 kind-3 boss** 时走另一支（boss attack）。

## 1. 消弹圈 = 节点（场）✅

### 1.1 节点住在 Player 里

| 项 | 一手 |
| --- | --- |
| 首节点（内嵌） | `player+0xb0bc`（`0x41cf3f lea esi,[ecx+0xb0bc]`）|
| 活动节点指针数组 | `player+0xb100`（`0x41c8ec lea esi,[edi+0xb100]`）|
| 活动计数 / 空闲计数 | `player+0xc110` / `player+0xc114`（`0x41c904` / `0x41cf33`）|
| 空闲链表 | `player+0xb908`（`0x41cf4e`）|
| 池初始化 | `0x41ec45 mov DWORD PTR [esi+0xc114],0x200`（512 个空闲节点）|

### 1.2 字段（节点）

| 偏移 | 含义 | 一手 |
| --- | --- | --- |
| `+0x0` / `+0x4` | 圆心 x / y（**建完就不再动**） | `0x41cf81` / `0x41cf91` |
| `+0x8` | **当前半径**（float；逐帧增长） | `0x41c936` `fld [eax+0xc]` → `fadd [eax+0x8]` → `fstp [eax+0x8]` |
| `+0xc` | **dr**＝每帧半径增量 | 同上（被 `fld`）|
| `+0x24` | **寿命**（帧；每帧 `--`，到 0 释放） | `0x41c931 dec DWORD PTR [eax+0x24]` |
| `+0x28` | 额外标量（kind 0/4 用；kind 1 不用） | `0x41cfa0` / `0x41d0f3` |
| `+0x38` | **kind**（1 / 2 / 3 / 4） | `0x41cffd`(=1) / `0x41d0f6`(=4) |
| `+0x3c` | 活动位 | `0x41cf7d` |
| `+0x40` | **延迟**：> 0 时只递减、不参与半径与寿命 | `0x41c8f6`（`jle` 才进推进支）/ `0x41c92a` |

### 1.3 建立 / 推进 / 消费

| 阶段 | 函数 | 一手要点 |
| --- | --- | --- |
| 建立（底层） | `0x41cf30` | `(this=player; pos*; arg2→+0x24; arg3→+0x40)`；从空闲链表取或退到 `+0xb0bc` |
| 建立（kind 1） | `0x41cfe0` | `(pos, r₀→+0x8, dr→+0xc, 寿命, 延迟)`；`+0x38 = 1`（`0x41d000`）|
| 建立（kind 4） | `0x41d0d0` | `(pos, r₀, dr, X→+0x28, 寿命, 延迟)`；`+0x38 = 4`（`0x41d0f6`）|
| 推进 | `0x41c8e0` | 遍历 `player+0xb100[0..+0xc110)`：延迟 > 0 ⇒ 只递减；否则寿命 `--`、`r += dr`、寿命到 0 ⇒ 释放回空闲链表 |
| **消费（判定）** | `0x41dff0` | `(this=player; 点*; …)`：kind ∈ {1,2,3} 且延迟 ≤ 0 ⇒ `dx²+dy² ≤ r²`（`0x41e04d`–`0x41e078`）⇒ 返回非 0 |
| 消费（弹被消） | `0x414a7b`（`BulletManager::on_tick`）| `call 0x41dff0` 非 0 ⇒ `0x414a94 mov WORD PTR [esi+0xdbe],0x5`（**弹状态 5 = 消去**）|

### 1.4 在册的实例（全部一手：把调用点的 push 逐条读出来）

| 谁 | 建点 | r₀ | dr | 寿命 | 延迟 | 终点半径 |
| --- | --- | --- | --- | --- | --- | --- |
| 自机弹命中（kind 0）| `0x41fe93`–`0x41fea3` | 0 | **1.6** | **70** | 0 | **112** |
| CA 释放那一下（kind 1）| `0x41e875`–`0x41e88c` | **16** | **20** | 8 | 0 | **176** |
| CA L1（kind 1 + kind 4）| `0x403c30` | 0 | **4.0** | **48** | 0 | **192** |
| CA L2 | `0x403c90` | 0 | 4.0 | **64** | 0 | **256** |
| CA L3 | `0x403cf0` | 0 | **3.5** | **128** | 0 | **448** |
| boss attack | `0x41795b` / `0x41799a` | **500** | 0 | **30000** | 0 | 500 |

> ⚠ **两条订正**（初读错过、复核时按 push 顺序重读）：
> ① 自机弹命中那个节点的寿命是 **70 帧**（`0x41fe95 push 0x46`），不是 6 —— `6` 是 `+0x28` 那个额外标量
> （`0x41fe97 push 0x6` 落在 `[ebp+0x14]` ⇒ `+0x28`，见 `0x41d0f3`）；
> ② 「延迟」与「寿命」是两个字段：`+0x40` 在前（`0x41c8f6` 只递减），`+0x24` 才是寿命（`0x41c931`）。
- **画出来的环走同一个律**：`etama.anm` script 91/92/93 = `pos(16.0f,…)` + `posTime(48/64/128, 0, 192/256/448)`
  （起点 **16**、终点 = 上面那一列终点半径、时长 = 寿命）—— 与判定**只对齐终点**，过程不等
  （详见 [`../th18/14-clear-range-barrier.md`](../th18/14-clear-range-barrier.md) §2.4/§2.6）。

## 2. 蓄力与「拦 Z」✅

### 2.1 入口与两条路

`Player::on_tick`（`0x41e900`）在 `0x41eabd` 调 `0x41f810`（蓄力 / 射击状态机）。它的分派：

| 行 | 一手 | 语义 |
| --- | --- | --- |
| `0x41f82a`–`0x41f836` | `is_rising_edge(input, 1)` | Z 本帧按下？（掩码 1 = Z）|
| `0x41f83e`–`0x41f846` | `cmp BYTE PTR [edi+ecx+0xb4],1` | 每 side 一个**模式字节**（≠1 走 `0x41f892` 蓄力支）|
| `0x41f9d7`–`0x41fa06` | 模式 0 + `is_active(1)` | **Slow 档（默认）**：按住 Z ⇒ 落进蓄力支 `0x41fa08` |
| `0x41fa17`–`0x41fa22` | `push 0xa` → `Timer::is_ge` → `je 0x41fc16` | ★ **按住满 10 帧**才停在蓄力支；否则本帧走**原生射击**支 `0x41fc16` |
| `0x41fbd8`–`0x41fc11` | `player+0x30384 = 0`、计时器置 −1 | 松手 / 无 CA 时的收尾 |

⇒ **「Z 点一下 = 发一发」与「长按 = 蓄力且不发弹」在原版是同一条闸**：闸只看**按住时长**（10 帧），
不看气槽、不看等级。

### 2.2 蓄力量与气槽

| 量 | 一手 |
| --- | --- |
| 当前蓄力量 | `player+0x30384`；每帧 `+= ds:0x4b36b8 × [shot_data+0x24]`（`0x41fa75`–`0x41faa4`）|
| 钳上界 | `0x41fab0 fcomp [player+0x30388]` ⇒ 超过就写回上限（`0x41fabd`–`0x41facb`）|
| 气槽（上限） | `player+0x30388`，`add_charge` `0x41bc90` `+= arg`（低速态再多 `arg×0.15`，`0x48ef60`），**上限 400.0**（`0x48e3c4`）|
| 1 格 = 100 单位 | `add_charge` 里 `(int)(新旧上限/100)` 不同就通知 HUD（`0x41bd0d`–`0x41bd26`）、以及 `0x41fa80`–`0x41faa0` 的 `/100` 判级 |
| 每升一格「叮」 | `0x41fb15 cmp edi,eax` / `0x41fb1d`–`0x41fb38`：`push 0x32`（= `se_chargeup.wav`）|

### 2.3 松手时按蓄力量发档（一手门槛）

| 蓄力量 | 分支 | 效果 |
| --- | --- | --- |
| < 100 | `0x41f92b`–`0x41f93c` → `0x41fbd8` | 什么都不发（蓄力量清零）|
| ≥ 200 | `0x41fb8e`–`0x41fbd3` | `0x403c30`（消弹圈 192 / 48 帧）|
| ≥ 300 | `0x41fb42`–`0x41fb8c` | `0x403c90`（256 / 64 帧）|
| ≥ 400，场上有 kind-3 boss | `0x41f984`–`0x41f993` → `0x41fb42` | 退回 L3 那一支 |
| ≥ 400，场上**没有** kind-3 boss | `0x41f984` → `0x41f999` | 另一支（boss attack；`0x40f7d0` 查 kind-3 敌）|

> ⚠ **门槛与「a/b」显示是两套刻度**：`a = floor(蓄力量/100)`（HUD 上的档数，0..4），而**发放门槛**是
> 200/300/400。⇒ 「1 格气就能放 C1」这条**不是**原版：原版最小那一档要 **200（= 2 格）**。

## 4. 对 109 号卡的意义（我们据此改了什么）

| 现象（owner 2026-09-18 单卡实跑）| 一手依据 | 改法 |
| --- | --- | --- |
| #1「花映冢未拦截 Z」| §2.1 的闸 = **10 帧**，与气槽无关 | `pofv_charge_suppress()` 改成「按住满 `POFV_SUPPRESS_AFTER_FRAMES`(10) 帧就拦」。旧实现要「等级 ≥ C1 **且** 气 ≥ 1 格」，而气槽空时 `max_level = 0` ⇒ 等级恒 0 ⇒ **永不拦** |
| #3「没有任何蓄力机制」| §2.2：蓄力量只被气槽**钳上界**，是**时间**在涨 | `pofv_charge_hold()` 的等级不再被气槽夹（涨到 4 档为止）；能不能放出去由 `pofv_charge_usable_level() = min(a, b)` 判 |
| #4「暴风的连锁不该这么快」| §1：场是**锚定 + 逐帧扩张 + 有限寿命**，消费是**逐帧点测试** | 暴风改成场（`pofv_storm_*`）：活的场每帧都判；**连爆档不再是 30 帧窗口的节拍器**，而是「点着它的那个场的档 + 1」|
| #5「暴风缺乏范围」| §1.4：TH09 **最小**的场终点半径 = 176（CA 释放）/192（CA L1）| 连爆档 1 的终点半径改成 **176**（一手），旧值 64 比 TH09 最小的圈还小一半 |
| （顺带）CA 的半径表 | §2.3 / §1.4 | C1/C2/C3 = **192 / 256 / 448**（一手原值），不再是占位 80/128/200 |
| （顺带）#2 音效 | §2.2 的 `push 0x32` | 已在 2026-09-20 接完（`TUNING.md` §4 / §4.1），本文只做交叉印证 |

## 5. 未解 / 边界（别把没查的写成查了）

| # | 事实 | 影响 |
| --- | --- | --- |
| 1 | **节点系统没有敌人侧消费者**：`0x41dff0` 的全部调用点都在弹幕侧（`0x414a56`/`0x414a7b` 的 `BulletManager::on_tick` + `0x44xxxx` 的弹型 tick），**没有** EnemyManager 的调用点 | ⇒ 「暴风**引爆范围内其他小怪**」这一条在 TH09 的节点系统里**找不到实现**。它来自用户口径（`local/MEMORY.md` §1.3m），在 109 里是**我们自己的伤害源**（`ce_damage_rect`）实现的 🟡 |
| 2 | 敌人掉血的唯一写点 | `0x4110d9 sub DWORD PTR [ebx+0x2e48],edi`（EnemyManager::on_tick 的自机弹碰撞支）—— 全 exe 扫 `+0x2e48` 的写点只有这一处是「减」 |
| 3 | `ds:0x4b36b8` | 蓄力量每帧增量的倍率（§2.2），**全 exe 只有读、没有写点**，落在 `.data` 的零填充区 ⇒ 每帧增量原值取不到（🚧 与 `th18/14` §7 #1 同一条）|

```bash
import struct
d=open('local/th09.v1.50a/th09.exe','rb').read(); pe=struct.unpack_from('<I',d,0x3C)[0]
nsec=struct.unpack_from('<H',d,pe+6)[0]; opt=pe+24; base=struct.unpack_from('<I',d,opt+28)[0]
secoff=opt+struct.unpack_from('<H',d,pe+20)[0]
secs=[( *struct.unpack_from('<IIII',d,secoff+40*i+8), ) for i in range(nsec)]
def rd(a,n=4):
    for vsz,va,rsz,ra in secs:
        if va<=a-base<max(vsz,rsz): return d[ra+(a-base-va):ra+(a-base-va)+n]
for i in range(0x26):
    print(hex(i), [hex(x) for x in struct.unpack('<6I', rd(0x4a0b48+i*0x18, 0x18))])
PY
```
