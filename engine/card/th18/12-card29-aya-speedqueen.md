# TH18 原生卡 29「SPEEDQUEEN」（文 / Aya）的**起步无敌**：条件、量、以及为什么能刷成永久无敌

> **版本**：TH18 v1.00a（`th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th16:0x…`。
> **可信度**：条件 ✅ 一手（四条独立站点 + 输入位表）· 量 ✅ 一手（`addss` 立即数）· 「能刷」✅ 一手推演（可复跑）
> · 🟡 「实战里能刷多快」没实跑过（要人手的 1 帧精度）。

## 1. 结论表

| # | 断言 | 可信度 | 一手 |
| --- | --- | --- | --- |
| 1 | 触发条件 = **上一帧方向 == 0 ∧ 这一帧方向 ≠ 0 ∧ 没按 Shift** | ✅ | 卡片 `0x40ca95`–`0x40cab2`（三条门） |
| 2 | 量 = **+4 帧**（`float 4.0f`，加法不是赋值） | ✅ | `0x40cb16 addss xmm1,[0x4b9248]`（`0x4b9248` = 4.0f） |
| 3 | **没有「已在无敌中就不再累加」的闸** ⇒ 计时器可单调上升 | ✅ | `0x40cafc`–`0x40cb2a` 全段无比较/钳位，只有 `addss` + 写回 |
| 4 | 「上一帧方向」= **卡片自己缓存的** `card+0x58`，每帧刷新 | ✅ | 读 `0x40ca95`、写 `0x40cb3b`（尾，全分支汇合） |
| 5 | ★ 按 **Z（射击）** 时：卡片**整段不走**，只把缓存**钉成 0** 就返回 | ✅ | `0x40c80a test [player+0x4779c],0x200` → `0x40c84c/0x40c853` → `ret` |
| 6 | 那个 `0x200` 位 = **「这一帧按着 Z」**，每帧先清后置 | ✅ | 清：`0x45c921 and ecx,0xfffffdff` + `0x45c927` 写回；置：`0x45ea17 or [player+0x4779c],0x200`（`0x45ea06 test [0x4ca428],0x1` = 输入 bit0） |
| 7 | 之后**开火 / 按 Shift 都不会取消**已有的无敌 | ✅ | 计时器写点穷举见 §5；判据只读 `player+0x47778 > 0` |
| 8 | 「以 1 帧精度反复制造触发」⇒ 每 2 帧净 +2 帧 ⇒ 事实上的永久无敌 | ✅ 推演 | 见 §4 两条配方 |

**与社区解明的对照**：`engine/card/th18/08-catalog.md` 第 70 行把 29 号卡写为
「停射时超高速移动；移动中判定极小，**起步瞬间无敌**」 —— 与 §2 的条件逐条吻合（「停射」= 松开 Z，
「起步瞬间」= `上一帧方向 == 0 ∧ 这一帧方向 ≠ 0`）。

## 2. 条件：三条门 + 「谁把上一帧方向钉成 0」

`CardAya__on_tick` = **`0x40c7f0`**（卡片虚表 +0x24 那个槽的实现；`ecx` = 卡片对象，`ebx` = `player`）。

```
40c80a: test DWORD PTR [player+0x4779c],0x200
40c814: je   0x40c869              ; ★ 位没置 ⇒ 走「主路」（下面那段）
      ; ---- 位置着 Z 的那一支：不判方向、也不加无敌，只把状态压回起点就返回 ----
40c816–40c849: 读 SHT 行的两个速度字段 × 常量 0x4b9310 写进 player+0x477b4/+0x477bc
40c84c: mov  [card+0x54],1
40c853: mov  [card+0x58],0         ; ★★ 「上一帧方向」被钉成 0
40c85a: ... ret                    ; ★ 本帧**不**走加法

40c869: ...（主路：状态机/特效/别的分支）
40ca95: mov  eax,[card+0x58]       ; eax = 上一帧方向（缓存）
40ca98: cmp  eax,[player+0x4793c]  ; 与这一帧的方向比
40ca9e: je   0x40cb30              ; 相同 ⇒ 跳（含「两帧都没动」）
40caa4: test eax,eax
40caa6: jne  0x40cb30              ; 上一帧 != 0 ⇒ 跳
40caac: cmp  [player+0x476cc],0    ; 聚焦？
40cab2: jne  0x40cb30              ; 聚焦 ⇒ 跳  ★ 所以「没按 Shift」
40cab4–0x40cb1d: 算 xmm1 = 现有计时器 + 4.0（或 ×时间缩放因子）
40cb1e/0x40cb22/0x40cb2a: cvttss2si → 写回 player+0x47778(cur)/+0x4777c(cur_f)
40cb30: mov  eax,[player+0x4793c]
40cb3b: mov  [card+0x58],eax       ; ★ 尾：不管走哪一支，都把缓存刷成这一帧的方向
```

`player+0x4793c` = **移动方向**（`0` = 没按方向，`1`..`8` = 八向），写点在 `0x45b2cc`–`0x45b3ca`（`Player::move` 段，
八向各一条 `mov …,0x1`..`0x8` + 一条 `mov …,0x0`）。`player+0x476cc` = 聚焦标志（≠0 = 按着 Shift）。

**★ 那个 `0x200` 位是谁置的（本文补上的一环；此前是 🟡）**：`Player::on_tick` 每帧先清、`Player::move` 再按输入置：

| 动作 | 地址 | 一手 |
| --- | --- | --- |
| 清位 | `0x45c921 and ecx,0xfffffdff` + `0x45c927 mov [player+0x4779c],ecx` | 在 `Player::on_tick` 里（同一函数里还有无敌计时器的每帧递减 `0x45c5bc`） |
| 置位 | `0x45ea17 or DWORD PTR [player+0x4779c],0x200` | 由 `0x45ea06 test BYTE PTR [0x4ca428],0x1` 把门 —— `0x4ca428` = 输入按住位、**bit0 = Z（射击）**（`engine/card/th18/04-active-cards.md` §1 的位表） |
| 调用 | `0x45c97c call 0x45ea00` | `Player::move` 由 `Player::on_tick` 调 ⇒ 位的时序 = 每帧「清 → 按输入置」 |

⇒ 卡片看到的 `0x200` = 「**这一帧按着 Z**」。
⇒ **按住 Z 时卡片不加无敌**（走了那个「压回起点并返回」的支），但**把 `card+0x58` 钉成 0**；
⇒ **松开 Z 的那一帧**，只要「按着方向 ∧ 没按 Shift」⇒ `上一帧方向 == 0 ∧ 这一帧方向 ≠ 0 ∧ !聚焦` ⇒ **+4**。
（这就是用户口径「**放开 Z / Shift，按着方向键那一下给无敌**」的真身：条件里其实**只认 Z**；
「放开 Shift」本身不给 —— 聚焦期间尾段照常刷缓存，所以松开 Shift 那帧 `上一帧 == 这一帧`，跳过了。
但**按住 Shift 期间若同时按 Z**，`0x200` 照样被置 ⇒ 松 Z 那一帧只要还没松 Shift 也**不给**。）

## 3. 量：`addss`，没有上限闸

| 分支 | 地址 | 一手 |
| --- | --- | --- |
| 加法 A（时间缩放表项在区间内） | `0x40cafc mulss xmm1,[0x4b9248]` → `0x40cb04 addss xmm1,[player+0x4777c]` | `xmm1` 来自 `0x4b35c0` 表（索引 = `player+0x47780`，**全 exe 只有写 0 的站点** ⇒ 实际取表项 0） |
| 加法 B（默认） | `0x40cb0e movss xmm1,[player+0x4777c]` → `0x40cb16 addss xmm1,[0x4b9248]` | `0x4b9248` = **4.0f** |
| 写回 | `0x40cb1e cvttss2si eax,xmm1` → `0x40cb22 movss [player+0x4777c],xmm1` → `0x40cb2a mov [player+0x47778],eax` | `cur_f` / `cur` 两个字段一起写 |

⇒ **量 = 4 帧，语义是「加」**（不是置值）；整段 `0x40ca95`–`0x40cb2a` 里**没有**任何
`cmp 计时器` 或钳位 ⇒ **只要反复满足条件，计时器就单调上升**。

## 4. 「能刷成永久无敌」：两条配方（各 +4 / 2 帧 ⇒ 净 +2 帧/帧）

| 配方 | 人手动作 | 为什么成立 |
| --- | --- | --- |
| A（**点 Z**，最简单） | 按住一个方向键，**每 2 帧点一下 Z**（按 1 帧、松 1 帧） | 按 Z 的帧：卡片走「钉 0 + 返回」（不加）。松 Z 的帧：`上一帧==0 ∧ 方向≠0 ∧ !聚焦` ⇒ **+4** ⇒ 2 帧 +4 |
| B（**抖方向**，不碰 Z） | 不按 Z，每 2 帧在「方向键按住 / 全松」之间切一次 | 松的帧把缓存刷成 0；按的帧 ⇒ `上一帧==0 ∧ 方向≠0` ⇒ **+4** ⇒ 2 帧 +4 |

两条都是 **+2 帧/帧的净增**（触发 +4、同帧自然递减 −1，平均每帧 −0.5 的摊销 ⇒ 净 +2）
⇒ 计时器无上界 ⇒ 只要人手跟得上，**就能攒出一大坨无敌**（实战里等于「想不想」的问题，不是「能不能」）。

⚠ 连续朝一个方向跑**不会**累计（缓存每帧刷新 ⇒ 只有起步那一帧给）—— 这就是「起步瞬间无敌」的字面语义。

## 5. 攒到的无敌**不会**被后续输入取消

无敌计时器 = `player+0x47774` 的 `zTimer{prev@+0x47774, cur@+0x47778, cur_f@+0x4777c}`：

| 面 | 一手 |
| --- | --- |
| 判据（谁是「无敌」） | 命中判定读 **`player+0x47778 > 0`** ⇒ `0x45cd1c` / `0x45ce78` / `0x45d055` |
| 每帧递减 | `0x45c5bc`–`0x45c634`：`cur <= 0` 直接跳；否则 `cur_f -= 1.0`（或 ×时间缩放因子）⇒ `cur = (int)cur_f` |
| 写点（除本卡） | 复活 280（`0x45c372`）、死亡结算 180（`0x45d280`）、`Player__die` 6（`0x45d50d`），另有 60 / 40 / 110 / 120 见 [`engine/player/th18/03-player-hit-gate.md`](../../player/th18/03-player-hit-gate.md) §6(b) |
| **开火 / 聚焦 / 放 B** | **没有任何一处**在按 Z、按 Shift、放灵击时清这个计时器或缩短它 |

⇒ 攒完之后：**按 Shift 只是让条件 `!聚焦` 不成立（不再加），已有量照常 −1 帧/帧**；
**继续开火**只是让卡片走那个 early-return 支（不加），同样不影响已有量。
⇒ 用户问的「后续开火、按 shift 都不会退出无敌」= **对**。

## 6. 本仓的用法与刻意偏差（卡 111 的支援特技⑥「恋恋」）

- 条件：**复刻**（`native/cards/signal_core.{h,c}` 的 `signal_koishi_tick()`，(a) 路 =
  `last_dir == 0 && dir != 0 && !focus`，与 §2 逐条同形；`move_dir` 直接读 `player+0x4793c`、
  `focusing` 直接读 `player+0x476cc`）；量：**复刻 4 帧**（`SIGNAL_KOISHI_INVULN_FRAMES`）。
- **刻意不累加**（用户 2026-09-15 拍板）：我们走 SDK 的无敌**声明层**
  （`ce_invuln_request` / `ce_invuln_apply`，聚合 = **取 max**、**置值**语义）—— 那一层是与
  107 / 109 / 117 共用的契约 ⇒ 全卡组里「抖 1 帧刷永久无敌」这条口子被**结构性地**堵住。
  登记：`TUNING.md` §2.1g / `AUDIT.md` §DE-3b / `NEXT.md` §2F。
- (b) 路（用户口径「**全**键位放开」）是 ❓ 自定，覆盖「站着不动把键全放开」这种原生不触发的情形；
  两个诊断计数分开印（`nat` / `usr`）。

```bash
grep -n "40c7f0:\|40ca95:\|40ca9e:\|40caac:\|40cafc:\|40cb04:\|40cb16:\|40cb3b:" local/_scratch/th18.dis

sed -n '/^  45c910:/,/^  45c935:/p' local/_scratch/th18.dis      # 每帧清 0x200

grep -n "0x47774\|0x47778\|0x4777c" local/_scratch/th18.dis      # 计时器写点普查
```
