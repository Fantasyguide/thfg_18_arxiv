# anm/th18 §3 — ASCII 文字系统：字形集由「页 + 字体 id」两段决定

> **版本**：TH18 v1.00a（`th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；
> 引用其他版本写成 `th15:0x…` / `th16:0x…`。
> **方法**：一手反编译（2026-09-10）：`AsciiManager__create_string` `0x419b90`、
> `AsciiManager__draw_string` `0x41a2b0`、`AsciiManager__drawf_debug` `0x41a110`、
> `FUN_00416ae0`（默认值）、`PopupManager__on_draw` `0x464180` + 构造函数 `0x463dd0`；
> 对照 TH15 的 `AsciiManager__create_string` `th15:0x40c410`、字符串绘制 `th15:0x40c960`、
> `Gui::on_draw_2e` `th15:0x436990`。
> **可信度**：字形映射表与字段复制表 ✅ 一手；「某字体在游戏里长什么样」只有**间接**证据（精灵尺寸/位置），
> 需要实机截图才能最终确认。

## 0. 一句话

一条字符串的**字形集**由两个数决定：

1. **页**（`vm+0x20`，ExpHP 名 `zAnmVmPrefix.__anm_loaded_index_2__new_in_um__used_in_ascii`）
   = 取哪一份**已装载 anm**（`zAnmManager.preloaded[页]`，TH18 在 `mgr+0x312072c`）；
   ASCII 文字系统常年是 **页 2 = `anm_02_ascii`（`ascii.anm`）**。
2. **字体 id**（环境 `mgr+0x19244`，`create_string` 抄进每条记录的 `+0x120`）
   = 在这份 anm 的**精灵表**里选哪一段字形块（见 §2 的表）。

`group`（`mgr+0x19248`）与字体无关，是**渲染分组**（同组的字符串一起做进出场动画）。

⚠️ **页不是 `+0x2c` 这个「字段名」**：`+0x2c` 只是「ascii 管理器里内嵌的第一个 VM」的 `+0x20`。
TH15 的 ascii 管理器内嵌 VM 在 `+0x10`（页在 VM+0x28 = `mgr+0x38`，一手反汇编）、TH18 在 `+0x0c`（页在 `+0x2c`）——
两作偏移不同，别跨作抄。

## 0b. 一条字符串的完整调用链（`font_id = 2` 是怎么生效的）

```
写环境字体           create_string 抄进记录           draw_string 每帧解释
mgr+0x19244 = 2  →   record+0x120 = 2          →   switch(record+0x120):
   （或 TH15 +0x1923c）                               字体 2/3 → 字形号 = char + 0x94（数字/大写）
                                                                    char + 0x74（小写）
                                                                    / : - * % $ . + → 固定 0xce..0xd4/0x101
                                                     ↓
                                    字形号 → 精灵表项 = preloaded[页]+0x11c + 字形号*0x44
                                                     ↓
                                            取该项的 UV/尺寸写进 VM 顶点 → 画
```

要点：**`font_id` 本身不带字形**，它只是「用哪一套字符→精灵号偏移」的编号；
真正的字形来自**页选中的 anm 的精灵表**。页 = 内嵌 VM 的 `anm_loaded_index_2`
（TH18 `mgr+0x2c`、TH15 `mgr+0x38`），值是 **2** ⇒ `preloaded[2]` = `anm_02_ascii` = `ascii.anm`。
`ascii.anm` 的精灵表**跨 entry 全局编号**：0..319 = entry0 `ascii.png`，
所以字体 2 的数字 = 精灵 **196..205**（`char + 0x94`：'0'=0x30 → 0xC4），
落在 `ascii.png` 的 **(0..72, 160)** 那一行、8×10 px。

### 0c. ⚠️ 陷阱：`drawf_debug` `0x41a110` 会把字体**强制改成 1**

`AsciiManager__drawf_debug` 是「调试用 printf」：它 `create_string` 之后还会执行

```
0041a14e  IMUL EAX, [ESI+0x19224], 0x138     ; num_strings * 记录步长
0041a15d  MOV  dword ptr [EAX + ESI + 0xc0c], 1
```

记录基址 = `mgr + 0xc24 + idx*0x138`，而 `create_string` 已把 `num_strings` 加到 `idx+1`
⇒ 该地址 = `mgr + idx*0x138 + 0xd44` = **刚建那条记录的 `+0x120`（font_id）**
⇒ **不管调用前把环境字体设成几，画出来都是字体 1**（映射 `char + 0x42`）。

⇒ 想控制字体**必须**自己调 `create_string` `0x419b90`（thiscall `mgr, pos[3], text`）。
卡侧 `ce_hud_text_raw` 原先用的就是 `drawf_debug` —— 这就是「字体扫描五行全长一个样、
换字体毫无效果」的真因（2026-09-10 反汇编坐实并修掉）。

### 0d. 分辨率变体：同一批精灵号有三套字形

ascii 管理器构造（`th18:0x419390`）按全局 UI 缩放 `DAT_0056aca0` 选文件装进 preloaded 槽 2：

| `DAT_0056aca0` | 装载 | 字体 2 的数字尺寸 |
| --- | --- | --- |
| > 1.6 | `ascii1280.anm`（贴图 512×512）| 16×20 |
| > 1.1 | `ascii_960.anm`（384×384）| 12×15 |
| 否则 | `ascii.anm`（256×256）| 8×10 |

三套是**各自重画**的（不是放大），精灵号与字符映射完全相同 ⇒ 卡侧不用管，跟着引擎走即可。

## 1. 字符串记录的字段复制（`create_string` `0x419b90`，一手）

记录步长 **0x138**，记录基址 = `mgr + 0xc24 + idx*0x138`（`idx = mgr+0x19224` 计数器，上限 0x140），
文本首字节就在记录 `+0`。环境 → 记录的复制表：

| 记录偏移 | ← 环境字段（TH18） | 含义 |
| --- | --- | --- |
| `+0x100` | 调用参数 `pos` | 位置（**乘过 `DAT_0056aca0`** 这个全局缩放因子）|
| `+0x10c` | `mgr+0x19228` | 字色 |
| `+0x110`/`+0x114` | `mgr+0x19230`/`+0x19234` | 缩放 x/y |
| `+0x11c` | `mgr+0x19238` | 内部字段 |
| `+0x120` | **`mgr+0x19244`** | **字体 id** |
| `+0x124` | `mgr+0x19240` | 描边开关（0/1）|
| `+0x128` | `mgr+0x19248` | **渲染分组** |
| `+0x12c` | `mgr+0x1924c` | 存活帧数 |
| `+0x130`/`+0x134` | `mgr+0x19250`/`+0x19254` | 水平/垂直对齐 |
| **页** | **不复制** | `draw_string` 现读 `mgr+0x2c`（= 内嵌 VM 的 `+0x20`）|

⇒ 改字体要**在 `create_string` 之前**写 `mgr+0x19244`；改页要**在绘制那一帧**之前写 `mgr+0x2c`。
`FUN_00416ae0` 是「恢复默认」：字色白 / 副色黑 / 缩放 1.0 / 描边 0 / **字体 0 / 分组 0** / 对齐 1,1
（它**不碰页**——页是装载期定下来的）。

## 2. 字体 id → 字形基址（`draw_string` `0x41a2b0` 的 switch，一手）

精灵索引 = `字符码 + 基址`（`+0x120` 为 0/1/2/3/4/5/10/11 时；6..9 是另一套）。

| 字体 id | 基址 / 映射 | 备注 |
| --- | --- | --- |
| 0 | `char − 0x20` | ASCII 0x20.. → 精灵 0..；**环境默认值** |
| 1 | `char + 0x42` | |
| 2 / 3 | `'a'..'z' → char+0x74`；`'A'..'Z' → char+0x94`；`/ : - * % $ . +` → 固定 `0xce/0xcf/0xd0/0xd1/0xd2/0x101/0xd3/0xd4`；其余 → `char+0x94`（数字走这条）| **TH15 面板那五行用的就是 2** |
| 4 / 5 | `0xef`（10 → `0x10d`、11 → `0xfe`）；`/ . s * ,` → 基址 +10/+11/+12/+13/+14 | |
| 6 / 8 | `0x120` | `ascii_big`（`320 + char−0x20`）|
| 7 / 9 | `0x1e4` | `ascii_big2`（`516 + char−0x20`）|

### 2b. `ascii.anm` 的精灵布局（`local/th18.v1.00a/anm/ascii/ascii.anm.txt` 一手）

精灵索引是**整个 anm 文件全局编号**（跨 entry 连续），所以字体基址能直接对到某一 entry：

| 精灵区间 | entry / 贴图 | 字形尺寸 | 内容 |
| --- | --- | --- | --- |
| 0..319 | entry0 `ascii/ascii.png`（256×256）| 14×14（尾部混 8×8 / 8×10）| 小字 + 三排数字块 |
| 320..417 | entry1 `ascii/ascii_big.png` | 22–32 × 39 | 大字（= 字体 6/8）|
| 418..515 | entry2 `ascii/ascii_bigf.png` | 同上 | 大字的**描边版** |
| 516..613 | entry3 `ascii/ascii_big2.png` | 16–26 × 47 | 更大（= 字体 7/9）|
| 614..711 | entry4 `ascii/ascii_big2f.png` | 同上 | 更大字的**描边版** |
| 712..714 | entry5 `ascii/loading.png` | | 读盘画面 |

entry0 内部还有分块：`196..238` 是 **8×10** 一排（字体 2 的数字 = `0x30+0x94 = 196`）、
`239..268` 是 **16×16**（两行 15 个）、`269..283` 是 14×14、
`289..298 / 300..309 / 310..319` 是**三套 8×8 数字**。

### 2c. 符卡弹窗（符卡名 + `BONUS %.1f`）不用字符串系统（一手）

`PopupManager__on_draw` `0x464180` 自己把字符**逐字**画成精灵（不调 `draw_string`）：
行内字符码 + `0x121`(289) / `0x12c`(300) / `0x136`(310) 三个基址按字号档位选，
取字形的 anm 来自**弹窗 VM 自己的 `vm+0x20`**，而构造函数 `0x463dd0` 把它设成
`*(int*)ASCII_MANAGER_PTR->ascii_anm`（= ascii.anm 的索引 = 2）。
⚠️ 这三段是 8×8 的**小数字块**，不是「好看的大字体」——用户说的「bonus/history 那一排」
若是这里的数字，那它的观感来自弹窗 VM 的缩放，别直接拿这三段当字体用。
（TH16 的弹窗反过来是走字符串系统的：`th16:0x44a31e` 写 `font_id = 2`。）

### 2d. 分组 = 四个绘制趟，且字符串只活一帧（一手，卡里踩过）

字符串的 `+0x128`（`render_group`）决定它由哪个绘制趟画：

| 趟（update func）| 组号 | 备注 |
| --- | --- | --- |
| `AsciiManager__on_draw_58` `0x419940` | **0** | 直接 `draw_group(0)` |
| `AsciiManager__on_draw_37` `0x419950` | **1** | 带相机/渲染状态设置 |
| `AsciiManager__on_draw_48` `0x419a80` | **2** | |
| `AsciiManager__on_draw_3f` `0x419b10` | **3** | |

`AsciiManager__draw_group` `0x41a180` 只画 `+0x128 == 组号` 的记录，然后 `flush_sprites`。

★ **字符串活不过下一帧**：`AsciiManager__on_tick` `0x4198b0` 每帧把每条记录的 `+0x12c`
（`remaining_time`）减 1，≤ 0 的记录被压缩掉；而 `create_string` 把环境 `+0x1924c`
（`duration`，默认 **0**）抄进这个字段。⇒ **串必须在同一帧内、在它所属组的绘制趟之前创建**，
否则永远不显示。卡侧结论：**用组 0**（它的趟跑在卡的 `on_draw` 之后）；照抄原作的
`group = 1` 会让串「当帧没人画、下帧被清」= 数字消失。

### 2e. 字号：ASCII 空间是 640×480 那一套

`FUN_00416ae0`（重置默认）把 `scale`（`+0x19230`）设成 **1.0**；TH15 画面板文字时用的就是
这个环境值。TH18 的 ASCII 坐标空间 = 640×480（= 1280×960 表面的 **1/2**），
所以「和原作一样大」= **scale 1.0**；写成 2.0 就是实打实的 2 倍（卡里踩过）。

### 2f. 单个字形的几何：锚点表 + 字距 + 对齐（一手，2026-09-10 补）

`draw_string` 画每个字形时**借用管理器内嵌 VM 的顶点路径**（`FUN_0047e8f0` / `FUN_0047ed50`），
所以字形的落点完全由那套公式决定：

| 量 | 一手出处 | 值 |
| --- | --- | --- |
| 锚点（水平）| `flags_lo`（`vm+0x534`）**bits 22–23** → 系数表 `0x4cdb00` | ASCII 置 **0 = 居中**（表 `(-0.5, 0.5, -0.5, 0.5)`）|
| 锚点（垂直）| 同字段 **bits 24–25** → 系数表 `0x4cdb30` | ASCII 置 **1 = 顶**（表 `(0, 0, 1, 1)`）|
| 四角公式 | `0x47ed50` | `角 = sprite_size × 系数 − anchor_offset`（`vm+0x84/+0x88`），再乘 `scale × scale_2`，再加 `pos` |
| 分辨率 | `flags_hi`（`vm+0x538`）bits 22–24 | ASCII **清 0** ⇒ 尺寸 ×1（**字形就是贴图的像素尺寸**）|
| 字距 | `0x41a2b0` case 2/3 | `scale_x × 7`；**`.` 特例 `scale_x × 4`** |
| 行高（只用于垂直对齐）| 同上 | `scale_y × 10` |
| 水平对齐 | `record+0x130` | `0` = 居中（每字退半个字距）、`1` = 左（不退）、`2` = 右（退满整串宽）|
| 垂直对齐 | `record+0x134` | `0` = 居中（退半个行高）、`1` = 顶（不退）、`2` = 底（退一个行高）|

⇒ **一个字符的墨迹落点**（表面 px）= `x × DAT − Σ字距`（按对齐退）`+ Σ前面各字的字距`，
y = `y × DAT − 垂直退量`（字形单元**顶边**贴在那里，锚点索引 1 = 顶）。
字形单元本身在 `ascii1280` 里是 **16×20**（`ascii_960` 12×15、`ascii` 8×10），
墨迹不一定铺满单元（`.` 的墨迹在单元第 12–17 行）——**要切图就切整格，别按墨迹裁**。

⚠️ **怪癖**：字距变量 `local_c` 只在「真的画了一个字」时更新，而空格走的是「跳过整个 switch」那条路
⇒ **空格紧跟 `.` 之后时，它的字距是 4 而不是 7**（`0x41a2b0` 的 `local_c` 初始化/更新点）。

⚠️ **ASCII 文字不可能被暂停模糊罩盖住**（2026-09-10 实跑 + 反汇编坐实）：
模糊罩 = `text.anm` script59 的 UI VM（层 38 → 绘制桩优先级 `0x3e`），而四个 ASCII 绘制趟里
只有 **组 1**（`0x419950`，`0x37`）比它早；可那一趟**先把相机切成相机 0**，而它跑的时刻
渲染目标还是 **surface 1**（`0x2c` 切过去、`0x3a` 才回后备缓冲；surface 1 装层 20–23）
⇒ 串落进 surface 1 的相机 0 坐标系、跑到视口外，**实跑看不见**。
要「数字也跟着被罩住」只有一条路：**把数字做成贴图 VM**（UI 层 25 → 折到组 38 → 与罩子同桩，
罩子暂停时后起 ⇒ 盖在上面）。mod 侧实现见 `mods/th18.v1.00a/card-expand/SDK.md` §16。

## 3. 跨作对照（TH15 ↔ TH18）✅

| 项 | TH15 v1.00b | TH18 v1.00a |
| --- | --- | --- |
| ascii 管理器全局 | `th15:0x4e9a58` | `th18:0x4cf2ac` |
| 内嵌 VM / 页字段（VM 内偏移）| `+0x10` / **`VM+0x28`**（= `mgr+0x38`）| `+0x0c` / **`VM+0x20`**（= `mgr+0x2c`）|
| 字体 id 字段 | `+0x1923c` | `+0x19244` |
| 分组 / 对齐 | `+0x19240` / `+0x19248`、`+0x1924c` | `+0x19248` / `+0x19250`、`+0x19254` |
| 记录步长 | 0x138 | 0x138 |
| 字体 2/3 映射 | `+0x74` / `+0x94` / `0xce..0xd4` | **逐条相同** |

⇒ 复刻 TH15 的文字只需照抄字体 id：**TH15 面板五行 = 字体 2 + group 2 + 水平对齐 2**、
顶上的大号章节奖数字 = **字体 4 + align 0/0**（`th15:0x436990` 一手）。

## 4. 用法（card-expand）

- `sdk.h` 的 `ce_hud_text_ex(x, y, bgra, shadow, font, group, align_h, scale, fmt, …)`
  逐项「先存后改、画完还原」；`font = -1` 表示不动（用环境值）。
- `ce_hud_font_page(page)` 切页（写 `mgr+0x2c`）——**TH18 里我们只用过 page 2**，
  大字体（`ascii_big`/`ascii_big2`）是字体 6/7 不是页。
- 实测踩坑：把 `font` 猜成 7/11 都不对（那两档是超大字号）；**正确做法是去原游戏代码里
  读它写的是哪个 id**（TH15 面板 = 2，一手 `th15:0x436990`）。
