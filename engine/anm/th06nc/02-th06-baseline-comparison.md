# TH06 ↔ TH06NC 的 ANM VM 对照

> **版本**：跨版本。本文出现的地址一律带版本前缀（`th06:0x433960` / `th06nc:0x1400069b0`）。

状态：结构对照 ✅ 一手（两个库各自的反汇编 + 跳表 + 字节）；
本文同时**收口**了 [`01`](01-vm-and-anchor-opcodes.md) §6 那条 🟡 —— 结论是**被证伪**，见 §4。

一句话：**NC 的 ANM VM 就是 TH06 那台机器换 x64 重编译一遍**，
VM 结构体重新排过布局、指针变宽，指令集在尾部加了四条。
不是「相似」，是同一份设计。

---

## 1. 对照怎么做的

两边各建一个 Ghidra 库、各导一份 HTML，然后**只比对我们自己库里的东西**，
社区源码只用来对语义、不用来取地址：

| | TH06 v1.02h | TH06NC |
| --- | --- | --- |
| exe | `local/th06.v1.02h/th06.exe` | `local/th06nc/th06nc.exe` |
| VM | `th06:0x433960`（`AnmManager__run_vm`） | `th06nc:0x1400069b0`（`AnmManager__ExecuteScript`） |
| HTML | `tooling/ghidra/serve.sh th06.v1.02h` | `tooling/ghidra/serve.sh th06nc` |

TH06 那侧的 VM 地址有**两个上游独立佐证**：ExpHP 叫它 `AnmManager__run_vm`、
th06-re XML 叫它 `th06::AnmManager::ExecuteScript`，落在同一地址。

## 2. 分派结构

| 项 | TH06 | TH06NC |
| --- | --- | --- |
| 跳表 | `th06:0x434a63`，**32 项**（绝对地址） | `th06nc:0x140007494`，**36 项**（RVA） |
| 上界 | `cmp …,0x1f` / `ja` | `cmp DL,0x23` / `ja` |
| 表尾 | 紧接 `0xCC` 填充 | — |
| 越界落点 | 推进尾部 | 推进尾部 |
| opcode 6 与 22 共用 handler | ✅ 都是 `th06:0x43431b` | ✅ 都是 `th06nc:0x1400070e3` |
| opcode 18/19/20 | ❌ **三个独立 stub**（`th06:0x433f0a` / `th06:0x433f24` / `th06:0x433f3e`，等距 `0x1a`） | 共用 `th06nc:0x140006d44` |

18/19/20 那条是**代码生成差异不是语义差异**：TH06 的三个 stub 各自置自己的 flag 位后
汇入同一段公共代码，NC 的编译器把它折成了一个带运行时判别的 handler。

指令头两边完全相同：`{s16 time; u8 opcode; u8 argsSize}`，args 在 `+4`，
下一条 = 当前 + 4 + argsSize。

## 3. 反编译结构：26 个 case 逐字同序

把两边 `ExecuteScript` 的反编译各自抽出 `case` 标签，**得到完全相同的 26 个标签、
完全相同的顺序**（0、15 合并在最前，然后 1–5、7、8、12、14、16–21、23–31）。
一个 2002 年的 32 位 MSVC 二进制和一个 2022 年的 64 位二进制，
Ghidra 各自独立反编译出同样的 case 归并结构——这本身就是「同一份源码」的强证据。

NC 多出的四个是 `case ' '` / `'!'` / `'"'` / `'#'`（0x20–0x23），排在最后。

## 4. ✅ 收口：两边都**不会**按文本宽度改写精灵矩形

[`01`](01-vm-and-anchor-opcodes.md) §6 曾推测「NC 加锚点是因为本地化文本宽度可变」，
并把「精灵矩形会不会被改写」列为没证实的一环。现在两边都查了，**答案是不会**：

- **TH06** ✅：`th06:0x434b60`（`AnmManager__DrawVmTextFmt`）读 `vm+0xc0` 的精灵，
  取它的 `startPixelInclusive` 与 `textureWidth/Height` 交给 `th06:0x434af0` 往纹理里画，
  然后只做 `*(uint *)(vm + 0x80) |= 1`。**全程不写精灵**。
  全仓社区源码里 `widthPx` / `heightPx` 也只出现在读侧（唯一的写在加载器 `LoadSprite`）。
- **TH06NC** ✅：`th06nc:0x140007530` 是同一形状——读 `vm+0x100` 的精灵、
  用它的 `+0x30/+0x34/+0x2c` 调字形渲染 `th06nc:0x14007d2c0`、
  然后 `*(uint *)(vm + 0xc4) |= 1`。**同样不写精灵**。

**结论**：锚点作用的是**固定尺寸的槽**，不是实测文本宽度。
§6 那条「因为文本宽度可变」的因果**不成立**，已在 01 改标。

**剩下的 ❓**：那么锚点对文本槽究竟起什么作用，仍未解。
候选是 `th06nc:0x14007d2c0` 自己在槽内做对齐——本文没验。
不要把这条写成已解释。

## 5. VM 结构体字段映射

偏移全变了（64 位重排 + 指针变宽），但**每条 opcode 写几个字段、写哪类字段是对应的**。
下表是从两边反编译里按 case 抽「被赋值的 vm 偏移」比出来的：

| 语义 | TH06 | TH06NC |
| --- | --- | --- |
| `flags` | `+0x80` | `+0xc4` |
| 缩放 x / y | `+0x18` `+0x1c` | `+0xe4` `+0xe8` |
| 缩放速度 | `+0x20` `+0x24` | `+0x7c` `+0x80` |
| 颜色 | `+0x7c` | `+0xec` |
| alpha | （op3 走字节写） | `+0xef` |
| 旋转 xyz | `+0x4` `+0x8` | `+0x9c` `+0xa0` `+0xa4` |
| 角速度 xyz | `+0xc` `+0x10` `+0x14` | `+0xa8` `+0xac` `+0xb0` |
| uvScroll x / y | `+0x28` `+0x2c` | `+0x2c` `+0x30` |
| 位移 / 插值目标 | `+0x90` `+0x94` `+0x98` | `+0x18` `+0x1c` `+0x20` |
| `currentInstruction` | `+0xbc`（**1 个 dword**） | `+0xf8` `+0xfc`（**2 个 dword = 8 字节指针**） |
| 脚本时间 | — | `+0xb8` |
| 精灵指针 | `+0xc0` | `+0x100` |
| fontWidth / fontHeight | `+0x10c` `+0x10d` | `+0x108` |
| VM 步长 | — | `0x120` |

`flags` 那行有两处独立佐证：`ExecuteScript` 与 `DrawVmTextFmt` 在各自 exe 里用的是同一偏移。

`currentInstruction` 那行是最干净的一条：TH06 写 1 个 dword、NC 写 2 个，
**正好是 32→64 位指针变宽**，不是语义变化。

> ⚠️ 上表由脚本按 case 块粗切得出，**公共尾部会被算到最后一个 case 头上**
> （TH06 记在 op31、NC 记在 op35）。那两行不可信，其余行两边字段数一致。

## 6. 纯 flag 指令两边一一对应

只写 `flags` 一个字段的 opcode，两边完全一致：

| opcode | TH06 | TH06NC |
| --- | --- | --- |
| 0 `exit` | 只写 flags | 只写 flags |
| 13 / 14 混合模式 | 只写 flags | 只写 flags |
| 23 锚点 | 只写 flags | 只写 flags |
| 25 / 29 | 只写 flags | 只写 flags |
| **32 / 33 / 34** | — | 只写 flags |

opcode 23 的字节级对照见 [`01`](01-vm-and-anchor-opcodes.md) §4：

```
TH06   th06:0x434201    8b 82 80 00 00 00   mov eax,[edx+0x80]
                        80 cc 03            or  ah,3            ; flags |= 0x300
TH06NC th06nc:0x140006fbe  41 81 a3 c4 …    and [r11+0xc4],~0x300
                           41 81 8b c4 …    or  [r11+0xc4],0x400
```

**TH06 只置位，NC 先清后置**——这正是「两个开关位」变成「3 位枚举」的直接体现。

## 7. 差异清单（到目前为止）

| 差异 | 性质 |
| --- | --- |
| 指令集 0–31 → 0–35 | **真差异**，见 [`01`](01-vm-and-anchor-opcodes.md) |
| 锚点从 2 个开关位 → 3 位枚举 | **真差异**；opcode 23 语义未变但位型变了 |
| VM 结构体偏移全变 | 编译差异（x64 重排 + 指针变宽） |
| 18/19/20 从 3 个 stub → 1 个共用 handler | 代码生成差异 |
| 跳表从绝对地址 → RVA | x64 惯例 |

**尚未逐条一手复核的**：0–31 里除上述之外的具体语义，本文只做了字段级对形，
没有逐条读参数与算法。不要把「结构对上了」当成「每条语义都验过了」。

## 8. 自己看

```sh
tooling/ghidra/serve.sh th06.v1.02h 6094   # TH06

```
