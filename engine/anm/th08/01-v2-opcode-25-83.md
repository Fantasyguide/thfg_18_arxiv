# anm/th08 §1 — v2 的两条「无名指令」查到落点：`25`（旋转开关）与 `83`（自机弹四边形变体）

> **版本**：TH08 v1.00d（`th08.exe`，imagebase `0x400000`）。本文裸地址默认属该版本。
> **一手（2026-09-26）**：卡 108 把妖侧弹体贴图照搬原作时，逐条核对「源脚本里哪几条指令没翻过来」⇒
> `ins_25` 与 `ins_83`。两条都在 `AnmManager::ExecuteScript`（`0x45ea00`）里，分发表
> **`0x45ea95 jmp DWORD PTR [edx*4+0x46206d]`**（`edx = opcode + 1`，`cmp ecx,0x5a; ja` 上界 ⇒ 表长 0x5b）。
> 解表：`op 25 → 0x45f8d7`、`op 83 → 0x460314`（校验：`op 82 → 0x45f2d3` = `blendMode`、
> `op 84 → 0x45ecdb` = `color2`，与 `v2.anmm` 逐条对得上）。

## 1. `25` = 「按 VM 的 rotation 画」的开关（写 `zAnmVm+0x1fc`）

```
45f8d7  mov ecx,[ebp+0x8]          ; vm
45f8da  mov edx,[ebp-0x4]          ; 当前指令
45f8dd  mov ax,[edx+0x8]           ; 参数（16 位）
45f8e1  mov WORD PTR [ecx+0x1fc],ax; ★ 写 zAnmVm+0x1fc
45f8e8  jmp 0x461785               ; 推进指令指针
```

**读者（一手，`Player::UpdateBulletVms` `0x4512f0`）**：循环 0x80 个 `PlayerBulletVm` 槽（stride 0x484），
只处理 `state == 1`（在飞）的那些：

```
451343  movsx eax,WORD PTR [edx+0x1fc]   ; ★ 读同一格
45134a  test eax,eax / je 451360         ; 为 0 ⇒ 不做事
451351  mov edx,[ecx+0x450]              ; = 该 VM 的 rotation（引擎按飞行角维护）
45135b  call 0x40ec00                    ; 把 rotation 交给绘制
```

⚠ **`PlayerBulletVm` 的结构是 `AnmVm(0x2a4) + …`**（`Player.hpp:73-78`）⇒ `bullets[i]+0x1fc` **就是那颗弹
VM 自己的字段** —— 所以「这个偏移没人读」的说法只对**别的** VM 类别成立（见 §3 的口径订正）。

**对位（TH18）**：`424 rotateAuto`（`v8.anmm`；TH16 文档记它写 `flags_hi` bit7）。TH18 的原生自机弹脚本
逐条都写 `rotateAuto(1)`（`pl00.anm` script5/6 起手 `layer(13); type(1); …; rotateAuto(1);`）
⇒ **`ins_25(N)` ≡ `rotateAuto(N)`**。卡 108 的生成器已按这条翻译（`AUDIT.md` §BE #106）。

## 2. `83` = 自机弹的**绘制变体选择子**（写 `zAnmVm+0x200`）

```
460314  mov ecx,[ebp+0x8]               ; vm
460317  mov edx,[ebp-0x4]               ; 当前指令
46031a  mov eax,[edx+0x8]               ; 参数（32 位）
46031d  mov DWORD PTR [ecx+0x200],eax   ; ★ 写 zAnmVm+0x200
460323  jmp 0x461785
```

`zAnmVm+0x200` 的 vendor 名字是 **`playerBulletHitAnimationType`**（`AnmPrefix` 尾部，见 `AnmManager.hpp`）
—— **这个名字会误导**：它不是「命中动画」，而是**绘制变体选择子**。一手（`AnmManager::DrawPlayerBullet` `0x45e960`）：

```
45e96c  mov ecx,[eax+0x200]              ; 读它
45e975  cmp ecx,0x5 / ja 45e9d7          ; ★ > 5 ⇒ 走**通用 anm 绘制路径**
45e97e  jmp DWORD PTR [ecx*4+0x45e9dd]   ; 0..5 = 六个专用绘制例程
        0 → 0x462ff0 · 1 → 0x463800 · 2 → 0x463210 · 3 → 0x463470 · 4 → 0x463cf0 · 5 → …
```

六个例程做的事（读 `0x462ff0` 正文）：用 `spriteSize(+0x28/+0x2c) × scale(+0x18/+0x1c) / 2.0`
（`0x4b42ec` = **2.0**）算出半个边长，再按 `flags(+0x1f8)` 的 flip 位算四个角，把**顶点直接写进全局四边形缓冲**
（`0x18bdcd0`/`0x18bdc98`/`0x18bdcec`/`0x18bdcb4`/`0x18bdcb8`…）⇒ 即 **TH08 自机弹的四边形是引擎手搓的**
（0..5 是六种 flip/anchor 变体，`> 5` 才退回通用 anm 绘制）。

**对位（TH18）**：**没有这个字段、也没有这套手搓路径** —— TH18 的弹就是走通用 anm 绘制
（`AnmManager__draw_vm` 配合脚本的 `type()` / `rotateAuto` / `flipX`/`flipY` 位）。而且六个变体**画的是同一张
sprite、同一个位置与尺寸**，差别只在 flip/anchor 处理 ⇒ **不翻译 `ins_83` 在 TH18 侧没有可见后果**
（卡 108 的生成器据此把它标成「v8 没有这个助记符 ⇒ 省略」，理由写在产物脚本的注释里）。

## 3. 口径订正：`engine/enemy/th08/02-familiar-anm-57-58.md` §3.2 的适用范围

那份文档的结论是「`ins_25` 在 TH08 里是 dead store ⇒ 不建议翻成 `rotateAuto`」—— 它的**普查方法**没错
（`grep +0x1fc` 后逐条归函数），但**适用范围要收窄**：清单里已经列到的 `Player::UpdateBulletVms` /
`Player::DrawBulletVms` 读的**正是** `AnmVm+0x1fc`（因为 `PlayerBulletVm` 内嵌 `AnmVm`）⇒
**对「自机弹」这一类 VM 它是活的**；对**使魔那几支脚本**（那类 VM 的绘制不走 `DrawPlayerBullet`）
它才可能是死存。`AUDIT.md` §BE #106 的实跑判据（弹的尖头应指向飞行方向）已证这条翻译是对的。
