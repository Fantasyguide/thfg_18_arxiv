# ANM v8 sprite 四边形几何 —— TH16 一手（`draw_vm` 的 mode 0/1/2/3 路径）

> **版本**：TH16 v1.00a（`th16.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th18:0x…`。
> **方法**：不经 Ghidra 渲染——`tooling/pe_read.py` + capstone 直解 `draw_vm` 的 sprite 分支
> （`0x468504`/`0x468542`/`0x4686e0`）、两个角函数（`0x465c40`/`0x4660b0`）与批量组装
> （`0x465280`），锚点表与颜色模式跳表逐字节直读；再用自写解析器跑 `local/th16.v1.00a/dat/`
> 的 54 个真实 `.anm` 统计用量。
> **可信度**：mode 0/1/2/3 的**顶点位置、UV、颜色**公式全 ✅（每条指得到机器指令）；
> mode 4/8/15 走另一条路（`0x467410`），本文**不覆盖**，见 [§6](#6-还没搞清楚的)。
> **衔接**：Drawing 组自身语义与 render state 见 [`09-drawing.md`](09-drawing.md)；
> `zAnmVm` 字段图见 [`02-vm-core.md`](02-vm-core.md) §3.3；`421 anchor`/`423 colorMode`/`429 uvScale`
> 的写入侧见 [`07-general.md`](07-general.md) §2。本文只讲**读出来怎么变成顶点**。
> **不含版权字节**：只写偏移、地址与公式。

## 0. 一句话结论

**这是播放器真正要画的那件事。** [`09-drawing.md`](09-drawing.md) 解的是 Drawing 组（600–613）那 5 种特殊
几何，但真实数据里**只有 4.7% 的 script（90/1929）用到 Drawing 组**；绝大多数 script 就是
`300 sprite` + `302 renderMode`，画的是一个**四顶点的贴图四边形**。这个四边形的顶点由
`draw_vm` 的 sprite 分支算出来，公式如下（`I` = 4 个角，顺序恒为 **TL, TR, BL, BR**）：

```c
// ① 锚点 → 单位四边形（两张 4×float4 表直读，见 §2）
x[i] = ANCHOR_X[(flags_lo >> 21) & 3][i];       // 0x4a3048
y[i] = ANCHOR_Y[(flags_lo >> 23) & 3][i];       // 0x4a3078
// ② 乘 sprite 尺寸、减锚点偏移
x[i] = x[i] * sprite_size.x - anchor_offset.x;  // +0x70 / +0x80
y[i] = y[i] * sprite_size.y - anchor_offset.y;  // +0x74 / +0x84
// ③ 分辨率档（313 resolutionMode，flags_hi bits20-22）
// ④ 乘有效缩放（自身 scale × scale_2，若挂父且未 ignoreParent 再乘父的同一乘积）
sx = scale.x * scale_2.x;  sy = scale.y * scale_2.y;      // +0x50 / +0x58
if (parent && !(flags_hi & 0x10000)) { sx *= p.scale.x * p.scale_2.x; sy *= ...; }
x[i] *= sx;  y[i] *= sy;
// ⑤ 旋转（**只有 mode 1/3**）：θ = 有效 z 旋转 = 0x464dd0(vm)
//    mode 0/2 完全不转
xr =  x[i]*cos(θ) - y[i]*sin(θ);
yr =  x[i]*sin(θ) + y[i]*cos(θ);
// ⑥ 平移到最终位置（0x406c40 = pos + entity_pos）
out[i].x = xr + final_pos.x;
out[i].y = yr + final_pos.y;
out[i].z = pos.z + pos_2.z + entity_pos.z;      // 四个角同一个 z
```

顶点格式 = FVF `0x144`（XYZRHW\|DIFFUSE\|TEX1），stride **28**（`09` §4.4），
四个角写进静态缓冲 `0x4df830` / `0x4df84c` / `0x4df868` / `0x4df884`（间隔正好 `0x1c` = 28）。

## 1. 分发：哪些 mode 走这条路

**① 发现**：`09-drawing.md` §3 的 mode→handler 表把 0/1/3 指到 `0x468504`/`0x468542`、2 指到 `0x4686e0`，
但没解 handler 体。**② 推测**：这几个 handler 共用同一套角计算。**③ 验证**（逐条反汇编）：

| mode | handler | 算角函数 | `0x465280` 的第 2 参 | 谁设的 |
| :---: | --- | --- | :---: | --- |
| 0 | `0x468504` | `0x465c40`（**不旋转**） | `1` | 默认 / `302` |
| 1 与 3 | `0x468542` | `0x4660b0`（**旋转**） | `0` | `302` |
| 2 | `0x4686e0` | `0x465c40`（**不旋转**） | `0` | `302` |
| 4 / 8 / 15 | `0x468584` / `0x468621` / `0x468647` | — 走 `0x467410`，**本文不覆盖** | — | `302` |

**④ 结论**（✅ TH16）：**mode 0 与 mode 2 的顶点位置完全一样**，差别只在传给 `0x465280` 的 flag
（bit0）；mode 1 与 mode 3 共用同一个 handler，连 flag 都一样 ⇒ **在几何层 1 和 3 无法区分**。

**每条 handler 开头都有同一个早退**（`0x468504`/`0x468542`/`0x4686e0` 的头四条）：
`if (color_1.A == 0 && color_2.A == 0) return;` —— 读的是 `+0x523` 与 `+0x527`（两个 D3DCOLOR 的 A 字节，
02 §3.3 的字节序 `+0x520`=B `+0x521`=G `+0x522`=R `+0x523`=A）。**全透明直接不进批量缓冲**，
不是靠 blend 去消。播放器省掉这条会多提交一堆空四边形。

**⑤ 证据**：`0x468504`–`0x46858f`、`0x4686e0`–`0x46871f`；跳表见 `09-drawing.md` §3。

## 2. 锚点：两张 4×float4 表（`421 anchor` 的落地）

**① 发现**：`0x465c4c`–`0x465c92` 与 `0x4660f4`–`0x46611d` 都是
「取 `flags_lo` 的两段 2 位 → `<< 4` → 加表基址 → 拷 4 个 float」。

**② 推测**：`07-general.md` §2.1 已记 `flags_lo` bits21–22 = `421` 的 h、bits23–24 = v，
那这两张表就是逐角系数。**③ 验证**（直读 PE）：

| `(flags_lo>>21)&3` | 语义（07 §2.1） | `0x4a3048` 的四个 float（对应 TL/TR/BL/BR 的 x） |
| :---: | --- | --- |
| 0 | 中 | `-0.5, +0.5, -0.5, +0.5` |
| 1 | 左 | ` 0.0, +1.0,  0.0, +1.0` |
| 2 | 右 | `-1.0,  0.0, -1.0,  0.0` |
| 3 | （未定义） | `-0.5, -0.5, +0.5, +0.5` ← **是一份 y 型图案**，见下 |

| `(flags_lo>>23)&3` | 语义 | `0x4a3078` 的四个 float（y） |
| :---: | --- | --- |
| 0 | 中 | `-0.5, -0.5, +0.5, +0.5` |
| 1 | 顶 | ` 0.0,  0.0, +1.0, +1.0` |
| 2 | 底 | `-1.0, -1.0,  0.0,  0.0` |
| 3 | （未定义） | ` 0.0,  0.0,  0.0,  0.0` ← 退化成零宽 |

**④ 结论**（✅ TH16）：

1. **角顺序是 TL, TR, BL, BR** —— 由 h=0 的 `(-0.5,+0.5,-0.5,+0.5)` 与 v=0 的 `(-0.5,-0.5,+0.5,+0.5)`
   逐位配对读出来的，不是假设。
2. 表的第 4 项（值 3）**两张都不是有效锚点**：x 表的第 4 项是 y 型图案（八成是复制粘贴留下的），
   y 表的第 4 项全 0（四边形塌成一条线）。`421 anchor` 写的是 `n & 3`，所以值 3 可达；
   ZUN 数据里是否出现过**没查** ❓。播放器照抄这两张表即可，不需要为值 3 另立分支。

**⑤ 证据**：`0x465c5b`/`0x465c92`（表基址）、`0x466115`/`0x46611d`（SSE 版同两张表）；表内容直读
`0x4a3048`/`0x4a3078` 各 64 字节。

## 3. 位置：不旋转（`0x465c40`）与旋转（`0x4660b0`）

两个函数**签名相同**：`(vm, out0, out1, out2, out3)`，`__cdecl`，`RET 0x14`。步骤一一对应，
`0x4660b0` 是 SSE 向量化版（`MULPS`/`SUBPS` 一次算四个角）并多了旋转。

| 步骤 | 不旋转 `0x465c40` | 旋转 `0x4660b0` |
| --- | --- | --- |
| 锚点取表 | `0x465c4c`–`0x465c7e`（逐角标量） | `0x4660f4`–`0x466140`（`MOVUPS` 整块） |
| × `sprite_size` | `0x465cb2`–`0x465d1d` | `0x466123`–`0x46614f`（`SHUFPS` 广播 + `MULPS`） |
| − `anchor_offset` | `0x465d22`–`0x465da5` | `0x466152`–`0x46616d`（`SUBPS`） |
| `313` 分辨率档 | `0x465daa`–`0x465f01` | `0x466178`–`0x4661cf` |
| 有效缩放 | `0x465f06`–`0x465fb3` | `0x4661db`–`0x466251` |
| **旋转** | **无** | `0x4660da` 取角 + `0x466254`–`0x466346` |
| 平移 | `0x465fb8`–`0x46606b` | `0x4661d6` + 上面同一批加法 |
| 写 z | `0x466070`–`0x466095` | `0x46634b`–`0x466374` |

**旋转角一手**（`0x4660da`）：`CALL 0x464dd0` 后取 `[EAX+8]` —— 就是
[`04-variables.md`](04-variables.md) §6.2 的**有效 z 旋转**（变量 `10026`，自身 `rotation.z` 累加根 VM 的，
受 `flags_hi & 0x10000` 闸门）。`0x4660e9` `FLD θ; FSINCOS; FSTP; FSTP` ⇒ 先弹出的是 **cos**
（`[ebp-0x30]`），后弹出的是 **sin**（`[ebp-0x34]`）。

**旋转式**（`0x466254`–`0x466285`，逐角重复四次）：
`x' = x·cos − y·sin`、`y' = x·sin + y·cos` —— 标准 2D 正向旋转，**在缩放之后、平移之前**。

**z 是四角共用的一个标量**（`0x466070` / `0x46634b`）：`entity_pos.z + pos.z + pos_2.z`
（`+0x5e8` + `+0x34` + `+0x4e8`）。注意 `0x465fbd` 那一段也往 z 上加过 `final_pos.z`，但随后被这一步
**整个覆盖**——是死写，播放器不必复刻。

**⑤ 证据**：上表每格的地址；`0x406c40` = `final_pos = pos + entity_pos`（`+0x2c..0x34` 加 `+0x5e0..0x5e8`）。

## 4. UV：`sprite` 的四角 + 滚动 + `uv_scale` 子矩形

**① 发现**：`0x465280` 里 `0x46541f`–`0x465553` 一段把 `+0x3a8`（sprite 的 UV 四角，02 §3.3）
与 `+0x78`（`uv_scroll_pos`）、`+0x68`（`uv_scale`）拌在一起写进四个顶点的 `+0x14`/`+0x18`。

**③ 验证**（记 `U[i]`/`V[i]` = `+0x3a8 + i*8` 的两个分量，`su`/`sv` = `uv_scroll_pos`，
`ku`/`kv` = `uv_scale`）：

| 顶点 | u | v |
| :---: | --- | --- |
| 0 (TL) | `su + U[0]` | `sv + V[0]` |
| 1 (TR) | `su + U[0] + (U[1] − U[0])·ku` | `sv + V[1]` |
| 2 (BL) | `su + U[2]` | `sv + V[0] + (V[2] − V[0])·kv` |
| 3 (BR) | `su + U[2] + (U[3] − U[2])·ku` | `sv + V[1] + (V[3] − V[1])·kv` |

**④ 结论**（✅ TH16）：`uv_scale`（`429 uvScale`，`wipe` 默认 `(1,1)`）是**沿 u/v 方向的线性插值系数**——
`(1,1)` 时四角就是 sprite 的原始 UV 四角；小于 1 时**从左/上侧裁掉一部分贴图**（右边界与下边界
朝左上收），这就是「只画贴图的一部分」（进度条式）的机制。`uv_scroll_pos` 是四角**统一**的平移。

⚠️ **不对称**：`ku` 只作用在 1、3 两个角，`kv` 只作用在 2、3 —— 也就是**收缩恒以 TL 为锚**，
与 `421 anchor` 无关。播放器把它实现成「以中心缩 UV」会画错。

**⑤ 证据**：`0x465424`（`U[0]+su`）、`0x465487`–`0x465498`（`(U[1]−U[0])·ku`）、
`0x4654b5`（`U[2]+su`）、`0x4654d2`–`0x4654f0`（`(V[2]−V[0])·kv`）、
`0x465508`–`0x46551e`（`(U[3]−U[2])·ku`）、`0x46552e`–`0x465553`（`(V[3]−V[1])·kv`）。

## 5. ★ 颜色：`423 colorMode` 的语义（本文补出）

**① 发现**：`0x4656f7`–`0x465708` 把 `(flags_lo >> 0x11) & 3`（**bits 17–18**）当下标跳
`0x465a14` 的 4 项表。[`07-general.md`](07-general.md) §2 只记了 `423 colorMode` **写**这两位（值 0/1/2/3），
**没写它做什么**。

**③ 验证**：跳表直读 = `{0x46570f, 0x46570f, 0x4658b7, 0x4658b7}`，即 **{0,1} 走平涂支、{2,3} 走渐变支**。

- **平涂支** `0x46570f`：`TEST flags_lo, 0x60000` ⇒ 值 0 取 `color_1`、值 1 取 `color_2`；
  随后 `0x4658a5`–`0x4658b2` + `0x4659e9`/`0x4659ee` 把**四个角写同一个颜色**。
- **渐变支** `0x4659c2`–`0x4659ee`：`v3` 恒 `color_2`、`v0` 恒 `color_1`，中间两个角按
  `(flags_lo & 0x60000) == 0x40000`（= 值 2）分叉。

**④ 结论**（✅ TH16）——`423 colorMode` 的四个值：

| 值 | bits17–18 | v0 (TL) | v1 (TR) | v2 (BL) | v3 (BR) | 效果 |
| :---: | :---: | :---: | :---: | :---: | :---: | --- |
| 0 | `00` | c1 | c1 | c1 | c1 | **平涂 `color_1`**（默认） |
| 1 | `01` | c2 | c2 | c2 | c2 | **平涂 `color_2`** |
| 2 | `10` | c1 | c2 | c1 | c2 | **水平渐变**（左 c1 → 右 c2） |
| 3 | `11` | c1 | c1 | c2 | c2 | **垂直渐变**（上 c1 → 下 c2） |

> ★ 这同时**否掉** [`09-drawing.md`](09-drawing.md) §9 原先的猜测「rect 族的 `flags_lo` bit 21–24 疑似
> `423 colorMode`」——21–24 是**锚点**（§2），`423` 在 **17–18**。

**⑤ 证据**：`0x4656f7`/`0x465708`（下标与跳）、跳表 `0x465a14` 直读、
`0x465715`/`0x465717`/`0x46571f`（平涂选色）、`0x4659c2`–`0x4659ee`（渐变四角）。
