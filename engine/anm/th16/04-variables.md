# ANM 脚本变量表 — TH16 一手逐条确认（10000–10035，36 个变量号）

> **版本**：TH16 v1.00a（`th16.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th18:0x…`。
> **方法**：**不经 Ghidra 渲染**——读侧跳表 `0x45f578`（36 项）与写侧两张 lvalue 表（`0x45f710`/`0x45f758`、
> `0x45f8fc`/`0x45f91c`、`0x45f830`/`0x45f870`）逐字节直读 PE 解出；四个 helper（`get_int_var` `0x45f610`、
> `get_float_var` `0x45f2d0`、`get_int_var_ptr` `0x45f890`、`get_float_var_ptr` `0x45f780`）逐条读
> `local/th16.v1.00a/state/f/*.html` 的反汇编（**不用** `data/functions.jsonl` 的反编译文本——Ghidra 丢了 XMM 返回值）。
> **可信度**：36 条的**类型 / 可写性 / case 地址 / vm 字段落点**全部 ✅（每条指得到一条读/写该字段的机器指令）；
> **语义**栏里，寄存器/位置/旋转/随机族/常量 ✅、相机与朝向 6 条 🟡（社区 `wip:1`，只证到「舞台相机镜像块」这一层）、
> `i4`/`i5` 的「通用寄存器」命名 🟡、`10033`/`10034` 语义 ✅（通用浮点暂存）；**`10035` 语义 🟡**（2026-09-09 审阅推翻原 RV2 定论，见 §8）。
> **衔接**：变量槽编号与编码宽度见 [`03-math-jumps.md`](03-math-jumps.md) §3；随机族 PRNG 流划界见同文 §7.4；
> `zAnmVm` 字段图见 [`02-vm-core.md`](02-vm-core.md) §3。本文不重复这些论证，只给逐号定论与可写性划界。
> **不含版权字节**：只写偏移、地址与语义。

## 0. 一句话结论

10000–10035 共 **36 个变量号**，是 ANM VM 唯一的一组变量命名空间。一手结论四条：

1. **可写 22 个、只读 14 个**（分母 = 36，见 [§3](#3-专项可写性划界-22-可写--14-只读)）：可写 = 10000–10009、
   10013–10015、10023–10025、10027–10029、10033–10035；只读 = 10010–10012、10016–10021、10022、10026、10030–10032。
2. **类型**：`$`（int32）8 个（10000–10003、10008、10009、10022、10029），`%`（float32）28 个（其余全部）。
   判定依据是**谁能写它**：走 `get_int_var_ptr` 的号是整型、走 `get_float_var_ptr` 的号是浮点（[§2](#2-36-条变量表)）。
3. **随机族划界**（承 [`03-math-jumps.md`](03-math-jumps.md) §7.4）：10010–10012 与 10022 走 **Stream B**（`0x4a6d80`，
   表现流）；10030–10032 走 **Stream A**（`0x4a6d88`，回放流）。两组是逐字节同公式的镜像（[§5](#5-专项随机族-prng-流划界)）。
4. **整型读是「非对称」的**：`get_int_var` 对 19 个只有浮点语义的号（10010–10021、10023–10026、10030–10032）
   **返回变量号本身**，而不是字段值——用整型指令读 `pos.x`/相机/随机浮点会拿到一个 10000+ 的数字（[§4](#4-专项跨类型读是非对称的)）。

## 1. 怎么核的：case 地址与字段落点都是直读字节得到的

**① 发现**：`get_float_var` `0x45f2d0` 入口把 XMM1 里的变量号 `cvttss2si` 成整数后
`add eax,-10000; cmp eax,0x23; jmp [eax*4+0x45f578]`——一张 **36 项**跳表，覆盖 10000–10035。
`get_int_var` `0x45f610` 是两级表（索引 `0x45f758` 36 项 + 跳表 `0x45f710` 18 项）。

**② 推测**：变量号 → case 地址的映射就在这两张表里；但**表项顺序 ≠ case 代码顺序**（见下）。

**③ 验证**：直读 PE 解出 36 项跳表（`python3 tooling/pe_read.py … 0x45f578 --dwords 36 --base 10000`），
得到 §2 表的 case 地址；再逐条读 `state/f/0045f2d0.html` 反汇编，把每个 case 的
`MOVSS/MOVD XMM0,[ECX+0x…]`（或 `CALL`）对到 vm 字段。两张表互相独立、结果一致。

**★ 表项顺序 ≠ case 代码顺序**（brief 已警告，这里给出实证）：跳表下标 10（=10010）指向 `0x45f3e7`，
下标 11（=10011）指向 `0x45f39b`、下标 12（=10012）指向 `0x45f3c1`——**case 体的物理排列是 10011、10012、10010**，
`10010` 的代码排在 `10011`/`10012` 之后。照反编译 switch 的顺序猜会错位，必须回到跳表下标。

**④ 结论**：36 个 case 地址与 36 个字段落点全部一手 ✅（TH16）。

**⑤ 证据**：跳表 `0x45f578`；`get_int_var` 两级表 `0x45f758`/`0x45f710`；四个 helper 反汇编见 `state/f/`。

## 3. 专项① 可写性划界：22 可写 / 14 只读

**① 发现**：两个 `_ptr` helper 各带一张「变量号 → vm 字段指针」的两级表（直读 PE 解出）：

| lvalue helper | 基址 | 上界 | 索引表 / 跳表 | 覆盖的可写号 |
| --- | --- | --- | --- | --- |
| `get_int_var_ptr` `0x45f890` | 10000 | `cmp 0x1d`（29） | `0x45f91c`(30) / `0x45f8fc`(8) | 10000–10003、10008、10009、10029 |
| `get_float_var_ptr` `0x45f780` | 10004 | `cmp 0x1f`（31） | `0x45f870`(32) / `0x45f830`(16) | 10004–10007、10013–10015、10023–10025、10027、10028、10033–10035 |

**② 推测**：能写 = 有 lvalue case；不能写 = 落默认分支（把入参指针原样退回 = 写进指令流，见
[`03-math-jumps.md`](03-math-jumps.md) §9 的第一坑）。

**③ 验证（穷举 + negative set）**：把两张表逐项展开，可写号**恰好**是：

- 整型可写（7）：`10000,10001,10002,10003,10008,10009,10029`
- 浮点可写（15）：`10004,10005,10006,10007,10013,10014,10015,10023,10024,10025,10027,10028,10033,10034,10035`
- **negative set（14，只读）**：`10010,10011,10012,10016,10017,10018,10019,10020,10021,10022,10026,10030,10031,10032`

7 + 15 = 22 可写；36 − 22 = 14 只读。**与社区 `mut` 字段统计一致（22 可写 / 14 只读）**，但本表是可写性的一手来源
（每条对到一条 `LEA EAX,[ECX+off]`），不是照抄 `mut`。

**④ 结论**（✅ TH16）：22 可写 / 14 只读，如上穷举。

**⑤ 证据**：`0x45f890`/`0x45f780` 反汇编（`state/f/0045f890.html`、`0045f780.html`）；索引/跳表字节直读 PE。

> 一个易踩的错：**写 `10013`（`pos.x`）是直接改 `+0x2c`，绕过了 `400 move` 的插值器**——播放器不能把变量当
> 纯「寄存器」，见 [`03-math-jumps.md`](03-math-jumps.md) §9。

## 4. 专项② 跨类型读是「非对称」的

**① 发现**：`get_float_var` `0x45f2d0` 对 36 号**全有 case**（`jmp [eax*4+0x45f578]` 直跳），int 槽走
`MOVD + CVTDQ2PS`（int→float 转换）。而 `get_int_var` `0x45f610` 是两级表，直读索引表 `0x45f758`（36 字节）后：

- **int→float 转换**：7 个 int **存储**号（10000–10003、10008、10009、10029）在 `get_float_var` 里都是
  `MOVD + CVTDQ2PS`（int32→float）✅；第 8 个 int 号 **10022** 是计算型随机，走另一条 `raw(u32)→double→float`
  的路（§5），**不是** `CVTDQ2PS`。
- **float→int 只有 9 个号转换**（`CVTTSS2SI`，截零）：10004–10007、10027、10028、10033–10035。
- **其余 19 个浮点号，整型读返回变量号本身**（索引表里指向槽 17 = 默认分支 `0x45f708`，`MOV EAX,EDX` 把入参原样退回）。

**② 推测**：整型指令读一个「只有浮点语义」的变量，不会得到字段值，而是得到 10000+ 的数字本身。

**③ 验证（穷举）**：索引表 `0x45f758` 逐字节解出，指向默认槽 17 的号是
`10010–10021`（12 个）、`10023–10026`（4 个）、`10030–10032`（3 个）= **19 个**；这 19 个正是 pos/rot/camera/lookat/
随机浮点/有效旋转——**全部是浮点语义**。做 `cvttss2si` 的 9 个号（10004–10007、10027、10028、10033–10035）则是有
「整型可读意义」的：F0–F3 与两个随机刻度、三个 mystery angle。

**④ 结论**（✅ TH16）：**跨类型读不对称**。float→int 只对 9 个号做了 `cvttss2si`；int→float 对 7 个 int 存储号做了
`cvtdq2ps`、10022 单独走 u32→float。整型指令读 `pos.x`（10013）拿到的不是坐标，而是 `10013` 这个数。
播放器/汇编器必须复刻这一点，否则「用 `$` 读 `pos-x`」会静默产出垃圾值。

**⑤ 证据**：`get_int_var` 索引表 `0x45f758`（36 字节，直读 PE）；默认分支 `0x45f708`；
`get_float_var` `0x45f2d0` 反汇编。变量号编码宽度（int32 vs float32）见 [`03-math-jumps.md`](03-math-jumps.md) §3。

## 5. 专项③ 随机族 PRNG 流划界

承 [`03-math-jumps.md`](03-math-jumps.md) §7.4 的穷举（ANM 子系统 16 个 PRNG 调用点，negative set 空）。落到变量表上是：

| 变量 | 公式 | 流 | 分支地址（读侧） |
| :---: | --- | :---: | --- |
| 10010 | `vm[+0x4d8] · randf_pm1()` ⇒ `[-π,π)` | B `0x4a6d80` | `0x45f3e7` |
| 10011 | `vm[+0x4d4] · randf01()` ⇒ `[0,1)` | B | `0x45f39b` |
| 10012 | `vm[+0x4d4] · randf_pm1()` ⇒ `[-1,1)` | B | `0x45f3c1` |
| 10022 | `raw % vm[+0x4dc]`（整读）/ `raw→float`（浮读） | B | `0x45f4d8` |
| 10030 | 同 10010 | **A** `0x4a6d88` | `0x45f54a` |
| 10031 | 同 10011 | **A** | `0x45f4fe` |
| 10032 | 同 10012 | **A** | `0x45f524` |

**10022 的两面**（社区 `wip:2` 在此被一手钉死 ✅）：

- **整读**（`get_int_var` `0x45f6e5`）：`raw(u32) % vm[+0x4dc]`，`DIV` 无符号，模数为 0 时短路成 0；
  `+0x4dc` 默认 `0x10000` ⇒ `[0, 65536)`，且可由 10029 改写。
- **浮读**（`get_float_var` `0x45f4d8`）：`raw(u32)` 当作**无符号**整数转 float——`CVTDQ2PD` 后按符号位
  `ADDSD [0x494850/58]`（`0.0` / `2³²`）再 `CVTPD2PS`。**完全不走模数**，值是均匀分布在 `[0, 2³²)` 的 u32 转 float。

⇒ 社区的 `rand` 描述「0 到 65536 exclusive」只对**整读**成立（默认模数）；**浮读**是这个号的另一面
（`wip:2` 里那句「unsigned 32-bit integer cast to float」是对的）。

## 6. 专项④ helper 变量：10016–10021（相机）与 10026（有效旋转）

### 6.1 10016–10021 不在 vm 里，读的是「舞台相机镜像块」

**① 发现**：`get_float_var` 的六个 case **没有 `[ECX+…]`**，读的是绝对地址：

```
10016: MOVSS XMM0,[0x4c16c8] ; ADDSS XMM0,[0x4c168c]     10019: MOVSS XMM0,[0x4c16b0]
10017: MOVSS XMM0,[0x4c16cc] ; ADDSS XMM0,[0x4c1690]     10020: MOVSS XMM0,[0x4c16b4]
10018: MOVSS XMM0,[0x4c16d0] ; ADDSS XMM0,[0x4c1694]     10021: MOVSS XMM0,[0x4c16b8]
```

**② 推测**：10016–10018 是「某全局基值 + 某摇晃向量」，10019–10021 是「某朝向向量」。

**③ 验证**：`Stage__on_tick_11` `0x409e50` 每帧 `MOVSD.REP` 把 `Stage+0x1ec` 起 **0x4b dword** 整块拷进

### 8.0 一句话结论

**10033–10035 是三个额外的可写浮点脚本暂存（变量号 10033–10035 是 36 号里的最后三个；物理上 `+0x4c0` 紧挨 F0–F3 的

| 点 | 说明 |
| --- | --- |
| `10033`/`10034` 当普通可写 float 槽实现即可 | 无隐式语义；读 = `MOVSS [vm+0x4c0/4c4]`，写 = 存回该偏移，整读 = `Math.trunc`（`CVTTSS2SI`） |
| ⚠️ **`10035` 不能只当暂存** | 在 `vm+0x5c4 == 2` 的 VM 上，`on_tick` callable #2（`th16:0x405700`）每帧会读它、加上 `rotation.z` 后喂极坐标（§8 的更正块）。播放器实现该 callable 时若把 `10035` 当纯暂存，画面会错 |
| `509 copyParentVars` 必须带上它 | 它是父→子变量通道的一员；漏拷会让 `effect.anm` 的 89 条引用全部跑错（子继承不到偏移/角度） |
| 初值 `0.0` | `wipe` 只 `memset 0`，`+0x4c0` 不显式置值；模板预跑（`time<=0` 段）可能已把它写成非零，实例化照拷 prefix |
| 别按「角度」做归一 | 没有任何 wrap/归约逻辑；它就是裸 float。ZUN 用它存 ±π/4、π/10 等小值，但引擎不保证 |
