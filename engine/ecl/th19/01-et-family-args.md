# 01 — TH19 的 `et*`（子弹类型）族：三个结构体与逐参语义

> **版本**：TH19 v1.10c（`th19.exe`，imagebase `0x400000`）。裸地址默认属该版本。
> 一手来源：handler 反汇编（地址见每行"handler"列）。派发机制见 [`00-opcode-table.md`](00-opcode-table.md)。
> 置信度：✅ = handler 直接读出；🟡 = 有部分 handler 证据但语义未定；❓ = 未解。

## 1. 三个结构体（★ 这是"贴图/位置/偏移"分家的关键）

| 结构体 | 基址 | 槽内布局（已证部分） | 谁写 |
| --- | --- | --- | --- |
| **子弹类型记录** | `this+0x5ac` | `[0]`=sprite id、`[4]`=color、`[0x14]`/`[0x18]`=两个角度、`[0x1c]`=速度上限、`[0x20]`=速度下限、u16 `[0x46c]`/`[0x46e]`=两计数、u16 `[0x470]`=style、`[0x478]`/`[0x47c]`=两个 int | `602` `604` `605` `606` `607` `608` |
| **偏移向量** | `this+0x4e6c` | `[0]`/`[4]` = (x, y)；`618` 还会把第三分量清 0 | `603`（笛卡尔）／`618`（极坐标） |
| **基准位置** | `this+0x4f2c` | `[0]`/`[4]` = (x, y)；`[8]` = 有效标志（`620` 置 `1.0f`） | `620` |

## 3. 由此得到的两条"读 ECL 时最容易犯的错"

1. ★ **`602` 的两个 int 不是像素坐标**，是 **sprite id ＋ 配色**；贴图的实际取舍要看 `bullet.anm` 的 **entry 表 → sprite 表**
   （见 [`../../../METHOD.md`](../../../METHOD.md) 的「读 anm 贴图必须走 entry 表 → sprite → 三元组」）。
2. ★ **出生点 = 基准位置 ＋ 偏移**：`620` 给基准、`603`/`618` 给偏移、`601` 才真正发射。
   只看 `620` 或只看 `618` 都会得出"位置"的片面结论（本仓 2026-10 就因此在早苗 C4 上误判过一轮）。

## 4. 路径段结构（`609`／`610`／`611`／`612` 共用 handler `0x5027a3`）

四个 opcode **共用一个 handler**，靠入口处 `movzx ecx, WORD[esi+4]` 读 opcode 再与 `0x263`/`0x264` 比较分流。

* `p0` = 发射器号（0..23，越界会打 `"error et_ex ID over"` @`0x599480`）；`emitter = this+0x5ac + p0*0x488`。
* **段号**：`609`/`610` = `p1`（显式）；`611`/`612` = 内部游标 `[this+0x4e2c + p0*4]`（用后自增）
  ⇒ ★ **这就是 611 比 609 少一个参数的原因**。
* 段结构：`emitter+0x28 + k*0x2c`（每段 `0x2c` 字节）

| 参数（`609` 八参） | 写入 |
| --- | --- |
| `p1` | 段号 |
| `p2` | `+0x24` |
| `p3` | `+0x20` |
| `p4` | `+0x10` |
| `p5` | `+0x14` |
| `p6` (float) | `+0x00` |
| `p7` (float) | `+0x04` |

`611` 七参：`p1→+0x24, p2→+0x20, p3→+0x10, p4→+0x14, p5→+0x00, p6→+0x04`。
`610`/`612` 在此基础上再加 `+0x18/+0x1c/+0x08/+0x0c`（曲线量）。

★ **语义命名仍未定** 🟡：段字段 `+0x00..+0x24` 的写点全是一手，但消费者（`0x4ee0d0`／`0x4ee880`／`0x4f1340`）未读，
所以只能给出观察：`2097152`（`0x200000`）落在 `+0x20`（同批取值 0/1/2/4/0x10/0x80 ⇒ 像位掩码）、
`20`/`120` 落在 `+0x10`（同批 1/4/8/0x3c/0x78/0xc8/200 ⇒ 像帧数）。
