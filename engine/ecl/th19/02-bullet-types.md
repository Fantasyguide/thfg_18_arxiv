# 02 — `ins_602(num, type, color)`：弹型表（owner 一手，2026-10-18）

> **版本**：TH19 v1.10c（`th19.exe`，imagebase `0x400000`）。本文裸地址默认属该版。
> **来源**：★ **owner 2026-10-18 直接给的表**（一级证据），并注明「`type` 与 `bullet.anm` 里描述文件的内容存在对应关系」。
> 相关：[`00-opcode-table.md`](00-opcode-table.md)（派发）、[`01-et-family-args.md`](01-et-family-args.md)（`et*` 族字段）。

## 1. 语义（一手）

```
602(int num, int type, int color)
  给 num 号弹幕设置「子弹类型 type」和「颜色 color」。
  两个 int 写进子弹类型记录 this+0x5ac 的槽 num： [0] = type、[4] = color   ← handler 0x502366 一手
  ★ type 与 bullet.anm 的描述文件内容对应；具体画法由引擎按 type 决定（点/玉/激光段/旋转…）。
```

## 3. 跨版本注意（owner 原话）

* ★ **绀珠传（TH15）以前：24 是「红色炎弹」，25 为原 26**，之后**相对顺序不变** ⇒ 拿旧作的 map／笔记对照时要**整体移位**。
* ★ **44–47（阴阳玉）是虹龙洞（TH18）加进来的**。
* ★ **48–49 是锦上京（TH19）加进来的**。
* ★ 「高光」那一批**本身不带高光**：只在被“会发光的弹幕”使用时才出现 ⇒ **推测**是 ZUN 的编译器自动加的样式。

## 4. 由这张表得到的两个直接结论

1. ★ **`602($A, 38, 6)` = 激光段 + 颜色 6** ⇒ 魔理沙 C3／C4 的"激光"在**类型层**是自洽的，
   不需要"另找一张激光图"来救。8×8 的 `sprite38` 是**激光段瓦片**（引擎沿光束重复/拉伸），
   不是"被拉长的点"。
2. ★ **`602(0, 0, 4)` = 点弹 + 颜色 4** ⇒ 早苗 C3 一手是**点弹**；她那条看起来像"被拉长的条"，
   应归因于**运动拉伸**（或 `609` 段让弹体变长），而不是"贴图本身是条"。
