# TH10 风神录 消弹 → 出不出实体道具

> **版本**：TH10 v1.00a（`local/th10.v1.00a/th10.exe`，487,936 B，imagebase `0x400000`，md5 `7dc488d82c81dd4aee4ba098b8804d83`）。本文裸地址默认属该版本；引用别作一律写 `th11:0x…`。
> **一手工具**：`objdump -d -M intel --start-address=… --stop-address=… local/th10.v1.00a/th10.exe`；调用点穷举用同 build 的全量反汇编 `local/_scratch/th10_full.asm`（`grep -nE 'call +0x…'`）。
> **命名辅助（非一手，只用来取名字）**：`local/vendor/th-re-data/data/th10.v1.00a/statics.json` —— `0x4776f0` `BULLET_MANAGER_PTR` · `0x4776f4` `SPELLCARD_PTR` · `0x477818` `ITEM_MANAGER_PTR` · `0x47781c` `LASER_MANAGER_PTR`。
> **素材**：蒸馏自 `local/_scratch/research-cancel-original-th06-th11.md` §TH10（一手研究）。本轮**只读复核**又对 5 处数据提了订正，逐条给指令原文列在 §2.3，**冲突处不替研究者圆场**。
> ⚠ 跨作坑：`th11:0x40af90` 是 TH11 的消弹圈；**TH10 的 `0x40af90` 是另一个函数**（vendor 名 `EffectManager::operator new`，非一手）⇒ 地址绝不能裸搬。

## 1. 发现（一手事实）

### 1.1 一句话

**没有 `mode` 参数**（"撒不撒"是入口的**栈参 bool**）；子弹侧撒**写死的 `type 8`（微信仰点）**，**每颗被消的弹恰好一颗**、掉在**弹自己的位置**、`state = 5` ⇒ **要走过去收**。
撒之前过**场地门**（越界只消不撒）；激光是**另一套 manager（链表+虚函数）**、`0x41c800` 自身不撒；**消弹链零 RNG**；**boss 击破 / 符卡结束 / 关卡切换都不出道具**。

### 1.2 消弹路径盘点（逐条点名 + 谁调）

| # | 路径 | 子弹侧入口 | 调用点（一手） | 撒？ |
| --- | --- | --- | --- | --- |
| ① | 灵击 Bomb | `0x408100` | `0x405b13`（`Bomb::on_tick` 每帧走 `0x405ac0`） | **撒**（`arg2 = (~player->flags)&1`） |
| ② | **state 0（复活上升）清弹** —— ★ 2026-09-15 **二轮订正**：原标「决死」，实为**复活清弹**（见 §3-🟡3） | `0x408100` | `0x4258d4` / `0x4258f0`（`Player::on_tick` 内，**状态跳表 index 0 那一支**） | **不撒**（两处第二刀都压 `0x0`；这一条读数**仍然成立**） |
| ②′ | 符卡击破 / 冲击波一族 | `0x408100` | `0x41181e`（压 `0x1`）/ `0x411866`（压 `0x0`） | **分两支**（前者撒） |
| ②″ | 矩形档（同族、另一函数） | `0x408210` | `0x410d19`（传 `0x1`）/ `0x410de8`（传 `0x0`） | **分两支** ★本轮新增 |
| ③ | 擦弹消去 graze-cancel | **无入口**（inline 写状态） | `0x4064ad: mov WORD PTR [ebp+0x446],0x3` | **不撒** |
| ④ | 激光（另一套 manager） | `0x41c800` | `0x405b33` / `0x41182b` / `0x411873` / `0x4258fd` | 函数自身**不撒** |
| ⑤ | boss 击破 / 符卡结束 / 关卡切换 | **不经任何入口** | 见 §1.9 | **不撒** |

* ③ 的判据 = 擦弹判定：`0x40649c: call 0x4266b0` → `0x4064a1: cmp eax,ebx`（`ebx = 0`）→ 命中才写 `state = 3`；**这条旁路不进 `0x408100` ⇒ 擦弹消去的弹一颗道具都不掉**（与 ①② 的观感差别就在这）。
* **"消弹本身"是更底层的原语 `0x408030`**（只置 `state = 3` + 火花），全 exe **8 个调用点**：`0x4070e0` / `0x407243` / `0x4081b2`（**在 `0x408100` 体内，唯一一处后面接着撒道具**）/ `0x40848d` / `0x415d62` / `0x425879` / `0x425a59` / `0x425d55` ⇒ 其余 7 处**只消不撒**。
* 另有 `0x408460`–`0x40849d` 一个 2000 槽 sweep（`state ∈ {0,3}` 门、调 `0x408030`、不撒），asm 里搜不到对它的 `call` ⇒ 🟡 疑为间接引用（vtable / 表），归属未钉死（§3-🟡6）。

### 1.3 出的那几条 / 不出的那几条

**会撒 `type 8` 的只有 3 个调用点**（全在子弹侧）：

| 调用点 | 谁 | 撒的判据 |
| --- | --- | --- |
| `0x4081e7` | 灵击（`0x405b13`）/ `0x41181e` 两遍 | 前者 `arg2 = (~player->flags)&1`；后者硬压 `0x1` |
| `0x4083ae` | 矩形档（`0x410d19`） | 单参 flag 压 `0x1` |

**不出实体的（逐条否定）**：擦弹消去 ③；`0x408030` 的 7 个旁路；`0x411866`（`arg2 = 0`）；**state 0 复活清弹 `0x4258d4` / `0x4258f0`（`arg2 = 0`）** ★（原标「决死」）；矩形档 `0x410de8`（flag 0）；激光 `0x41c800` 自身；⑤ 全部。

### 1.4 撒出来的是什么（`item type 8` 的**实体**）

```
4081d4: a1 18 78 47 00   mov  eax,ds:0x477818   ; ITEM_MANAGER_PTR
4081d9: 68 9a 99 19 3f   push 0x3f19999a        ; 0.6f   （速度）
4081de: 68 db 0f c9 bf   push 0xbfc90fdb        ; −π/2   （角度）
4081e3: 6a ff            push 0xffffffff        ; −1
4081e5: 6a 08            push 0x8               ; ★ type = 8（写死在体内）
4081e7: e8 14 39 01 00   call 0x41bb00          ; ItemManager::spawn_item
```

* **`ecx = edi = &bullet->pos`**（`0x408143: lea edi,[esi+0x3b4]`，全程未被改写）⇒ 道具掉在**弹自己的位置**，**不是灵击圆心**；**初速 `(0, −0.6)`**：角度 `−π/2` 交给 `0x41beb0`（`fsincos` 角度助手，**纯函数**）⇒ `(sin,cos) × 0.6`，向上飘。**速度 `0x3f19999a = 0.6f`、角度 `0xbfc90fdb = −π/2`**（逐字节复核）。
* **type 8 走独立小池**（`0x41bb00` 的 `cmp ebp,0x8 / je 0x41bccd`，`0x41bb09`/`0x41bb0f`）：游标 `IM+0x21ceb8/0x21cebc`、**1024 槽环形**（`cmp edi,0x400` 后 32/16/8 取模）；`0x41bd58: mov eax,0x8` → `[edx+0x3e0]/[edx+0x3e4] = 8`（type 与外观组）；**`0x41bd69: mov [edx+0x3dc],0x5` ⇒ `state = 5`**；位置从 `ecx` 拷到 `item+0x3ac`。
* **`state = 5` ⇒ 当场不入账、要走过去收**（`0x41ba67` 的 `cmp eax,1 / cmp eax,4` 才是自动回收档）；**收集那一帧**才 `+10 信仰`（`0x41b5d6: push 0xa` → `0x41be80`）+ `+10 分`（`0x41b5f2: call 0x409d90`）⇒ **每颗弹 = 1 颗微信仰点 = +10 信仰 / +10 分（显示口径），且要走到弹的原位置去捡**。

### 1.5 判定形状 / 遍历

* **形状 = 圆（球）**：`d² = dx²+dy²` vs `(R + r × 0.5)²` —— `0x408187: fmul DWORD PTR ds:0x470b0c`（**`0x470b0c = 0.5f`**）→ `0x40818d: fadd [esp+0x28]`（+ 灵击半径 `R`）；命中判据 `0x4081ad: test ah,0x5` / `0x4081b0: jnp 0x4081ec`（`jnp` = `(R+r/2)² < d²` = 圈外 ⇒ **不消也不撒**）。
* **遍历 = 定长槽数组**：**2000 槽**（`0x40810b: mov ebp,0x7d0`）× stride `0x7f0`，基址 `BM+0x60` —— **不是链表**。`state == 0`（空槽）与 `state == 3`（已消）两道门跳过 ⇒ **天然去重，一颗弹最多撒一颗**。
* **`R` 的来源**：`Bomb::on_tick` 每帧从灵击 anm VM 的 `scale.y` 写进 `bomb+0x3c`，现取现用（🟡 见 §3-🟡2）。
* **没有 mode 参数**：`eax = BULLET_MANAGER_PTR`、`ebx` = 圆心 `&float3`、**3 个栈参 + `ret 0xc`**；帧 = `sub esp,0x18` + 3 push（`0x408100`–`0x408107`）⇒ **`[esp+0x28]` = 半径、`[esp+0x2c]` = 撒不撒、`[esp+0x30]` = 条件消**（压栈序：后者先压）。

### 1.6 场地门（TH10 **有**门，而且就是 ±192 / 0..448 那一套）

| 门 | 指令 | 语义 | 调用侧取值 |
| --- | --- | --- | --- |
| 场地门 | `0x4081c3: call 0x4086b0`（两次 `push 0x40000000` = `2.0f`） | 返回 1 = 越界 ⇒ `0x4081ca: jne` ⇒ **只消不撒** | 固定 `2.0f/2.0f` |
| 撒不撒 | `0x4081cc: mov eax,[esp+0x2c]` / `0x4081d2: je 0x4081ec` | `== 0` ⇒ **不撒**（弹照样被消） | 见 §1.3 |
| 条件消 | `0x40812a: mov eax,[esp+0x30]` + `0x408132`/`0x408137` | `≠0` **且** `bullet+4 ≠ 0` ⇒ **连消都不消** | 灵击两支分别压 `0x0`/`0x1` |

**`0x4086b0`（函数体 `0x4086b0`–`0x408708`，`ret 0x8`）= 场地边界判定，本轮首次读完**：

```
4086b0: fld [esp+4] / fadd [ecx]      ; pos.x + mx
4086b6: fcomp ds:0x470b40             ; vs −192.0f → 0x4086c1: jnp 0x408703（左越界⇒1）
4086c3: fld [ecx] / fsub [esp+4]      ; pos.x − mx
4086c9: fcomp ds:0x470b3c             ; vs +192.0f → 0x4086d4: je  0x408703（右越界⇒1）
4086d6: fld [esp+8] / fadd [ecx+4]    ; pos.y + my → vs 0x470b04（0.0f）
4086ea: fld [ecx+4] / fsub [esp+8]    ; pos.y − my → vs 0x470b38（448.0f）
4086fe: xor eax,eax / ret 8           ; 0 = 场地内
```

**四个常量真值（本轮直读 PE 节表）**：`0x470b40 = −192.0f`、`0x470b3c = +192.0f`、`0x470b04 = 0.0f`、`0x470b38 = 448.0f`。
⇒ **TH10 的门 = 「`x` 外扩 2.0 之外出 ±192、`y` 外扩 2.0 之外出 0..448 ⇒ 只消不撒」**，判据是**弹自己的位置**。**这与 TH16/TH18「屏外不撒」是同族门，只是外扩量 = 2.0（不是 32）** ⇒ 研究稿 T10.2(d) 的「**没有** ±192/192/448 参与、是"以弹为中心的 ±2.0 小矩形"」**不成立**（§2.3-A）。
⚠ **消弹本身没有场地门**：屏外的弹照样被消掉，只是不撒道具。

### 1.7 激光侧 = 另一套 manager（链表 + 虚函数）

`0x41c800`（`eax` = `LASER_MANAGER_PTR`，`ebx` = 圆心，2 个栈参，`ret 0x8`）：

```
41c800: mov  ecx,[eax+0x18]           ; ★ 链表头（manager->list）
41c804: add  eax,0x440                ; 圆心写进 manager+0x440（给被调方读）
41c827: cmp  DWORD PTR [ecx+0xc],0x1  ; 跳过占位节点
41c839: call DWORD PTR [eax+0x1c]     ; ★ 每个激光对象自己的虚函数
41c849: ret  0x8
```

⇒ 与子弹侧（定长数组 + 内联撒道具）**完全不同形**：撒不撒由**每个激光对象的 `vtable+0x1c`** 决定，`0x41c800` 体内**没有** `0x477818` / `call 0x41bb00`。**TH10 原版的灵击确实消激光**（`0x405b33: call 0x41c800`）—— 这对我们的卡是**已知偏差**（§5）。

### 1.8 RNG —— ❌ 消弹链上零消耗（确定性）

* `0x408100` 全函数体内**零 RNG 调用**：只有 `fld/fmul/fadd/fcom` + `call 0x408030`（消弹）+ `call 0x4086b0`（场地门，纯比较）+ `call 0x41bb00`（撒道具）+ `call 0x41beb0`（`fsincos`，纯函数）。
* `0x41bb00` 的 **type 8 分支**（`0x41bccd`–`0x41bd99`）同样**零 RNG**：只有环形游标算术 + 常量写。
* ⇒ **数量 = 命中弹数、位置 = 各自弹位、速度 = 固定 `(0,−0.6)`**，全确定。🟡 限定：只说「消弹 → type 8」这条链；`0x408030`（火花特效）内部**没读完**（怎么钉：读全函数体找 RNG 入口）。

### 1.9 boss 击破 / 符卡结束 / 关卡切换 —— 全部「什么都不出」

* **boss 击破**：清弹走 **ECL / 敌机死亡处理器**；`0x408100` 的 5 个、`0x41c800` 的 4 个调用点已穷举（§2.1）⇒ **与 TH18「满屏弹幕消失但一颗点都不出」同档**。
* **符卡结束**：**引擎侧没有"符卡结束清弹"函数**（否定结论同 TH18）；符卡奖励是另一条链（`0x409874`）。**关卡切换**：整池重建（不是逐弹消）⇒ **不走撒道具路径**。
* ⚠ 相关但不同的副作用：TH10 灵击**会作废当前符卡奖励**（`0x40550f` 清 `zSpellcard.bonus`）—— 属符卡侧，与"出不出实体"无关。

## 2. 验证（怎么排除掉别的路）

### 2.1 入口穷举（否定证据）

```
grep -nE 'call +0x408100|call +0x41c800' local/_scratch/th10_full.asm
  0x408100 × 5：405b13(灵击) 41181e 411866 4258d4 4258f0(state 0 复活清弹)
  0x41c800 × 4：405b33(灵击) 41182b 411873 4258fd
grep -nE 'call +0x41bb00' … → 全 exe 13 处（§2.3-D）
```

⇒ `0x408100` 只有 **5** 个调用点（研究正文写"各为 4 处"是笔误，它自己的清单是 5 + 4，**清单对**）；**"消弹原语" `0x408030` 另有 8 处**（§1.2）—— 这是「屏上弹没了却一颗道具都不掉」的全部旁路。

### 2.2 撒/不撒靠**调用侧压栈**判定（读法可复核）

callee 帧 = `sub esp,0x18` + 3 push ⇒ 三参落位 `[esp+0x28]`（半径，**最后压**）、`[esp+0x2c]`（撒不撒）、`[esp+0x30]`（条件消，**最先压**）。用研究稿自己认过的两处**校准**：

* `0x411816 push 0x0` / `0x411818 push 0x1` / `0x41181d push esi` → `0x41181e: call` ⇒ 第二刀 = `0x1` ⇒ **撒**（与研究稿"`0x41181e` 撒道具"一致）；`0x41185e`/`0x411860` 两刀都是 `0x0` → `0x411866: call` ⇒ **不撒**（也一致）。
* 同一读法套到 **state 0（复活上升）** 那两处（原标「决死」）：`0x4258b4 push ebx` / `0x4258b5 push 0x0` / `0x4258d3 push edi` ⇒ 第二刀 `0x0` ⇒ **不撒**；`0x4258e8 push 0x0` / `0x4258ea push 0x0` / `0x4258ec push ecx`（随后 `fstp [esp]` 覆写成半径）⇒ 第二刀 `0x0` ⇒ **不撒**。
* 灵击两支都把第二刀压成 `(~eax)&1`，`eax = [PLAYER_PTR+0x378c]`（`0x405acd` 起，中途未被改写）⇒ **撒不撒跟着玩家 flags bit0 走**（正常灵击帧 = 撒）。

### 2.3 ★ 本轮只读复核对研究稿的 5 处订正（冲突不粉饰）

| # | 研究稿 | 本轮复核（一手） | 影响 |
| --- | --- | --- | --- |
| **A** | 「门是弹位 ±2.0f 矩形，**没有** ±192/192/448 参与」（原标 🟡） | `0x4086b0` 体内四个常量正是 `−192.0f`/`+192.0f`/`0.0f`/`448.0f`，margin = 2.0 | 门形与 TH16/TH18 **同族**（外扩 2.0 vs 32） |
| **B** | §1 表「②决死 ✅会撒」 | `0x4258d4`/`0x4258f0` 两处第二刀都压 `0x0` ⇒ **不撒**（读数对，**但这两处是 state 0 复活清弹、不是决死** —— 2026-09-15 二轮订正，见 §3-🟡3） | 「出的那几条」少一条；★ 「决死不撒」这个结论**不成立** |
| **C** | 「撒 `type 8` 的调用点**唯一** `0x4081e7`」 | **第二处** `0x4083ae`（矩形档 `0x408210` 体内），参数与 `0x4081e7` 逐字节同形 | 入口不是唯一 |
| **D** | 「`0x41bb00` 全 exe **8** 个调用点」 | 实为 **13** 处；消弹链只占其中 2 处 | 结论方向不变 |
| **E** | 正文「两函数调用点**各为 4 处**」 | `0x408100` = **5**、`0x41c800` = **4** | 纯笔误（它自己的清单已对） |

**C 的指令原文**（`0x408210`–`0x408456` = 矩形档，1 参 + `ret 4`）：

```
40838c: mov  eax,[esp+0x48]      ; 唯一那个参数的副本
408393: test eax,eax / je 0x4083b3 ; flag 0 ⇒ 不撒
40839e: push 0x3f19999a / 4083a3: push 0xbfc90fdb
4083a8: push 0xffffffff / 4083aa: push 0x8     ; 与 0x4081e7 同形
4083ac: mov  ecx,edi                           ; 弹自己的位置
4083ae: call 0x41bb00                          ; ★ 第二处 type 8
```

矩形档的几何（`0x408300`–`0x408384`）：`fmul ds:0x470b0c`（同一个 `×0.5f`）先把弹半径减半，再做**四个**浮点比较（`0x408342`/`0x408355`/`0x408368`/`0x408377`，对 `[esp+0x14]`/`[esp+0x2c]`/`[esp+0x30]`/`[esp+0x18]`）⇒ 形状 = **矩形 + 弹半径半宽**。**谁调它本轮没钉死**（§3-🟡4）。

## 3. 结论（可信度 + 适用范围）

**一句话**：TH10 的消弹撒 **`item type 8`（微信仰点）实体**，每颗弹一颗、值 **+10 信仰 +10 分**、掉在**弹自己位置**、**`state = 5` 要走过去收**；形状 = 「2000 槽定长数组 + 圆判定 `(R + r/2)`」；撒之前过**场地门（`x ∈ ±192`、`y ∈ 0..448`，各外扩 2.0）**与**栈参 bool**；激光走独立的**链表 + `vtable+0x1c`**；**全链零 RNG**；boss 击破 / 符卡结束 / 关卡切换**不出道具**。

**适用范围**：本文只对 md5 `7dc488d82c81dd4aee4ba098b8804d83` 那个 build 负责。**没有 `mode` 参数 ⇒ TH18 的 `mode` 号与本文毫无对应**（反向亦然）。

## ★ 2026-09-15 追加订正：道具 state 语义（「要不要走过去收」= **不用**）

来源：`local/_scratch/research-th10-item-motion.md`（421 行；样本 md5 `7dc488d82c81dd4aee4ba098b8804d83`）。
起因：用户实玩口径「**TH10 我实际玩的也是直接飞过来吸收**」⇒ 回头核本文与旧研究稿的「`state 5` ⇒ 要走过去收」。

**一手（`ItemManager::on_tick` `0x41afd0`，管理器 `ds:0x477818`，槽基 +`0x14`、步长 `0x3f0`）**：

| state | 含义 | 一手落点 |
| --- | --- | --- |
| `0` | 空槽 | `0x41b010` 起的比较链 |
| `1` | 普通下落 | 同上 |
| `2` | **上升中**（取消弹道具的"弹起段"） | 同上 |
| `3` | **飞向自机** | 同上 |
| `4` | 被自机扩展矩形吸住后飞向自机 | `0x41b7ed` |
| `5` | **刚 spawn 的待机倒计时**（只减 `item+0x3ec`，**不参与收集**） | `0x41b01b` / `0x41b04a` |

- **取消弹的那颗 type-8 必被吸**：初速 `(0, −0.6)` 向上（`0x4081d9` = `0.6f`、`0x4081de` = `−π/2`）
  ⇒ `state 2` 重力 `+0.03/帧` ⇒ 约 20 帧后 `0x41b185`–`0x41b1a4` **无条件**把 state 置 3（飞向自机，
  初速取自表 `0x476fa0` = `5.0/7.0f`，逐帧 `+0.2` 上限 `12.0f`）。
- 另两条吸引门：自机**过线**（`player.y < 128.0f`，常量 `0x470bf4`，`0x41b072`）⇒ 全场 `state 1` 转 `3`；
  进自机**扩展矩形**（`0x41b74c` 起，按低速键选 ±50/59 px 或 ±20/24 px）。
- **收集判定是矩形包含**（`0x41b347`–`0x41b3bb`，`player+0x4324…+0x4334`，实时半宽 ±10/12 px，
  **不是距离/半径、也不看 z**）。

**⇒ 结论**：`state 5` 只是"刚生成时的待机倒计时"，**与"要走过去收"无关**。
旧稿的引证 `0x41ba67` 那两处 `cmp eax,1 / cmp eax,4` 比的是 `item+0x3e0` = **type ∈ {1,4}**（P 类道具），

`+0x3dc` = state、`+0x3e0` = type）。
