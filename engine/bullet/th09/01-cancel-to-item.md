**① 的逐指令（判据顺序很要紧）**：

```
414a29: mov al,[esi+0x10bc] / test / jne 0x414ad4   ; ≠0 ⇒ 整颗跳过碰撞段
414a37: mov al,[esi+0xdc3]  / test / jne 0x414a66   ; 本帧已命中 ⇒ 跳过第一测
414a56: call 0x41e350                               ; 圆 + 60px AABB
414a5b: cmp eax,1 / 414a60: [esi+0xdc3]=1           ; ==1 ⇒ 标记本帧命中

414a84: eax==1 ⇒ 0x414a94（state=5）
414a89: eax==2 且 test ah,0x10（flags & 0x1000）⇒ 0x414aba（**不杀**）
414a94 / 414aaf: mov WORD PTR [esi+0xdbe],0x5      ; ★ 杀（两支）
414aba: call 0x40f8e0(&player+0x36c, …)             ; ★ 登记（不是杀）
```

⇒ `flags & 0x1000`（`0x414a8f` / `0x414aaa test ah,0x10`）= **免疫位**：带这一位的弹被杀判定拒绝。
⇒ **杀 = 写 `state=5`；登记 ≠ 杀**（`0x414aba` 只登记，由 ② 那一步去杀）。

**场地门常量真值（`0x41a6eb`，我亲手从 PE 读出）**：`x` 侧两个比较对 **`0x48e808 = −144.0f`** 与 **`0x48e804 = +144.0f`**；`y` 侧两个比较对 **`0x48e314 = 0.0f`** 与 **`0x48e3b8 = 448.0f`**；`w,h` 各先乘 **`0x490f54 = 0.5f`**。

⇒ **TH09 的战场 = `x ∈ [−144, +144]`、`y ∈ [0, 448]`** —— 这就是 PoFV 那一列**比历代窄**的战场（历代是 ±192；`448` 与 TH16/TH18 相同，但左右界完全不同、而且**没有 32 的外扩**）。

**★ 门的作用点在"越界寿命"上，不在"撒不撒"上**（因为根本没有东西可撒；`0x4149c5` 起，✅ 我逐指令读过）：

```
4149c5: call 0x41a6eb(x,y,w,h)
4149cc: eax!=0（在场内）⇒ 414a20: mov WORD PTR [esi+0xdc0],0x0     ; 计数清零
4149ce: eax==0（出界）  ⇒ test DWORD PTR [esi+0xdb4],0xdc0
            flags 位 == 0 ⇒ 4149fb: 计数==0 ? 立即 0x412930() 释放 : 计数--
            flags 位 != 0 ⇒ 4149da: inc WORD PTR [esi+0xdc0]; cmp 0x80(128) ⇒ 释放
```

⇒ TH09 的"场地门"= **「出界弹给 0..128 帧宽限再回收」**，只影响"这颗弹还活不活"，与"出不出东西"无关。⇒ 与 TH16/TH18（`x ∉ (−224,224)` / `y ∉ (−32,480)` ⇒ **不撒也不计数**）、TH11（把 `item.x` 钳到 ±192）、TH08（`pos[0]` 对 `−64.0f`/`448.0f` ⇒ 不撒）、TH10（弹位 ±2.0f 矩形）**全都不同形**。

## 2. 验证（怎么排除掉别的路）

### 2.1 这作没有 `cancel` 命名 ⇒ 入口靠"找 `state` 写点"挖出来（方法论）

`cancel` 这个词在 TH09 的函数名与代码里**完全不存在**。§1.1(d) 的 12 个写点就是这么来的：把 `state` 字段（`+0xdbe`）的**全部**写点用一条正则捞出来（`grep -nE 'mov +WORD PTR \[e[a-z0-9]+\+0xdbe\]'` ⇒ 正好 12 处），再逐个回到指令边界看**它的上文是谁**（碰撞 / 脚本 / VM / 登记）⇒ 入口就是这 4 个。
⇒ 给下一个作的经验：**vendor 符号里没有 `cancel` 时，照这套做，别在函数名上耗时间。**

### 2.2 三条"看着像、其实不是"的路（否定面）

## 3. 结论（可信度 + 适用范围）

**一句话**：**TH09 没有实体道具系统** —— 全世界对象只有 `Gui` + 3×7 side 管理器 + `EffectSys` + `ExAttackManager`（一手穷举，无 ItemManager），

## 5. ★ TH09 没有 `mode` 参数 ⇒ 我们在 TH18 里该取哪个 mode（以及代价）

### 5.1 两边根本不是一个东西

- **TH09 侧**：消弹**没有任何"撒不撒 / 撒什么"的入参** —— §1.2 的 4 个入口里，① 是"命中即杀"（参数只有弹指针）、②③④ 同理；**没有 `mode`、没有 `arg`、没有 bool**。
- **我们卡的调用面**是 **TH18 引擎**：`ce_cancel_radius(pos, r, max_count, mode)`（= `th18:0x429370`）与逐弹的 `Bullet__cancel(b, mode)`（= `th18:0x428e90`），而 **TH18 的 `mode` 表是 TH18 自己的**（详见 [`../th18/01-cancel-to-item.md`](../th18/01-cancel-to-item.md) §2.1）：

| TH18 `mode` | 引擎会做什么 | 像不像"TH09 那一下" |
| --- | --- | --- |
| **0** | **纯删除**：不撒、**连计数器都不动** | ★ **唯一对得上** |
| 1 | 撒 **`type 9`**（点道具）+ 推 `REPLAY_SAFE_RNG` | ❌ TH09 **一颗都不掉** |
| 4 | 多数 `type 9` + 少数 `type 2`（钱），也推 RNG | ❌ 更不符 |
| 3 | 不撒，但 **`inc [mgr+0x7a41d0]`**（动计数器） | 🟡 "不撒"对，副作用不对 |

### 5.2 为什么 `mode 0` 是"那一下"，以及代价（不是"最接近"三个字）

TH09 的那一下 = **`state=5` → 消失，什么也不给，也不动任何"点数/道具类"计数器**（§1.1(d)、§1.6：只动 combo / charge，而那两个在我们的 TH18 侧由我们自己算）。⇒ 只有 `mode 0` 同时满足"不撒"和"零副作用"；`mode 3` 会多出原版没有的计数器副作用（而我们的账本来就读 `ce_cancel_radius` 的返回值 / 自己的闩锁，多一个计数器只会污染共用闩锁）。

1. **用 0 ⇒ 引擎一点忙都不帮**："消弹 → 收益"必须**全靠卡侧的数值条**（combo / 充能 / SP）自己记账 —— 我们现在就是这么做的（`pofv_core.c` 三槽）。
2. **用 0 ⇒ 放弃"满地都是点、要走过去捡"的手感**。但 TH09 原版**本来就没有这个手感**（收益是数值条，§1.6）⇒ 这是**方向更对**，不是损失。
3. **用 1 / 4 ⇒ 双重错**：① 凭空撒出 TH09 不存在的点道具（原版零掉落）；② 每次消弹都推 `REPLAY_SAFE_RNG`（`th18:0x428e90` 的 1/4 支各有 float/int 抽取）⇒ 装卡后的老 replay 有必然 desync 点。
4. **用 3 ⇒ 隐蔽错**：不动道具，但把 TH18 的消弹计数器（`th18:0x428e90` 路径里的 `inc`）推起来，会搅乱"本帧消弹颗数"这类共用闩锁。
5. **★ 注释口径**：写下来时**必须**说"这是 **TH18 引擎的 `mode 0`**"，**不能**写成"TH09 的 `mode 0`" —— TH09 **没有 mode 这个概念**。否则下一个人会把 TH18 的 mode 表当成 TH09 的（这正是研究稿 §1.1-U2 警告的那类错误）。

### 5.3 我们卡现状（只读；**本节不改任何代码**）

`grep -n "ce_cancel\|cancel" mods/th18.v1.00a/card-expand/native/cards/pofv.c` ⇒ 关键点 + `pofv_core.h`：

| 位置 | 现状 | 判断 |
| --- | --- | --- |
| `pofv_core.h:168` | `#define POFV_BULLET_CANCEL_MODE_BLAST 1` | ❌ **不符**：蓝圈逐弹 `Bullet__cancel(b, 1)`（`pofv.c:202`）⇒ TH18 引擎按 mode 1 **撒 `type 9` 点道具 + 推 RNG**，而 TH09 原版**一颗道具都不掉** |
| `pofv_core.h:169` | `#define POFV_BULLET_CANCEL_MODE_CA 0` | ✅ **对**：红圈走 `ce_cancel_radius(..., 0)`（`pofv.c:239`）= 纯删除 |
| `pofv.c:190` 的注释 | "逐弹 `Bullet__cancel(b, mode = 1)`（引擎 `0x4290e0`：加分 + 掉点道具），**不另造道具**"（⚠ 引文里那个 `0x4290e0` 是 **TH18** 的地址） | ⚠ 口径不对：注释承认引擎"掉点道具"，却说"不另造道具" —— **"不另造"≠"不撒"**；TH09 口径是**引擎侧也不该撒** |

⇒ **结论（判据）**：卡 109 要让 `POFV_BULLET_CANCEL_MODE_BLAST` 也等于 **TH18 的 `mode 0`**（或蓝圈改为 `mode 0` + 自己记账），否则引擎会替我们撒出 **TH09 原版不存在**的点道具。
研究稿 §99-N30 记"该宏值不在可读范围"，本轮读出真值（🟡 读的是**我们自己的源码**，不是原版一手）⇒ **N30 收口**；这条同时要进卡的 Tuning / 审计登记（**我只登记，没改**）。
