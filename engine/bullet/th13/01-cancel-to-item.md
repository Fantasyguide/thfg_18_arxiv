## 0. 一句话

★ **TH13 根本没有 mode 号**：消弹入口的第 3 个栈参就是 **bool「撒不撒」**（`0x4114f0` / `0x411770`；`0x411df0` 连这个开关都没有，硬编码不撒）。
为真时**每颗被扫到的弹变 1 个 `type 9`**（走过去捡：PIV 计数器 `+10`、分数 `+1`）。
出的是 **ECL 615 `etCancel` / 635 `etCancel2` / 712 `etCancelRect` ＋ 玩家炸弹**；
**一颗都不出**的是 `etClear`(616) / `etClear2`(636) / `etClearAll`(613)、玩家中弹、对话/消息、**灵界**，
以及 ★**全部 ECL 走到的激光半边**（ECL 只走到 `+0x24` / `+0x1c` 槽，而那 9 个槽里没有撒点）。
全链**不消耗 RNG**；场地门与 TH16/17/18 **逐条同形**（边距 `32.0`）。

## 1. 发现（一手事实）

### 1.1 核心入口 `0x4114f0`（`(pos, radius, bool bSpawnItems)`）

- 三个栈参：`[ebp+8] = pos`、`[ebp+0xc] = radius`、`[ebp+0x10] = bSpawnItems`（`0x411527 mov eax,[ebp+8]`、
  `0x4114f0` 起 633 字节，`0x41174d` 附近的循环收尾）。★ **与 TH12 不同：位置走栈参，不走 `ebx`**。
- 循环：`mov [ebp-0x8],0x7d0`（`0x41150b`，**2000 弹槽**）、`movzx eax,[edi+0x5fa]` ＋
  `cmp eax,0x2 / je` / `cmp eax,0x1 / jne`（`0x411512`–`0x411521`，**存活 = state ∈ {1,2}**）。
- 开关是**第 3 个栈参**，`0` 时整段撒道具逻辑跳过：

```asm
4115c0  cmp DWORD PTR [ebp+0x10],0x0
4115c4  je 0x41163b              ; ★ bool=0 ⇒ 不撒（只取消）
4115c6  fld [ebx] ; fadd [0x4aec68](=32.0，double) ; fcomp [0x4ae8d8](=−192.0)   ; 场地门（x 下界）
        ; 同形四次：x−32 vs 192.0 / y+32 vs 0.0 / y−32 vs 448.0
411618  fld [0x4aefd8]           ; 速度 = 2.2f（常量）
411627  fld [0x4aec2c]           ; 角度 = −π/2（常量，不取 rand）
411630  push 0x9 ; call 0x42f020 ; ★ 每颗弹 1 个 item type 9
```

- 另有一个**独立的场地门函数** `0x412320`：`(ecx = pos, [ebp+8] = x 边距, [ebp+0xc] = y 边距)` → **0 = 场内 / 1 = 场外**；
  常量同一套（`[0x4ae8d8] = −192.0`、`[0x4ae8a0] = 192.0`、`[0x4ae878] = 0.0`、`[0x4ae8d0] = 448.0`，**全 double**）；
  调用处传的边距 = `[0x4ae8e8] = 32.0f`（`0x411897`–`0x4118a9`，两轴同值）。

- **ECL opcode → handler 是机械可验的**：派发在 `0x41b2d6`（`cmp edx,0x2bf / ja`；`movzx edx,[edx+0x41f9d8]`；
  `jmp [edx*4+0x41f760]`），**索引 = opcode − 300**。我按这条链解出来并与 eclmap 对名：
  613 → `0x41e36e`、615 → `0x41ee6b`、616 → `0x41eee3`、635 → `0x41ef19`、636 → `0x41ef3e`、**712 → `0x41eea1`**、545 → `0x41f1d4`（逐个吻合）。
- **712 `etCancelRect` 的 handler 是 `0x41eea1`**（素材订正过一次的那条）：body 里读 2 个 float（pos/size）后
  `0x41eed9 call 0x4119c0`，**整个 handler 里没有任何激光调用**。

### 1.3 撒出来的是什么

- `ItemManager__spawn_item` `0x42f020`（8 栈参，**实体**，要走过去收）。TH13 全作只有 **10 处** `call 0x42f020`，
  其中弹幕侧 3 处（`0x411632` / `0x4118ca` / `0x411bf6`）、激光侧 3 处（`0x431ebd` / `0x433b2b` / `0x43733c`）、
  敌机动态掉落 3 处（`0x417af5` / `0x417bd7` / `0x41abd1`）、玩家死亡掉落 1 处（`0x4434c1`）
  ⇒ **`type 9` 只出现在消弹路径**（「type 9 = 消弹专属道具」在本作尤其干净）。
- `ItemManager__on_tick__body` `0x42e380` 在 `0x42e8a8` 用 `type-1` 查 **9 项**跳转表 `0x42ed9c`
  （`cmp eax,0x8 / ja` ⇒ **本作只有 type 1..9**）；**type 9 → `0x42eb46`**：`fld [0x4aebec]`（= float **0.1**）→ `call 0x42f510`，`esi = 0x4be7b8`。
- PIV 助手 `0x42f510`：`[ebp+8] × [0x4ae868]`（= double **100.0**）→ ftol → `add [esi+0x24], eax`（钳 `[esi+0x2c]`）
  ⇒ **`[0x4be7dc] += 10`**。横向标定：同函数 type 8（`0x42e8bd`）用 `100.0f` ⇒ `+10000` ⇒ type 9 是**最小的那档 PIV 道具**。
- 分数：type 9 尾部 `push 0xa` → `0x413bf0(0xa)`（本作 `0x413bf0` 即 TH12 `0x40e730` 的同形函数，`arg/10`）⇒ **分数 +1**。
- 每颗 **1 个**（每个入口的循环体内一次 `push 0x9`）。

### 1.4 ★ 激光侧：一条都不出（与 TH15/TH17 相反）

- 三个激光类的虚表基址（`0x42ffd0` 写 `[esi] = 0x4ab0cc`，`LaserManager::allocate_new_laser` `0x42ff2a` 调用 ⇒ 显式写入）。
  我按 dword 读了这四个槽，**与素材逐格一致**：

| 类 | vtable | `+0x1c` | `+0x20` | `+0x24` | `+0x28` |
| --- | --- | --- | --- | --- | --- |
| A | `0x4ab0cc` | `0x432e00` | **`0x431bf0`**（含 `0x431ebd push 0x9`） | `0x4327c0` | `0x432320` |
| B | `0x4ab19c` | `0x434940` | **`0x433870`**（含 `0x433b2b push 0x9`） | `0x4342e0` | `0x433ef0` |
| C | `0x4ab134` | `0x437b80` | **`0x4371b0`**（含 `0x43733c push 0x9`） | `0x4378d0` | `0x437660` |

- ★ **否定结论（一手）**：全作只有 3 处激光侧撒点，全部落在三个类的 **`+0x20`** 方法体内
  （按各槽地址排序即可判定：`0x431ebd < 0x432320 < 0x4327c0 < 0x432e00`，B、C 同理）
  ⇒ **`+0x1c` / `+0x24` / `+0x28` 这九个槽里一处撒点都没有**。
- 而 ECL 的激光半边只走 **`+0x24`**（615/616 经 `0x4302a0`：`0x4302e1 mov eax,[eax+0x24]`）和
  **`+0x1c`**（613 经 `0x430300`：`0x43031b mov eax,[edx+0x1c]`；545 经 `0x430220`：`0x430280 mov eax,[edx+0x1c]`）
  ⇒ ★★ **TH13 的 ECL 消弹在激光侧一颗道具都不出**（TH15/TH17 恰好相反：那边 ECL 走得进会撒的槽）。
- 三处撒点的 recipe 与弹幕侧**完全相同**：速度 `2.2f`、角度 `−π/2`、场地门 `32.0`/`−192`/`192`/`0`/`448`。

### 1.5 顺带钉到的：矩形族入口 `0x4119c0`（712 走的就是它）

- `0x4119c0(pos, &size, float)`（`0x4119c6 mov ecx,[ebp+8]`、`0x4119cd mov esi,[ebp+0xc]`、`0x411a55 fld [ebp+0x10]`）
  ＝ 矩形清弹；**只有 3 个栈参，没有「撒不撒」开关**，撒点 `0x411bf6` 前**只有场地门**这一个判断
  （`0x411bd5 call 0x412320` → `test eax,eax / jne 0x411bfb`）⇒ **矩形族无条件撒 type 9**（这是我本轮复核出的、素材清单里没写的一条）。
- 它的 6 个调用点：`0x41eed9`（712）＋ **5 个非 ECL**：`0x40ac0d` / `0x40ac90` / `0x40ad0c`（同一函数内，ExpHP 名 `BombMarisa__method_10`）、
  `0x40c71b`（`BombSanae__method_10`）、`0x40ce74`（`BombYoumu__on_tick`）——**名字来自 ExpHP，只用于指认，不是一手**。
  ⇒ 4 个机体的炸弹里，**灵梦走半径入口 `0x411770`，另三个走矩形入口 `0x4119c0`**，两条都撒（见 §3.3 第 4 条）。

### 1.6 boss 击破 / 符卡结束 / 关卡切换 / 灵界

- **符卡打掉 / 捕获** = `etCancel(640.0f)`；**超时** = `etClear(640.0f)` —— 两者都是 `unless ($TIMEOUT == 0)` 的两支
  （我重跑了 `thecl -d 13`：`st01bs.ecl:130/133`、`st02bs.ecl:145/148`、`st02mbs.ecl:238/241` 等同一形状）⇒ 前者 **✅ 撒**、后者 **❌**。
- **boss 终盘**：`enmKillAll(); +60: etClearAll(); spellEnd();`（如 `st02bs.ecl:695`）⇒ 弹幕侧走 `0x411df0()`（硬编码不撒）、
  激光侧走 `0x430300` → `+0x1c`（无撒点）⇒ **❌ 两边都不出**（与 TH12 相反）。
- **对话 / 消息**：`GuiMsgVm` `0x4287a8` → `0x411df0()` ⇒ 清弹但**不出货**。
- **敌机死亡 / `enmKillAll`**：引擎侧不清弹（6 个入口的全部调用点里没有敌机管理器）。
- ★ **灵界（Trance，本作特有）本身不消弹**：6 个入口的直接 `call` 调用点**共 22 处**，发起方全落在四个区
  ——`0x40b2xx`（炸弹）、`0x41exxx`/`0x41fxxx`（ECL handler）、`0x4287a8`（`GuiMsgVm`）、`0x4433xx`/`0x4436xx`（玩家）——
  **没有任何一处落在 `0x405xxx`（TranceManager）**。⇒ 一手支持「我们卡 113 不消弹」这个现状。

## 2. 验证（怎么排除掉别的路）

1. **调用点穷举**（全 `.text` 扫 `call rel32`）：`0x4114f0` × 2、`0x411770` × 6、`0x411df0` × 3、`0x4302a0` × 6、
   `0x430300` × 4、`0x430220` × 1、`0x4119c0` × 6、`0x42f020` × **10**、场地门 `0x412320` × 2。逐个回指令边界读实参 ⇒ §1.2 / §1.4 的表是全集。
2. **激光侧的两重独立证否**：(a) 撒点清单只有 3 处且都在 `+0x20` 方法体内（地址区间判定）；
   (b) 虚表 dword 是直接读出来的（§1.4 表），不靠名字猜。
3. **常量与表按字节读**：`32.0` / `2.2f` / `−1.5707964f` / `−192.0` / `192.0` / `0.0` / `448.0` / `0.1f` / `100.0f` / `100.0`
   全部读原始字节；opcode 表两级（byte 表 `0x41f9d8` → 指针表 `0x41f760`）用 7 个已知 op 交叉验证后才用。
4. **ECL 脚本侧我重跑了，不是转抄素材**：`thecl -d 13` 过 `dat/st0*bs.ecl`，§1.6 的击破/超时两支逐行可见。
5. **三处对素材的订正（我先复核再写，不替它圆场）**：
   - **712 handler = `0x41eea1`** ✅ 正确（素材已自行订正过）：我按 `opcode − 300` 解码复核，一致。
   - **入口表里 `0x430300` 的槽号**：素材 §2 的入口表写「激光全清 → `vtable[0x28]`」，实测是 **`+0x1c`**
     （`0x43031b mov eax,[edx+0x1c]`）。素材同一节的 ECL 表那一行写的是 `+0x1c`（正确）⇒ **素材两张表自相矛盾，以 `+0x1c` 为准**。
   - **「ECL 614（同族）→ handler `0x41e3ef`」是错的**：eclmap 里 **614 = `etCopy`**（不是消弹族，
     handler `0x41d61a`：读两个 int、按 `i×0x380` 索引，不是清弹）；而 `0x41e3ef` **不在 handler 指针表里**，
     全文件 **0 处直接 `call`、0 处 dword 引用** ⇒ 它不是 ECL handler。（它本身确实做「`0x411df0` + `0x430300`」，
     所以素材是「看到一个清弹函数就归给了 614」；**这条订正只改归属，不改「613 etClearAll 不出货」的结论**。）

## 3. 结论（可信度 + 适用范围）

### 3.1 结论

> **TH13：出不出实体靠入口的第 3 个 bool。ECL 615 `etCancel` / 635 `etCancel2` / 712 `etCancelRect`
> ＋ 玩家炸弹 ⇒ 撒 `type 9`（PIV 计数器 `+10`、分数 `+1`），每颗弹 1 个、落地走过去收。
> `etClear`(616) / `etClear2`(636) / `etClearAll`(613) 的弹幕半边、玩家中弹、对话开始、**灵界**，
> 以及**全部 ECL 激光半边** —— 一颗都不出。全程不消耗 RNG；场地门 `32.0`/`−192`/`192`/`0`/`448`（与 TH16/17/18 同形）。**

### 3.2 可信度与适用范围

- **✅ 高**：6 个入口 ＋ 22 处调用点逐条回指令边界；虚表槽号直接读 dword；x87 常量逐个读出；
  opcode↔handler 用两级表机械还原并与 eclmap 对名；item 语义用 9 项跳转表 ＋ `0x42f510` 的三处调用值横向标定。
- **范围：仅 TH13 v1.00c（md5 `6f39c0708ee4daa94f5053526c4e10cc`），不可外推。**
  唯一可互证的一条：TH13 的 type 9 处理与 TH12 逐条同形（`th13:0x42eb46` vs `th12:0x426c24`，都是 `0.1f` ⇒ `+10`）。
