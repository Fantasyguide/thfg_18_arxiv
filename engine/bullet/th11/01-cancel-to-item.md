## 1. 发现（一手事实）

### 1.1 一句话

**没有 `mode` 参数**：子弹侧**撒的 type 写死在体内**（`0x40af90` 的 `0x40b0a2: mov ecx,0x8`），"撒不撒"是**栈参 bool**；撒的是 **`item type 8`** 实体、**每颗被消的弹恰好一颗**、掉在**弹自己的位置**、`state = 5` ⇒ **要走过去收**；**消弹链零 RNG**；**boss 击破 / 符卡结束 / 关卡切换都不出道具**。

### 1.2 ★ 更正：`th11:0x424fe0` **不是**消弹，是**激光**侧（保留，不许抹掉）

既有笔记 `local/_scratch/research-th11-bomb-lifefrag-hud.md` §2.3 把 `0x424fe0` 记成"消弹圈"。**本轮一手否掉这条命名**（本轮复核了指令原文）：

```
424fe0: a1 94 8e 4a 00   mov  eax,ds:0x4a8e94      ; ★ 0x4a8e94 = LASER_MANAGER_PTR（vendor statics.json）
424fe7: 8b 48 18         mov  ecx,DWORD PTR [eax+0x18]  ; 链表头
425021: 8b 01            mov  eax,DWORD PTR [ecx]       ; vtable
425023: 8b 40 1c         mov  eax,DWORD PTR [eax+0x1c]  ; 槽 +0x1c
42502d: ff d0            call eax
42503c: c2 0c 00         ret  0xc
```

* ⇒ `0x424fe0` 与 `0x424f10` / `0x425040` / `0x425070` 是**同一族"管理器链表虚函数派发原型"**（分别派发 `vtable+0x1c` / `+0x14` / `+0x24`）；`0x424fe0` 这一支**只作用于激光**，体内**不撒任何道具**（该区间 `grep '4a8e90|424230'` 零命中）。
* **真正的消弹是 `0x40af90`**（子弹管理器 `0x4a8d68` 的**定长数组**版，§1.4）。
* ⇒ §2.3 的**结论"原版灵击确实清弹"仍然成立**（bomb 同时调了 `0x40af90` 与 `0x424fe0`），但**"清弹入口 = `0x424fe0`"这条地址归属是错的**。本文按更正后的口径写。

### 1.3 消弹路径盘点（逐条点名 + 谁调）

| # | 路径 | 子弹侧入口 | 激光侧入口 | 调用点（一手） |
| --- | --- | --- | --- | --- |
| ① | 灵击（普通弹 / 一发式） | `0x40af90` | `0x424fe0` | `0x45df37` + `0x45df5a`（同属一个 bomb 函数） |
| ② | 灵击（持续型 / 符卡窗口） | `0x40af90` ×2 + `0x40b0e0` | `0x424fe0` ×2 | `0x406fbd` / `0x406fdf`；`0x43113f` / `0x43115e` / `0x43116f` / `0x431180` |
| ③ | 每弹型清弹分发 | `0x40af90`（循环内） | `0x424fe0` | `0x4074f5` + `0x407517`（循环 `0x4073b0: mov ebp,0x4a3dfc` ⇒ `0x40751f: cmp ebp,0x4a3e10`） |
| ④ | 决死 Bomb | `0x40af90` ×2 | `0x424fe0` ×2 | `0x43113f` / `0x43115e`（压 `0x1` 那一对）+ `0x43116f` / `0x431180`（压 `0x0` 那一对） |
| ⑤ | 擦弹消去 graze-cancel | **无独立入口**：`state → 3` 在 `0x40ae90` 体内 | ❓ 未找到 | `0x40aecb: mov eax,0x3` / `0x40aed0: mov WORD PTR [esi+0x4b2],ax`；判据 `0x40aebe: call 0x40b8a0` |

| ⑦ | boss 击破 / 符卡结束 / 关卡切换 | **不经任何入口** | **不经任何入口** | 见 §1.9 |

* **`0x40ae90` 是"每颗弹的消去例程"**（本轮读完，`0x40ae90`–`0x40af81`，内含 3 个 `ret`）：门是 **`state ∈ {1,2}`**（`0x40ae91`–`0x40aea2`，否则 `xor eax,eax` 直接返回），随后写 **`state = 3`**（`0x40aecb`/`0x40aed0`，或另一支 `0x40af77`），并写 `[esi+0x384] = 1`。它的 **8 个调用点**是：`0x409af4` / `0x409c84` / `0x40b061`（**在 `0x40af90` 体内，唯一后面接着撒道具的**）/ `0x40b187` / `0x40b2eb` / `0x40b60f` / `0x418435` / `0x418895`。
* ⇒ **撒道具与"消弹本身"是分开的两件事**：`0x40ae90` 只负责消（**8 处调用点里 7 处不撒**），撒道具在 `0x40af90` 等 4 个变体里**内联**（§2.1）。

**出的那几条 / 不出的那几条**

* **出的**：**子弹侧 4 个变体**（`0x40af90` / `0x40b0e0` / `0x40b210` / `0x40b3a0`，体内各一处 `call 0x424230`，§2.1）⇒ 上表 ①②③④ 四条路**都会撒 `type 8`**。
* **不出的**：`0x40ae90` 的其余 7 个调用点（`0x409af4` / `0x409c84` / `0x40b187` / `0x40b2eb` / `0x40b60f` / `0x418435` / `0x418895`，含擦弹消去 ⑤ 那一族）；**激光侧 `0x424fe0`**（体内无 `0x4a8e90`、无 `call 0x424230`）；**⑦ boss 击破 / 符卡结束 / 关卡切换**（不经任何入口）。

### 1.4 撒出来的是什么（`0x40af90`；`item type 8` 的**实体**）

```
40b061: e8 2a fe ff ff   call 0x40ae90        ; 先消（state=3）
40b066: d9 05 a8 81 49 00 fld ds:0x4981a8     ; = 2.0f（是给下面场地门的参数，不是速度！★§2.3-C）
40b078: e8 23 08 00 00   call 0x40b8a0        ; ★ 场地门（弹位, 2.0f, 2.0f）
40b07f: 75 30            jne 0x40b0b1         ; ★ 越界 ⇒ 跳过撒道具
40b081: 39 44 24 28      cmp [esp+0x28],eax   ; ★ 撒不撒 flag == 0 ⇒ 跳过
40b087: d9 05 84 83 49 00 fld ds:0x498384     ; = 0.6f（速度）
40b08d: 8b 15 90 8e 4a 00 mov edx,ds:0x4a8e90  ; ITEM_MANAGER_PTR
40b09a: 8b c7            mov eax,edi          ; ★ edi = &bullet->pos
40b09c: d9 05 2c 84 49 00 fld ds:0x49842c     ; = −π/2（角度）
40b0a2: b9 08 00 00 00   mov ecx,0x8          ; ★★ type = 8（写死在体内）
40b0aa: 6a ff            push 0xffffffff      ; −1
40b0ac: e8 7f 91 01 00   call 0x424230        ; ★★★ ItemManager::spawn_item
```

* **参数**：`[esp]` = 角度 **`0x49842c = −π/2`**、`[esp+4]` = 速度 **`0x498384 = 0.6f`**（另 `push -1`），type 走 **`ecx`**。
  ⇒ 与 TH10 的 `(type=8, −1, 角度 −π/2, 速 0.6)` **同形**（★§2.3-C 订正研究稿的"速度 2.0/0.6"）。
* **位置 = 弹自己的位置**：`0x40b005: lea edi,[esi+0x43c]`（`edi` 全程未被改写）、`0x40b09a: mov eax,edi`。
* **撒道具在槽循环体内、且在 state 门与圆判定之后** ⇒ **一颗弹最多一颗**（`state = 3` 去重，见 `0x40afde`）。
* **type 8 走独立小池**（`0x424230` 的 `mov ebp,0x8` + `cmp ebx,ebp / je`，`0x424235`/`0x42423f`/`0x424241`；type 8 分支 `0x424418`–`0x4244f0`）：游标 `IM+0x265e68/0x265e6c`、**1024 槽环形**（`0x424447: cmp ecx,0x400` 后 32/16/8 取模）、stride `0x478`；**`0x4244a7: mov [edx+0x464],0x5` ⇒ `state = 5`**；`0x4244b1`/`0x4244b7` 把 `[edx+0x468]`/`[edx+0x46c]` 写成 8（type 与外观组）；位置 `0x4244bf`–`0x4244dc` 从 `edi`（弹位）拷到 `item+0x434`；末了 `0x4244eb: call 0x424670`（`fsincos` 角度助手，纯函数）。
* **`state = 5` ⇒ 当场不入账、要走过去收**（`state 1/4` 才是自动回收档；同 TH10 口径）。
* 🟡 **TH11 侧 type 8 的"值多少"没逐指令钉死**（研究 §T11.2(b) 明确标 🟡、并禁止把 TH10 的 `+10 信仰 / +10 分` 当一手推论）⇒ **本文不写它值多少**。见 §3-🟡2。

### 1.5 判定形状 / 遍历

* **遍历 = 定长槽数组**：**2000 槽**（`0x40afcf: mov ebp,0x7d0`）× stride **`0x910`**，基址 **`BM+0x64`**（`0x40afa0: add esi,0x64`）—— **不是链表**；空槽/已消门：`0x40afd4: movzx eax,[esi+0x4b2]` → **`state == 0`（`0x40afde: je`）或 `== 3`（`0x40afe8: je`）⇒ 跳到下一槽 `0x40b0b1`**（天然去重 ⇒ 一颗弹最多撒一颗）。
* **形状 = 圆（球）**：`d²` vs `(R + r × 0.5)²` —— `0x40b01e: fld [esi+0x45c]`（弹半径）→ `0x40b024: fmul QWORD PTR ds:0x497e60` → `0x40b02a: fadd [esp+0x24]`（+ 灵击半径 `R`）。
  **`0x497e60` 是 8 字节 double = `0x3fe0000000000000` = `0.5`**（本轮直读 PE 节表）⇒ **与 TH10 的 `×0.5f` 同值**（★§2.3-D 订正研究稿的"读出 0.0"）。
* **符卡窗口副作用（只改半径）**：`0x40afa3: test BYTE PTR [eax+0x8e0],0x1`（`eax` = `SPELLCARD_PTR`）且符卡 id ∈ `[0x9e, 0xa1]`（`0x40afb3`/`0x40afba`）时，`R = R / 3.0`（`0x40afc5: fdiv QWORD PTR ds:0x498168`，**`0x498168` = double `3.0`**）。
* **没有 mode 参数**：本函数是 `eax`/`ebx` 传管理器与圆心、**3 个栈参 + `ret 0xc`**；帧 = `sub esp,0x14` + 3 push（`0x40af95`–`0x40afaa`）⇒ **`[esp+0x24]` = 半径、`[esp+0x28]` = 撒不撒、`[esp+0x2c]` = 条件消**。
* **第三参 `[esp+0x2c]` = "条件消"门**（与 TH10 同族）：`0x40afee: cmp DWORD PTR [esp+0x2c],0x0` / `0x40aff3: je 0x40afff` → `0x40aff5: cmp DWORD PTR [esi+0x4],0x0` / `jne`（跳过）⇒ **`≠0` 且 `bullet+4 ≠ 0` 时连消都不消**。

### 1.6 ★ 场地门 —— 两件**不同**的事，量纲警告必须写

**(a) 撒道具之前的门（"只消不撒"那一档）**：`0x40b078: call 0x40b8a0`（参数 `(弹位, 2.0f, 2.0f)`）返回 **非 0 ⇒ `0x40b07f: jne 0x40b0b1` 跳过撒道具**；随后 `0x40b081: cmp [esp+0x28],eax`（`eax` 此时 = 0）⇒ **撒不撒 flag == 0 也跳过**。⚠ **弹已经被消了**（`0x40b061` 在两道门之前）⇒ **"消了" ≠ "撒了"**。

**(b) `0x40b8a0` = 场地边界判定**，与 TH10 的 `th10:0x4086b0` **同形**（`ret 0x8`）：`pos.x + mx` 与 `−192.0`、`pos.x − mx` 与 `+192.0`、`pos.y + my` 与 `0.0`、`pos.y − my` 与 `448.0` 比较，**越界 ⇒ `mov eax,1; ret`**，场地内 ⇒ `xor eax,eax`。本作这四个界是**8 字节 double**：`0x497ec8 = −192.0`、`0x497ea0 = +192.0`、`0x497ec0 = 0.0`、`0x497eb8 = 448.0`（本轮直读）。
⇒ **与 TH16/TH18 的场地同界（±192 / 0..448），外扩量这里 = 2.0**（擦弹消去那一支传的是 `0x497fdc = 8.0f`）。

**(c) 撒出来之后还有一道"钳位"，它不是门**：`ItemManager::spawn_item` 把 `item.x` **钳进 `[−192.0, +192.0]`** —— `0x42426f: fld ds:0x497f10`（**`0x497f10 = −192.0f`**）/ `0x424295: fcom [edx]` / `0x42429e: fstp [edx]`（写 −192），`0x4242a4: fld ds:0x497f00`（**`0x497f00 = +192.0f`**）/ `0x4242b3: fstp [edx]`（写 +192）。
⇒ **语义是"照撒，但把 x 拉进场内"**（不是"越界就不撒"）。TH11 侧**没有** y 方向的同类钳位（🟡：没在 `0x424230` 里找到 y 的同类比较）。
⚠ **两条互补**：门（外扩 2.0）先挡掉"偏出 2px 以上"的弹；只有落在 **±2px 带内**的弹才会**通过门**却**被钳位**——所以钳位不是冗余的那一条，但它**不代表"原版把屏外的弹也算成道具"**。

**⚠ 量纲警告（本任务要求写清）**：TH11 的 **`±192` 钳位** 与 TH16/TH18 的 **"`x ∉ (−192−32, 192+32)` ⇒ **不撒**"** **不是同一个东西**（一个是**钳位**、一个是**门**，且常量也不同：`192/192` 对 `192+32`）。讨论"像不像原版"时**必须说清是哪种**。

### 1.7 激光侧 = 另一套（链表 + 虚函数），撒不撒**未证明**

* 子弹侧 `0x40af90` 体内**直接内联**了 `type 8` 的撒道具（§1.4）。
* 激光侧 `0x424fe0` 体内**没有** `0x4a8e90`（`ITEM_MANAGER_PTR`）也没有 `0x424230`：它只做链表派发（§1.2）。
* ❓ **激光对象自己的 `vtable+0x1c` 指向哪个函数、会不会撒道具，未定位到**：`0x424230` / `0x40ae90` / `0x424670` 这三个地址的 dword **在全 exe 文件里 4 字节对齐搜索均 0 命中** ⇒ 虚表**不是**以裸 dword 字面量存在（运行时构造）⇒ **静态找 vtable 这条路走不通**。若将来按"激光也撒"来复刻，**属未证实的类推，必须标 ❓ 而不是 ✅**。
* 原版灵击**确实消激光**（`0x45df5a: call 0x424fe0`，一手）—— 这一条对我们的卡是**已知偏差**（§5）。

### 1.8 RNG —— ❌ 消弹链上零消耗（确定性）

* `0x40af90` 体内**零 RNG**：`fld/fmul/fadd/fcom` + `call 0x40ae90`（消弹）+ `call 0x40b8a0`（门，纯比较）+ `call 0x424230`（撒道具）+ 尾部 `call 0x412990`（外圈收尾，🟡 内部未读完）。
* `0x424230` 的 **type 8 分支**（`0x424418`–`0x4244f0`）**零 RNG**：只有环形游标 + 常量写 + `call 0x424670`（`fsincos`，纯函数）。
* ⇒ **数量 = 命中弹数、位置 = 各自弹位、速度 = 固定 `(sin,cos)(−π/2) × 0.6`**，全确定。🟡 限定：只说「消弹 → type 8」这条链；`0x40ae90`（火花/状态写）只读了 `0x40ae90`–`0x40af63` 段，其它 type 的撒道具分支未查。

### 1.9 boss 击破 / 符卡结束 / 关卡切换 —— 全部「什么都不出」

* **boss 击破**：清弹走 **ECL / 敌机死亡处理器**，不在 §1.3 那张表里 ⇒ **与 TH18「满屏弹幕消失但一颗点都不出」同档**。
* **符卡结束**：引擎侧**没有"符卡结束清弹"函数**；TH11 的符卡侧只有**半径 `/3`** 这一个副作用（`0x40afc1`–`0x40afcb`，符卡 id ∈ `[0x9e,0xa1]`）。**关卡切换**：整池重建 ⇒ **不走撒道具路径**。

## 2. 验证（怎么排除掉别的路）

### 2.1 入口穷举 + 函数边界划分（撒道具的变体是**4 个**，不是 1 个）

```
grep -nE 'call +0x40af90' …  → 11 处：406fbd 4074f5 4079e7 408037 416656 416690 4166ca 416703 43113f 43115e 45df37
grep -nE 'call +0x40b0e0' → 1（406fdf）    'call +0x40b210' → 1（407b75）    'call +0x40b3a0' → 2（415a6b 415ade）
grep -nE 'call +0x424fe0' → 12 处（全部与 §1.3 成对）    'call +0x40ae90' → 8 处
grep -nE 'call +0x424230' → 21 处（全 exe；其中 4 处在消弹变体体内）
```

按 `ret` + `int3` 对齐切出的**函数边界**与体内那一处 `call 0x424230`：

| 变体 | 函数范围（收尾） | 体内撒道具 | 调用点 |
| --- | --- | --- | --- |
| `0x40af90` | `0x40af90`–`0x40b0db`（`ret 0xc`） | `0x40b0ac` | 11 |
| `0x40b0e0` | `0x40b0e0`–`0x40b209`（`ret 0xc`） | `0x40b1d2` | 1（`0x406fdf`） |
| `0x40b210` | `0x40b210`–`0x40b398`（`ret 8`） | `0x40b36b` | 1（`0x407b75`） |
| `0x40b3a0` | `0x40b3a0`–`0x40b5b6`（`ret 4`） | `0x40b508` | 2（`0x415a6b` / `0x415ade`） |

⇒ **4 个子弹侧变体都会撒 `type 8`**（★§2.3-A 订正研究稿的"只有 `0x40af90` 会撒"）；callers 已穷举，**不在这张表里的路不撒**。

### 2.2 撒道具的两道门就是"撒不撒"开关（订正研究稿的一句注）

研究稿 T11.2(c) 的注里写：「另有一道后置门 `40b0a1: cmp [esp+0x28],eax` …属'外圈/内圈'两档，**与'出不出实体'无关**（只影响半径）」—— **不成立**：本节两条 `jne/je 0x40b0b1`（`0x40b07f` / `0x40b085`）的目标 `0x40b0b1: add esi,0x910` 正是**下一个槽**，两条都**跳过了 `0x40b087`–`0x40b0ac` 的撒道具块**；而消弹（`0x40b061: call 0x40ae90`）在它们**之前**已经发生。⇒ 这两条是**撒道具的开关**，不是半径档。

### 2.3 ★ 本轮只读复核对研究稿的 5 处订正（冲突不粉饰）

| # | 研究稿 | 本轮复核（一手） | 影响 |

## 3. 结论（可信度 + 适用范围）

**一句话**：TH11 的灵击/决死清弹**撒 `item type 8` 实体**（**4 个子弹侧变体**，type 写死 `mov ecx,0x8`、每颗弹一颗、掉在**弹自己位置**、角度 `−π/2`、速度 `0.6`、`state = 5` ⇒ **要走过去收**）；子弹侧 = 「**2000 槽定长数组** + **圆判定 `(R + r×0.5)`**」；撒之前过**场地门（±192 / 0..448，外扩 2.0 ⇒ 越界只消不撒）**与**栈参 bool**；撒之后 `spawn_item` 再把 `item.x` **钳到 ±192**；激光侧是完全独立的「**链表 + 虚函数 `+0x1c`**」，**未能证明它撒道具**；**全链零 RNG**；boss 击破 / 符卡结束 / 关卡切换**都不出道具**。

**适用范围**：本文只对 md5 `6af1e3b37f28293f4fc127ee01d2632c` 那个 build 负责。**没有 `mode` 参数 ⇒ TH18 的 `mode` 号与本文毫无对应**（反向亦然）。

**✅ 已肯定（可复现）**：① `0x40af90` 全函数（2000 槽 / stride `0x910` / 双 state 门 / 圆判定 / `mov ecx,0x8` / `call 0x424230`）；② `0x424230` 的 type 8 分支（1024 槽环形 / `state = 5` / 位置取自弹位 / `fsincos`）；③ 场地门两处常量（六个真值直读）；④ `item.x` 钳位两条 `fcom` 与 `±192.0f` 原文；⑤ `0x4a8e94 = LASER_MANAGER_PTR` + `0x424fe0` 体内无 ITEM_MANAGER 引用 ⇒ **更正 §2.3 的地址归属**；⑥ 4 变体 × 调用点穷举（否定证据）；⑦ `0x40ae90` 的门是 `state ∈ {1,2}`。

**逐条口径差异**

1. **U1｜撒实体 vs 按颗数记账**：原版是**真实体**（`state = 5`、**要走过去收**、每颗弹一颗）；我们 `mode 0` 纯删除 + 按**颗数**记账（每 100 颗小绿点 +10）⇒ **手感与粒度都不一致**（原版是每颗一颗点，我们是 100:10 的比率账）。这是**卡设计口径**（`signal.c:92`/`:331` 注释已写明"不建实体"），但**不是复刻**。
2. **U2｜「数值一致」这句在加值那一格撑不住**：研究稿 §1 表把 111 记成"✅ 数值一致（每 100 颗小绿点 +10）"，但同一份研究的 §T11.2(b) 明确把 **TH11 侧 type 8 的加值标 🟡 并禁止类推** ⇒ **"原版每颗 = +10 信仰 / +10 分"在 TH11 上没有一手**。卡侧 100:10 的口径**不能声称"与原版一致"**（要么补一手，要么标 ❓ 自定）。
3. **U4｜激光**：原版灵击消激光（`0x45df5a` → `0x424fe0`，12 处调用点之一）；我们 `signal.c` **一处都没有**（连注释登记也没有）⇒ **已知偏差但未登记**（`mof.c:70` 有同类登记，`signal.c` 缺）。另外**激光到底撒不撒道具也没证明**（§3-🟡1）⇒ 就算将来补"消激光"，也**不能顺手撒点**。
4. **U7｜±192 钳位我们没实现**：因为我们**不建实体**（`signal.c:595` 的 `mode 0` 只删不撒）⇒ 现在**无影响**；**若将来 111 改成建实体，必须补** `item.x → clamp(±192.0)`（`th11:0x42426f`–`th11:0x4242b3`，常量 `0x497f10`/`0x497f00`），否则偏出场地 2px 带内的弹会在 `±192` 外撒点。
5. **场地门（外扩 2.0）我们也没有**：原版**越界弹只消不撒**（`0x40b8a0` 返回 1，`0x40b07f: jne`）；我们 `mode 0` 一颗不落地记进颗数账 ⇒ **越界那部分我们会多发**（上界差异；弹飘出 ±192 / 0..448 之后才非零）。
