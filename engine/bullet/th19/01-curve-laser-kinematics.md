# TH19 曲线激光的运动学（早苗 C3 实例）

> **版本**：TH19 v1.10c（`th19.exe`，**带 DYNAMIC_BASE**：静态首选基址 `0x400000`，运行时实测见过 `0x4a0000` / `0x700000`）。
> 本文裸地址默认属该版本；引用其他版本一律写成 `th18:0x…`。

★★ 本文只回答一件事：**`609` 那套"段变换"的 `r`/`s` 到底是什么量纲、五段怎么接**。
★ 结论全部来自 **ECL 原文 ＋ 逐条算术**，动态探针只用于**交叉验证**（见 §5）。

## 1. 结论速查

| 参数 | 语义 | 单位 | 置信 |
| --- | --- | --- | --- |
| `a` | 该段**持续帧数** | 帧 | ✅ 一手（原文 `$C - 40`、`$D - 40` 与 `a` 自洽） |
| `b` | 该段**起始帧**（相对激光出生） | 帧 | ✅ 一手（`$C`/`$D` 逐段 +10/+8） |
| `r` | **航向速度增量/帧**（加速度） | px/帧² | ✅ 一手（原文把它写成"总量 ÷ 帧数"，§2.1） |
| `s` | **自转角速度** | rad/帧 | ✅ 一手（`0.19634955 rad = 11.25°`） |
| `mode` | 变换模式；`8` = 曲线推进 + 自转 | — | 🟡 语料里 C3 五段全是 `8` |

★★ **`s` 就是"转向"，`r` 不是。** `r` 只改变**速度大小**（沿当前航向），`s` 才改变**航向本身**。

## 2. 一手证据

### 2.1 `r` 的原式：**总量 ÷ 帧数**

★ 早苗 C3（`ExAttackFunc2`）原文 `pl02.txt:372`：

```
ins_609(0, 3, 1, 8, 10, $D, (_f(-40) * %C) / _f(10), 0.0f);
```

★ 段 3 的 `r` 被写成 ★ **`(−40 × %C) ÷ 10`**（10 = 该段帧数）⇒ ★ **`r` = 每帧增量**，
★ 段内累计变化 = `−40 × %C`。★ 若 `r` 是"弯曲加速度"，原文不会写成"总量 ÷ 帧数"这种形式。

### 2.2 `s` 的数值 = 11.25°/帧

* ★ 原文：`ins_609(0, 4, 1, 8, 8, $D, 0.0f, -0.19634955f)`（另一条分支是 `+0.19634955f`）；
* ★ 算术：★ `0.19634955 rad = 11.25°`（`11.25 × π / 180 = 0.19634954`）；
* ★ 段 4 是 **8 帧** ⇒ ★ `8 × 11.25° = 90°` ⇒ ★ **"原地转 90°"**。

### 2.3 五段时间轴（`%C = 0.1`，`$D = $A ≈ 130`，`%B = [-9888.0f]`）

| 段 | `a`(帧) | `b`(起始) | `r` | `s` | 速度曲线 | 观感 |
| ---: | ---: | ---: | ---: | ---: | --- | --- |
| 1 | 40 | 0 | `%C` = +0.1 | 0 | 0 → **+4 px/帧** | 慢慢加速下落（"慢弹"） |
| 2 | 90 | 40 | 0 | 0 | **4** 匀速 | 直上直下 |
| 3 | 10 | `$D` | −0.4 | 0 | 4 → **0** | 减速到停 ⇒ "到某高度停住" |
| 4 | 8 | `$D`+10 | 0 | **∓0.19634955** | 0 | ★ **原地转 ∓90°**（转向） |
| 5 | 120 | `$D`+18 | `0.05 + %B×0.05` | 0 | 0 → **6+** | ★ 横向加速离开（交错） |

★ 另有 `609(0, 0, 0, 128, 300, −9999994, −9999994.0f, −9999994.0f)` 一段：★ `mode 128`、`a = 300`，
★ 三个参数都是哨兵 `−9999994` ⇒ ★ **占位/无效段**（不是"前 300 帧竖直"，早先的读法已作废）。

## 3. 由这段原文得到的三个行为纠错

1. ★ **"左右交错" = `s` 的正负号**：原文有 `−0.19634955f` 与 `+0.19634955f` 两条分支（据 `%B`/难度选边），
   ★ 相邻两条激光各转一侧，视觉上就交错。
2. ★ **"到特定高度才转向"是假象**：★ 它由**固定帧号** `$D = $A` 决定，★ **与自机位置无关**。
3. ★ **初速为 0**：★ `ins_605(0, 0.0f, 0.0f)` ⇒ ★ 全部位移来自 `r` 的逐帧累加。

## 4. 卡侧等价实现（伪代码）

```
v = 0; theta = 0                      # 605(0,0,0)
for each laser:
    for seg in [1..5]:
        for f in seg.a:
            v     += seg.r            # 段1: +0.1 → 4；段3: −0.4 → 0；段5: +0.05
            theta += seg.s            # 只有段4 非 0：∓11.25°/帧
            pos   += v * (cos theta, sin theta)
```

★ 段切换按 `b`（帧号），★ 段结束按 `a`（帧数）—— ★ 两者在原文里是**并列参数**，不是"位置触发"。

## 5. 动态交叉验证（TH19 侧，只读探针）

★ 探针源码：[`mods/th19.v1.10c/runtime-probe/`](../../../mods/th19.v1.10c/runtime-probe/README.md)（thcrap 插件，只读、不挂钩子）。

| 观察 | 结果 |
| --- | --- |
| 扫 `0.19634955f`（`0x3e490fdb`） | ★ 运行时**只在 1 处**出现：`MEM_PRIVATE` 的 VM/参数区；周围是 16 位成对的 VM 操作数 |
| 跟 549 个 100ms 块 | ★ 该处 `r`=0 / `s`=0.19634955 **全程不变**，最后整片归零（被回收）⇒ **临时/脚本侧数据** |
| 扫 `0.4` / `0.1`（`0x3ecccccd` / `0x3dcccccd`） | ★ 命中集中在 `MEM_MAPPED`（**映射的 ECL 文件**，`prot=2`）⇒ **是脚本字面量**，不是运行时状态 |

★ 两条合起来的结论：★ **`r`/`s` 在 `609` handler 内部就被消费**，
★ 运行时**不存在"逐帧读段表 float 再积分"的通路** ⇒ ★ 与 §4 的"VM 逐帧解释"模型一致。

## 6. 与旧标定值的关系（明确作废）

| 旧值 | 状态 |
| --- | --- |
| `1.15 px/帧`（速度） | ★ **作废**：速度是 `r` 逐帧累加出来的（0→4→0→6+），不是常数 |
| `k=0.34`（曲线系数） | ★ **作废**：没有这种系数；转向由 `s`、加减速由 `r` |
| "转向在第 131–138 帧" | ★ **改名**：转向是 `s` 段（8 帧），起始帧 = `$D`+10（C3 时 ≈140） |
| "`609(0,0,0,128,300,…)` = 前 300 帧竖直" | ★ **作废**：那是哨兵占位段 |
