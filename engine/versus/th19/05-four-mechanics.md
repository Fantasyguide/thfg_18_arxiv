## 1. 蓄力攻击：5 个阈值 ↔ 4 个阶段

### 1.1 Manual 怎么说

04 §8：长按 CHARGE 把槽**蓄到当前最大值**；槽量决定阶段 ——
**フェーズ１** チャージアタック発動（**ゲージ消費無し**）／**フェーズ２** チャージスキル発動（消费・内容因角色而异）／
**フェーズ３** EXスペシャルアタック（消费・**每用一次等级上升**）／**フェーズ４** ボスアタック（消费・同上）。

### 1.2 代码在哪

蓄力阶段判定全在 `AuraCtrlInf` 的每帧函数 **`FUN_004e79e0`（`0x4e79e0`）** 的「释放」分支里（`AuraCtrlInf+0xcc` = 记录指针，`[record+0x2c]` = `S`）：

| 步 | 指令地址 | 内容 |
| --- | --- | --- |
| 蓄力中判定 | `0x4e7a7b` | `cmp [AuraCtrl+0x2c], 1 / jge 0x4e7c12`：`+0x2c >= 1` 才涨槽；否则只推 `FUN_004026c0(&AuraCtrl+0x28)`（暖机插值）`0x4e7a89` |
| 涨槽 | `0x4e7cc4` `0x4e7d29` | `charge < clamp(S+0x24)` 时 `FUN_00407b40(rate)`；`rate = clamp(S+0x88,0,200)*10/100` |
| 释放分支 | `0x4e7abb`–`0x4e7ac0` | `if (AuraCtrl+0x18 > 0)` 进释放判定（`+0x18` = 本次蓄力计时） |
| 阈值顺序 | `0x4e7af8` `0x4e80f8` `0x4e810d` `0x4e7adc` | 逐级 `clamp(S+0x34/0x30/0x2c/0x28, 0, 2500)`，与 `charge` 比较 |
| 段位音效 | `0x4e7d4c` `0x4e7e0f` `0x4e7ed2` `0x4e7f95` | 跨段时发 anm 事件 `0xb / 0x10 / 9 / 8`（对应 S+0x34/0x30/0x2c/0x28） |

**阶段 1（チャージアタック）** — 释放分支尾部，无条件执行（`0x4e841c` 比较 `charge >= clamp(S+0x28)`，`0x4e843b` 虚调）：

```asm
0x004e841c  cmp [ebx+0x94], eax        ; charge vs clamp(S+0x28)
0x004e8422  jl  0x4e843e
0x004e842a  mov eax,[edx+0x38]         ; ExtraAttackInf
0x004e842d  mov ecx,[eax+0x18]         ; EX<角色>Inf（角色专属额外攻击本体）
0x004e843b  call dword ptr [esi+0xc]   ; 槽 3 = チャージアタック本体（arg = player+0x68c）
```
- `EXReimuInf`（vftable `0x5a8a18`）槽 3 = **`0x53b110`**（把参数位置写进 `+0x9c..+0xa4`）。
- **不碰 `S+0x24`** ⇒ 与 Manual「ゲージ消費無し」一致 ✅。

**阶段 2（チャージスキル）** — 条件 `charge >= clamp(S+0x2c)` 且 `0x4e82f6` 的虛调返回 0：

```asm
0x004e82e8  mov esi,[record+0x38]      ; ExtraAttackInf
0x004e82f1  mov ecx,[esi+0x18]         ; EX<角色>Inf
0x004e82f6  call dword ptr [eax+0x10]  ; 槽 4 = 该角色的チャージスキル本体
0x004e82f9  test eax,eax
0x004e82fb  jne 0x4e83e8               ; 非 0 → 只做阶段1
```

- `EXReimuInf` 槽 4 = **`0x53af60`**：就地 `FUN_004d6b50(0x7b8,4)` 建 **`EXReigekiInf`** 并挂链，**末尾 `return 0`**（`0x53af60` 尾部）⇒ 返回值是「是否已处理」而非对象。

- 生成：`0x4e83b4 push "Ecl_EtBreakLv2"`（串 `0x5988a4`）→ `0x4e83e3 call 0x50d410`，`ecx = [record+8]`（**自家 EnemyCtrl**，`0x4e83b9`）。

**阶段 3（EXスペシャルアタック）** — 入口标签 `0x4e811d`（两条路都汇到这）：

**阶段 4（ボスアタック）** — 条件 `charge >= clamp(S+0x34)` 且槽 9 返回 0：
- **バリア回复 `0x4e7b8d`** → `FUN_0050e7d0`（`0x4e7b9b`）。
- 消费：`0x4e7bab`/`0x4e7bbb`/`0x4e7bc5`（`FUN_0040b3e0(S, S+0x34 − S+0x28)`）。

**生成块（一手）**：`0x40b300`（`0x4e7bdf`/`0x4e829b`/`0x4e838b`）先清 21 dword，再写
`+0x00..+0x07` = 玩家坐标、`+0x0c` = 0、`+0x10` = 0、**`+0x14` = `0xa`**（按 03 §3.4 = HP 三连，ECL 侧可能再改写）、`+0x50` = 0（`0x4e83bc`–`0x4e83dc`）。

## 2. 除霊オーラ与**沈静化**

### 2.1 Manual 怎么说

04 §7：オーラ触碰的敌人/敌弹**变慢**并**掉霊力道具**；对 ピュア霊/動物霊 施加 → **沈静化**（留在原地、耐久骤降、一定时间后**自然成仏**）。

### 2.2 敌弹侧（✅）

- 每帧在弹更新 **`FUN_004f5130`（`0x4f5130`）** 里做 aura 判定：`0x4f520d call 0x4e78e0`（ecx = `AuraCtrlInf`，arg = 弹坐标 `+0x650`）。
  `FUN_004e78e0`（`0x4e78e0`）→ 角色オーラ槽 7（`+0x1c`，Reimu = `0x416f10`：`dx²+dy² < (aura+0x9c)² + extra²`）。
- 进 aura 后：`FUN_004f5379` 起把弹状态 `*(int*)(bullet+0x1044) = 3`（`0x4f53xx`），并改 anm 状态。
- 「变慢」的同源写法在灵侧是「速度系数置 0.5」（见下）。

### 2.3 灵侧：**沈静化**（🟡）

**发现**：灵/動物霊（`EnemyInf+0x1230` 内嵌子对象）的每帧函数 **`FUN_00509030`（`0x509030`）** 里做 aura 判定，
返回 `-2` 时进入沈静化分支：

```asm
; FUN_00509030 内：iVar5 = *(record+0x18) = AuraCtrlInf；piVar1 = AuraCtrl+0x8c = 角色オーラ本体
;                 iVar5 = (*piVar1)->vft[7](point, 半径)   ← 与 §2.2 的槽 7 同一个「点在不在オーラ内」判定
0x0050916c  jle 0x509193       ; iVar5 > 0 → 减速分支
0x0050916e  mov [esi+0x2f8],0x3f000000 ; =EnemyInf+0x1528 ← 0.5f
0x00509178  mov [esi+0x0c4],0x3f000000 ; =EnemyInf+0x12F4 ← 0.5f
0x00509188  mov [esi+0x10c],eax        ; =EnemyInf+0x133C ← 同上（“遅くなり”）
0x00509193  cmp eax,-2 ; jne 0x50921f  ; 只有 -2 才是沈静化
0x005091a2  test [esi+0x5170],0x80080  ; 已沈静化(bit19)/bit7 → 跳过
0x005091ae  test [esi+0x5170],0x700000 ; 必须是動物霊 kind≠0
0x005091c8  call 0x402650              ; FUN_00402650(&EnemyInf+0x14FC, 0) ← 停住
0x005091ee  call 0x56bf30              ; ECL 子程序 "GhostPureOrinDisable"（串 0x599a14）
0x00509213  or   [esi+0x5170],0x80000  ; ★ 沈静化フラグ
```

**结论**：
- **沈静化フラグ = `EnemyInf+0x63A0` bit19（`0x80000`）** —— 写点 `0x509213`；读点见 `FUN_00509980` 里对 `@ORIN2`（`S+0x9c`）的判定：`(flags & 0x700000)!=0 && (flags & 0x80000)` 的灵会被 `S+0x9c != 0` 的一侧**跳过不打**（与能力文「沈静化した霊に当たらない」逐字对应）✅。
- **停在原地 = `0x5091c8`** 把运动组 `EnemyInf+0x14FC` 归零，并跑 ECL 子程序 `GhostPureOrinDisable`（串 `0x599a14`）——**耐久骤降/自然成仏很可能就在这个子程序里（脚本侧）** ❓。
- **减速 = `0x50916e`–`0x50918e`**：`EnemyInf+0x1528 / +0x12F4 / +0x133C = 0.5f`（🟡 三字段语义未逐个命名）。

**触发条件的意外发现（🟡，需 gameplay 复核）**：`-2` 这个返回值在 v1.10c 里**只有 `AuraOrinInf` 的槽 7（`0x41ca40`）会返回**
（`0x41ca40` 内 `return 0xfffffffe`）；其余 18 个角色オーラ的槽 7 都是 bool（如 Reimu `0x416f10`、共用 `0x418690`）。
⇒ **代码层面「沈静化」只有 Orin 的除霊オーラ会发动**（Manual 的表述读起来像所有角色都能沈静化）。
两者不一致的可能解释：Orin 的オーラ是「沈静化オーラ」的专属实现，其他角色只有减速+掉道具；**待实跑复核**。

**ピュア霊（ghost 对象）侧的「自然成仏」**（✅）：`FUN_0051b480`（`0x51b480`）里
`FUN_004026c0(ghost)` 推进计时后判 `ghost+0x28 <= ghost+0x38`（寿命计数 vs 阈值）；到期就 `switch(ghost+0x20)`
调 `FUN_0050d410("GhostWolf"/"GhostOtterR"/"GhostOtterL"/"GhostEagle")`（`0x51b59c`/`0x51b60b`/`0x51b616`/`0x51b67d`）——
即「成仏 = 变成動物霊被送出去」，见 §4。ghost 被 aura 沈静化时改的是哪个字段 ❓。
