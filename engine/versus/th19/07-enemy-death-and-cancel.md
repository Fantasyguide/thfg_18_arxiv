## 1. anm 槽系统：`manager + 0x64c0780`（0..0x3f）

**一手**：TH19 把**已加载的 anm 文件**放在一张**按槽号索引**的表里，槽号 **0..0x3f**（0x40 个）。

| 函数 | 作用 | 一手 |
| --- | --- | --- |
| `FUN_004ce900(id, path)` | **装**：分配 0x240 字节对象 → 写 `manager+0x64c0780 + id*4` → 调 `FUN_004ceb00(path)` 载文件 | `0x4ce900`（505 B）|
| `FUN_004ce870(id, name)` | **装 + 等**：已装则直接返回；否则 `FUN_004ce900` 并等 `[obj+0x22c]`（异步加载标志）落 0 | `0x4ce870`（144 B）|
| `FUN_004049a0(manager, id)` | **取**：`return *(manager+0x64c0780 + id*4)` | `0x4049a0` |
| `FUN_004049c0(obj)` | **取**（用对象自己的 `+0x1c` 当槽号）：`return *(DAT_005d19bc+0x64c0780 + *(obj+0x1c)*4)` | `0x4049c0` |

## 2. ECL 死亡指令族 `0x82`–`0x89`（`FUN_004fecc0` 的大 switch 内）

## 3. 消弹原语：`FUN_004ee770` / `FUN_004ee880`

**一手**（`0x4ee770`，266 B）：

```c

do {
  if (local_8 == 0) { FUN_0040e070(); return 0; }
  if ((*(int*)(local_8+0x1044) == 2 || == 1) && /* 弹类型 ∈ {1,2} */
```

## 6. 补（2026-10-05 第二轮）：起 VM 的原语与「负脚本号」分支

### 6.1 `FUN_004cb960` 的参数序（一手 `0x4cb960`，615 B）

```
__thiscall FUN_004cb960(this = anm 对象, out_vm, script_id, pos, …, flags, …)
```

- **`this`（ecx）= anm 对象**（槽表里某个已加载的 anm）；
- **第 3 个显式参数 = 脚本号**。死亡处理里的调用点逐字是：
  `FUN_0050d380(enemy+0x6330)`（取 anm，返回值走 ecx）→
  `FUN_004cb960(&local_c, extraout_ECX, *(enemy+0x632c), pfVar1, local_8, 0xffffffff, 0, 0)`（`0x50c1f0` 内）
  ⇒ **(anm = `effect.anm`，script = `enemy+0x632c`)** 与 §4 一致。

### 6.2 ★ 死亡 VM 有「负脚本号 ⇒ 不起」的分支

同一处外层是 **`if (-1 < *(int *)(param_1 + 0x632c))`** ⇒ 脚本号 **< 0 时整台 VM 都不起**。
⇒ 「敌人被击破时的画面」**不一定**来自这台 VM —— 有一部分敌人（负号档）根本没有它。
（这一点很重要：owner 要的那个圈若在**所有**击破时都出现，那它的来源就在**别的**调用点上。）

### 6.3 消弹的落地：`FUN_004eeb30`（一手 `0x4eeb30`，617 B）

```c
FUN_004eeb30(bullet, param_2):
    ...
    puVar1 = FUN_0040a490(local_3c, "bullet", *(...+0x690), bullet + 0x650, 0, 0xffffffff, 0);
    ...
    if (*(int *)(bullet + 0x698) == 1) { … FUN_0040dd20/FUN_0040dd00/FUN_004080e0(); }
    if (*(int *)(bullet + 0x698) == 2) { … FUN_00506940(local_44, 4, &local_78, 0); }
```

- **`FUN_0040a490`（`0x40a490`，46 B）= 通用生成器**：`{ FUN_004cb960(param_2, param_1, param_4, …); return param_2; }`
  ⇒ 就是 `FUN_004cb960` 的**带名字/带 out 参数**的包装；
- 消弹时**逐颗弹**起一个特效（名字参数 `"bullet"`）；`bullet+0x698` ∈ {1,2} 决定走哪条落地分支；

## 9. ★★★ 颜色的字节序：anm 的 `color()` 是 **B,G,R**（BGRA 内存序）

owner 2026-10-05 指出「ZUN 写的代码不是 RGB 吧」—— **成立**，且本仓早有记载：

> `engine/player/th15/01-graze-and-item-slowdown.md`：**D3DCOLOR 在内存里是 BGRA 字节序**
> （`+0x564`=B、`+0x565`=G、`+0x566`=R、`+0x567`=A）；那篇还带一条**因漏读该字节序而把颜色读错**的勘误。

佐证（跨版本）：thtk 的 ECL 编译器在落盘颜色字面量时做**整字反转**——
`thecl/ecsscan.c`：`(c&0xFF000000)>>24 | (c&0xFF0000)>>8 | (c&0xFF00)<<8 | (c&0xFF)<<24`
⇒ 与「文件里是小端 ARGB（字节 `[B,G,R,A]`）」一致。

⇒ **anm 里 `color(a,b,c)` = `B=a, G=b, R=c`** ⇒ **真实可见色 = RGB(c, b, a)（反读）**。

**三条候选的真实颜色**（此前我按 RGB 读，全反了）：

| script | 文件里的 `color` / `color2` | ★ 真实 RGB（反读）|
| :-: | --- | --- |
| 271 | `(192,192,64)` / `(112,112,32)` | `(64,192,192)` **青** / `(32,112,112)` 暗青 |
| 272 | `(192,224,192)` / `(32,112,32)` | `(192,224,192)` / `(32,112,32)` —— 绿 |
| **273** | `(255,64,64)` / `(255,112,32)` | **`(64,64,255)` 蓝 / `(32,112,255)` 蓝** |

⇒ **减法（`blendMode(2)`）下蓝色被减掉，剩下的正是暖色/褐** ⇒ owner 口径的
「**外黑边 / 中褐 / 芯透**」由此而来 ⇒ **本卡取 `script273`**（`script271` 另见 §8：全库无人引用，是死数据）。

### 9.1 ★ `color` / `color2` 的**内外归属**（由 owner 实跑钉死）

**`color` = 外（圆周）、`color2` = 内（圆心）**。

依据（owner 2026-10-05 的观察）：卡侧曾写成
`color(112,112,32) + alpha(1)` / `color2(192,192,64) + alpha2(224)`，
owner 看到的是「**外面透明、内部实心，反了**」⇒ **α≈0 的那一端在圆周** ⇒ `color` 在外 ✓。
（本仓 2026-09-13 那份 404/405 配方里记的「`color` 是内端」是**反的**，按本条更正。）

⇒ 于是「**外实内透**」= `script273` **原样**，**不需要对调**：

| 端 | 字段 | 文件值 | 真实色（BGRA 反读）| alpha | 减法结果 |
| --- | --- | --- | --- | :-: | --- |
| **外** | `color` | `(255,64,64)` | `RGB(64,64,255)` 蓝 | **224** | 减得最狠 ⇒ **黑边** |
| 中段 | 插值 | — | 蓝 | 中 | 部分减 ⇒ **褐** |
| **内** | `color2` | `(255,112,32)` | `RGB(32,112,255)` 蓝 | **1** | 几乎不减 ⇒ **透** |

⇒ 本卡最终脚本 = `enemy.anm` `script273` **逐字**，仅去掉 `jmp(offset156,0)` 的呼吸循环。

### 10.1 半径的求值链与 **mode 5** 的曲线（2026-10-05 核死）

| 步 | 一手 | 内容 |

| 建插值 | `0x51cc70` → **`FUN_004044b0`**（`0x4044b0`，119 B）| `t[0xf]=时长`、`t[0x10]=模式`；from/to 存 `t[0..3]`（矢量，x/y 各一对）；`t[10]=0xffffffff` |
