## 0. 一句话

Manual 的「击破動物霊后返还，**返还时还可能变为角色特有的 EX 攻击**」在代码里是：

**每侧在比赛开始时按角色建一个 `EX<角色>Inf` 对象**（构造表 `0x5a0320`）→ 它的 **vtable slot 11 是各角色自己的「何时发动」**（Ran 阈值 60 帧、Orin 阈值 10 帧…）→
到点调**基类 slot 11 = `FUN_0050d640`** → 登记进 per-side 结构并调 **slot 5 = `FUN_0050d8a0`** ⇒ 在**对手侧**生成 `"ExtraAttack"` 敌人。

⇒ **不是 rand**：是「按角色的计时器/计数阈值 + 你何时满足它」（时序/击破位置决定观感随机）。

| 谁调 `FUN_0050e150` | `FUN_00548df0` 的 `0x548f85`（`FUN_00548df0(param)`，param = 0/1）|
| 谁调 `FUN_00548df0` | `FUN_00516f00` 的 `0x518614`（ecx=0）与 `0x518626`（ecx=1）——**比赛初始化**，两侧各一次 |

## 2. 发动链（✅ 一手）

**各角色自己的 slot 11**（示例，均为一手）：

| 类 | slot 11 实现 | 阈值（同一函数内 `cmpl`）|
| --- | --- | --- |
| `EXRanInf` | `FUN_00419c00`（`0x419c00`，1066 B）| `cmpl $0x3c,0x8c(%esi)` → **60** |
| `EXOrinInf` | `FUN_0041d1b0`（`0x41d1b0`，891 B）| `cmpl $0xa,0x8c(%esi)` → **10** |
| （基类）| `FUN_0050d640`（`0x50d640`，172 B）= `ExtraAttackCharaBaseInf` slot 11 | — |

```
; 角色 slot 11 里（以 Ran 为例，0x419fd5 附近）：
lea 0x88(%esi),%ecx ; 计时器组（+0x88 subframe / +0x8c frames）
call 0x4026c0       ; 推进计时
cmpl $0x3c,0x8c(%esi)
jle  skip
... 复位 4 个槽结构（+0x04/+0x08/+0x0c/+0x10）...
mov %esi,%ecx
call 0x50d640       ; ★ 基类 slot 11 = 发动
```

```
; FUN_0050d640（0x50d640，基类 slot 11）—— ★ 2026-10-05 读全，语义修正如下：
;   idx = *(this+0x84)（槽索引 0..3，越界夹到 3）
;   若 this+0x74[idx] 非空 ⇒ idx+1（夹 3）
;   node = *(this+0x64)（★「当前节点」指针）；node == 0 ⇒ 清槽 return 0
;   do {
;     this+0x74[idx] = node[1]                      ; 槽里存节点的 +4 字段
;     done = (**(code **)(*(int *)*node + 8))()     ; ★ 问「节点内对象」的 vtable 槽 2 = 完成了吗
;     if (done) {
;        if (*(int *)(*node + 0x54) == 0) {          ; 首次完成才登记
;            base = (&DAT_005d1a98)[side * 0xf];
;            for (p = base+0x44; p != base+0x1d4; ++p)   ; ★ 修正：范围 = +0x44..+0x1d4
;                if (*p == 0) { *p = *(int *)(base+0x40); break; }   ;   即 0x190 字节 = 100 个 int（不是「四槽」）
;        }
;        (**(code **)(*(int *)*node + 0x14))()       ; ★ 调「节点内对象」槽 5 = 发动
;     }
;     node = this+0x74[idx]                          ; 下一个节点
;   } while (node != 0)
;
; ⇒ 「+0x74..+0x83 = 4 个槽 + +0x84 索引 + +0x64 当前节点」= 一条**队列/环**；
;   真正干活的是**各节点内对象的槽 2（完成？）/ 槽 5（发动）** —— 而 EX<角色>Inf 的槽 5 = FUN_0050d8a0 ⇒ EX 就是经这条队列发动的 ✓
```

```
; slot 5 = FUN_0050d8a0（0x50d8a0）：
if ((*(uint *)(DAT_005d1a54+0x140) & 0x80000) == 0) {
    FUN_0040b300();                                  // 清 spawn block
    local_58 = *(undefined8 *)(param_1+6);           // 位置
    local_44 = 200;                                  // block+0x14 = 200
    *(int *)(DAT_005d19bc + 0x710) = 1 - param_1[0x33];   // ★ 切到对手侧
    FUN_0050d410("ExtraAttack", &local_58);          // ★ 在对手侧生成 ExtraAttack
    (**(code **)(*param_1 + 0x44))(3);               // 再调 slot 17(3)
}
```

⇒ **「返还 → EX」= 这套 EX 对象到点发动**：`FUN_0050d8a0` 就是 Manual 说的「角色特有的 EX 攻击」的生成点（ECL 子程序名 = `plNN.ecl` 的
`ExtraAttack` / `ExtraAttack00`；另有 `"ExAttack"` 系由 `FUN_00418a80` / `FUN_0041b2e0` / `FUN_0041cf10` 生成，那是角色自身 EX 招式的另一路）。

## 3. 谁在「每帧」调 slot 11（✅ 一手）

* **持有者对象**：`FUN_0050e150`（`0x50e150`）里建好该角色的 EX 对象后 **`mov %eax,0x18(%edi)`**（`0x50e3ae`）⇒ **`持有者+0x18` = 该角色的 `EX<角色>Inf`**。
* **持有者的每帧方法 `FUN_0050df40`（`0x50df40`）**：

```
eax = DAT_005d19bc
edx = *(this + 0x1f4)              ; ★ 持有者带的 side
*(eax + 0x710) = edx               ; ★ 把「当前生成侧」设成它（同一全局，slot 5 里会把它改成 1-side）
ecx = *(this + 0x18)               ; ★ EX 对象
eax = *ecx ; call *0x2c(%eax)      ; ★★ slot 11 = 各角色的「何时发动」
...
ecx = *(this + 0x20) ; 若 > 0x64 / 0x64 以下各有分支（-> FUN_0050e820 等）
```
* **持有者怎么建**：`FUN_0050e5a0`（`0x50e5a0`，315 B）：`new` 出持有者后
  `+0x8 / +0xc / +0x14` 各挂一个子对象、**`+0x1f4 = 参数(0/1) = side`**、`+0x1f8` = 另值、`*(子对象+0x38) = 持有者`。
* ⇒ 即：**每侧一个持有者 → 持有者每帧把「当前侧」摆好 → 调该侧角色的 EX slot 11（阈值判定）→ 到点走基类 slot 11 → slot 5 在对手侧生成 `ExtraAttack`**。
* ★ **`FUN_0050de30` / `FUN_0050df40` 是被「绑定成回调」注册到持有者的**（不是普通 vtable）：
  `FUN_0050e5a0` 里对这些方法做 `push $0x50de30` / `push $0x50dda0` / `push $0x50dd30`（`0x50e5b8`、`0x50e2c1`、`0x50e2df` …）+ `call 0x4d5a60` / `0x4d5c70` / `0x4d5bb0`
  （= 成员函数/闭包绑定器），结果分别挂到 `持有者+0x8 / +0xc / +0x14`。
  ⇒ **`FUN_0050df40`（slot 11 派发 + 摆「当前侧」）就是这三个回调之一**，由容器在触发时调用；因此全 exe 里找不到 `call 0x50df40`
  也找不到它的 .rdata 表项（地址是 `push imm32` 现场绑的）——这解释了前两轮的两个「找不到调用者」。

## 4. 与「霊 / 動物霊」的接点（🟡）

* 已确认：領域会把灵换成 `GhostPure2G`（唯一带 `ins_1040(1)` 的一档，见 [`05-four-mechanics.md`](05-four-mechanics.md) §2.3b）；
  `ins_1040` 的 `FUN_0040f0e0()` 只是把 `DAT_005d1bd8+0xbc+side*4`（该侧活幽灵计数）**加一**，bit24 让销毁时减回去（`0x50aa67`）——**它不是 EX 的挂钩**。
* ✅ **本轮定案（门 bit19 从不被写）**：对字段 `DAT_005d1a54+0x140` 做过两轮全 exe 扫描（dword 的 `or/and/mov` 写 + **字节写 `0x142(%…)` 专扫**），
  只找到写 **bit2 / bit3 / bit4 / bit6 / bit7 / bit18 / bit24 / bit25** 的点与若干 `andl` 清位，**没有任何一处设或清 bit19**（`0x142(%…)` 更是 0 命中）
  ⇒ `FUN_0050d8a0` 的那道门（`(flags & 0x80000) == 0`）在 TH19 里**恒为真** ⇒ **它不是「一次性」机制** ✗（「一次性」语义只能来自按角色计时阈值 + `0x5d1a98[15*side]` 的 4 槽/索引 `+0x84` 记账）✓
* ★★ **本轮找到 EX 的「发射方法」**：**`FUN_0050e820`（`0x50e820`，79 B）** ——
  `++(*(持有者+0x1f8 → +0x2c) + 0x4c)`（**上限 999**）→ `ecx = *(持有者+0x18)`（= EX 对象）→ **`call *0x14(%eax)` = slot 5 = `FUN_0050d8a0`** ⇒ 对手侧生成 `"ExtraAttack"` ✓。
  它的调用者全在**领域／子弹侧**：`FUN_004e79e0`（`0x4e79e0`，3363 B，紧邻领域判定 `FUN_004e78e0`）、`FUN_004f77a0`（`0x4f77a0`）、`FUN_004f7b90`（`0x4f7b90`）✓
  ⇒ **EX 由「领域/子弹交互」触发，不是从灵死亡那条链、也不走 `+0x64`** ✓（这解释了上一轮「基类 slot 11 像 no-op」的矛盾：**主路径根本不经过它**）。
* ★ **触发条件是「计数到阈值」（一手，本轮）**：`FUN_004f77a0` / `FUN_004f7b90` 是**状态机**（状态 `param_1+4`，0/1/3/4…），在两个 case 里：
  `case 0`：`iVar3 = FUN_0040ea20()`；**`299 < iVar3` ⇒ 发射**；`case 1`：**`199 < iVar3`**（另一支是 **`0x95`(149)**）**且** `(**(code**)(**(int**)(DAT_005d1ad4 + 0x18) + 0x24))() == 0` ⇒ 发射。
  发射前都做 `FUN_0040e9e0(...)` + 把状态/`param_1+8` 复位（另一支还 `FUN_0040b2c0(2)`）⇒ **EX = 阈值型事件（300/200/150 分档）**，不是随机 ✓。
* ★★ **这两个状态机的身份（RTTI 一手）**：`FUN_004f77a0` = **`CPUStage6StoryInf` slot 1**、`FUN_004f7b90` = **`CPUStage5StoryInf` slot 1**
  ⇒ 这两处 EX 发射 = **CPU（story 模式对手）自己按阈值发动 EX**（149/200/300 分档）✓ —— 即 **EX 不只是「返还奖励」，CPU 也会自己用** ✓。
  `FUN_0050d8a0` 则确认是 `ExtraAttackCharaBaseInf` **与全部 `EX<角色>Inf` 的槽 5** ✓。
* ★★ **玩家/对战侧的 EX 触发路径（本轮，一手）**：`FUN_004e79e0`（`0x4e79e0`）里那段构造 **ECL 名字符串**（如 `"Ecl_EtBreakLv4"`）、
  维护一个 **0..3 的等级计数器 `DAT_0062b254`**、并按 `*(int *)(param_1 + 0xcc)` 那侧的数据选分支；在某个状态下 -> `FUN_0040b420()` →（可选音效）→ **`FUN_0050e820()` 发 EX** ✓。
  ⇒ 它是一台**「攻击/等级状态机」**，而它的**唯一调用者 = `0x4e7867`（即 `FUN_004e78e0`，引擎文档 §2.2 记的领域槽 7 判定）** ✓
  ⇒ **领域 → 攻击等级机 → EX** 这条链成立 ✓（即「EX 何时来」由领域驱动的等级机状态决定，不是概率、也不是击杀瞬间 ✓）。
* 另一条路 `FUN_004e79e0`（领域侧，**很可能是玩家侧/对战侧的 EX 触发**）：`*(char *)(*(int *)(*(int *)(param_1+0xcc) + 0x2c) + 0xb9) != 0` ∧ `FUN_0040b5d0() < FUN_0040b590()` ⇒ `FUN_00537b90(...)` 之后直接 `FUN_0050e820()` ✓（与上面那支不同的触发链）。
* `FUN_0050e820` 自己还会把 `*(持有者+0x1f8 → +0x2c) + 0x4c` **+1 并封顶 999** ✓（另有一个「发射次数/冷却」类计数）。
* ★ **`CPUStage*StoryInf` 的对象布局与共享全局（一手，本轮）**：构造器 `FUN_004f76e0`（`0x4f76e0`，176 B）写
  `+4 := 0`（状态）、`+8 := 0`（**EX 触发计数**，命中阈值后清零 ✓）、`(%ecx) := 0x5a846c`（vftable），并挂上全局块 **`0x62b250`** ✓；
  槽 1 的头部把状态夹在 `[0, 1000]` 再 switch ✓，触发时 `FUN_0040e9e0(x)` = `*(x+4) += 1`（推进状态）✓。
  ★★ **`0x62b250/0x62b254` 正是 `FUN_004e79e0`（攻击等级机）用的那个 0..3 等级块** ⇒ **CPU 的 stage AI 与「攻击等级机」共享同一全局状态** ✓（这解释了 story CPU 为何能按等级/时机发 EX）。
* 🟡 **还没读到**：a) `+8` 这个 EX 触发计数的**累加者**（stage ECL？全局 tick？）；b) `FUN_0040ea20()` 计的是什么（领域吸弹数？阶段帧数？）与那个 vtable 门（`DAT_005d1ad4+0x18` 的槽 9）的语义；b) `EX<角色>Inf+0x8c` 是 `FUN_004026c0`（通用计时器累加器）在 slot 11 里推进的（每被调一次加一帧）⇒
  「从何时开始有效」取决于**谁在什么状态下调 `FUN_0050df40`**（持有者的每帧方法；本轮没找到它的调用者，是 vtable 派发）；
  ② `FUN_0050d640` 里的 `this+0x64`：区域扫描（`0x50d000`–`0x50f400`）里**唯一的写点是 `0x50eb72`**，位于构造器 **`FUN_0050eac0`（`0x50eac0`，562 B）**
  —— 它先把 `+0x28..+0x70` 归零，再做 `+0x58=+0x50`、`+0x5c=+0x54`、`+0x60=+0x58`、`+0x64=+0x5c`、`+0x68=+0x60`、`+0x6c=+0x64`、`+0x70=+0x68`、`+0x74=+0x6c`、`+0x78=+0x70`、`+0x7c=+0x74` 的**连锁初始化**

## 4. 设计取法（给复刻用）

* 想要「返还时可能变成 EX」的观感：**按角色给一个阈值/计时器**（Ran 60 帧、Orin 10 帧是该作的实参），到点调一次 EX 生成（对手侧 `ExtraAttack`）。
* 想「不是 rand」：这套结构本身就是确定性的——随机感来自「什么时候满足阈值」。
