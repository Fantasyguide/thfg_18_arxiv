# TH18 自机「瞬移 / 隙间」（原生卡 41 WARP）—— 状态块、16 帧动画与钳位旁路

> **版本**：TH18 v1.00a（`th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th14:0x…`。
> **方法**：一手反汇编（`objdump -d -M intel`）+ 原生卡目录 [`engine/card/th18/08-catalog.md`](../../card/th18/08-catalog.md) §A 的 card 41 条目 +
> ExpHP 结构 [th-re-data](../../../local/vendor/th-re-data/)（`zPlayer`）+ 三条独立数值互证（量纲见 §4）。
> **可信度**：指令级 ✅；「单位 = 1/128 px」是三条数值互推的 🟡（见 §4）。
> **归属**：引擎知识。想复刻「穿墙」的卡（例：TH11 花映塚/地灵殿系统卡里霊夢×八雲紫的隙间）**直接调 `0x409a60` 即可**，见 §5。

## 0. 一句话结论

**TH18 原生就有一套「受控越界 + 换边」机制**：卡 41 WARP（`CardYukari`）按下 C 键时，若自机**已经被 x 钳位顶在左右边缘上**（`|x| > 0x5bff`，见 §4 与 §5）且正按着**朝那一侧**的方向键，
就调 `0x409a60(player, dir)` 把 `player+0x4779c` 的方向位置 1；引擎随后跑一段 **16 帧**动画（子机收起 → 位移 → **在第 8 帧换边** → 子机展开），
动画期间**左右钳位被旁路**（`0x45b725` / `0x45b195` 两处 `test [player+0x4779c],0x180`）。

⇒ **「穿墙」不是要自己写位移**，是调用原生那一对「设方向 / 清方向」的入口。

## 1. 状态块（`zPlayer` 上的一小段，ExpHP 结构里没有名字）

`player+0x4779c` 是一个 **dword 位域**；瞬移用它的一段，另外几位是别的机制在用（别混）：

| 位 | 偏移 | 谁用 | 语义 |
| --- | --- | --- | --- |
| bit1 `0x2` | `+0x4779c` | `0x416cda` 置 / `0x416d5a` 清 | 子机收起中（商店开场前 `0x416cd0` 也置它；`0x45b8e4` 用 `+0x477e8` 数帧）|
| bit2 `0x4` | `+0x4779c` | `0x420808` / `0x4208e3` | 未命名（`AUDIT` 未追）|
| bit3 `0x8` | `+0x4779c` | 只被 `0x45d3ab` 读 | 静音中弹音效（全 exe 无置位点）|
| bit4 `0x10` | `+0x4779c` | `0x45b47c` / `0x45cde2` / `0x45c72f` | 命中半径 ×`player+0x4797c`×3.6（DDC 残留，无置位点）|
| bit5 `0x20` | `+0x4779c` | `0x42e017` / `0x42e020` / `0x45c690` | 未命名 |
| bit7 `0x80` | `+0x4779c` | `0x409a60` 写 / `0x45b725`、`0x45b195` 读 | ★ **瞬移方向 1（自左向右）** |
| bit8 `0x100` | `+0x4779c` | 同上 | ★ **瞬移方向 2（自右向左）** |
| bit9 `0x200` | `+0x4779c` | `0x45ea17` 置 / `0x40c80a` 读 | 未命名（射击侧）|

瞬移自己还有 5 个字段（都在 `+0x477a0`–`+0x477b4`，引擎每帧在 `0x45b170` 里推）：

| 偏移 | 类型 | 语义（一手）|
| --- | --- | --- |
| `+0x477a0` | int | 上一帧的步数（`0x45b1ef`：`= [player+0x477a4]`；`0x409a60` 初值 `−1`）|
| `+0x477a4` | int | ★ **动画步数（0→0x10）**，步到 `0x10` 收尾；每帧由 `+0x477a8` 的浮点累加器 `cvttss2si` 得来 |
| `+0x477a8` | float | 步数累加器（`0x45b207`/`0x45b222`）|
| `+0x477ac` | int | 副计数器（`≥1` 就清 0；`0x45b1cb`）|
| `+0x477b0` | dword | bit0 = 瞬移已初始化（`0x409a63`–`0x409a7a`；置位时顺手把 `+0x477ac` 清 0）|
| `+0x477b4` | int | 与瞬移无关（`0x40c82d` / `0x40ca81` 写，值 `0x400`）|

## 2. 入口：`0x409a60(player /*ecx*/, dir /*[ebp+8]*/)`（`ret 4`）

```
409a63: mov eax,[ecx+0x477b0] ; test al,1 ; jne 409a80
409a6d: or eax,1 ; mov [ecx+0x477ac],0 ; mov [ecx+0x477b0],eax   ; 首次：置初始化位 + 清副计数器
409a80: mov eax,[ebp+0x8] ; shl eax,7                            ; dir 1 → 0x80、dir 2 → 0x100、dir 0 → 0（= 清）
409a86: mov [ecx+0x477a4],0 ; mov [ecx+0x477a8],0                ; 步数与累加器归零
409a9a: mov [ecx+0x477a0],0xffffffff                             ; 上一帧步数 = −1
409aa4: xor eax,[ecx+0x4779c] ; and eax,0x180 ; xor eax,[ecx+0x4779c] ; mov [ecx+0x4779c],eax
                                                                 ; ↑ 只改 bit7/bit8，其余位原样
409abb: shr eax,7 ; and eax,3 ; ret                              ; 返回 dir
```

**`dir = 0` 就是「清方向位」**（`shl 0` ⇒ 掩码 `~0x180` 清干净）——所以收尾也走同一个函数，
不需要另找一个「关掉瞬移」的 API。

## 3. 动画：`0x45b170`（`Player` 的每帧状态机之一）

| 帧 | 做什么 | 证据 |
| --- | --- | --- |
| 步 0（`[+0x477a4]==0`）| `call 0x416cd0` = **收起子机**（与商店开场前同一个函数；它也置 `+0x4779c` bit1）| `0x45b1a5`–`0x45b1ae` |
| 每帧 | 步数 `+0x477a4` 由 `+0x477a8` 累加器推进；`+0x477a0` 存上一帧步数 | `0x45b1e9`–`0x45b22a` |
| 步 1 | 播音效：方向 1 → `0x51`；方向 2 → `0x50`（`call 0x476be0(player, id)`）| `0x45b247`–`0x45b24a`、`0x45b26f`–`0x45b272` |
| **步 8** | ★ **换边**：方向 1 → `edx = 0xc000`；方向 2 → `edx = 0xffff4000`（= −0xc000）<br>然后 `call 0x45a600(player, edx?)` + `call 0x45a660(player)` | `0x45b25e`–`0x45b29f` |
| 步 <0x10 | 每帧把方向位对应的位移常量塞进 `[esp+8]`（方向 1 → `0xffffff00`、方向 2 → `0x100`）| `0x45b255`、`0x45b27d` |
| **步 ≥0x10** | `call 0x416d50`（= 展开子机，与 `0x416cd0` 配对）→ `call 0x409a60(player, 0)`（清方向位）| `0x45b2a4`–`0x45b2b8` |

⇒ **瞬移全程 16 帧、在第 8 帧换边、两侧各有一次子机收起/展开**。动画期间自机自己还能动（钳位只对 x 生效、被旁路）。

## 4. 钳位旁路与量纲（`0x45b725`、`0x45b195`）

同一条 `Player` 每帧里，位置累加器是 `player+0x62c`（x）/ `+0x630`（y），单位是**定点**：

```
45b705: add ecx,[edi+0x62c] ; mov [edi+0x62c],ecx      ; x += int(velocity.x)
45b725: test DWORD [edi+0x4779c],0x180 ; jne 45b7f6     ; ★ 方向位已设 ⇒ 跳过左右钳位
45b735: cmp ecx,0xffffa400 ; jl  → x = 0xffffa400       ; 左界 −0x5c00
45b7ad: cmp ecx,0x5c00     ; jg  → x = 0x5c00           ; 右界 +0x5c00
45b7c4: cmp edx,0x1000     ; jl  → y = 0x1000           ; 上界（**不受方向位影响**）
45b7df: cmp edx,0xd800     ; jg  → y = 0xd800           ; 下界
```

**单位 = 1/128 px** 🟡（三条独立数值互推，都对得上同一个尺度）：

| 量 | 原值 | ÷128 | 物理解释 |
| --- | --- | --- | --- |
| 左右钳位 `±0x5c00` | 23552 | **±184 px** | 游玩区半宽（384 宽 − 左右各 8 px 边距）|
| 卡 41 的门槛 = **顶到钳位** `0x5bff` | 23551 | **≈184 px** | 区间判定的写法（`lea +0x5bff` / `cmp 0xb7fe` / `jbe 退出`）语义是「**\|x\| ≤ 0x5bff 就退出**」⇒ 只有**已被钳在 ±0x5c00** 才放行（★ 2026-09-15 订正：旧稿把它读成 `0x4800`／144 px，是错的）|
| 换边位移 `0xc000` | 49152 | **384 px** | = 整个游玩区宽 ⇒ 正好换到另一侧 |
| 上钳位 `0x1000` | 4096 | 32 px | 游玩区上边距 |
| 下钳位 `0xd800` | 55296 | 432 px | 游玩区下边（448 高 − 16）|

⚠ **未实测**：三条比值自洽，但没有实跑量过 `player+0x62c` 的像素值 ⇒ 标 🟡。

## 5. 卡 41 WARP 自己的门（`0x40a1b0` = `c_press`）

```
40a1b6: test [player+0x4779c],0x180 ; jne 退出       ; 已在瞬移中 ⇒ 什么也不做
40a1c2: edx = [player+0x62c]                          ; 自机 x（定点）
40a1c8: eax = edx + 0x5bff ; cmp eax,0xb7fe ; jbe 退出 ; |edx| ≤ 0x5bff ⇒ 还没顶到边缘，退出（★ 区间判定：只有 |x| > 0x5bff，即已被钳在 ±0x5c00，才往下走）
40a1d5: if (edx < 0) { if (!(INPUT & 0x40)) 退出; call 0x409a60(player,1); return 1; }   ; 左半 + 左键
40a1ef: if (edx > 0) { if (!(INPUT & 0x80)) 退出; call 0x409a60(player,2); return 2; }   ; 右半 + 右键
```
（`INPUT` = `0x4ca428`；`c_press` 由 `Player__on_tick__body` `0x45c048` 按 C 键位 `0x400` 调用，返回值被丢弃。）

`__on_tick_2`（`0x40a180`）只做一件事：`[card+0x50] = (player+0x4779c & 0x180) ? (…|0x20) : (…&~0x20)`
——即把「正在瞬移」映射成主动卡的 `is_firing` 配色位。

⇒ **复刻要点**：换成我们自己的触发条件（例如双击方向键）之后，**效果侧一行都不用写**，
只需 `0x409a60(CE_PLAYER(), dir)`。§2 的 `dir=0` 由引擎自己在第 16 帧调，卡侧不必管。

## 6. 还缺什么 / 没验的

- ❓ `player+0x4779c` bit2/bit5/bit9 的语义（本表列了使用点，没读语义）。
- ❓ `0x45a600` / `0x45a660` 两个函数的名字与完备语义（本文只按调用点与参数推断「施加换边位移 / 刷新位置缓存」）。
- 🟡 1/128 px 的单位换算（三条互证，未实测）。
- ❓ 换边时 y 是否被夹（读数上 y 在 `0x45b7c4` 仍被夹，但换边那一帧在夹之前还是之后未逐帧核对）。

## 7. 订正记录

- ★ **2026-09-15**：本文 §0/§4/§5 原把卡 41 的贴边门槛读成 `0x4800`（≈144 px、「距边缘 40 px 内」）——
  **错**。`th18:0x40a1c8` 的 `lea eax,[edx+0x5bff]` + `cmp eax,0xb7fe` + `jbe 0x40a207`（退出）
