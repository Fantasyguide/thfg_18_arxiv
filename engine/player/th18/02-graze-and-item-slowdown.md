# th18 擦弹与「道具减速因子」—— TH15 的 LoLK 机制只剩一个死因子

> **版本**：TH18 v1.00a（`th18.exe`，md5 `9969cac756098c1da05a81de45437a70`，imagebase `0x400000`）。
> 本文裸地址默认属该版本；引用其他版本须写成 `th15:0x…`。
> **方法**：一手反汇编 + pyghidra 反编译 + ExpHP `th-re-data`（`zItemManager` 字段名）。
> **可信度**：字段与物理 ✅；「TH18 从不写 0.3」✅（全 exe 字面量扫描）。

## 0. 一句话结论

TH18 的 `Player__do_graze` `0x45e160` 比 TH15 少一半：只加两个计数 + 放一团火花 + 响一声，
**不加 PIV、不弹浮字、不碰道具**。而 TH15 用来做「擦弹让掉落物变慢」的那个因子
**还在**——`zItemManager` 里那个被 ExpHP 命名为 `lolk_item_slowdown_factor` 的 float
（`ITEM_MANAGER+0xe6bb14`），引擎每帧照旧把它乘进道具位移、照旧每帧 +0.1 恢复，
**但 TH18 里没有任何代码写它**（恒为 1.0）。写 0.3 就复活 TH15 的减速。

## 1. 擦弹落点 `Player__do_graze` `0x45e160` ✅

```
0x4ccd0c++  (GRAZE，clamp 99999999)
0x4ccd10++  (GRAZE_IN_CHAPTER，同样 clamp；死字段，见 chapter/th18/01 §2)
火花位置 = (弹坐标 + 自机坐标) * 0.5        ; 常量 0x4b9138 = 0.5f
AnmManager 分配 VM → copy_vm(脚本 0x18)     ; = 24，与 TH15 th15:0x457456 同号
vm+0x14e |= 0x1000                          ; 加法混合标志
SoundManager__play_sound_at_position(0x2a)  ; 与 TH15 同一个音效
```

与 TH15 的差别（[`../th15/01 §1`](../th15/01-graze-and-item-slowdown.md)）：
TH15 还额外 `CURRENT_PIV += 100`、弹擦弹数浮字、置道具减速因子 0.3 —— **TH18 三样都没有**。
**同一个 anm 脚本号（0x18）与同一个音效 id（0x2a）**，是「同一套代码被阉割」的直接旁证。

调用点：子弹 `0x42497a`（`FUN_004248a0`，判擦弹后置 `bullet+0x20 |= 4`）、
敌人本体 `0x42f69a`、三种激光 `0x44ab35` / `0x44cfef` / `0x44fa53`。

## 1b. 擦弹判定：两种模式 + 「每颗弹只擦一次」 ✅

判定函数有**两个**，子弹按自己的 `flags` 选（分派器 `0x4248a0`：`& 0x2` 才碰、`& 0x10` 走圆、
`& 0x40` 先按 `bullet+0xf38` 缩放半径）：

| 模式 | 条件 | 边距常量 | TH15 对应 |
| --- | --- | --- | --- |
| **圆形**（`flags & 0x10`） | `d² < (r + max(br/2.5, 40.0))² + br²` | `0x4b921c`=2.5、`0x4b92c4`=**40.0** | `th15:0x455d00`（`th15:0x4cff28`=2.5、`th15:0x4cffb8`=40.0） |
| **矩形**（其余） | 弹中心 vs 自机判定框外扩 24.0 | `0x4b92a4`=24.0 | `th15:0x455be0`（`th15:0x4cffa0`=24.0） |

- 自机判定圆半径 `player+0x4799c`（非聚焦）/ `+0x479a0`（聚焦）＝原生 **3.0**；
  矩形半宽高 `player+0x479a4`/`+0x479a8` ＝原生 **1.5**。
- **「额外圈」= 圆形模式的 40 px 边距**（圆弹 br≈4–8 → 有效擦弹半径 ≈ 43–50 px）。
  两作常量逐项相同，**不是 TH15 独有**。
- `flags & 0x10` 时若自机带 `inner.flags & 0x10`（DDC 残留的 player_scale 门，原生无人置位）
  还会再乘 `player_scale × 3.6` —— 见 [`_shared/version-residuals.md`](../../_shared/version-residuals.md)。

**同一颗弹能擦几次**：TH15 有 per-bullet 计时器 `bullet+0x1464`（擦后置 30 帧，`idiv` 余数门，
`th15:0x419cc5`）→ 能反复擦；TH18 擦后 `or [esi+0x20],4`（`0x424984`），
下次直接跳过（`0x42496f`）→ **一生一次**。

→ 想「框内有弹就一直慢」，必须每帧自己判框（本 mod 绀珠传卡 `cards/lolk.c`：
扫 2000 槽弹池，按子弹自己的模式判）。

## 2. 道具减速因子 `ITEM_MANAGER+0xe6bb14` ✅（残骸）

`ITEM_MANAGER_PTR` = `0x4cf2ec`。`zItemManager` 字段（ExpHP + 一手核对）：

| 偏移 | 字段 |
| --- | --- |
| `+0x14` | `normal_items[0x258]`（stride `0xc94`） |
| `+0xe6baf4` / `+0xe6bb04` | 两条 freelist 头 |
| **`+0xe6bb14`** | **`lolk_item_slowdown_factor`（float）** |
| `+0xe6bb18` | `num_items_onscreen` |

**物理（`0x445bf4`–`0x445c7d`，state == 1「飘落」分支）**：

```
pos += vel * GAME_SPEED(0x4ccbf0 = 1.0) * factor
vy  += GAME_SPEED * 0.03(0x4b90a4) * factor      ; 只有重力增量乘因子
```

**恢复与重置**：

| 处 | 地址 | 动作 |
| --- | --- | --- |
| 每帧尾（槽循环跑完后） | `0x446807`–`0x446821` | `if (factor < 1.0) factor += 0.1`（`0x4b90d8`，上限 `0x4b9178`） |
| ItemManager 重置 | `0x42ab27` | `factor = 1.0` |

**关键负结论**：全 exe 里 `e6bb14` 只出现 6 次（1 写 1.0、3 读、恢复处 1 读 1 写），
**没有任何地方写 0.3**（字面量 `0x3e99999a` 全 exe 两处都不在 ItemManager 上）。
→ TH18 原生**从不减速道具**；TH15 的「擦弹置 0.3」那一半被删掉了，只留下因子与恢复。

**只作用于飘落态**：state 2（上抛）与 state 3/4（吸引）的位移不乘这个因子。

| 奖励存活 / 耐久 / 超时 | `+0x78` bit1 / bit3 / bit7 | 0/1 |
| 当前攻击是否符卡 | `enemy+0x6238`（`life.is_spell`） | 0/1（ECL 522/568 切换） |

**符卡结束的下降沿是统一信号**（收卡 / 超时 / 被中断都会清 bit0），
道中 boss（`st01–06mbs`）没有符卡，只有非符段 —— 想切「非符 + 符卡」的波次，
就用这个下降沿当边界（[`chapter/th18/01`](../../chapter/th18/01-chapter-residuals.md) §4）。

## 4. 复刻注意

1. **写入时机要固定**（擦弹那一帧 / 固定 tick 槽）：道具物理不用 RNG，只要时机固定，replay 不失同步。
2b. **卡侧谁在读它**（2026-09-10）：`CE_ITEM_SLOWDOWN`（engine.h）= 同一地址。绀珠传卡（115）
   每帧写 0.3 复活 TH15 的减速；季节卡（116）的季节点是**自建 VM**，所以它每帧读这个因子、
   只在**飘落态**把位移与重力增量乘上去（吸引/真空飞行不乘 —— 与原生 state 3/4 同）。
   ⚠️ TH16 的同名因子（`itemmgr+0xe4b974`）**也从不被写 0.3**（`0x418597` 写 1.0、`0x4300ab` 是 +0.1 恢复），
   所以 TH16 的季节点本来就不减速 —— 这条只在同时装了绀珠传卡时才有区别。
   🟡 时序：两张卡都在 `on_tick_2`（AbilityManager 优先级 0x16）里跑，卡链表的先后决定我们读到的是
   本帧的 0.3 还是「上一帧 +0.1 恢复后」的值（差 0.1，只影响减速开始的那一帧）。要完全对齐就把
   季节点物理挪到 `on_item_frame`（`0x446ee3`，在道具池 body 前），暂未做。
2. **别改恢复常量**（`0x4b90d8` / `0x4b9178`）——那是全局副作用；想要更长的减速窗口就每帧重写因子。
3. **改过逻辑的 replay 换回原版必然失同步**（道具轨迹变了）——这是所有改玩法的 mod 的通病。
