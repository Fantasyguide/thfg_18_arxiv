# TH18 自机中弹判定链与「中弹无伤」闸门 —— TH13 灵界闸门 `th13:0x444ca6` 在 TH18 的落点

> **版本**：TH18 v1.00a（`th18.exe`，md5 `9969cac756098c1da05a81de45437a70`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th13:0x…`。
> **方法**：Capstone 5.0.7 线性反汇编（带 resync，全 `.text` 204073 条指令的操作数穷举）+ pyghidra headless 反编译 + ExpHP `th-re-data` 命名/结构体。
> **可信度**：链与早退分支 ✅（逐条指令 + 穷举调用者）；「无原生免费闸门」✅（命中链区间绝对操作数穷举）；mod 落点 🟡（只做静态验证，未实跑）。
> **写给**：卡 113（TH13 灵界复刻）的「中弹无伤」立项，见 [`HANDOVER-113.md`](../../../mods/th18.v1.00a/card-expand/HANDOVER-113.md) §3.5。

## 0. 一句话 + 直接答案

> **TH18 的「on_hit 体」= `Player__die` `0x45d3a0`（同一个函数里就做完音效 2 + 特效 VM `0x1d` + 状态 4 + 无敌 6 帧）；
> TH13 那条闸门 `th13:0x444ca6` 的**同一语义槽位就是 `0x45d3a0` 的函数入口**，但 TH18 在这一点上**没有任何闸门** ——
> 那是空的。要「灵界期间中弹无伤」，必须自己往 `0x45d3a0` 的入口插一个站点（§6 (a)）。**

### 0.1 跨版槽位对照（一手，两侧都读过指令）

| 语义槽位 | TH13（`th13.exe`）| TH18（本文默认版本）| 可信度 |
| --- | --- | --- | --- |
| 子弹 × 自机判定（含状态/无敌早退）| `th13:0x443fd0` 等四份（四角色各一）| `0x45cc20` AABB / `0x45cd90` 圆 / `0x45cea0` 激光 OBB | ✅ |
| 命中后「on_hit 体」：音效 + 特效 + 状态 4 + 无敌 6 | `th13:0x444ca0` | `0x45d3a0` | ✅ |
| ★ **中弹无伤闸门** | `th13:0x444ca6`（`test dword [0x4be830],0x100`，非 0 即跳函数尾）| **不存在** —— 要自己插在 `0x45d3a0` 入口 | ✅ 负结论 |
| 真正扣命（+ 记死亡数）| `th13:0x444a10` 的 `dec [0x4be7f4]` | `0x45d090` 的 `0x45d19b`/`0x45d38b` | ✅ |

### 0.2 三条结论先摆出来

1. **判定函数有三个**（不是 TH13 的「每角色一份」）：`0x45cc20`（AABB，子弹矩形模式）、
   `0x45cd90`（圆，子弹圆模式 + 敌本体）、`0x45cea0`（OBB，三种激光 + 敌本体）。
   三者都以 **同一个返回值协议** 收尾：**1 = 击中 / 2 = 擦弹 / 0 = 无事**。✅
2. **擦弹与击中不共用循环，而是由返回值「互斥二选一」**：判定函数内部先判命中盒（→ 返回 1），
   不中才去判外扩的擦弹盒（→ 返回 2）；调用侧再按 `cmp eax,1` / `cmp eax,2` 分流。
   分流点逐条地址见 §1.2。✅
3. **miss 计数不在 `Player__die` 里**，它在 8 帧之后的 `Player__commit_death_and_enter_state2` `0x45d090`。
   ⇒ 只要在 `0x45d3a0` 入口早退，**音效、特效、状态 4、无敌、决死窗口、救援广播、扣命、记 miss 会一起被跳过**（§3）。✅

## 1. 全链：三条来源 × 自机判定 → `Player__die`

### 1.1 调用图（`.text` 全量 `E8`/`E9` 扫描 + 全文件 dword 扫描，见 §7）

| 来源 | 入口（调用者）| 判定函数 | 命中体 |
| --- | --- | --- | --- |
| 子弹（矩形模式）| `Bullet__on_tick` `0x423e10`：`0x423ff9` / `0x424612` | `0x45cc20` | `0x45cd27` → `0x45d3a0` |
| 子弹（圆模式）| 同上：`0x42494b` | `0x45cd90` | `0x45ce81` → `0x45d3a0` |
| 敌本体（圆）| `EnemyData__step_game_logic` `0x42ed40`：`0x42f580` | `0x45cd90` | 同上 |
| 敌本体（OBB）| 同上：`0x42f667` | `0x45cea0` | `0x45d060` → `0x45d3a0` |
| 激光 line / infinite / curve | `0x44a950` / `0x44ce80` / `0x44f920` | `0x45cea0` | 同上 |

调用侧还有一层调度：`BulletManager__on_tick__body` `0x424c50` 按 `bullet+0xf68` 状态字决定
走「可致死」还是「只擦弹」（`0x424d9f push 1` → `0x424da3 call 0x4248a0`，第 3 参 = 1 = 只擦弹）。🟡 状态字语义未解，见 §7。

**发现**：`0x45d3a0` 全 exe 只有 3 处 `call`（`0x45cd27` / `0x45ce81` / `0x45d060`），
**无 `jmp` 型尾调、无任何数据表引用** ⇒ 这三处就是它的全部入口集合，且全部来自中弹判定链。
**结论**：在 `0x45d3a0` 入口下闸，**不会误伤任何非中弹路径**。✅（TH18 v1.00a）

### 1.2 ★ 分流点：擦弹与击中是怎么分开的

**它们不共用一段循环，也不共用一次比较**：每个判定函数内部是「先判命中盒，命中就 `return 1`；
不命中才继续判外扩的擦弹盒，命中就 `return 2`」。分流 = 命中盒那条比较指令。

| 判定函数 | 命中盒判据（分流指令）| hit 分支入口 | graze 分支入口 | 调用侧分流 |
| --- | --- | --- | --- | --- |
| `0x45cc20` AABB | `0x45ccc2`–`0x45cced` 四条 `ja 0x45cd37` | `0x45ccef` | `0x45cd37` → `0x45cd74` | `0x424952 cmp edi,1` |
| `0x45cd90` 圆 | `0x45ce0e comiss` / `0x45ce11 jb 0x45ce40` | `0x45ce40` | `0x45ce13` → `0x45ce58` | `0x424952 cmp edi,1` |
| `0x45cea0` 激光 OBB | `0x45d014`/`0x45d019`/`0x45d021`/`0x45d026` 四条 `ja 0x45d074` | `0x45d028` | `0x45d074` | `0x44aa5e cmp eax,1` |
| 敌本体（圆）| 同 `0x45cd90` | 同 | 同 | `0x42f678 cmp eax,2` |
| 激光 infinite | 同 `0x45cea0` | 同 | 同 | `0x44cf18 cmp eax,1` |
| 激光 curve | 同 `0x45cea0` | 同 | 同 | `0x44f9e9 cmp eax,1` |

- **① 发现**：`0x45ce11 jb 0x45ce40` 之后 `0x45ce40` 起是「命中盒成立」那半段；
  `0x45ce13`–`0x45ce36` 是擦弹盒（`max(40, br/2.5)` 边距）那半段，`0x45ce58 mov eax,2`。
  两条路互斥：命中盒成立时根本不执行擦弹盒的比较。
- **② 推测**：这是「一颗弹一帧内最多给一种结果」的设计，避免同时记擦弹 + 判死。
- **③ 验证**：调用侧的 `0x424952 cmp edi,1; jne 0x424966` 与 `0x424966 cmp edi,2; jne 0x424abd`
  证实返回值只有 1/2 两条出口；`0x45e160`（`Player__do_graze`）只在 ret==2 时被调（`0x42497a`）。✅
- **④ 结论**：**分流点 = 上表第三列那几条比较指令**；**擦弹在「命中盒成立」的那一帧本来就不会发生**（返回值已经把这条路切掉）。
  ⇒ 任何落在 **hit 分支之内**（含 `0x45d3a0` 入口）的闸门，**都不能「顺手」跳掉本帧的擦弹**，
  因为本帧的擦弹决定在分流那一刻就已经是「否」了。✅（TH18 v1.00a）
- **⑤ 证据**：`0x45ce0e`/`0x45ce11`/`0x45ce40`/`0x45ce58`、`0x45ccc2`–`0x45cd74`、`0x45d014`–`0x45d083`、
  `0x424952`/`0x424966`/`0x42497a`、`0x44aa5e`/`0x44aaac`/`0x44ab35`、`0x42f66c`/`0x42f678`/`0x42f69a`。

> **擦弹本身不在这些判定函数里落账**：`0x45e160`（`Player__do_graze`）只做「`GRAZE++` + 火花 anm `0x18` + 音效 `0x2a`」，
> 见 [`02-graze-and-item-slowdown.md`](02-graze-and-item-slowdown.md) §1。擦弹的**判定**（外扩盒）确实在这三个函数里，
> **但落账**在 `0x45e160`；两条链只通过返回值 2 相连。⇒ 在 hit 分支下闸，`0x45e160` 一次也不会被影响。✅

### 1.3 三个判定函数的逐条 early-out

**`0x45cc20`（AABB，stdcall 3 参，`ret 0xc`）** —— 门在本函数内的顺序：

| 地址 | 条件 | 结果 |
| --- | --- | --- |
| `0x45ccc2`–`0x45cced` | 四个轴都不重叠（玩家盒外）| 转擦弹盒 `0x45cd37` |
| `0x45ccf6` / `0x45ccff` | `GUI_PTR->msg != 0`（对话中）| `0x45cd7f` **返回 0**（不判）|
| `0x45cd05` | 第 3 参 `!= 0`（只擦弹模式）| `0x45cd74` 返回 2 |
| `0x45cd10` / `0x45cd15` / `0x45cd1a` | `player+0x476ac ∈ {2,4,3}` | `0x45cd7f` 返回 0 |
| `0x45cd23` | `player+0x47778 > 0`（无敌）| 跳过调用，`0x45cd2c` 返回 1 |
| `0x45cd27` | 以上全过 | `call 0x45d3a0`，`0x45cd2c` 返回 1 |

**`0x45cd90`（圆，stdcall 2 参，`ret 8`）**：判据 `dist² < 玩家半径² + 弹半径²`（不是 `(a+b)²`）。

| 地址 | 条件 | 结果 |

**顺带（调用侧的门）**：`0x4248cf test cl,2`（`bullet+0x20 & 2` 才判）、`0x4248e9 comiss;jbe 0x424abd`

  扣命与死亡计数 **在 `0x45d090`**，而 `0x45d090` 全 exe 只有 1 个调用点 `0x45c135`（在 `0x45be90` 的 case 4 里）。
- **② 推测**：`0x45d3a0` 早退 ⇒ 状态永远不进 4 ⇒ case 4 永不执行 ⇒ `0x45d090` 永不被调 ⇒ 扣命与死亡计数自动落空。
- **③ 验证**：`0x45c135` 位于 `0x45be90` 的 `case 4` 分支与 `0x45c114` 的卡广播之后（见
  [`01-position-and-state-timers.md`](01-position-and-state-timers.md) §3 的状态机）；`CURRENT_LIVES` 的写点穷举（§7）
  只有 `0x45d19b`–`0x45d1a3` 一处是减法，其余是关卡初始化赋值。
- **④ 结论**：**在最前面 return 就能把「音效 + 特效 + 状态 + 无敌 + 决死窗口 + 救援广播 + 扣命 + 记 miss」一次全跳过**，
  不需要逐点处理。✅（TH18 v1.00a）
- **⑤ 证据**：§3 表内全部地址；`0x45c135` 的唯一性来自全 `.text` `E8` 扫描（§7）。

> **两条与任务书不一致的一手更正**：
> ① TH13 的闸门指令是 **`test dword ptr [th13:0x4be830], 0x100`**（`th13:0x444ca4` 起 10 字节
> `f7 05 30 e8 4b 00 00 01 00 00`），**不是** `test byte ptr …,0x100` —— 后者在 x86 里不可编码
> （`F6 /0` 的立即数只有 8 位，`0x100` 会被截成 0）。任务书里的 `th13:0x444ca6` 是这条指令的
> **操作数 `0x4be830` 所在的字节**（指令本身起于 `th13:0x444ca4`），两个地址指同一条闸门。
> ② **TH13 的 `Player::on_hit` 里没有「记 miss」**：`th13:0x444ca0`–`th13:0x444de7` 全体只有
> 音效 2（`th13:0x444ccc`）、特效 `0x19`（`th13:0x444cf3`）、符卡奖励分处理、状态 4（`th13:0x444d75`）、
> 无敌 6（`th13:0x444db4`）与两次 anm 调用。⇒ 「on_hit 记 miss」这条 🟡 **待复核**，`0x45d3a0` 早退是否够，
> 要看 miss 到底记在哪（本文的「一起跳过」结论不依赖它，因为 `0x45d090` 的死亡计数也在下游）。

### 3.1 ★ 「入口早退 ⇒ 一个字节都不发生」的写点对账（一手，可复跑）

§3 的「一起跳过」不靠推理，靠**写点唯一性**：

## 4. `th13:0x444ca6` 的 TH18 对应点 —— 直接答案

> **部分对应：语义槽位找到了（= `Player__die` `0x45d3a0` 的函数入口），但 TH18 在那个槽位上没有闸门。**

- **① 发现**：TH13 的闸门是 `th13:0x444ca4` 的 6 字节 `test dword [th13:0x4be830],0x100` +
  `th13:0x444cae jne th13:0x444de4`（跳到函数尾），即「on_hit 体的第一件事」。
  TH18 的 on_hit 体 `0x45d3a0` 的对应位置是 `0x45d3ab`，那里的指令是
  `test byte ptr [edi+0x4779c], 8` —— 它只门控**音效**（`0x45d3b7`），**不门控 miss / 扣命 / 状态**。
- **② 推测**：TH18 把「灵界」整套机制换成了卡牌系统，所以没有全局的 `GAME_FLAGS & 0x100` 等价物。
- **③ 验证**：命中链区间 `0x45cc20`–`0x45d588` 的**绝对操作数穷举**（§6）显示，
  该区间读的全局只有 `0x4cf410`（PLAYER）、`0x4cf2e0`（GUI，判对话）、`0x4cf2b8`（BOMB）、
  `0x4cf2c0`（SPELLCARD）、`0x4cf298`（ABILITY_MGR）、`0x4cf2c8`（ANM_MGR）与几个死亡计数 ——
  **没有任何「游戏状态 / 暂停 / 演示 / 练习」类标志**被读。TH13 的 `GAME_FLAGS` 对应物 `0x4cccc8`
  在这个区间里**一次都没出现**（它全 exe 有 65 处引用，全在别处）。
- **④ 结论**：**TH18 没有现成闸门；`0x45d3a0` 的入口就是我们要插站点的地方**。
  插进去以后，**这一点的行为与 TH13 闸门等效**：判定函数仍然返回 1（和 TH13 的 `th13:0x4440a5`
  先 `call on_hit` 再 `mov eax,1` 一样），只是 on_hit 体被整段跳过。✅（TH18 v1.00a）
- **⑤ 证据**：`0x45d3a0`/`0x45d3ab`/`0x45d3b7`、`th13:0x444ca4`/`th13:0x444cae`、§6 的区间操作数穷举表。

### 4.1 顺带：原版灵界**会吃弹**

- **① 发现**：TH13 判定函数在命中时返回 1（`th13:0x4440a5` `call th13:0x444ca0` 之后紧接
  `th13:0x4440aa mov eax,1`），且返回值的用法与 TH18 逐条同形：
  TH13 `th13:0x40dcfd cmp eax,1` → `th13:0x40dd0c mov eax,3` + `th13:0x40dd17 mov word [ebx+0xbbe],ax`（弹状态 → 3）；
  TH18 `0x424952 cmp edi,1` → `0x4249be mov eax,3` + `0x4249c8 mov word [esi+0xf68],ax`。
- **② 推测**：两作的「命中 → 弹状态置 3」是同一套代码的跨版本搬运。
- **③ 验证**：两侧的弹状态字段名不同（TH13 `+0xbbe` / TH18 `+0xf68`，都是 **word**），
  状态转移调用不同（`th13:0x4126b0` / `0x412f20`），但**常量 3 与「先写状态字再调转移函数」的顺序完全一致**。
- **④ 结论**：TH13 闸门跳的是 on_hit 体、**不是**判定函数的返回值 ⇒
  **原版灵界期间撞到判定点的弹会被消掉（吃弹）**，擦弹照常。✅（TH13 v1.00c；TH18 侧为 🟡 同形推断）
- **⑤ 证据**：`th13:0x4440a5`/`th13:0x4440aa`/`th13:0x4440b4`、`th13:0x40dcfd`–`th13:0x40dd1e`、
  `0x424952`/`0x4249be`/`0x4249c8`。⇒ **若「复刻」要含吃弹，落点必须选 §6(a) 而不是 §6(c)。**

## 5. 有没有现成的「免费闸门」

> **没有。** TH18 不存在一个「本帧/本状态不判定中弹」的全局标志或恒 0 判定位可以直接借用。
> 但**我们也不需要它**：thcrap 断点回调跑在 DLL 自己的代码里，闩锁放在 DLL 的数据段即可（§6）。

## 6. mod 侧落点候选

### (a) ★ 推荐：`0x45d3a0` 入口插一个站点（6 字节）

| 项 | 内容 |
| --- | --- |
| 站点地址 | `0x45d3a0` |
| 覆盖字节 | `55 8b ec 83 ec 14`（6 字节；`push ebp` / `mov ebp,esp` / `sub esp,0x14`）|
| 相对寻址 | **无**（≥5 字节硬门满足）|
| 闩锁 | DLL 自己的 `volatile` 全局（断点回调在 DLL 里跑，不需要引擎字段）|
| 落闸动作 | 回调里判 `latch != 0` ⇒ 返回 0，并把 `regs->retaddr` 改成 `0x45d584`（该函数唯一的 `c3`）|
| 放行动作 | 返回 1（原 6 字节照常执行）|

**为什么可行**：① 站点在**分流之后**（见 §1.2：这一帧的擦弹已经被返回值 1 排除了，闸门不可能顺手跳掉擦弹）；
② 站点在**判定函数之外、`Player__die` 之内**，覆盖子弹 / 敌本体 / 三种激光**全部**命中路径（§1.1）；
③ `0x45d3a0` 只有 3 个调用者且全部来自中弹判定链（§1.5），**没有旁路会被误伤**；
④ 站点在函数序言，此刻栈上只有调用者的返回地址 ⇒ 跳到 `0x45d584` 的裸 `c3` **栈完全干净**；
⑤ 与 TH13 闸门的行为对齐：判定函数仍返回 1 ⇒ **弹照样被吃掉**（§4.1），擦弹照常。

**风险**：
1. 站点盖住函数序言：**返回 1 那条路必须原样执行这 6 字节**（thcrap 的 `expected` 匹配 + 原指令回放），
   `sub esp,0x14` 无重定位问题，但 `expected` 一旦写错，thcrap 是「记日志然后跳过」（静默失效）—— 必须进 `sites.py` 的校验。
2. 闸门一开，`0x45d3a0` 尾部的**卡虚表 `+0x10` 广播（`0x45d574`）也一起被跳过** ⇒ 灵界期间不会再有卡收到「即将死亡」事件。
   这对 113 是想要的（灵界期间不该再触发救援链），但**「灵界结束补死」那条路必须先落闸再调 `Player__die`**，否则补死会被自己的闸门挡掉。
3. 灵界期间撞弹的弹会被消掉（= TH13 行为）。若用户口径是「灵界不吞弹」，改用 (c)。
4. 站点是新的全局（非 per-card），多张卡同时想用要各自带闩锁；113 只需一张，暂不冲突。

**怎么静态验证**：① 反查 `0x45d3a0` 的调用者只有 3 处、无 `jmp`、无数据表引用（本文 §7 已做，可复跑）；
② 站点 6 字节无反/相对寻址 + `expected` 与 `th18.exe` 逐字节相符（`sites.py check`）；
③ `0x45d584` 的字节是 `c3`，且是 `0x45d3a0` **唯一的 `ret`**（`0x45d3a0`–`0x45d585` 区间内只有这一条），
前面紧接它自己的 `pop edi; pop esi; pop ebx; mov esp,ebp; pop ebp`；
④ 实跑：断点日志在灵界内每帧能看到命中、灵界外不命中；A♠ 的 `ce_invuln_*` 对账仍全绿。

> **本仓已实装**（2026-09-13，`BP_ce_player_die`）：站点 / 覆盖字节 / 跳转靶与本表逐字节一致，
> 声明层 `ce_no_hit_declare()`（`mods/th18.v1.00a/card-expand/native/`）。语义依据与写点对账见 §3.1。

### (c) 备选：三处「命中分支入口」各插一个站点（7 字节）→ 强制返回 0

| 站点 | 字节 | 返回 0 时的跳转靶 |
| --- | --- | --- |
| `0x45ccef`（AABB）| `a1 e0 f2 4c 00 85 c0` | `0x45cd7f`（`xor eax,eax` + `ret 0xc`）|
| `0x45ce40`（圆）| `a1 e0 f2 4c 00 85 c0` | `0x45ce38`（`xor eax,eax` + `ret 8`）|
| `0x45d028`（激光 OBB）| `a1 e0 f2 4c 00 85 c0` | `0x45d083`（`xor eax,eax` + `ret 0xc`）|

**为什么可行**：三处都在**分流之后**（进到「命中盒成立」那半段）、在 `GUI msg` / 状态 / 无敌三个检查**之前**；
三处字节**完全一致**（都是 `mov eax,[0x4cf2e0]; test eax,eax`），`expected` 可以共用一份常量；
返回 0 = 「这一帧没撞」，弹**穿过去**、不消弹。
**风险**：① 与 TH13 不同（§4.1：原版灵界吃弹）⇒ 这是**行为差异，不是复刻**；
② 3 个站点是 1 个站点的三倍出错面；
③ `0x45cea0` 的跳转靶 `0x45d083` 会 `pop esi` / `pop ebx`，必须确认站点处的 prologue 已经压过这两个寄存器（`0x45cea0` 在 `0x45cec6`/`0x45cea0` 已 `push`，站点在 `0x45d028` ⇒ 成立 ✅）。
**怎么静态验证**：站点字节与 `expected` 逐字节比对；跳转靶首指令必须是 `xor eax,eax`；
实跑判据 = 灵界中弹后**弹仍在场上**且不扣命、不播音效、擦弹计数照涨。

## 7. 反证面：我扫了什么，什么没查实

### 7.1 扫过的面（可复跑）

| 面 | 手法 | 结果 |
| --- | --- | --- |
| 调用者完备性 | 全 `.text` 扫 `E8`（call rel32）与 **`E9`（jmp rel32）** | `0x45d3a0` 只有 3 处 call、**0 处 jmp**；七个关键函数全部只有 call |
| 间接引用 | 全文件搜 7 个函数地址的 little-endian dword（含 `.rdata`/`.data`）| **0 命中** ⇒ 无跳表 / 无 vtable 间接调用 |
| 字段读写的完备性 | 全 `.text` 线性反汇编（204073 条指令，66 处 resync）对 21 个偏移/全局做操作数穷举 | §1.3 / §5.1 / §6(b) 的表全部来自这一遍 |
| 命中链区间的全局 | `0x45cc20`–`0x45d588` 的绝对寻址操作数枚举 | 只有 27 个全局，无任何游戏状态标志（§5.2）|
| 常量语义 | 直接读 `.rdata` 的 float | `0x4b9288`=16.0、`0x4b92a4`=24.0、`0x4b921c`=2.5、`0x4b92c4`=40.0、`0x4b9244`=3.6、`0x4b9138`=0.5 |
| 跨作对照 | TH13 侧同链逐条反汇编 | 槽位表（§0.1）与返回值协议逐条同形 |

**线性反汇编的已知盲点（诚实声明）**：66 处 resync 意味着有 66 个字节位置无法解码（多为数据、`int3` 填充、
或 SSE 前缀被切错）。因此「某偏移只有 N 个读写点」是**近似完备**，不是形式化完备；
落到站点结论上的关键项（`0x45d3a0` 的调用者、`0x47778` 的读点）都另外用**字节模式**复核过。
