> **版本**：TH14 v1.00b（`local/th14.v1.00b/th14.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；
> 引用其他版本写作 `th13:0x……`。
> **方法**：一手平坦反汇编（`objdump -D -b binary -m i386 -M intel`，产物 `local/_scratch/th14_full.asm`）
> + PE 节区 VMA 换算直读原始字节 + **全 exe 4 字节小端穷举 + 指令边界复核**（脚 `local/_scratch/th14_xref.py`）
> + **`call rel32` 全表扫描**（脚 `local/_scratch/th14_calls.py`）+ 逐指令仿真器（线下支闭式）
> + ExpHP 社区符号只取词汇（`local/vendor/th-re-data/data/th14.v1.00b/`）+ 社区攻略交叉（🟡 处注明）。
> **可信度**：载体 / 量纲 / 难度两表 / 涨入口穷举 / 无跌路径 / 蓝点公式 / 一括回収ボーナス = ✅；
> 两个与社区口径差 10× 的读数 = 🟡（§7）；线下支除数 = ✅（÷450，与 TH16/TH17 同魔数互证）。

## 0. 一句话结论

TH14 里「点道具（蓝点）被收时的身价」= HUD 上那个**最大得点**，载体 `0x4f584c`：
**存储 = 显示 ×100**，**显示 = `trunc10(存储/100)`**，上限 `0x4f5854`。

初值/上限按**难度两表**在 **run 初始化**时算出（`0x4d9cb8` / `0x4d9ca0`，显示 `10000` / `{100000,250000,500000,500000,500000}`）。

全 exe 只有**四条**写这条全局的路径（初始化、擦弹 `+1` 显示、绿点、满 P 道具），**一条跌的路径都没有**
（miss / 灵击 / Boss 奖都不碰它，✅ 与社区「今作ではミスによる減少は無い」一致）。

**蓝点（道具 type 2）被收时**：自动回收（或自机在回收线上方）⇒ **显示分 += 最大得点**，无乘数；
线下 ⇒ `trunc10( 0.75 × 最大得点 × (1 − (自机 y − 线)/450) )`（下限 10）。

**第二项**：蓝点**自身**的算式里**没有**加数；但同一条链上另有一项**独立入账**的
**一括回収ボーナス**（按同批回收件数 ×0.5/0.8/1.2/1.6/2.0 乘到该批 Σ 值上），
且**最大得点本身**就是「难度基础值 + 四条加数」的结构（见 §6）。

## 2. 量纲：存储 = 显示 ×100；HUD 取 `trunc10(存储/100)`

| 环节 | 一手 |
| --- | --- |
| 存储 → 显示 | `trunc10(存储/100)`（`0x51eb851f` 魔数 `sar 5` 得 `/100`，再 `idiv 10` 去余数） |
| 显示 → 存储 | `×100`（初始化 `imul ecx,0x64`；加法器 `mulss xmm1, ds:0x4c1b54`，该常量原字节 `0000c842` = **100.0f**） |
| HUD 取值点 | `0x431824`–`0x43185d`（`Gui::on_draw_2d` 函数体内）：算完 `trunc10(PIV/100)` 后 `push ecx` 交给 `0x40bb60` |
| HUD 格式化 | `0x40bb60`（`%d` 及分组格式串 `0x4bd574`/`0x4bd544`/`0x4bd550`），**直接把值印出来，不再乘除** |
| 取值函数 | `0x435620`（`trunc10(PIV/100)`，无栈参数，独立小函数）——**死代码**：`call rel32` 全 exe 命中 **0**，4 字节地址引用也 **0** |
| 难度索引 | `0x4f5834`（ExpHP `DIFFICULTY`），0=E 1=N 2=H 3=L 4=EX 5=PH 残留 |

> ★ 与 TH13 同形：`th13:0x42b450` 那个 `trunc10(PIV/100)` 取值函数**也是死代码**，
> 真正在用的是内联副本（TH14 的内联在 HUD `0x431824` 与道具处理体 `0x4394f5`/`0x439589`）。
> 「有取值函数但没人调」在两作都成立，不要据此否定量纲。

**★ 分数侧量纲（蓝点入账要对得上，必须钉）**：`SCORE` `0x4f5830` 存的是**显示分 / 10**，
显示分 = `SCORE × 10 + [0x4f5838]`（末位单独存）。三条独立证据：

1. HUD 把**两个数**一起交给格式化器：`0x4314d4 push ds:0x4f5838` 与 `0x4314dd push DWORD PTR [ebx+0x140]`（显示分计数器）→ `0x40bc70`；
2. `0x40bc70` 在 `<100` 分支算的是 `arg3 + 10*arg2`（`0x40bc96`–`0x40bca9`，格式 `"%d"`），
   在 `<100000` 分支用 `"%d,%.2d%d"`（`0x4bd544`）把 `arg3` 当**最后一位**拼上去 ⇒ 印出来 = `10*SCORE + 末位`；
3. 存档侧同构：run 初始化把高分的 int32 与**独立字节**分别读进 `0x4f5898` / `0x4f589c`
   （`0x435c68` / `0x435c71`，后者是 `movsx eax,BYTE PTR [...]`）。
   配合上限 `0x3b9ac9ff`（`0x41d5e0` 的 `add_to_score`）＝显示的 10 位上限，与 TH10 的「HUD 10 位、第 10 位单独存 scorefile 字节」同构。

⇒ 于是道具弹窗里印的 `value` **就是**入账的**显示分**（不是内部单位），
`SCORE += value/10` 才自洽。这条是 §5 与 §7 判读的地基。

`add_to_score(x)` = `0x41d5e0`：`SCORE += x/10`，钳 `0x3b9ac9ff`（`x` 为**显示**单位）。

## 3. 初值与上下限：按难度的两张表（✅ 代码 + 原始字节 + 社区三方一致）

初始化在 `0x435caa`–`0x435cef`（`GameThread::thread_start` `0x435ab0` 内的 run 初始化段；
同段 `0x435c95` 把 `SCORE` 清零 ⇒ 这是**整局**初始化，**跨关不清**，所以最大得点会带过下一关）：

```
435caa  edx = ds:0x4f5834            ; DIFFICULTY
435cb0  ecx = [edx*4 + 0x4d9cb8]     ; B[diff]
435cb7  ecx *= 0x64                  ; ×100
435cc1  eax = [edx*4 + 0x4d9ca0]     ; A[diff]
435cd0  eax *= 0x64                  ; ×100
435cdb  ds:0x4f5854 = eax            ; ★ 上限 = A[diff] × 100（存储）
435ce0  ds:0x4f5850 = ecx            ; 同一份初值的第二拷贝
435cea  ds:0x4f584c = (int)(B×100)   ; ★ 身价初值 = B[diff] × 100（存储）
435cf6  ds:0x4f58c8 = [edx*4+0x4d9c88]   ; 第三张表 C[diff]，用途未追 ❓
```

表值（`local/_scratch/pe_tables.py` 直读原始字节）：

## 5. 蓝点（道具 type 2）被收时的分值：逐指令

**入口**：道具 tick 里命中自机收集框后走类型分派 `0x438b3e`–`0x438b4a`
（`eax = [item+0xbf4(类型)] − 1`，跳表 `0x439088`，共 11 项）：
type 1 → `0x4390c0`（P 小）、**type 2 → `0x4394a0`（蓝点）**、type 3 → `0x439300`（大 P）、
type 8 → `0x439220`（满 P）、type 9/10/11 → `0x438b95`/`0x438b9f`（绿点）。
**type 2 = 蓝点**的旁证（跨版本锚）：`th13:0x42ed9c` 那张同类跳表的第 2 项指向 `th13:0x42e9e5`，
而 TH13 读 PIV 的两个站点 `th13:0x42ea1a`/`th13:0x42eaa4` 就在该处理体内 —— 两作同构同号。

**① 分档门（`0x4394a6`–`0x4394ea`）**：

```
4394a6  cmp DWORD PTR ds:0x4f5828,0x1     ; CHARACTER == 1 ?
4394b0/4b5  eax = 0x80(128.0f) / ecx = 0x94(148.0f) ; cmove → 线 = CHARACTER==1 ? 148.0f : 128.0f
4394cf  xmm1 = [PLAYER(0x4db67c) + 0x5e4] ; 自机 y
4394d7  comiss xmm0(线), xmm1 ; jae 0x439582   ; 自机在线上方 ⇒ 满值支
4394e3  cmp [item+0xbf0(状态)], 3 ; je 0x439582 ; 道具已在「自动回收」态 ⇒ 满值支
       否则落 0x4394f0（线下支）
```

**② 满值支（`0x439582`–`0x4395db`）**：

```
4395xx  q = trunc(PIV/100)（0x51eb851f + sar 5）
        value = trunc10(q)                     ; 去个位；若 <= 0 则 10（0x4395be）
4395cf  popup(pos = item+0xbac, value, 色 0xffffff00)   ; 0x457f00 = 十进制数字弹窗（自己拆位）
4395db  sum(0x4f5878) += value ; count(0x4f5880)++   ; 供 §6 的一括回収ボーナス用
4395fd  SCORE(0x4f5830) += value/10（= 显示分 += value），钳 0x3b9ac9ff
439627  inc 0x4f5848                     ; 点道具回收计数
```

⇒ **线上 / 自动回收：入账显示分 = 最大得点 = `trunc10(PIV/100)`，无乘数、无加数** ✅
（社区：[wikiwiki 稼ぎ](https://wikiwiki.jp/thk/%E8%BC%9D/Score)「**自動回収時に最大得点と等しくなり**、
下で回収するとスコアは下がる」——同值同结构。）

**③ 线下支（`0x4394f0`–`0x439580`，逐指令 + 仿真）**：

```
4394f0  q = trunc(PIV/100) ; rem = q % 10（idiv 10）
439518  A = 3*(rem − q) / 4        ; 有符号 /4 的 cdq+and 3+sar 2 惯用形
43952d  n = A * (自机y取整 − 线)     ; ★ 用的是**自机** y，不是道具 y
439530  X = div450(n)              ; mov eax,0x91a2b3c5 / imul / add edx,esi / sar edx,8
439543  B = 3*(q − rem) / 4
43954f  total = X + B
439551  value = trunc10(total/10)   ; 若 <= 0 则 10（0x439567）
43957b  popup(..., value, 色 0xffffffff) → 汇入 ② 的入账段
```

> ★ **除数 = 450**（✅）：`0x91a2b3c5` = `ceil(2^40/450)`，配 `add edx,n; sar edx,8`
> 就是**有符号除以 450**（逐指令仿真：`n = -750000` → 1666 = ⌊750000/450⌋ 等，正负样本全等）。
> 这串魔数在**本仓 TH16 / TH17 的同一支公式里已被独立核实为 ÷450**，且**闭式逐字相同**
> （[`../th16/01`](../th16/01-point-item-value.md) §4 线下支、[`../th17/01`](../th17/01-point-item-value.md) §5 B. 线下档），三作互证。
> ⚠ [`../th13/01`](../th13/01-point-item-value.md) §5 把同一魔数记成「除数 ≈163.09 🟡、穷举 100..400 无整数解」——
> 那是把 `imul` 的**无符号**高位当被除数（漏掉 `add edx,esi` = 加回 n 这一步）算出的等效比；
> 真值 **450 恰在它穷举的 100..400 区间之外**，§5 那一行应订正（本文不代改他人文档）。

闭式（与逐指令仿真逐点相等，`th14` 线下支）：

```
value_线下 = trunc10( 0.75 × 最大得点 × (1 − (自机y − 线)/450) ) ，下限 10
线 = (CHARACTER == 1) ? 148.0f : 128.0f
```

实测（PIV 存储 1000000 = 最大得点 10000、线 128）：y=129 → 7480；y=200 → 6300；y=300 → 4630；
y=450 → 2130；y≥578（深度 ≥450）→ 10。

⇒ 线下**不是**折扣到 0，而是**从 75% 起按深度线性衰减到 0（深度 450 px）**，地板 10。

## 6. 「第二项」：蓝点自身没有加数，但链上有两处独立的加项（★ 用户最关心的一条）

**(a) 蓝点自身：`value` 只由 PIV 决定**。逐指令看，`0x4394a0` 里对 PIV 只做 `/100`（魔数）与
`trunc10`，唯一的减项是线下深度折扣；**没有任何 `+常量`、没有乘数、没有擦弹/连击/难度项** ✅。

**(b) 一括回収ボーナス（同批回收件数倍率）——独立入账，加在蓝点分之后** ✅

```
438dad  eax = ds:0x4f5884(计时器) ; 若 <=0 跳过，否则 dec
438dc0  计时到 0 才继续（→ 438dc6 取 0x4f5888 记下的回收点坐标，y − 48 作弹窗位置）
438dd3  esi = ds:0x4f5878        ; ★ 这一批的 Σ值
438df1  eax = ds:0x4f5880        ; ★ 这一批的件数
438dfe  cmp eax,0x3c(60) → esi = 2*Σ        （0x438e0b add esi,esi）
438e2f  cmp eax,0x32(50) → esi = trunc10(1.6*Σ)
438e84  cmp eax,0x28(40) → esi = trunc10(1.2*Σ)
```

- **计时器武装点** `0x438996`：道具进入 state 3（自动回收）时写 `ds:0x4f5884 = 8`（`edx = 8` 见 `0x438d8c`），
  **type 11 除外**（`cmp ecx,0xb` + `cmovne`）。⇒ 一括判定窗口 = **8 帧**。
- 件数 < 20 时**没有**加分（弹窗也不出数）⇒ 与社区倍率表的「0〜19 → 0」一致。
- 社区同表（🟡→✅）：[wikiwiki 解析データ](https://wikiwiki.jp/thk/%E8%BC%9D/Data)「同時回収数 20〜29 ×0.5 / 30〜39 ×0.8 /
  40〜49 ×1.2 / 50〜59 ×1.6 / 60〜 ×2.0」，以及「残機のかけら = 最高倍率を出した時 / ボムのかけら = ×2.0 以外の時」，
  与 `0x438e25` 的 `edi` 标志分支逐条吻合。

**(c) 最大得点本身也是「基础值 + 加数」**：`PIV显示 = min(上限[diff], 初值[diff] + 擦弹数 + 2×绿点(type9) + 20×绿点(type10/11) + 100×满P道具)`。
⇒ 用户在做「总最大得点公式」时，**蓝点那一侧只有一项**，但**最大得点这一侧有四条加数**，
再加上 (b) 那条**按件数倍率独立入账**的批次加分 —— 这三层要分开写，别混成一个式子。

## 7. 与社区读数的两处 10× 差异（🟡 如实登记，待实跑裁决）

| 项 | 社区口径 | 本作一手的算式 | 差 |
| --- | --- | --- | --- |
| P 小道具（type 1） | 「スコアが 10 増加」 | `value = 0x64` → `SCORE += 10` ⇒ 显示 **+100** | 10× |
| 绿点（弹幕清除那支，type 10） | 「5 個につき最大得点が 10 上昇」= +2/个 | `add_to_piv(20.0f)` ⇒ 显示 **+20**/个 | 10× |

| 蓝点 | 「自動回収時に最大得点と等しい」 | 显示分 += `trunc10(PIV/100)` | ✅ 一致 |

两处 10× 都出现在**社区数字比一手小一个十进制档**的位置。本文**不裁定**谁对，标 🟡：
