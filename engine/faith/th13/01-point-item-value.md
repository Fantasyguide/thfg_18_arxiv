# TH13 点道具身价（最大得点 / PIV）—— 载体、量纲、难度两表、两条涨入口（擦弹 / 道具·神灵）

> **版本**：TH13 v1.00c（`local/th13.v1.00c/th13.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；
> 引用其他版本写作 `th18:0x……`。
> **方法**：一手平坦反汇编（`objdump -D -b binary -m i386 -M intel --adjust-vma=0x1000`，产物 `/tmp/th13_full.asm`）
> + 常量/表按 PE 节区 VMA 换算直读原始字节 + 全 exe 地址穷举（**绝对寻址 11 处** + **寄存器相对寻址** `[GLOBALS+0x24]` 形态，两类都扫过）
> + ExpHP `th-re-data` 的 `statics.json` / `type-structs-own.json` **对名**（🟡 只用来校名，结论一律以一手为准）。
> **可信度**：载体 / 量纲 / 难度两表+续关表 / **两个**涨入口 / 取值函数 / §5 线上线下分档 = ✅；
> 四个擦弹调用点与道具·神灵侧的**事件身份** = ✅（第 2 轮补齐）；
> 「神灵 type 1 到底加多少最大得点」= ✅ **已判定**（既非 ① 也非 ②，见 §6）。
> **第 2 轮（本轮）**：钉死 §6 的冲突，订正第 1 轮「PIV 只有一个写点」这一**错误**（漏了 `esi = 0x4be7b8` 传参式的 `[esi+0x24]` 加法器）。

## 0. 一句话结论

TH13 的「最大得点」= **点道具身价**，载体 `th13:0x4be7dc`（`CURRENT_PIV__SCALED` = `GLOBALS` + `0x24`），
**存储 = 显示 × 100**（一次加值是 `+100` 存储 = **+1 显示**），上限在 `th13:0x4be7e4`（`MAXIMUM_PIV__SCALED` = `GLOBALS` + `0x2c`，同样 ×100 存储），
两表按难度在 **run / 关卡初始化**时算出来（`th13:0x42bb70`–`th13:0x42bbb9`）。
除初始化外有**两个**加法器，两者都把结果夹到 `MAX_PIV`：

| 加法器 | 加的单位 | 调用点 | 事件 |
| --- | --- | --- | --- |
| `th13:0x445900` | **+100 存储 = +1 显示**（硬编码，自带弹窗） | 4 | **擦弹**（子弹 ×2 / 撞敌机 ×1 / 激光 ×1，§3） |
| `th13:0x42f521`（`FUN_0042f510`） | **参数就是「显示值」**，内部 ×`double 100.0`（`th13:0x4ae868`）折算成存储 | 4 | **道具** ×2（`th13:0x42e8d9` / `th13:0x42eb55`）、**神灵 type 1** ×2（`th13:0x438bbe` 普通 **10.0** / `th13:0x438d6d` 灵界 **100.0**） |

⇒ 第 1 轮的「全 exe 只有一个写点」是**错的**（穷举只扫了绝对寻址，漏了 `esi = 0x4be7b8` 传参式的 `[esi+0x24]`）。
订正见 §1 / §3 / §6。

## 1. 载体、量纲与使用点（✅ 穷举）

| 项 | 一手 |
| --- | --- |
| 载体 | `th13:0x4be7dc`（`CURRENT_PIV__SCALED` = `GLOBALS`(`th13:0x4be7b8`) + `0x24`） |
| 上限 | `th13:0x4be7e4`（`MAXIMUM_PIV__SCALED` = `GLOBALS` + `0x2c`） |
| 同族 | `th13:0x4be7e0` = `MINIMUM_PIV__SCALED`（`GLOBALS` + `0x28`，§2）；`th13:0x4be7d0` = `GLOBALS` + `0x18` = **擦弹数**（§3 注） |
| 量纲 | **存储 = 显示 × 100**（`+100` 存储/次 = `+1` 显示；取值函数见 §4） |
| 读点（`imul DWORD PTR ds:0x4be7dc`，共 7 处） | 清单见本表下方的「读点清单」（2026-09-23 拆出：原单元格 228 字符 > 文档门 200） |
| 写点（**寄存器相对**，第 2 轮补） | `th13:0x42f521`（`add [esi+0x24],eax`，`esi` = `0x4be7b8`）与 `th13:0x42f52c`（夹取）—— **`FUN_0042f510`**，即道具/神灵那条加法器 |
| 写点（绝对寻址，共 3 处） | `th13:0x42bbb9`（run/关卡初始化）、`th13:0x445928`（擦弹加法器内）、`th13:0x445931`（擦弹加法器内的夹取） |

> **读点清单**（7 处 `imul DWORD PTR ds:0x4be7dc`；2026-09-23 从上一行表格单元格搬出，**内容不改一字**）：
> `th13:0x4280c0`（HUD `Gui::on_draw_2e`）、`th13:0x42b455`（**取值函数**，§4）、
> `th13:0x42ea1a` / `th13:0x42eaa4`（`ItemManager::on_tick__body` 的点道具入账/弹窗）、
> `th13:0x438c51` / `th13:0x438c80` / `th13:0x438daa`（**神灵奖励区**，`SpiritItem::on_tick`）。

> 穷举口径（**第 2 轮订正**）：绝对寻址 `grep -c 4be7dc /tmp/th13_full.asm` = **11**（7 读 + 3 写 + 1 在加法器里读入 `ecx`）——
> 这个口径**不足**。`GLOBALS` 基址 `th13:0x4be7b8` 会被装进 `esi`/`ecx`/`eax` 再以 `[reg+0x24]` / `[reg+0x2c]` 访问，
> 第一轮误判为「没有寄存器相对形态」。
> 第 2 轮的补扫做法（可复现）：① 全 exe 找 `mov reg,0x4be7b8` 后同函数内的 `[reg+0x24|0x2c]` 写入；
> ② 对**不在函数内设 `esi`** 的 `[esi+0x24]` 写者，回查其调用点前 30 行是否有 `mov esi,0x4be7b8`。
> ② 只命中一家：`FUN_0042f510`（4 个调用点全部 `mov esi,0x4be7b8`）。
> 其余 `[esi+0x24]` 写者（`th13:0x44ad60` 数字弹窗、`th13:0x447b0e` 回放头拷贝等）经查 `esi` 是各自的对象，与本字段无关。

## 2. 初值与上限：按难度的两张表 + 续关表（✅ 一手 + 表值直读）

初始化在 `th13:0x42bb70`–`th13:0x42bbb9`（`esi = 0x4be7c4` = `GLOBALS` + `0xc` = `DIFFICULTY`）：

```
2bb5a  esi = 0x4be7b8 (= GLOBALS 基址)
2bb5f  ds:0x4be7d0 = 0                        ; GLOBALS+0x18 = 擦弹数清零
2bb65  ds:0x4be7c0 = 0
2bb6b  call 0x42d3c0
2bb70  esi = ds:0x4be7c4                      ; 难度（0=E 1=N 2=H 3=L 4=EX）
2bb76  eax = [esi*4 + 0x4c0ab0]  ; A[diff]
2bb7d  eax *= 100
2bb80  ds:0x4be7e0 = eax                      ; ★ MINIMUM_PIV__SCALED = A×100（结构体名见下）
2bb85  ecx = [esi*4 + 0x4c0ac8]  ; B[diff]
2bb8c  fild ds:0x4be7e0 ; fld 100.0(double) ; fdiv st(1),st   ; st = A×100/100 = A
2bb92  ecx *= 100
2bb9d  ds:0x4be7e4 = ecx                      ; ★ MAXIMUM_PIV__SCALED = B[diff] × 100（存储）
2bba9  fmul [esp+0x14] = A ; call 0x971f0     ; 100.0 × A → 取整（ftol）
2bbb2  edx = [esi*4 + 0x4c0ae0]  ; C[diff]    ; ★ C 表的去向（第 2 轮补）
2bbb9  ds:0x4be7dc = eax                      ; ★ CURRENT_PIV__SCALED 初值 = A[diff] × 100（存储）
2bbc9  ds:0x4be844 = edx                      ; ★★ C[diff] → CONTINUES_REMAINING
```

表值（直读原始字节）：

| 难度索引 | 难度名 | `A`（初值，**显示**） | `B`（上限，**显示**） | `C` = **残机续关数** |
| --- | --- | --- | --- | --- |
| 0 | Easy | 5000 | 100000 | 3 |
| 1 | Normal | 10000 | 250000 | 3 |
| 2 | Hard | 15000 | 500000 | 6 |
| 3 | Lunatic | 20000 | 500000 | 9 |
| 4 | **Extra** | 20000 | 500000 | 0 |
| 5 | （表留的第 6 格，本 build 不可达） | 100000 | 1000000 | 0 |

- **`C` 表的用途 = 续关次数（✅ 第 2 轮钉死）**：`th13:0x2bbc9` 把 `C[diff]` 写进 `ds:0x4be844`；
  ExpHP `statics.json` 命名 `th13:0x4be844` = **`CONTINUES_REMAINING`**（🟡 对名），
  读者一手可验：`th13:0x44075d` `dec DWORD PTR ds:0x4be844`（用掉一次续关）、
  `th13:0x43fbb8` / `th13:0x440577` `cmp DWORD PTR ds:0x4be844,0`（还有没有续关）、`th13:0x43e35f` 读它。
  ⇒ C[diff] = **该难度允许的续关次数**（E3 / N3 / H6 / L9 / EX0）。
- **难度索引 4 = Extra（✅ 第 2 轮钉死）**：难度**名表指针**在 `th13:0x4bb914`，5 项、顺序
  `[Easy, Normal, Hard, Lunatic, Extra]`（字符串本体 `th13:0x4ab8fc`/`0x4ab8f4`/`0x4ab8ec`/`0x4ab8e4`/`0x4ab8dc`，直读）⇒ 索引 4 = Extra。
  代码侧一致：`th13:0x44da9e` 有一条把 `DIFFICULTY` 直接写成 **4** 的分支（同段 `th13:0x44db00` 用 `cmp esi,4 / jl` 把「普通难度 0..3」与它分开）；
  另有初始化默认值 `th13:0x42d594` 写 **1**（Normal）。
- **索引 5 = 本 build 不可达（🟡→✅ 足够）**：`A`/`B`/`C` 三表各留了 6 格，但名表只有 5 项，
  且扫过的 `DIFFICULTY` 写点里**没有一个写 5**。⇒ 第 6 格是表的填充/上一代残留，不是「Phantasm」。
- 同一段还把 `th13:0x4be7d0`、`th13:0x4be7c0` 清成 `edi`（= 0）并调 `th13:0x42d3c0`（本仓已知：那里也把灵界槽设成 200）。
- 结构体名（🟡 ExpHP `th-re-data` `type-structs-own.json` 的 `zGlobals`，基址就是 `th13:0x4be7b8`）：
  `+0x00 CHARACTER`、`+0x08 CURRENT_SCORE`、`+0x0c DIFFICULTY`、`+0x10 CONTINUES_USED`、`+0x24 CURRENT_PIV__SCALED`、
  `+0x28 MINIMUM_PIV__SCALED`、`+0x2c MAXIMUM_PIV__SCALED`、`+0x30 CURRENT_POWER`、`+0x34 __POSSIBLY_MAX_POWER`。
  ⇒ §1 里 `0x4be7e0` 的「中间量」其实是 **`MINIMUM_PIV`**（本 build 只在上面这段里被写一次、读一次，没有别的读者 🟡）。

## 3. 涨入口之一：擦弹加法器 `th13:0x445900`（+1 显示/次，✅）

```
45900  prologue（eax = 弹窗用的位置指针，存 edi）
45904  cmp ds:0x4be7d0, 0x5f5e0ff ; jge skip    ; GLOBALS+0x18 = 擦弹数（上限 99,999,999）
45914  ++ds:0x4be7d0
4591a  eax = ds:0x4be7dc                        ; CURRENT_PIV__SCALED
4591f  ecx = ds:0x4be7e4                        ; MAXIMUM_PIV__SCALED
45925  eax += 0x64                              ; ★ +100（存储）= +1 显示
45928  ds:0x4be7dc = eax
4592d  cmp eax,ecx ; jle …
45931  ds:0x4be7dc = ecx                        ; ★ 夹到 MAXIMUM_PIV
45937  起弹窗 VM：FUN_0046f820(out, script=0x64, pos=edi, 0.0f, -1, 0)，anm 句柄 = [EFFECT_MANAGER_PTR+0x10]
45958  播音：SoundManager::play(id=0x2a, pos.x=[edi])（`th13:0x460c50`）
```

⇒ **一次调用 = 最大得点 +1（显示）**，且**加法器自己负责弹窗**（所以调用点就是「会飘 +N 的那些事件」）。

**`th13:0x4be7d0` 就是擦弹数（GRAZE）** ✅：① 与本函数同批的**两个只读小函数** `th13:0x445980` / `th13:0x4459a0`
做的正是「`GRAZE < 99999999` 就 `++GRAZE`」（不带 PIV、不带弹窗）；
② `th13:0x42b430` / `th13:0x42b440` 是两个返回 `ds:0x4be7d0` 的死访问器（与 §4 的 `th13:0x42b450` 同一族）；
③ HUD 绘制 `Gui::on_draw_2e` 在同一屏同时取它与 PIV（`th13:0x428123` 取擦弹、`th13:0x4280c0` 取 `trunc10(PIV/100)`），
两者都走同一个数字排版助手 `th13:0x4003ec0`。

调用者共 **4** 处（**第 2 轮钉死：四家全是「擦弹」族**）：

| 调用点 | 所在函数 | 门 / 现场 | 判为 |
| --- | --- | --- | --- |
| `th13:0x40dd84` | `Bullet::on_tick`（`th13:0x40db10`） | 上一步算出的碰撞结果 `eax == 2`，且 `test byte [ebx+0x20],4` 未置位 → 调用 → `or dword [ebx+0x20],4` | **子弹擦弹**（`0x4` = 「这颗已经擦过」的闩锁） |
| `th13:0x40e073` | `Bullet::on_tick`（同上函数） | 同上形状的另一分支（`je` 直接落到函数尾） | **子弹擦弹**（第二个弹种/分支） |
| `th13:0x41a1ac` | `FUN_00419a90`（敌机 tick：累计伤害→掉神灵的那支） | `call th13:0x444260` 返回 `eax == 2` 且 `[edi+0x4030] & 0x200` 且 `[edi+0x2bc] % 6 == 0` | **撞敌机擦弹**（每 6 帧一次） |
| `th13:0x431a1a` | **`VTABLE_LASER_LINE` 槽 4 = `th13:0x4ab0dc`** 所指的函数（激光类 tick；同族槽 4：曲线 `th13:0x4355f0`、无限 `th13:0x433470`、光束 `th13:0x437ff0`） | 间接虚调用返回 `eax == 2` 且 `[edi+0x2c] % 3 == 0` | **激光擦弹**（每 3 帧一次） |

⇒ 四家**都不是**「道具 / 神灵 / Boss 奖」——那些走的是下面的第二加法器。
第 1 轮「涨入口只有这一条通道」由此**推翻**：它只是**擦弹**这一条通道。

### 3.1 第二加法器：`th13:0x42f521` = `FUN_0042f510`（★ 第 2 轮新发现，道具 / 神灵走这条）

`th13:0x42f510` 只有 0x23 字节，`ret 0x4`（`__stdcall`，1 个 float 参数），**对象基址走 `esi` 隐式传参**：

```
2f510  push ebp ; mov ebp,esp
2f513  fld DWORD PTR [ebp+0x8]              ; 参数 = 「显示值」增量
2f516  fmul QWORD PTR ds:0x4ae868           ; ★ × double 100.0  → 存储单位
2f51c  call 0x971f0                         ; ftol（浮点→整数）
2f521  add DWORD PTR [esi+0x24],eax         ; ★★ CURRENT_PIV__SCALED += …
2f524  eax = [esi+0x2c]                     ; MAXIMUM_PIV__SCALED
2f527  cmp [esi+0x24],eax ; jle 2f52f
2f52c  mov DWORD PTR [esi+0x24],eax         ; ★ 夹到 MAXIMUM_PIV
2f52f  pop ebp ; ret 0x4
```

- `th13:0x4ae868` 直读原始字节 = `00 00 00 00 00 00 59 40` = **double 100.0**
  （ExpHP `statics.json` 亦记作 `double(100)`，🟡 对名；一手字节已是铁证）。
- `esi = 0x4be7b8` 时 `+0x24` = `0x4be7dc`（`CURRENT_PIV__SCALED`）、`+0x2c` = `0x4be7e4`（`MAXIMUM_PIV__SCALED`）——
  **4 个调用点无一例外都在调用前一条就 `mov esi,0x4be7b8`**（§1 的穷举口径）。
- ⇒ 这个函数的**参数就是「显示侧的最大得点增量」**，函数自己完成「显示 → 存储」换算。

| 调用点 | 所在函数 | 传入的「显示值」 | 事件 |
| --- | --- | --- | --- |
| `th13:0x42e8d9` | `ItemManager::on_tick__body`（`th13:0x42e380`，`[item+0xba4] == 8` = **满 P 道具**） | `fld ds:0x4aeaf0` = **100.0f** | **火力已满时 ⇒ 最大得点 +100** + 弹窗 100；⚠ 未满支走 `th13:0x43d210`（订正块 ④） |
| `th13:0x42eb55` | 同上（另一支） | `fld ds:0x4aebec` = **0.1f** | **道具**：**+0.1**（→ `ftol(0.1×100)` = **+10 存储**），随后 `FUN_00413bf0(player, 10)` 给分 |
| `th13:0x438bbe` | `SpiritItem::on_tick`（`th13:0x438730`，收神灵 type 1，`DIFFICULTY <= 4` 门） | `fld ds:0x4aeea4` = **10.0f** | **神灵 type 1 普通：最大得点 +10** |
| `th13:0x438d6d` | `SpiritItem::on_tick`（灵界态第二张分派表，同 `DIFFICULTY <= 4` 门） | `fld ds:0x4aeaf0` = **100.0f** | **神灵 type 1 灵界内：最大得点 +100** |

⇒ **`th13:0x42e8d9` 那支是「弹窗数字 = 加值」的活教材**：同一处 `mov ecx,0x64`（= 100）喂给
`FUN_0044ad60`（数字弹窗；它内部自己做十进制展开：`0x66666667` + `sar edx,2` = ÷10 取位，`th13:0x44ad96` 起），
**弹出来的 100 就是加进最大得点的 100（显示）**。
神灵 type 1 的弹窗则用 anm 脚本 `0x66`/`0x67`（贴图里烤死了 10 / 100），同样对应 10 / 100 的显示增量。

## 4. 取值函数：`trunc10(PIV/100)`（✅）

`th13:0x42b450` 是一个独立小函数（`ret`，无栈参数）：

```
2b450  eax = 0x51eb851f ; imul ds:0x4be7dc ; sar edx,5 ; (符号修正)
2b468  idiv 10 ; sub → 向下取整到 10 的倍数
2b475  ret                                     ; —— 返回值 = trunc10(PIV / 100)
```

⚠ 这个函数**全 exe 无人引用**（`call 0x2b450` 0 处；原始字节里也搜不到 `0x0042b450` 这个指针）⇒ 它是**死代码**，
真正在用的是同一段算式的**内联副本**（下面）。
同族的死访问器还有 `th13:0x42b430` / `th13:0x42b440`（两个都只 `mov eax,ds:0x4be7d0; ret`，即擦弹数 getter，§3）——
`th13:0x42b450` 就是这一小段「死访问器群」的第三个（也是唯一带运算的那个）。

⇒ **「最大得点」显示值 = `trunc10(PIV/100)`**（10 的倍数）。同式的内联出现在
`th13:0x4280c0`（**HUD**，`Gui::on_draw_2e`；第 1 轮写「弹窗」有误）与
`th13:0x438c51` / `th13:0x438c80` / `th13:0x438daa`（神灵 type 3 的分数弹窗+入账）。
点道具侧（`th13:0x42ea1a` / `th13:0x42eaa4`）读的是同一个 PIV，但走的是 §5 的线上/线下两支；
入账分值还会再 `/10` 一次（`0x66666667` + `sar edx,2` = ÷10）⇒ 与本仓既有的
「分数 = `PIV/100` 取整 10 的倍数；实际入账 值/10」一致。

## 5. 蓝点（点道具）分值与线上 / 线下分档（✅ 第 2 轮补）

- PIV 只被当乘数用（`imul`），**但加值的通道有两条**（§3 + §3.1）⇒ 第 1 轮「没有第二项结构、只有一个通道」不成立。
  点道具/相关得分的值仍然是 `f(PIV)`（`trunc10(PIV/100)` 起，再按各自分支 /10 等）。
- **线上 / 线下确实分档（✅）**：实物在 `ItemManager::on_tick__body`（`th13:0x42e380`）的点道具那一支
  （分派索引来自 `[item+0xba4]`，跳表 `th13:0x42ed9c`，入口 `th13:0x42e9e5`）：


## 6. ☑ 第 2 轮判定：既不是 ① 也不是 ② —— 10 / 100 就是**显示单位的 PIV 增量**

**发现**：既有文档 `engine/spirit/th13/01-spirit-and-trance.md` 写「收神灵 **type 1** = 最大得点 **+10**（灵界内 **+100**）」
（`th13:0x42f510` + 常量 `th13:0x4aeea4` = 10.0f / `th13:0x4aeaf0` = 100.0f）。
第 1 轮怀疑它是显示侧的数（读法 ①）或另一个浮点累加器（读法 ②），并把 `th13:0x404adc` 跳表 / `th13:0x404465` 的 `'.'` 扫描当成反证。

**验证**（一手，逐条）：

1. `th13:0x42f510` 的正文是 `[esi+0x24] += ftol(farg * *(double*)0x4ae868)`，**4 个调用点全部在调用前 `mov esi,0x4be7b8`**；
   `0x4be7b8 + 0x24` = **`0x4be7dc`**（`CURRENT_PIV__SCALED`），`+ 0x2c` = **`0x4be7e4`**（`MAXIMUM_PIV__SCALED`），夹取也在函数内。
2. `th13:0x4ae868` 原始字节 `00 00 00 00 00 00 59 40` = **double 100.0** ⇒ 传 10.0f 得 **+1000 存储 = +10 显示**；传 100.0f 得 **+10000 存储 = +100 显示**。
3. 神灵那两处调用点（`th13:0x438bbe` / `th13:0x438d6d`）与常量 `0x4aeea4` / `0x4aeaf0` 的关系是一手可读的 `fld 常量 → push → call`，
   中间**没有任何转换**。
4. 同一加法的**道具侧**（`th13:0x42e8ca`）传入 100.0f 后紧接 `mov ecx,0x64` 去画数字弹窗 ⇒ **弹窗上的数就是加进 PIV 的数**（显示单位），
   不是「只是显示」。
5. 第 1 轮的「唯一写点」前提（§1 穷举）**本身是错的**：漏了 `esi` 传参式的寄存器相对寻址。

**对第 1 轮那段反证的处置**：`th13:0x4042a0`（`jmp [eax*4+th13:0x404adc]` → 汇合 `th13:0x404413` → `th13:0x404465` 起扫字符串 `'.'`）
确实是**数字/浮点排版**例程（`[ebx]` 是格式串、`[ebx+0x110]` 是被格式化的浮点）。它**也**用了 `0x4aeea4`(10.0f) / `0x4aeea0`(14.0f) / `0x4aeea8`(9.0f)
——**同一个 `.rdata` 常量槽被两处无关代码共用**（`0x4aeea4` 在 `th13:0x40436a` 与 `th13:0x438baf` 各被 `fld` 一次；`0x4aeaf0` 更被 3 处用）。
以「常量出现在排版函数里」推「它在神灵奖励里也是排版」是**共址谬误**。

**结论**：读法 ① **否**（10/100 不是「只是弹窗的数」——弹窗确实显示 10/100，但同一对常量同时是加进 `0x4be7dc` 的显示增量）；
读法 ② **否**（没有第二个浮点累加器；唯一的浮点只出现在「显示 → 存储」的 ×100 换算里，`th13:0x42f516`）。
**⇒ 既有文档 `engine/spirit/th13/01-spirit-and-trance.md` 的「+10 / 灵界内 +100」是对的（✅）。**
**⇒ 本仓卡 113 的现行实现（按「+10 显示 / 灵界内 +100 显示」）也是对的：`卡 113 无需修改`**（不存在「大了 10 倍」）。
本轮**只在 §1/§3 订正本文件自己的「唯一写点 / 唯一涨入口」错误**，卡侧不动。
