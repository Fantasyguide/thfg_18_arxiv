# TH11 信仰（最大得点）—— 量纲、绿点三档与「蓝点分 = 最大得点 ×(交信度 + 擦弹倍率)」

> **版本**：TH11 v1.00a（`th11.exe`，688,128 B，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th10:0x…`。
> **方法**：一手平坦反汇编（`objdump -d -M intel`，产物 `local/_scratch/th11_full.asm`）+ 常量/表按 PE 节区 VMA 换算直读原始字节
> + 逐指令仿真器对抗复核（4,800 组输入与简化式逐一相等）+ ExpHP 社区符号只取词汇。
> **可信度**：量纲、初值/上限两表、绿点三档、蓝点公式、写入点穷举全部 ✅；
> 「擦弹项是 100 擦弹一阶梯」与「总倍率上限 9.99」两条超出社区措辞，按仓规标 🟡（§2.4）。

## 0. 一句话结论

TH11 的**信仰就是 HUD 左上角那个「最大得点」**：载体 `GLOBALS+0x10` = `0x4a56f0`，
**显示 = `trunc10(⌊存储/100⌋)`**（存储 = 显示 ×100，**与 TH10 的 ×10 方向相反，别搬数字**）。
初值按难度给（`{25000,50000,100000,200000}`，EX 走索引 4），上限 = **初值×2**（表 `0x4a79fc`）。

它只有**一个涨入口**（`add_to_piv` `0x424640`，被三类绿点道具调用）与**一类跌源**（miss）；
**点道具（蓝点）的分值 = 最大得点 × (交信度 + 擦弹倍率)** —— 这就是社区口径
`緑点 * (交信度 + Graze倍率)` 的一手形式。

**订正**：`0x4a56f4`（`GLOBALS+0x14`）**不是擦弹计数**，它是**交信度**（见 [th11/02](02-koushin-signal.md)）；
擦弹计数是 `0x4a5754`（`GLOBALS+0x74`，ExpHP 名 `GRAZE`，钳 `0x5f5e0ff`）。两者在擦弹事件里**同时**被更新
（一个 +1、一个 +500/+800），只盯 `0x40baa0` 会把它们看成同一个东西。

## 1. 量纲与定点约定（后面所有结论都建立在这里）

`GLOBALS = 0x4a56e0`（10 项偏移与 ExpHP `zGlobals` 逐项吻合，且每项都有独立的功能性用法）：

| ExpHP 字段 | 地址 | 一手用法 |
| --- | --- | --- |
| `+0x4 CURRENT_SCORE` | `0x4a56e4` | `0x40ceb9: mov eax,ds:0x4a56e4`（`add_to_score`） |
| `+0x8 CURRENT_POWER` | `0x4a56e8` | `0x420a00`（`collect_power`）、灵击扣减 `0x4311f1` |
| `+0x10 CURRENT_PIV` | `0x4a56f0` | `0x424640`（`add_to_piv`）、HUD `0x41ce04` |
| `+0x14 __field_14` | `0x4a56f4` | **本文命名 = 交信度**（`0x40baa0` 累加、`0x423b7c` 读） |
| `+0x18 __field_18` | `0x4a56f8` | 交信度的影子值（每帧 −30、夹到 ≤`0x4a56f4`），**全 exe 找不到读者** ❓ |
| `+0x40 DIFFICULTY` | `0x4a5720` | `0x423c8c: cmp eax,0x4` + 跳表 |
| `+0x48 CURRENT_STAGE` | `0x4a5728` | `0x41f981: cmp ds:0x4a5728,0x7`（Extra） |
| `+0x64 RANK` | `0x4a5744` | 各道具分支 `add eax,N; cmp eax,0x400` |
| `+0x68 MAXIMUM_POWER` | `0x4a5748` | `0x420a0e: cmp ecx,eax`（火力上限） |
| `+0x6c POWER_PER_LEVEL` | `0x4a574c` | 火力 HUD `0x41cc1d: idiv ds:0x4a574c`；**也是灵击的 `BOMB_COST`** |
| `+0x74 GRAZE` | `0x4a5754` | `0x40bb1c: inc DWORD PTR ds:0x4a5754`（`Bullet::do_graze` `0x40bb10`） |

**四条量纲（一手）**

| 量 | 载体 | 存储 ↔ 显示 | 钳位 |
| --- | --- | --- | --- |
| 信仰 / 最大得点 | `0x4a56f0` | **显示 = `trunc10(⌊存储/100⌋)`** | 上限 `0x4a576c`、下限 `0x4a5768` |
| 交信度 | `0x4a56f4` | 显示 = `⌊存储/100⌋` ∈ [0,130] | `0x32c8` = 13000（`0x40bab5`） |
| 分数 | `0x4a56e4` | **显示 = 存储 ×10**（与 TH10 相同） | `0x3b9ac9ff` |
| 擦弹计数 | `0x4a5754` | 显示 = 存储（整数计数） | `0x5f5e0ff` = 99,999,999 |

```
th11:0x424640 add_to_piv(x)     ; ret 4 —— 全文件唯一的「信仰增加」入口
424640: mov eax,ds:0x4a56f0 ; add eax,[esp+4]      ; ★ 注意：不除 10（TH10 除 10）
424649: mov ecx,ds:0x4a576c ; cmp eax,ecx / mov ds:0x4a56f0,eax / jle / mov ds:0x4a56f0,ecx
th11:0x40ceb0 add_to_score(x)   ; CURRENT_SCORE += x/10（魔数 0x66666667 + sar 2），钳 0x3b9ac9ff
```

**★「显示 = 存储 ÷ 100」的四重独立证据**：① HUD `0x41ce04` 读 `0x4a56f0` → `÷100` → 截断到 10 的倍数；
② 收集弹窗 `0x423c9d` 用 `ebx/100` 当显示数，而同一分支 `0x423cba` 加的是**未除**的 10000；
③ 回放往返 `/100`（`0x435866`）↔ `×100`（`0x435ac1`），另一组 `0x436e1d` ↔ `0x43701c`；
④ 关卡 6/Extra 的 LAST BONUS = `0x41ebe7` 调 `0x41f510`（显示最大得点）后 `imul 0x3e8` 再进 `add_to_score`，
社区独立记载「ラストボーナス = 緑点 × 1000，2500万〜4億」——`25000×1000 = 2500万`、`400000×1000 = 4億` 两端同时命中。

## 2. 蓝点（点道具 type 2）的得分公式

### 2.1 三个取值函数

```
th11:0x41f4e0 graze_term()   : min(⌊GRAZE/100⌋, 0x383)      ; 0x383 = 899（百分之一单位 ⇒ 8.99）
th11:0x41f510 piv_display()  : trunc10(⌊CURRENT_PIV/100⌋)    ; 就是 HUD 上那个数
th11:0x41f640 koushin_term() : 交信度 ≥ 0x2710(10000) ? 100 : min(⌊v/100⌋, 100)
th11:0x41f680 koushin_display(): 同一式的不封顶版（信号格/文字用）
```

### 2.2 主链（`ItemManager::on_tick__body` `0x423550` 的 type 2 分支）

```
; 交信度未满（v < 10000）：弹窗白色 0xffffffff
423b7c: cmp DWORD PTR ds:0x4a56f4,0x2710 / jge 0x423be8
423b88: call 0x41f640 → A ; 423b8f: call 0x41f4e0 → B ; 423b94: add ebx,eax   ; X = A + B
423b9b: call 0x41f510 (eax = 0x4a56e0) → Y                                     ; Y = 最大得点
423ba0: imul ebx,eax ; …/100… ; …/10*10 → S = trunc10(X*Y/100)
423bca: if (S <= 0) S = 10             ; 423bce: mov ebx,0xa —— 下限 10 分
423bd8: call 0x438440（弹窗）; 423bde: call 0x40ceb0（显示分 += S）
; 交信度已满（v ≥ 10000）：同式，A 直接硬编码 100，弹窗黄色 0xffffff00（0x423bf9 add eax,0x64）
```

### 2.3 公式（量纲逐项写明）

```
Y = trunc10(⌊CURRENT_PIV/100⌋)          [整数，HUD 上那个 6 位数]
A = min(⌊交信度/100⌋, 100)              [百分之一单位 ⇒ 0.00..1.00]
B = min(⌊GRAZE/100⌋, 899)               [百分之一单位 ⇒ 0.00..8.99]
★ 蓝点显示得分增量 S = trunc10( (A+B) × Y / 100 )，S ≤ 0 时取 10
```

| GRAZE（交信度满、Normal `Y`=50000） | S | 说明 |
| --- | --- | --- |
| 0 | 50000 | 倍率 1.00 |
| 100 | 50500 | 每满 100 擦弹 +0.01 |
| 8,900 | 94500 | 倍率 1.89 |
| 89,900 及以上 | 499500 | **9.99 封顶** |

**「`0.0001` 与 `8.99` 的真身」**

| 社区写法 | exe 真身 | 指令原文 |
| --- | --- | --- |
| `graze × 0.0001` | **两次整数 ÷100**：`⌊graze/100⌋` 后再整体 `/100` ⇒ 步进 0.01 | `0x41f4e0: mov eax,0x51eb851f / imul / sar edx,0x5`；整体 `/100` 在 `0x423ba3` |
| `8.99` | **整数 `0x383` = 899** | `0x41f4f7: cmp eax,0x383` / `0x41f4fe: mov eax,0x383` |
| `1.00`（信号强度上限） | 整数 `0x64`(100)，阈值 `0x2710`(10000) | `0x41f645` / `0x41f64c` |

⇒ **用浮点常量扫是对的靶子错的方向**：TH10 那篇扫 `float 8.99f` 零命中，不是因为机制不存在，而是因为它是整数。

### 2.4 「超过社区」的两条（按仓规标 🟡）

1. 擦弹项是**阶梯**：`⌊graze/100⌋` ⇒ **不足 100 的零头不计**（社区写 `graze×0.0001`，读起来像连续）。
2. `8.99` 只封**擦弹项**，总倍率上限 = 1.00 + 8.99 = **9.99**。

四道闸门自评：一手到底 ✅（指令 + 常量原字节）· 对抗证伪 ✅（逐指令仿真器与简化式在 4 组难度 ×
`v ∈ {0…13000}` × `graze ∈ {0…10⁶}` × `piv` 五档共 **4,800 组**上**零不一致**；且若 `0.0001` 真是浮点乘数，
`0x41f4e0` 里不会出现 `0x383` 整数钳位与 `÷100` 魔数）· 量纲常识 ✅（899 + 100 = 999 = 9.99，与 `"%1.2f"` 自洽）·
交叉对名 ✅（社区稼ぎ wiki 的两段结构与 `A + B` 一一对应）—— **但未经他人复核 ⇒ 标 🟡**。

## 3. 初值与上限

```
th11:0x41f8f0（一局初始化）
41f981: cmp DWORD PTR ds:0x4a5728,0x7 / jne ; ==7(Extra) ⇒ mov ds:0x4a5720,0x4
41f9e4: mov edx,[eax*4+0x4a79fc]   ; ★ 上限表 B[diff]
41f9eb: mov ecx,[eax*4+0x4a79e8]   ; ★ 初值表 A[diff]
41f9f2/41f9f5: imul edx,edx,0x64 / imul ecx,ecx,0x64
41f9f8: mov ds:0x4a576c,edx        ; ★ MAX_PIV = B[diff]×100
41fa25: mov ds:0x4a5768,ecx        ; ★ MIN_PIV = A[diff]×100
41fa2b: mov ds:0x4a56f0,eax        ; ★ CURRENT_PIV = A[diff]×100
```

```
th11:0x4a79e8 int32[5] = [25000, 50000, 100000, 200000, 200000]   ; 初值（显示单位）
th11:0x4a79fc int32[5] = [50000,100000, 200000, 400000, 400000]   ; 上限 = 2× 初值
索引 = DIFFICULTY（0x4a5720）：0=E 1=N 2=H 3=L 4=EX
```

⇒ 「信仰上限 = 初值 × 2」**逐项成立**（5/5）；`MAX_PIV` 只在 `add_to_piv` 里被读一次（`0x424649`），
`MIN_PIV` 只在两个 miss 函数里被读（`0x4327d7`、`0x433d15`）。**练习模式是否另走一条改 `DIFFICULTY` 的路未查** ❓。

## 4. 绿点三档与满 P 转换

道具类型分派表 `0x423f00`（11 项，见 [item/th11/01](../../item/th11/01-item-types-and-popup.md) §1）：

| type | 语义 | 一手 | 数值（存储 → 显示） |
| --- | --- | --- | --- |
| **3** | 绿点（大） | `0x423c82`；跳表 `0x423f2c` 五项全指 `0x423c98: mov ebx,0x2710` | `+10000` → **显示 +100** |
| **9** | 绿点（中） | `0x423cd7`: `push 0x3e8` + `call 0x424640` | `+1000` → 显示 +10 |
| **8** | 绿点（小） | `0x423cc4`: `push 0xa` + `call 0x424640`；另 `0x423ccd call 0x40ceb0(0xa)` | `+10` → 显示 **+0.1**，另 +10 分 |

⇒ 社区「绿点（小）每 100 个 +10」**是观测口径**，不是「计数到 100 再结算」——代码里没有这种计数器，
只是 HUD 只画整数部分。比例 大:中:小 = 100 : 10 : 0.1 与社区表一致。

**满火力时 P 类道具被改写**（`0x424333 cmp ecx,ds:0x4a5748`）：

```
字节表 th11:0x424578 = [0,1,1,0,1,1,1,1,1,0,0]   ; 下标 = type−1（≠0 ⇒ 改写）
跳表   th11:0x424570 → 目标 type 9（绿点·中）
```

⇒ **type 1 / 4 / 10 / 11（所有 P 点）在满火力时变成 type 9**。这一条同时**关掉了 TH10 那篇的未决项**
（TH10 是转成 type 9 = 小信仰点，见 [th10/01 §3.6](../th10/01-faith-and-points.md)）。

## 5. 信仰就是 HUD 上的「最大得点」

```
th11:0x41c660 Gui::on_draw_2a
41cdae: mov eax,ds:0x4a56f4    ; 交信度 → min(v/100,100)
41cdda: mov edx,ds:0x4a5754    ; GRAZE → ÷100、钳 0x383 ⇒ 擦弹项
41ce04: mov edx,ds:0x4a56f0    ; ★ CURRENT_PIV → ÷100 → 截断到 10 的倍数（edi）
41ce1f: add edx,ebx            ; X = 擦弹项 + 交信度项
41ce31: fdiv QWORD PTR ds:0x497e50 (double 100.0)
41ce46: push 0x494198          ; ★ 格式串 "%.6d*%1.2f"
41ce4b: call 0x4015a0          ; AsciiManager::printf  ⇒ 形如 "050000*1.00"
```

⇒ **HUD 上是 `最大得点 * 倍率`**：`050000` 才是信仰，`1.00` 是 `min(graze/100,899)/100 + min(v/100,100)/100`。
同一函数还用 `"%.9d%d"`（`0x494170`）画 10 位分数 —— **TH11 的 HUD 是 `AsciiManager` 文本（`front.cpp`），
不是 TH10 那种 vm 数字组**。
🟡 这一整段是无分支的线性文本绘制（`[esi+0x31c3]` 给它 alpha），我没能排除它是调试覆盖层；
**但全 exe 只有这一处把 `CURRENT_PIV` 变成数字**，所以「信仰显示 = `piv/100`」不受影响。

## 6. 写入点穷举（含否定结论）

**`CURRENT_PIV` `0x4a56f0` 的全部引用**：写 = `0x41fa2b`(初值)、`0x424651`+`0x424658`(`add_to_piv`)、
`0x4327f6`+`0x4327fd`(miss#1)、`0x433d22`+`0x433d29`(miss#2)、`0x435ac7`(回放读档)、`0x437022`(回放读档)；
读 = `0x41ce04`(HUD)、`0x424640`、`0x4327e2`、`0x433d10`、`0x435866`、`0x436e1d`、`0x41f510`。

| 来源 | 一手 | 数值（显示） |
| --- | --- | --- |
| 初值 | `0x41fa2b` | `A[diff]` = 25000…200000 |
| **唯一的涨入口** | `add_to_piv` `0x424640`；调用者**只有 3 个**：`0x423cba`(大)/`0x423cc6`(小)/`0x423cec`(中) | +100 / +0.1 / +10 |
| miss #1 | `0x4327d0`: `sub eax,0x989680`（= −10,000,000 存储） | **−100000**，地板 `MIN_PIV` |
| miss #2 | `0x433d10`（另一条落命路径） | 同上 |
| 回放读档 ×2 | `0x435ac7` / `0x437022`（`×100`） | — |

**否定结论（与 TH10 同构）**

- ❌ **没有信仰衰减**：没有任何逐帧/每秒/连击槽相关的减项。「敌人数量影响信仰涨落」「连击槽空扣信仰」在 TH11 不成立。
- ❌ **没有「擦弹供养信仰」**：擦弹只动 `0x4a5754`（计数）与 `0x4a56f4`（交信度），`add_to_piv` 的三个调用点全是道具。
- ❌ **没有「消弹供养信仰」的直接路径**：消弹只掉小绿点（type 8），要经道具才落到 `add_to_piv`。
- ✅ 唯一涨源 = 三类绿点；唯一跌源 = miss。交信度另有**清零**路径（miss / 登场期 / 被判中弹），**放灵击不会清零它**（[th11/02 §4](02-koushin-signal.md)）。

## 7. TH10 ↔ TH11 对照（同一套 Globals 形状，数值一个都不能搬）

| 项 | TH10（`th10:0x474c4c`） | TH11（`th11:0x4a56f0`） |
| --- | --- | --- |
| 初值 | 定值 50000，与难度无关 | 按难度 25000/50000/100000/200000/200000 |
| 量纲 | 存储 = 显示/10 | **存储 = 显示×100** |
| 上限 | 存储 `0x1869f` | 初值 ×2 |
| 涨源 | 大/小/微信仰点 | 大/中/小绿点 |
| miss | `−=(信仰−50000)/3` | **−100000 显示** |
| 灵击 | 非决死 −3000 | 不动信仰（只清交信度） |
| 信仰 → 分 | 蓝点 = 信仰 | **蓝点 = 最大得点 ×(交信度 + 擦弹倍率)** |

- 🟡 `0x4a573c`（HUD 第 10 位数字）是「分数的第 10 位」还是「关卡号」，未判定。
