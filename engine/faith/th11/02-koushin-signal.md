# TH11 通信强度（交信度）槽 —— 每帧增减、擦弹源、满槽效果与 HUD 信号格

> **版本**：TH11 v1.00a（`th11.exe`，688,128 B，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th10:0x…`。
> **方法**：一手平坦反汇编（产物 `local/_scratch/th11_full.asm`）+ 常量/表按节区 VMA 直读原始字节 +
> `local/th11.v1.00a/anm/front/front.anm.txt`（`thanm` 导出）+ ExpHP 结构 `zAnmVm`/`zGlobals` 交叉。
> **可信度**：载体/量纲/每帧四档/擦弹四源/满槽效果/HUD 写点 ✅；「整段自动回收谓词」的化简、G2 的实体身份、另两个 HUD 组的归属 🟡/❓。

## 0. 一句话结论

**通信强度（= 交信度）是 `GLOBALS+0x14` = `0x4a56f4` 的一个 int32 定点值**：**存 0…13000 = 显示 0.00…130.00**，
「满」的判据是 `≥ 0x2710`(10000)。它干三件事：**乘进最大得点**（点道具分值的 `A` 项）、
**满槽时把落下中的道具全收**、**驱动左下角那条信号格**。

涨源**两条、互相独立**：① **擦弹**（4 个 `槽 += 表[难度]` 站点，+2.00…+8.00/次）；
② **每帧**（`0x420a70`：玩家在回收线 `y < 128.0f` 上方时未满 **+50.00/帧**、已满按高度 **+0.16/+0.12/+0.09**）。
跌源只有一条：**每帧**在回收线下方 **−0.30**（下限 0）。**放灵击本身不写这个变量**（§4）。

| --- | --- | --- | --- |

| 2 | <100 线上 +50/f；≥100 线上 +0.09/f | `0x420a70`：未满任何线上档都是 **+5000 并钳到 10000**；已满时按 y 分 `+16/+12/+9` | ✅ 对 + 细化（0.09 是最靠下那一档） |

## 1. 载体、量纲与上下限

| 事实 | 一手 |
| --- | --- |
| 载体 | `0x4a56f4`（`0x4a56e0 + 0x14`）；ExpHP 表里叫 `__field_14`（无名 ⇒ 命名是自己钉的） |
| 硬上限 13000 | `0x40baa9: cmp eax,0x32c8` / `0x40bab5: mov DWORD PTR ds:0x4a56f4,0x32c8`；每帧函数里 `0x420b2a`–`0x420b35` 再钳一次 |
| 「满」阈值 10000 | `0x42364a`、`0x423b7c`、`0x41b67f`、`0x41cdb6`、`0x41f645` 五处同值 `0x2710` |
| 下限 0 | `0x420b03 add [edi+0x14],esi`(esi=−30) / `0x420b06 jns` / `0x420b08 mov [edi+0x14],edx`(0) ⇒ 只钳「负→0」 |
| 显示 = ⌊存储/100⌋ | `0x41cdb6`–`0x41cdd8`：`槽 ≥ 10000 ? 100 : 槽*100/10000`（魔数 `0x68db8bad` + `sar edx,0xc`） |
| 加值入口 | `0x40baa0`（`槽 += 参数`，钳 13000）；尾部副作用把 `GLOBALS+0x1c` 的 zTimer 设成 `{prev=9, current=10, current_f=10.0f, game_speed=&0x4a7948, control 置 bit0}` |
| 影子值 | `0x4a56f8`（每帧 −30、下限 0、夹到 ≤`0x4a56f4`）——**全 exe 找不到读者** ❓ |

**写点穷举 = 7 处**：`0x40baae`+`0x40bab5`（加/钳）、`0x420a8f`…（每帧四档，用相对 `edi` 的写法，
`grep 0x4a56f4` 抓不到 —— **这条是「只看绝对地址穷举」最容易漏的一处**）、`0x41fb24`（一局开始清零）、
`0x431097`/`0x431227`/`0x4312c0`（玩家状态 0/2/4 清零）、`0x432807`（miss 清零）。

## 2. 每帧增减：`0x420a70`（「+50 / +0.09 / −0.3」的真身）

调用点 `0x4207cd`–`0x4207e6`（`GameThread::on_tick`）：`Gui` 有对话 VM 时跳过、`Gui` 计时器 `< 0x5a`(90 帧) 时跳过，
否则 `edi = 0x4a56e0` 后 `call 0x420a70`。

```
420a76: fld ds:0x497f8c (64.0f) / fcomp [player+0x880]        ; 档 1：y < 64
420a8f: mov eax,[edi+0x14] ; cmp eax,0x2710 ; jge → +16
420a99: add eax,0x1388 (5000) ; cmp eax,0x2710 ; mov [edi+0x14],eax ; jl …；否则钳 0x2710
420ab9: fld ds:0x498080 (80.0f)  …                            ; 档 2：64 ≤ y < 80：已满 +12
420ade: fld ds:0x497f30 (128.0f) …                            ; 档 3：80 ≤ y < 128：已满 +9
420b03: add DWORD PTR [edi+0x14],esi (−30) ; jns ; 否则置 0     ; 档 4：y ≥ 128（线下）
420b0b: cmp [edi+0x20],0 ; jg 跳过 ; 影子值 0x4a56f8 −30、下限 0
420b2a: 钳 ≤0x32c8 ; 420b40: 影子值 ≤ 槽
```

| 玩家 `pos.y` | 槽 < 10000 | 槽 ≥ 10000 |
| --- | --- | --- |
| `< 64` | **+5000（+50.00）**，钳到 10000 | **+16（+0.16）** |
| `64 … 80` | +5000，钳到 10000 | **+12（+0.12）** |
| `80 … 128` | +5000，钳到 10000 | **+9（+0.09）** |
| `≥ 128`（线下） | **−30（−0.30）**，下限 0 | 同左 |

常量（`.rdata` 原字节）：`0x497f8c` = 64.0f、`0x498080` = 80.0f、`0x497f30` = **128.0f = 道具回收线**、`0x497f20` = −1.0f（喂 `Timer::set`）、`0x49822c` = 10.0f。
⇒ **+5000 再钳 10000 的写法 = 「未满时一帧直接补满」**，不是真的按 +50/帧 累加。

## 3. 擦弹 → 槽（4 个站点 + 4 张难度表）

**擦弹计数器**（TH10 那篇找不到的东西，TH11 有）：`0x4a5754`（`GLOBALS+0x74`，ExpHP 名 `GRAZE`），
自增函数 `0x40bb10`（`cmp ds:0x4a5754,0x5f5e0ff` / `jge` / `inc`），另有内联自增点 `0x4275e6`，
一局开始归零 `0x41fa19`，HUD 显示 `0x41cd47`。

| # | 站点 | 所在函数 | 增益表 | 门 |
| --- | --- | --- | --- | --- |
| G1 | `0x408c49` | `Bullet::on_tick` | `0x4a7950` = **{800,500,500,500,500}** | 判定返回 2 且该弹未擦过（`or [bullet],0x4` 去重） |
| G2 | `0x411eaa` | `EnemyData::on_tick` | `0x4a79d4` = {800,500,500,500,500} | `[enemy+0x1580]&0x200`、判定返回 2、`[+0x158] % 3 == 0` |
| G3 | `0x4260ec` | `sub_425040_player_and_lasers` | `0x4a7a68` = {500,400,300,200,200} | `[ebp+0x2c] % 3 == 0`（每 3 帧 1 次） |
| G4 | `0x4275c4` | 同上（另一类 laser 结构体） | `0x4a7a7c` = {500,400,300,200,200} | `[esi+0x18] % 3 == 0` |

⇒ 表值 ÷100 就是显示增量：**Easy 子弹/敌体 +8.00**、N/H/L/EX +5.00；激光 +5.00/+4.00/+3.00/+2.00/+2.00。
满槽所需擦弹数：子弹/敌体 **E 13 次、其余 20 次**；激光 E 20 / N 25 / H 34 / L·EX 50。
四个站点**都不读玩家 y** ⇒ 「擦弹只在线上才加」不成立（✅ 负结论）。

## 4. 归零与订正

| # | 地址 | 语义 |
| --- | --- | --- |
| R1 | `0x432807` | **miss 结算**（`0x4327d0`：残机 −1、`PIV −= 0x989680`、地板 `0x4a5768`，然后 `xor ebp,ebp` + 写槽 0） |
| R2 | `0x41fb24` | **一局开始**（`0x41f8f0` 里 Player 初始化之后） |
| R3 | `0x431097` / `0x431227` / `0x4312c0` | **玩家状态 0（登场 60 帧，每帧）/ 4（被判中弹）/ 2（死亡中）** |
| R4 | `0x40baa0` | 加值（钳 13000），不是归零 |

**★ 订正（本轮的第三处交叉更正）**：有研究稿把 R3 那三处写成「**灵击**各状态的入口都清零 ⇒ 放灵击把倍率打回 0.00」，
**不成立**：灵击分支（`0x4311cd`–`0x4311f9`，含决死分支 `0x431265`–`0x4312b2`）里**没有**对 `0x4a56f4` 的写入，
`0x4a56f4` 的全部 7 个写点已在 §1 穷举。⇒ **放灵击不改交信度**；被打 / 死亡 / 登场才清零。
（R3 那三处的地址本身是对的，错的是把它们归给了灵击。）

🟡 「**每关**开头归零」：确认了「一局开始」与「玩家登场期每帧」两处写 0，但**没有**实跑确认每次进新关都重建玩家对象
（场景初始化 `0x40d500` 只被间接调用）。另：`0x4a56f4` **不在** `0x435b0f`/`0x436e6a` 那份快照里
（快照含 score/power/PIV/残机/命碎/RANK/GRAZE），旁证它是「每帧重算的氛围量」。

## 5. 满槽（≥ 100.00）的两个效果

### 5.1 把落下中的道具切成「被收走」

`ItemManager::on_tick__body`（`0x423550`）里 `state == 1`（落下中）的处理：

```
423611: cmp eax,0x1 ; … player->state ∈ {2,4} ⇒ 不判
423630: cmp DWORD PTR [edi+0x454],0x28        ; 道具自带 zTimer.current ≥ 40
42364a: cmp DWORD PTR ds:0x4a56f4,0x2710 ; jge 0x423713   ; ★ 满槽 ⇒ 收
42365c: fcomp [ecx+0x880] ; je 0x423715                   ; 否则：玩家在线上方（y < 128.0）⇒ 收
423713: → 0x423805: mov [edi+0x470],目标y ; 42380b: mov [edi+0x464],3   ; ★ item->state = 3（吸附玩家）
```

⇒ **收 ⟺ (道具寿命 ≥ 40 帧 ∧ 槽满) ∨ 玩家在回收线上方**（🟡 这条化简是我对控制流的重构：
FPU 栈复用让 `A`/`B` 的角色只能靠分支反推）。同族：灵梦×萃香的特技用同一手法全收（`0x4245e0`，
见 [player/th11/02](../../player/th11/02-support-special-effects.md)）。

### 5.2 点道具分值的 `A` 项饱和在 1.00

`0x423b7c`（交信度未满）调 `0x41f640` 取 `min(⌊v/100⌋,100)`；`0x423be8`（已满）直接 `add eax,0x64`
—— 两条合起来的公式见 [th11/01 §2](01-faith-and-points.md)。**满槽只让倍率到 1.00，超过 100 的部分不参与计分**。

### 6.2 引擎侧写点（`Gui::on_tick` `0x41b380`）

```
41b4e2 / 41b533: lea eax,[edi+0x31c8] ; mov ecx,0x4 ; loop { mov WORD PTR [eax],dx(3 或 2) ; add eax,0x434 }
41b55d: lea esi,[edi+0x2e4c] ; mov ebx,0x4 ; loop { push esi ; call 0x44b4b0 ; add esi,0x434 }   ; 复位 4 个 VM
41b579: mov ecx,ds:0x4a56f4 ; ×100 ; ÷10000 ⇒ eax = 槽/100
41b593: cmp DWORD PTR [edi+0x43cc],0x14 ; jl 0x41b679      ; ★ 进场 20 帧内不发档位中断
41b5a0: cmp eax,0x64  ; jl → 档 0：若曾记录过档则写 7（常态白）
41b5d1: cmp eax,0x6e  ; < 110 → 写 8      | 41b608: cmp eax,0x78 ; < 120 → 写 9 | 否则写 10
41b5b9 / 41b5f0 / 41b62a / 41b65b: mov WORD PTR [edi+0x35fc],…   ; ★ VM1
41b5c0 / 41b5f7 / 41b631 / 41b662: mov WORD PTR [edi+0x3a30],…   ; ★ VM2
41b5a5…: 档状态存 [edi+0x4420] 的 bit6..8（0x1c0），只在档变了才写 label（不每帧重发中断）
41b679: ecx = min(槽,10000) ; ÷100 ; ÷10 ⇒ level = min(⌊槽/100⌋,100)/10      ; 0..10
41b6cf/41b6d5/41b6e1/41b70b: 条宽 = 9.0 + 4.0×level（写 [ebx+0x32cc]），UV 同理；[ebx+0x32f8]/[ebx+0x3308]
41b701/41b717: or DWORD PTR [ebx+0x3684],8 / [ebx+0x3ab8],8                ; flags_lo |= 8（可见）
```

⇒ **档位 = 100 / 110 / 120 → label 7/8/9/10（白 → 闪得越来越快）**；**连续条宽 = `9.0 + 4.0×level` px**：
槽 0 → 9 px、槽 10.00 → 13 px、槽 100.00 及以上 → **49 px（饱和）**。
`level = min(⌊槽/100⌋,100)/10`，`0x41b679` 这里把槽钳到 10000。

### 6.3 ★ 订正：这两组写的是 `pending_interrupt`，不是 script id

**订正依据（本轮一手四条，互相独立）**：

1. `zAnmVm`（ExpHP）size = `0x434`、`+0x0 __id`、`+0x37c pending_interrupt`、`+0x3a2 script_number`。
2. `Gui+0x2e4c` 起的 **4 个 VM** 是在 `0x41a76a`–`0x41a78e` 用 `call 0x44acd0` 装载的、脚本号 = `0x20+n`
   即 **front.anm script 32..35**（同一函数还用同样的循环装了 `Gui+0x10` 起的 9 个 VM ← script 10..18、
   `Gui+0x25e4` 起的 2 个 VM ← script 3/4）。
3. 于是 `0x31c8` = `0x2e4c+0x37c`（VM0）、`0x35fc` = `0x3280+0x37c`（VM1）、`0x3a30` = `0x36b4+0x37c`（VM2）
   —— `0x41b4e2`/`0x41b533` 的 `stride 0x434` 循环正好覆盖 4 个 VM 的**同一个字段**，`0x41b5b9` 等只写 VM1/VM2。
4. 标签集合对得上：7/8/9/10/11 只出现在 **script33/script34** 里（两层条），而 2/3 在四个脚本里都有
   ⇒ 「只给两层条写档位标签、给 4 个 VM 一起写淡回/压暗」与代码完全一致。

⇒ **信号格 = front.anm script32–35**（`assertLabel` 在两层条上表现闪色）。
另有研究稿把同一处读成「把 script id 写成 7/8/9/10 ⇒ 4 档图标」：那是把 `+0x37c` 当成了 `+0x0`；
它列出的 script 7/8/9（`pos(428,102/126/150)`、layer 22 的静态图）**不在** Gui 的任何装载循环里
⇒ 那三个脚本的归属**保持 ❓**（`Gui+0x10` 那组是 10..18）。**「HUD 5 格」的说法在 exe 里也没有落点**：
没有 5 格的脚本/VM，只有 1 条槽底 + 2 层条 + 1 个图标。

### 6.4 显示串

```
41cdae: mov eax,ds:0x4a56f4 ; ≥10000 ? 100 : (v*100)/10000      ; 交信度项
41cdda: mov edx,ds:0x4a5754 ; ÷100 ; 钳 0x383                     ; 擦弹项
41ce1f: add edx,ebx ; 41ce31: fdiv QWORD PTR ds:0x497e50 (100.0)
41ce46: push 0x494198 ("%.6d*%1.2f") ; 41ce4b: call 0x4015a0
```

⇒ 屏幕左下那串 `NNNNNN*M.MM`：`M.MM` = `min(graze×0.0001, 8.99) + min(槽×0.0001, 1.00)`，`NNNNNN` = 信仰（截断到 10 的倍数）。
