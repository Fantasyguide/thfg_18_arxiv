# TH18 点道具（金钱道具）身价 —— 载体是 MONEY 的派生量、难度两表、唯一涨入口与收取高度系数

> **版本**：TH18 v1.00a（`local/th18.v1.00a/th18.exe`，imagebase `0x400000`；`.text` = VA `0x401000`–`0x4ac7ca`，文件偏移 `0x400`）。
> 本文裸地址默认属该版本；引用其他版本写作 `th13:0x42e9e5`。
> **方法**：一手平坦反汇编（`local/_scratch/th18_full.asm`，地址即 VA）+ 常量/表按 PE 节区 VMA 换算**直读原始字节**
> + 每个全局做**绝对寻址穷举**（逐条回指令边界；另用「立即数形态」反查确认全 exe 没有别处算过这些全局的基址）
> + 自写逐指令整数仿真（Python 复刻 `0x446b00` 两条分值支，与化简式逐值对照）。
> **可信度**：载体 / 量纲 / 难度两表 / 线上·线下两条分值支 / 涨跌入口穷举 = ✅；
> 「非金钱 item type 的语义身份」= 🟡（只读到它写哪些全局，没逐条追语义）；§6 是对 mods 侧既有数值的**订正**（有反证）。

## 0. 一句话结论

TH18 **没有**一个独立积累的「最大得点 / PIV」全局。所谓「身价」是**资金力（`0x4ccd34`，即本作的 MONEY）的派生量**，
在**每一次**收道具时现场重算：

```
ecx(身价, 1/1000 点) = clamp( (1 + MONEY) × K(难度) × 100 , 0x4ccd28 , 0x4ccd2c )
                        K = 500.0f(EASY) / 1000.0f(其余)        下限 0x4ccd28 / 上限 0x4ccd2c
```

然后引擎自己按**收取高度**乘一个系数（这就是 mods 侧说的 `coeff_06`）：
**线上（自机在回收线以上）或道具 `state == 3`（真空飞行）= 1.0**；
**线下 = `0.9 × (1 − d/450)`**，`d = trunc(player_y − poc_height)`（px，`0x446c17`–`0x446cf3`）。
最后：弹窗 = `10 × floor(ecx/1000)`（下限 10），`SCORE(0x4cccfc) += floor(ecx/1000)`，并 `MONEY += 1`。

⇒ 全链只有**一份**身价、**一个**弹窗、**一次** SCORE 落笔；**没有「基础身价 + 另一份额外项」的结构**（§5）。

## 1. 载体、量纲与使用点（✅ 穷举）

| 项 | 一手 |
| --- | --- |
| 身价（当前值，缓存） | `0x4ccd24`（每次收取重算并写回；除两个兜底分支外**无读者**） |
| 身价下限 / 上限 | `0x4ccd28` / `0x4ccd2c`（run 初始化写一次，之后只读） |
| **资金力** = MONEY | `0x4ccd34`（唯一乘数来源；商店花的也是它） |
| 难度 | `0x4ccd00`（`0`=EASY `1`=NORMAL `2`=HARD `3`=LUNATIC `4`=EXTRA：EXTRA 起关卡 `0x46605d` 直接写 4，且 `0x442666` 把「第 7 关」的索引抬到 ≥ 4） |
| SCORE | `0x4cccfc`（钳 `0x3b9ac9ff`） |
| 难度系数常量 | `0x4b93ac` = **500.0f**（EASY）、`0x4b93d4` = **1000.0f**（其余）、`0x4b9304` = **100.0f**（乘 100 那一步） |
| 回收线 / 自机 y | `player+0x47998`（ExpHP 名 `poc_height`，默认 128.0f）/ `player+0x624`（`zPlayer.inner` 的 y） |

**量纲链（`ecx` 的 1/1000 单位）**

```
ecx（身价，单位 = 1/1000 点）
  ├─ 线上/真空：esi(弹窗值) = 10 × floor(ecx/1000)          ← 单价是 10 的倍数
  ├─ 线下：     esi(弹窗值) = 10 × floor( 9q·(1 − d/450) / 10 )，q = floor(ecx/1000)   （≤ 10 时顶到 10）
  └─ 两条都走同一尾巴：SCORE += esi/10（`mul 0xcccccccd` + `shr edx,3`），钳 0x3b9ac9ff
```

⇒ **「点」= `ecx/1000`**；**弹窗显示值 = 10 × 点**（本作沿用 TH10/TH11/TH13 的「弹窗比入账大 10 倍」约定）。
⇒ 身价的**存储口径**：`(1+MONEY)×100000`（NORMAL 起），即「点数 = `(1+MONEY)×100`」量级。

**穷举口径（✅ 完整）**：逐条指令解析 `ds:` 绝对操作数得到
`0x4ccd24` **13** 处（1 初始化写 + 10 分支写 + 2 兜底读）、`0x4ccd34` **25** 处、`0x4ccd28` **9** 处、`0x4ccd2c` **5** 处。
另用「立即数形态」反查（`mov reg,0x4ccd…` / `lea`）得 **1 处命中，且是假阳性**：
`0x446b05 or BYTE PTR [ecx+0x4ccd00],ah` 落在 `0x446b06 mov eax,ds:0x4ccd00` 的**指令内部**
（`0x446b00` 才是函数头：`55 8b ec 83 ec 08` 之后的 `a1 00 cd 4c 00`）——
正是 [`METHOD.md`](../../../METHOD.md) 硬规矩 4 说的那种「字节序列命中 ≠ 指令边界命中」。
⇒ 全 exe **没有任何地方算过这些全局的基址**（无相对寻址形态），上面的清单就是**全部**读者/写者（含否定结论）。

## 2. 初值与上下限：`0x4ccd28` / `0x4ccd2c` 是**上下限**，值来自两张难度表

### 2.1 `0x4ccd28` / `0x4ccd2c` 的身份（✅）

它们是**身价的钳位界**，不是身价本身。初始化在 `0x442840`–`0x4428cd`
（`GameThread__thread_start`，`esi = ds:0x4ccd00` = 难度）：

```
442840  eax = [esi*4 + 0x4b666c] * 100     ; imul eax, [esi*4+0x4b666c], 0x64
442848  edi = [esi*4 + 0x4b6654] * 100
44286e  ds:0x4ccd28 = eax                  ; ★ 下限 = 表A[难度] × 100
442898  ds:0x4ccd2c = edi                  ; ★ 上限 = 表B[难度] × 100
442887  xmm1 = (float)eax
44289e  xmm1 /= 100.0f ; 4428a6 xmm1 *= 100.0f   ; 数值上是恒等往返（源码残留）
4428ae  eax = (int)xmm1
4428b2  if (eax >= edi) eax = edi          ; 先夹上限
4428ba  if (eax <  ds:0x4ccd28) eax = ds:0x4ccd28   ; 再夹下限
4428cd  ds:0x4ccd24 = eax                  ; ★ 身价初值 = 下限（= 1,000,000）
```

### 2.2 两张表的地址与每难度常数值（直读原始字节 ✅）

| 难度 | `0x4b666c`（下限表） | `0x4ccd28`（×100） | `0x4b6654`（上限表） | `0x4ccd2c`（×100） |
| --- | --- | --- | --- | --- |
| 0 EASY | 10000 | 1,000,000 | 200000 | 20,000,000 |
| 1 NORMAL | 10000 | 1,000,000 | 500000 | 50,000,000 |
| 2 HARD | 10000 | 1,000,000 | 700000 | 70,000,000 |
| 3 LUNATIC | 10000 | 1,000,000 | 1000000 | 100,000,000 |
| 4 EXTRA | 10000 | 1,000,000 | 500000 | 50,000,000 |
| 5（未用） | 100000 | 10,000,000 | 1000000 | 100,000,000 |

- 原始字节：下限表 `10270000 10270000 10270000 10270000 10270000 a0860100`；
  上限表 `400d0300 20a10700 60ae0a00 40420f00 20a10700 40420f00`（各 6 项，索引 5 无路径可达：难度由菜单写 0–4，
  EXTRA 走 `0x46605d` 写 4 且 `0x442666` 抬到 ≥ 4）。
- 换算成「点」（÷1000）：下限恒 **1000 点**；上限 = **20000 / 50000 / 70000 / 100000 / 50000 点**（E/N/H/L/EX）。

### 2.3 「资金力」（`0x4ccd34`）的上下限

- **没有任何显式钳位**（✅）：写点共 8 处（§3.1），其中 3 处带**前置门**（≥ 价格 / ≥ 200 / 减 `min(M/3,100)` 恒非负），
  其余是 `inc` 与「赋值」；全 exe 找不到对 `0x4ccd34` 的 `cmp`+`cmov` 式夹取 ⇒ **上限只受 `int32` 与身价上限的间接影响**。
- 「200（`0xc8`）」不是货币上限，是**卡的开门条件**：`0x40a516`（自动灵击让位）、`0x40da10`（六文钱救命）。
- 资金力**吃得动身价**：身价 = `(1+MONEY)×K×100`，因此 `MONEY ≥ 0x4ccd2c/(K·100) − 1` 之后身价**饱和在上限**
  （EASY 上限 20,000,000 ⇒ `MONEY ≥ 399` 封顶；NORMAL 50,000,000 ⇒ `≥ 499`；HARD 700 ⇒ `≥ 699`；LUNATIC 999）。

## 4. 金钱道具被收时的分值公式（逐指令）

### 4.0 入口与身价（`0x446b00` 头部）

```
446b00  prologue ; esi = ds:0x4cf410 (PLAYER_PTR) ; edi = ecx (ITEM)
446b18  xmm2 = [esi+0x624]              ; ★ 自机 y
446b20  eax = ds:0x4ccd00 (难度) ; if (eax > 4) → 0x446bf3 ; jmp [eax*4+0x446d40]
        跳表 0x446d40 = {0x446b30, 0x446b86, 0x446b86, 0x446b86, 0x446ba3}
446b30  xmm1 = (float)ds:0x4ccd34 ; × 500.0f  ; + 500.0f ; × 100.0f      ; 难度 0 = EASY
446b86  xmm1 = (float)ds:0x4ccd34 ; × 1000.0f ; + 1000.0f ; × 100.0f     ; 难度 1..3
446ba3  同上 1000.0f（只是钳位代码排布不同）                            ; 难度 4 = EXTRA
446b58  ecx = (int)xmm1
446b62..446b84  夹到 [0x4ccd28, 0x4ccd2c] 并写回 0x4ccd24
446bf3  （难度 > 4 的兜底）ecx = ds:0x4ccd24
446bf9  ← ★ 汇合点：ecx = 身价（1/1000 点），esi = PLAYER，edi = ITEM
```

`(x × K + K) × 100` 就是 `(1 + MONEY) × K × 100` —— 一次乘法被写成「`x*K + K`」是编译产物，
**EASY 系数 500、其余 1000**（✅ 与线索一致；常量按 PE 换算直读：`0x4b93ac` = `0000fa43` = 500.0f、
`0x4b93d4` = `00007a44` = 1000.0f、`0x4b9304` = `0000c842` = 100.0f）。

### 4.1 分支判据（谁算「线上」）

```
446bf9  xmm0 = [esi+0x47998]            ; poc_height（默认 128.0f / Kanako 224.0f）
446c01  comiss xmm0, xmm2               ; poc_height vs 自机 y
446c04  jae 0x446cb4                    ; ★ poc_height >= 自机 y ⇒ 线上（自机在回收线以上）
446c0a  cmp DWORD PTR [edi+0xc74], 3    ; 道具 state == 3（真空飞行）
446c11  je 0x446cb4                     ; ★ 或已被回收线吸住 ⇒ 线上
446c17  （否则）线下支
```

- `esi` 是 `PLAYER_PTR`（`0x4cf410`，ExpHP 静态名同名），`+0x624` 是 `zPlayer.inner` 的 y
  （`zPlayer+0x620 = inner`，`zPlayerInner+0x4` = y；同函数 `0x446030` 那处用它减道具坐标算碰撞距离）。
- 回收线字段就是 `player+0x47998`，ExpHP 名为 **`poc_height`**；Kanako 卡把它设成 224.0f（`0x40c275`），
  效果 = 回收线下移 ⇒ 线上区间变大（✅ 与 [08-catalog.md](../../card/th18/08-catalog.md) 卡 22 的登记一致）。

### 4.2 线上（或 `state == 3`）：系数 = 1.0（`0x446cb4`–`0x446cf6`）

```
446cb4  eax = 0x51eb851f ; imul ecx ; sar edx,5 ; (+符号修正)   ; edx = ecx/100 = V100
446cd2  idiv 10                        ; q = V100/10, r = V100%10
446cd9  ecx = V100 − r                 ; 丢掉个位（= 10q）
446cdb  imul 0x66666667 ; sar edx,2    ; q
446ce7  esi = 5q ; esi += esi          ; ★ esi = 10q = 10 × floor(ecx/1000)
446cf1  if (esi <= 0) esi = 10         ; 下限 10（保证至少 +1 分）
446cc0  push 0xffffff00                ; 弹窗颜色（黄）—— 三参里最先压栈，故在分支开头
```

⇒ **弹窗值 = `10 × floor(身价/1000)`；SCORE += `floor(身价/1000)`**（下方 4.4 的公共尾巴）。

### 4.3 线下：`0.9 × (1 − d/450)`（`0x446c17`–`0x446cf3`）

```
446c17  eax = 0x51eb851f ; imul ecx ; sar edx,5 ; (+符号修正)     ; V100 = ecx/100
446c37  idiv 10                        ; q = V100/10, r = V100%10 ; edi = r
446c3f  eax = r − V100 ; 446c41 ecx = 9*eax
446c49  imul 0x66666667 ; sar edx,2 ; (+符号修正)                 ; ecx = −9q
446c4b  eax = (int)xmm2                ; ★ d = trunc(自机 y − poc_height)，xmm2 在 446c1c 已差过
446c59  imul ecx,eax                   ; ecx = −9q·d
446c5c  eax = 0x91a2b3c5 ; 446c61 imul ecx ; 446c66 add edx,ecx ; 446c6a sar edx,8
                                       ; ★ = 有符号 ÷450（见 §6：0x91a2b3c5 = ceil(2^40/450)）
446c63  eax = V100 ; 446c68 sub eax,edi                    ; eax = 10q
446c6d  esi = (edx>>31) + edx          ; = −9q·d/450
446c72  ecx = 9*(10q) ; 446c7c imul 0x66666667 ; sar edx,2 ; edx = 9q
446c86  esi += edx                     ; esi = 9q − 9q·d/450 = 9q(1 − d/450)
446c88  ecx = (edx>>31) + esi          ; （edx = 9q ≥ 0 ⇒ 恒等于 esi）
446c8f  imul 0x66666667 ; sar edx,2 ; (+符号修正)          ; /10

446c39  push 0xffffffff                ; 弹窗颜色（白）—— 三参里最先压栈，故在分支开头
```

**化简式（✅ 仿真逐值核对）**

```
线上/真空：SCORE += q                     q = floor(ecx/1000)
线下：     SCORE += floor( 0.9 · q · (1 − d/450) · 10 ) / 10
                     = floor( 0.9 · q · (1 − d/450) )   （先按 10 取整，再 ≥1 下限）
           d = trunc(player_y − poc_height) ≥ 1 px
```

实测表（自写仿真器，`ecx` = 身价，弹窗值 = `esi`，入账 = `esi/10`）：

| `ecx` | `q` | 线上入账 | d=0 | d=100 | d=200 | d=300 | d=400 | d≥450 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1,000,000 | 1000 | 1000 | 900 | 700 | 500 | 300 | 100 | 1 |
| 20,000,000 | 20000 | 20000 | 18000 | 14000 | 10000 | 6000 | 2000 | 1 |
| 100,000,000 | 100000 | 100000 | 90000 | 70000 | 50000 | 30000 | 10000 | 1 |

⇒ 线下是**线性折扣**：贴着回收线 0.9、每 100 px 掉 0.2·q、`d ≥ 450` 落到下限（弹窗 10 ⇒ **+1 分**）。
⇒ 「离回收线越远 ⇒ 越不值钱」是引擎的设计意图 ✅；🟡 但 `450` 这个尺度与「游戏区高度/自机 y 可达范围」的对应关系**本文没量**

## 6. ⚠ 订正：线下除数不是 163.18，而是 **450**

mods 侧现有文档（`SCORE-LAYER-REWORK.md` §1 第 ⑦ 条、`native/sdk_core.h` 注释）把 `0x446c5c` 的魔数读成
「乘 `2^40/(0x91a2b3c5 + 2^32)`」⇒ 除数 **163.18**，于是曲线写作 `0.9 × (1 − d/163.18)`。本次一手复核**否定这个除数**：

- **① 发现**：`imul eax(=0x91a2b3c5), ecx` 是**有符号**乘法（`f7 e9`），随后 `add edx,ecx` 是**补正**，
  于是整段的含义 = 无符号魔数 `M = 0x91a2b3c5` 的 **÷2^(32+8)**，即除数 `D = 2^40 / M`。
- **② 反证（数值）**：`M = 0x91a2b3c5 = 2443359173`，而 `ceil(2^40/450) = 2443359173` —— **逐位相等**；
  `2^40/M = 449.99999997` ⇒ 除数就是 **450**。而 `M + 2^32` 这种算法没有指令依据（`add edx,ecx` 的正是
  「把负魔数的高位补回无符号口径」，不是「分子加 2^32」）。
- **③ 逐值验证**：把 `0x446c17`–`0x446cf3` 逐指令仿真，`d = 100/200/300/400` 分别落到 `0.7/0.5/0.3/0.1` 倍
  （见 §4.3 表）—— 与 `1 − d/450` 全等；若用 163.18，则 `d = 200` 起就已被顶到下限 10（= +1 分），
  与「`d ≥ 450` 才落底」的指令结构（`cmovle esi,10` 只在末尾）矛盾。
- **④ 结论**：线下系数 = `0.9 × (1 − d/450)`，`d` 单位 px ✅。
  ⚠ **mods 侧文档/注释里的 163.18 应改**（本文只做登记，未改 `mods/**`）。
- **⑤ 跨版本旁证**：TH13 的同类例程（`th13:0x42e9e5`–`th13:0x42ea9a`，判据用**道具 y** vs `th13:0x4ae9e8` = 128.0f）
  用的是**同一段魔数**（`th13:0x42ea52 mov eax,0x91a2b3c5` + `add edx,edi` + `sar edx,8`）与**同一个 ÷450**，
  只是系数是 **0.75**（`3*(r−V100)/4` 那一支）⇒ 形状 `k·(1 − d/450)` 是 ZUN 的跨作惯例，`k` 逐作不同
  （🟡 TH13 那支的门极性本文没复核，不属于本文范围）。
