# TH10 信仰 —— 载体、量纲、增减规则与「蓝点分 = 信仰」

> **版本**：TH10 v1.00a（`th10.exe`，487,936 B，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th11:0x…`。
> **方法**：一手平坦反汇编（`objdump -d -M intel`，产物 `local/_scratch/th10_full.asm`）+ 常量按 PE 节区 VMA 换算直读原始字节
> + ExpHP 社区符号只取词汇（`local/vendor/th-re-data/data/th10.v1.00a/`）+ 与 TH11 同形代码交叉对照。
> **可信度**：量纲、增减规则、蓝点主链、否定结论全部 ✅（指令原文 + 常量原字节，已逐条复核）；「Boss 阶段超时」的触发语境与线下公式的常量命名 🟡。

## 0. 一句话结论

TH10 的**信仰**（ExpHP 名 `CURRENT_PIV__SCALED`）是一条**独立的计分基准**，载体 `GLOBALS+0xc` =
`0x474c4c`；**显示值 = 存储值 × 10**，初值与下限都是**显示 50000**，上限 **显示 999990**。
它**只由三类信仰点道具供养**（大/小/微），只有三条回落路径（miss / 非决死灵击 / Boss 阶段窗口到时），
并且**直接就是点道具的身价**：线上蓝点得分 = 信仰，**没有任何乘数**。

两条负结论同等重要：

| 被否定的说法 | 一手事实 |
| --- | --- |
| TH10 有「擦弹倍率 `min(graze×0.0001, 8.99)`」 | ❌ **不存在**：`0.0001f` 全 exe 唯一处 `0x470c58` 只被 `fcomp` 当 epsilon 用；无 `8.99f`；13 个计分入口无一处读擦弹 |
| TH10 有「擦弹计数器」 | ❌ **不存在**：擦弹判定/火花/音效都有，擦弹处理体只置子弹自己的去重标志，不写任何计数器（§4.2） |
| TH10 有「连击槽空 ⇒ 逐帧扣信仰」 | ✅ **存在**：三条门全满足且槽 `0x474c58 <= 0` 时每帧 −180 显示（**§3.2b**）。本文旧版说「不存在」是**绝对地址 grep** 漏掉 `eax` 相对寻址所致 |

## 1. 载体、量纲与上下限

| 项 | 一手 |
| --- | --- |
| 信仰（存储） | `0x474c4c` = `GLOBALS+0xc`（`GLOBALS` = `0x474c40`） |
| 显示 = 存储 × 10 | 三重独立证据见下 |
| 初值 / 下限 | **显示 50000**（存储 `0x1388`）：`0x417931 push 0xc350` 喂 `set_faith`；下限出现在 `0x412948`、`0x412e94`、`0x426a2a`、**`0x418a3c`（逐帧衰减，见 §3.2b）** |
| 上限 | 存储 `0x1869f`（显示 999990），`add_to_piv` 的钳位 |
| 与难度无关 | 初值是常数（`0x417931`），跳表里没有它 —— 与 TH11 的「按难度给初值」不同 |

**★ 显示 = 存储 × 10 的三条独立证据**

1. `0x417941 call 0x418b80`（`set_faith`），而 `0x418b80` 内部把参数 `/10` 后才写 `[ecx+0xc]` ⇒ 传入的是显示单位。
2. **回放往返**：存档 `0x4290d3 mov ecx,ds:0x474c4c` 存**内部值**；读档 `0x4292f2`–`0x4292f8` 先 `lea eax,[eax+eax*4] / shl eax,1`（**×10**）再喂 `set_faith`。
3. **弹窗一致性**：大信仰点弹窗（`0x41b5ae push 0xff00ff00` → `0x42b9c0`）显示的数字与 `add_to_piv` 造成的显示增量相等。

**★ 定点约定（四条，TH10 与 TH11 完全不同，别搬）**

| 函数 | 语义 | 一手 |
| --- | --- | --- |
| `add_to_score(x)` `0x409d90` | `CURRENT_SCORE += x/10`，钳 `0x3b9ac9ff` | 魔数 `0x66666667` + `sar edx,2`；分数显示另按 ×10 画（HUD 10 位，第 10 位单独存 scorefile 字节） |
| `add_to_piv(x)` `0x41be80` | `信仰 += x/10`，钳 `0x1869f` | `0x41be9a cmp eax,0x1869f` |
| `sub_412e70(x)` `0x412e70` | `信仰 += (−x)/10`（**负魔数** `0x99999999`），钳 `0x1388` | `0x412e8a cmp eax,0x1388` |
| `set_faith(x)` `0x418b80` | `信仰 = x/10`（并重置连击计时器） | `0x418b93 mov [ecx+0xc],eax` |

## 2. 信仰 → 分数：全部落点

### 2.1 点道具（type 2，蓝点）主链 `0x41b4aa`

```
0x41b4aa: fld [edx+0x3c4] ; fcomp ds:0x470cd4 (144.0f)   ; 道具 y ≥ 144 → 线下分支
0x41b4bd: mov eax,ds:0x474c4c      ; ★ 信仰(存储)
0x41b4c2: lea ebx,[eax+eax*4] ; shl ebx,1   ; ×10 → ebx = 显示信仰（再向下取整到 10 的倍数，此处置恒为 0）
0x41b542: mov esi,ds:0x477840      ; POPUP_MANAGER
0x41b54a: push 0xffffff00          ; 黄色弹窗，显示 ebx
0x41b55e: call 0x405b60            ; Globals::add_to_rank(8)
0x41b569: call 0x409d90            ; ★ CURRENT_SCORE += 信仰×10/10 = 信仰
0x41b575: call 0x412ff0 (push 0x64) ; 连击计时器 +100
```

⇒ **线上（道具 `y < 144.0f`）显示得分 = 信仰本身，无乘数**。这也解释了这个量的名字：它是「点道具的价钱」。

**线下（`y ≥ 144.0f`）**：`0x41b4d5`–`0x41b52b`

```
= 5×信仰 − int( (y − 144.0f) × 0.003289473708719015 × (0.5×信仰 − 5000.0f) )
  再向下取整到 10 的倍数；弹窗色 0xffffffff
常量（.rdata 原字节）：0x470cd4 = 144.0f、0x470cd0 = 0.0032894737、0x470ce0 = 5000.0f、0x470b0c = 0.5f
```

### 2.2 type 5（点道具的另一档）`0x41b537`

`mov ebx,ds:0x474c4c` / `lea ebx,[ebx+ebx*4]` / `shl ebx,1` ⇒ 同样是**信仰×10**，**不判高度**，并入 `0x41b542` 的合流。

### 2.3 符卡奖励 `0x409874`

```
0x409879: lea eax,[eax+eax*2+0xa]  ; 3×stage + 10
0x40987d: imul eax,ds:0x474c4c     ; × 信仰(存储)
0x409884/87: ×5 / shl 1            ; ×10 → 奖励以「×10 单位」计
0x409889: cmp eax,0x5f5e100        ; 上限 100,000,000；zSpellcard+0x3794 钳 0x5f5e0ff
结算：0x409c85 imul 0x66666667（/10）→ 0x409c9d mov ds:0x474c44（SCORE += bonus/10）
```

⇒ **符卡奖励（显示分）= `(3×stage + 10) × 信仰`**；弹窗（`0x4172e0`）显示的正是这个数。

### 2.4 关卡结算 `0x416c70`（`GuiMsgVm::run`）

`imul eax,eax,0x3e8` ⇒ **显示分 += 信仰 × 100**；同段还有难度跳表给的残机/火力加成
（E `0x1312d00`、N `0x17d7840`、H `0x2160ec0`、L/EX `0x2625a00`；`0x416dfd` 终关重复同一套）。

### 2.5 不含信仰的计分口（对照）

击破敌机用的是 ECL 声明的 `[enemy+0x13bc]`（`0x40e231`–`0x40e23d`），与信仰、擦弹都无关。

## 3. 信仰的增减规则

### 3.1 增：道具分派表 `0x41b3c0`（`jmp [eax*4+0x41b8a0]`，`eax = type−1`）

| type | 语义 | 落点 | 信仰 | 连击计时器 |
| --- | --- | --- | --- | --- |
| 1 / 10 | P 点（红） | `0x41b3d5` | — | +60 |
| 2 | 点道具（蓝） | `0x41b4aa` | — | +100 |
| 3 | **大信仰点** | `0x41b57f` | **+5000 / +8000 / +10000** | +120 |
| 4 / 11 | 大 P | `0x41b62e` | — | +20 |
| 5 | 点道具（满额档） | `0x41b537` | — | 并入合流 |
| 7 | 1UP | `0x41b6fd` | — | +0 |
| 8 | **微信仰点** | `0x41b5d6` | **+10** | +3 |
| 9 | **小信仰点** | `0x41b5fc` | **+100** | +60 |

大信仰点的难度表（`0x41b57f`，索引 = `[0x474c74]` = 0..4 = E/N/H/L/EX）：

```
跳表 0x41b8cc = {0x41b595, 0x41b595, 0x41b59c, 0x41b5a3, 0x41b5a3}
0x41b595 → ebx = 0x1388 (E/N, 5000) ; 0x41b59c → 0x1f40 (H, 8000) ; 0x41b5a3 → 0x2710 (L/EX, 10000)
```

### 3.2 减：四条（写入点穷举；★ 2026-09-15 补上**逐帧衰减**那一条）

| 路径 | 一手 | 效果（显示单位） |
| --- | --- | --- |
| **miss**（`0x4269d0`，由 `0x425aa4` 调用） | `0x4269da lea edi,[esi-0x1388]` + 魔数 `0x55555555` + `sar edx,1` ⇒ `信仰 −= (信仰−5000)/3`；`0x426a2a` 钳 `0x1388` | 显示 `−=(信仰−50000)/3`，地板 50000 |
| **非决死灵击** | `0x425a15 push 0xbb8` + `0x425a1f call 0x412e70` | 显示 **−3000** |
| **Boss 阶段窗口到时** | `0x412932 mov eax,ds:0x474c4c` / `0x412937 sub eax,0xbb8` / `0x412948` 钳 | 显示 **−30000** |
| ★ **连击槽空 ⇒ 逐帧衰减** | `0x418a17`–`0x418a3c`（门在 `0x418740`–`0x418a5d`，见 §3.2b） | 显示 **−180/帧 = −10800/秒**，地板 50000 |

⚠ 上表前三条的**绝对寻址**穷举（`grep 'ds:0x474c4c'`）看不到第四条，因为第四条整个走
**`eax` 相对寻址**（`eax = 0x474c40` ⇒ `[eax+0xc]`）；这正是本文 2026-09-15 之前漏掉它的原因。

### 3.2b ★ 逐帧衰减 + 连击槽（2026-09-15 新增；口径与 `0x474c58` 的每帧 −1 完全同源）

`0x418a00` 是一个只被调用一次的小函数（**唯一调用点 `0x418764`**），它同时做「槽倒数」与
「信仰衰减」两件事：

```
418a00: mov ecx,[eax+0x18]        ; [0x474c58] = FAITH_TIMER.current（eax = 0x474c40）
418a03: test ecx,ecx / jle 0x418a17   ; ★ 槽 <= 0 ⇒ 跳到衰减；槽 > 0 ⇒ 只走下面这三条
418a08: push 0xbf800000 (-1.0f) / lea esi,[eax+0x14] / call 0x44bf40   ; 槽 -1/帧
418a16: ret
418a17: mov ecx,[eax+0xc]         ; [0x474c4c] 存储信仰
418a1a: mov esi,0x1388            ; 地板 = 存储 5000（显示 50000）
418a1f: cmp ecx,esi / jle 0x418a3f
418a23: mov edx,[eax+0x10]        ; [0x474c50] 速率
418a26: sub ecx,edx               ; 存储 -= 速率
418a28: cmp edx,0x12 / jge 0x418a37
418a30: mov DWORD PTR [eax+0x10],0x12   ; ★ 速率**就地**抬到下限 18（机器码 c7 40 10 12 00 00 00）
418a37: cmp [eax+0xc],esi / jge 0x418a3f
418a3c: mov DWORD PTR [eax+0xc],esi     ; 下钳 5000
```

**门 = 三条同时成立才跑**（`0x418740`–`0x41875d`，任一不满足跳 `0x418769` 直接跳过**整段**）：

| # | 地址 | 条件 | 语义 |
| --- | --- | --- | --- |
| ① | `0x418746` | `[ENEMY_MANAGER(0x477704)+0x10] == 0` | **当前没有 Boss**。那个字段是 **boss 对象指针**（非 0 时被解引用：`0x414adc` 读它的 `+0x23fc` 符卡计时画奖励条、`0x41217b`/`0x416142`/`0x41e760` 读 `+0x1068` 坐标 / `+0x2480` 标志）⇒ **不是「场上有没有敌人」** |
| ② | `0x418751` | `[GUI(0x47770c)+0x9eb8] == 0` | 没有对话 VM（= 不在对话中） |
| ③ | `0x418759` | `[edi+0x14] >= 0x5a`（90），`edi` = `g_GameThread` | 开场 90 帧（1.5 s）之后 |

⇒ ★★ **「连击槽为空」在这一手代码里不是门、而是 `0x418a06` 的 `jle` 分叉**：
槽 > 0 只 −1 帧、槽 ≤ 0 才扣信仰（**这一分叉与「门」是两件事**，别混）。
⇒ ★★ 因为槽的 −1 与信仰的衰减**在同一个函数、同一组门之后**，
**Boss 战 / 对话中 / 关卡前 90 帧内，槽与信仰一起冻结**（不是「槽照常倒数但不扣信仰」）。

**速率字段 `0x474c50` 的写点穷举**（绝对寻址 2 处 + 衰减自身的指针形态 1 处）：

| 地址 | 值 | 场景 |
| --- | --- | --- |
| `0x417a00` | **9** | 关卡开始（`mov DWORD PTR ds:0x474c50,0x9`，机器码 `c7 05 50 4c 47 00 09 …`）；紧接 `push 0x4187c0` 注册每帧任务 |
| `0x40e26b` | **1** | 敌机死亡处理路径（`c7 05 50 4c 47 00 01 …`；同段 `0x40e261 or [enemy+0x1444],0x2000` 置「已死已处理」位，随后 `0x40e27b call 0x4127a0`） |
| `0x418a30` | **18** | 衰减自身把速率抬到下限 |

⇒ ★ **有效速率恒 ≥ 18 存储/帧**（`0x418a30` 在本函数内、**读完 `0x418a23` 之后紧接执行** ⇒ 那两个写入值
`9`/`1` 在下一帧就被覆盖，字段**单调不减**）⇒ 实战 **−18 存储/帧 = −180 显示/帧 = −10800 显示/秒**。
⚠ **与社区/用户口径的冲突（🟡 如实登记）**：用户口径（TH10 老玩家，2026-09-15）记的是两档 ——
「槽空时**屏幕上无敌人 −10800/s、有敌人 −600/s**」，其中 **600/s = 1 存储/帧**恰是 `0x40e26b` 写的那个值。
但按上面的写点/读点穷举，**1 那一档在本 build 里读不出来**（它只在「本关第一次扣信仰恰好发生在某只敌人
死亡之后」那一帧生效，之后即被抬到 18）。⇒ 「两档」这条本文**不背书**，标 🟡；若确实观测到慢档，
需要重查是否另有版本 / 另有取速率的路径（本 build 的完整写点穷举已给，见上表）。

### 3.3 「全避 / 时符超时」的定案

`0x4127a0` 全函数（`0x1a0` 字节）逐条读过：该处**唯一判据**是**阶段计时器 `current ≥ 窗口结束值`**（`0x4128c2`
`cmp eax,[edi+0x2498]`，不到就 `0x4128c8 jl` 退出）；**没有任何**「本阶段是否被弹 / 是否放过灵击 / 是否全避」的读位。

- ⇒ ✅ 一手：**代码里不存在「全避 −30000」这条判据**，「时符必减」也没有独立分支。
- 🟡 未实测：捕获符卡时敌机 ECL 是否也会把同一计时器推到 end（若会，则捕获同样扣）—— 需要实跑或再查一层 `0x409c00` 的时钟副作用。
- 同函数另一分支写 HUD：`0x412890 add esi,0x3b` + 魔数 `0x88888889`/`sar edx,5` ⇒ **剩余秒数**写进 `GUI+0x9ec0`（HUD 那个 2 位数字是**Boss 阶段剩余秒数**，不是倍率）。

### 3.4 连击条（`FAITH_TIMER` `0x474c54`）

- 充能入口 `0x412ff0(frames)`，**上限 130**（`0x412ff0 cmp [edi+0x18],0x82`、`0x413035 mov [esi+0x4],0x82`、`0x41303c mov [esi+0x8],0x43020000`(=130.0f)）。
- **每帧 −1** 在 `0x418a10`（`zTimer::add(&GLOBALS+0x14, -1.0f)`，前置 `0x418a06 jle` 要求 `current > 0`）。
- ★ 读者有四个，**其中第一个驱动信仰衰减**（2026-09-15 订正；旧版这里写「只有三个」）：
  `0x418a00`（**槽 ≤ 0 ⇒ 信仰开始逐帧衰减**，见 §3.2b）、`0x4158b6`（画槽）、
  `0x426434`（信仰环绘制）、回放存/读 `0x4290dc`/`0x42a4cb`。
- ★★ **「槽空 ⇒ 扣信仰」存在**（§3.2b）：三条门全满足且槽 ≤ 0 时，**每帧 −180 显示**（速率下限 18 存储 × 10），
  地板存储 5000。社区那对「无敌人 −10800/s、有敌人 −600/s」里，**−10800/s 与本文的一手值同值**
  （18 存储 × 10 × 60）；**−600/s 那一档在一手里读不出来**（速率字段被就地抬到 18，见 §3.2b 的 🟡）。
- ⚠ 本文旧版那句「`0x474c54` 只被 HUD / 回放读」是错的 —— 漏点就是 `0x418a00` 走 `eax` 相对寻址
  （`[eax+0x18]`，`eax = 0x474c40`）。

### 3.6 满 P 时 P 类道具被改写（`ItemManager::spawn_item` `0x41bb00`）

```
0x41bbf7: cmp WORD PTR ds:0x474c48,0x64   ; 火力 = 100 单位 = 5.00（满）
0x41bc09: movzx ecx,BYTE PTR [eax+0x41be28]   ; 索引表，下标 = type−1
0x41bc10: jmp DWORD PTR [ecx*4+0x41be1c]      ; 跳表 {0x41bc1e, 0x41bc17, 0x41bc23}
```

⇒ **type 1 / 4（P 点、大 P）→ 9（小信仰点）；type 10 / 11（P 点变体）→ 5（点道具）**，其余不变。

## 4. 擦弹：判定存在，倍率与计数器都不存在

### 4.1 「擦弹倍率」的否定证据（可复现）

| # | 查法 | 结果 |
| --- | --- | --- |
| A | 全 exe 扫 `float 0.0001f` | 唯一命中 `0x470c58`；4 个引用全是 `fcomp DWORD PTR ds:0x470c58`（`0x4075f1`、`0x407606`、`0x41d337`、`0x41d349`）⇒ `fpatan`/`fabs` 的「是否为零」，不是乘数 |

### 4.2 擦弹判定与擦弹事件体（`0x4266b0`）

```
0x4266b0  Player::check_bullet_against_player(bullet_halfsize, bullet_pos, player)
  内层：敌弹中心 ± 半径×0.5 的 AABB 与自机 hurtbox(player+0x404..0x414) 重叠 ⇒ return 1（被弹，走 0x426cf0）
  外层：敌弹中心 ± 24.0f（0x470be8 = 24.0f，.rdata 原字节 00 00 c0 41）再测一次 ⇒ return 2（★擦弹）
  都不中 ⇒ return 0
```

擦弹事件体（`0x4064d9`–`0x406517`）**只做三件事**：置 `[bullet+0] |= 0x4`（本弹已擦过，去重）、
在子弹位置生成 `bullet.anm` **script 434**（`0x4064f7 push 0x1b2`，12 帧火花）、
播 `se_graze.wav`（id `0x1c`，`0x406514 call 0x43dd10`，声像 = 子弹 x）。

⇒ **没有任何 `inc`/`add`/`mov` 写向计数器**（`0x406240`–`0x4065c0` 全区间的 `inc/dec/add/sub [mem]` 扫描零命中；
`0x40e2c0`–`0x40e300` 同样）。另一处调用点 `0x40e2df`（`EnemyData::on_tick` 里撞敌机）**返回值被丢弃** ⇒ 只有视觉。

> 音效 id 不是名字表下标：`id → u16@(0x4749c8 + 8*id)` = 名字下标，`0x474b40 + 4*下标` 才是字符串。
> `0x1c` → 22 → `"se_graze.wav"`。（旁证：`0x1d`→se_powerup、`0x1b`→se_timeout、`0x2c`→se_extend、`0x26`→se_slash 全部与已知语义吻合。）
