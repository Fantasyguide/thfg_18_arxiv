# 章节面板 — 几何（图心锚）与关面板的两段淡出（TH15 一手）

> **版本**：TH15 v1.00b（`th15.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；
> 引用其他版本须写成 `th18:0x…`。
> **方法**：`thanm` 解包 spec（`local/th15.v1.00b/anm/front/front.anm.txt`）+ 逐条反汇编
> （`objdump -d -M intel`，PE 段内偏移核对）+ 本仓 2026-09-09 的实机留档。
> **可信度**：✅ 主体（锚点 / 可见块 / 两段淡出 / 文字 alpha 来源都有地址）；
> 🟡 两处（面板显示时长与 `mode` 的对应；`alphaTime` 到位的第 0 帧取值）。
> **缘起**：TH18 卡 115（绀珠传）的 `card-expand` 移植要复刻这块面板的**位置锚点**与
> **淡入淡出帧数**，owner 实跑报了三条（`mods/th18.v1.00a/card-expand/SINGLE-CARD-TEST.md` §th15 #1/#2/#3）。

## 0. 一句话结论

**面板七条子 VM 都用默认锚点（`anchor(0,0)` = 图心）**，所以 `pos` 是每条**可见内容块的中心**、
可见块 = **192×32** 的原生内容（不是 256 画布）；**关面板**走 `interrupt_tree(label 1)`：
六条标签条各自 `alphaTime(10, 0, 0)`（10 帧），而**五行数值跟的是父 VM 的 `color_1.A`**、
父 VM 自己 `alphaTime(20, 0, 0)`（20 帧）—— 也就是**条 10 帧 / 字 20 帧**两段不同长的淡出。

## 1. 面板 = `front.anm` script241 + 七个子脚本（补 §4a）

`local/th15.v1.00b/anm/front/front.anm.txt` 一手：

| VM | 脚本 | sprite | 相对父的 `pos` | 自己的淡出 |
| --- | --- | --- | --- | --- |
| 父 | 241 | 无（`type(0)` 无 sprite） | `(448, 402)` | `interruptLabel(1); alphaTime(20, 0, 0); +20: delete()` |
| 标签条 | 244–248 | 145 / 146 / 147 / 149 / 148 | `(0,0)` `(−64,50)` `(−64,90)` `(−64,130)` `(−64,170)` | `interruptLabel(1); alphaTime(10, 0, 0); +10: delete()` |
| 碎片条 | 242 / 243 | 150（符卡碎，绿）/ 151（残机碎，粉） | `(0,240)` | 同上（另外 `+90` 后才 `scaleTime(10,0,1,1)` 展开） |

- 父 VM 与七个子的关系是 `scriptNew()`（子 VM）——**`anchor` 一个都没写**；
- 每条 sprite 的原生矩形都是 **192×32**（`front02.png` 的 sprite145..151，见 entry 的 sprite 表）。

## 2. 锚点 = **图心**（`anchor(0,0)`）：三条独立证据

| # | 证据 | 说明 |
| --- | --- | --- |
| a | **引擎语义** | `anchor`（op 421）不写就是 `AnmVm::wipe` 的清零值 `(0,0)`，而锚点表里 `(0,0)` = **居中**（`engine/anm/th18/02-render-stages.md`；角公式见 `engine/anm/th18/03-ascii-text.md`）|
| b | **实机（本仓留档）** | 2026-09-09：把 192 宽的内容贴在 256 画布**左**侧时，用户看到整条**偏左**；把内容居中后就正了（`mods/th18.v1.00a/card-expand/assets/ability/make_lolk_ring_art.py` 注释）。**只有图心锚会有这个症状**（左锚时应当偏右 32 px）|
| c | **TH15 自身数据自洽** | `Gui::on_draw_2e` 的五行文字 y = 226/246/266/286（640 空间）×2 = 452/492/532/572，与四个标签子脚本 245–248 的 `pos.y`（402+50/90/130/170）**逐个相等** ⇒ 文字落在条的**中心线**上；按左上角算的话文字会贴在条的**上沿**、与美术里居中的标签错开 16 表面 px |

**旁证（非判据）**：同文件其它 UI 脚本要角锚时会**显式**写 `anchor(1,1)`（如 script2 / script6），
面板这七条一条都没写 ⇒ 默认值就是设计意图。

**推论（表面 px，卡 115 的落笔几何）**：每条可见块 = `(VM pos) ± (96, 16)`；
`DX ∈ {0, −64}`、`DY ∈ {0, 50, 90, 130, 170, 240}` ⇒ 整块外接盒
= **x [AX−160, AX+96]、y [AY−16, AY+240+16]**（第六碎片条在场时）。

## 3. 关面板：`Gui::on_tick` → `interrupt_tree(label 1)`

| 步 | 地址 | 事实 |
| --- | --- | --- |
| 判定 | `0x435551`–`0x435561` | `eax = gui+0x1a4`（显示计时）≥ `gui+0x1b4`（时长）⇒ 调 `0x43b0f0` |
| 关面板 | `0x43b0f0` | `push 1` + `push [gui+0x11c]` + `call 0x488620` ⇒ **给面板树发 label 1**；随后改 `gui+0x19c` 的 `0x800/0x1000` 两位 |
| 广播 | `0x488620`（ExpHP: `AnmManager::interrupt_tree`）| 取 VM → 调它的中断回调（表 `0x4cb4c8`，下标 `vm+0x5dc`）→ 写 `vm+0x49c = label` → **再对 `vm+0x598` 的子链上每个子 VM 做同样的事** |

⇒ label 1 同时到达父（241）与七个子（242–248）：
**条各自 10 帧淡出，父 20 帧淡出**（父自己没有 sprite，它的 alpha 只被"文字"读走 —— 见 §4）。

**时长值**（`gui+0x1b4`，来自 `engine/chapter/th15/01-chapter-and-bonus.md` §4c 的 `mode` 表）：
`mode 0` = `0x122` = **290 帧**、`mode 1` = `0xdc` = 220 帧 🟡（"帧"这一层是从 `0x435551` 的比较
推出来的：两个值同一量纲，且 `+0x1a4` 在同一函数里被逐帧推进）。

## 4. 五行数值的 alpha = 面板父 VM 的 `color_1.A`

`Gui::on_draw_2e` `0x436990` 起，画五行之前：

```
436ad7  call 0x488510        ; AnmManager::get_vm_with_id(mgr, gui+0x11c)  ← 面板**父** VM
436ae6  mov  al,[eax+0x53b]  ; VM 的 color_1.A
436aec  mov  [esi+0x19227],al ; AsciiManager 的颜色字节（esi = 0x4e9a58，色 dword 在 +0x19224）
```

- `vm+0x53b` = `color_1.A` 的判据：插值器 `AnmVm::step_interpolators` `0x47becf` 写的就是这个字节
  （`Th15` 的 VM 布局里 `color_1` 比 TH18 的 `+0x524` 靠后 `0x14`）；
- 于是**文字与面板共用同一个 alpha 源**：显示期都是 255，关面板时父 VM 走 `alphaTime(20,0,0)`，
  字跟着 20 帧淡完（比六条条晚 10 帧 —— 这是原版的实情，不是我们算错）。

**推论**：TH15 的面板**没有 alpha 淡入**：出现 = 六条 `scale(0.0f,1.0f)` → `scaleTime(10,0,1,1)`
横向展开（10 帧），五行文字从面板 VM 存在的那一帧起就是满 alpha。

## 5. 落笔（TH18 卡 115 的对位）

| TH15 | 卡 115 的落笔 |
| --- | --- |
| 七条子 VM，父 pos `(448,402)` | 六条独立 UI VM，位置 `(LOLK_PANEL_AX + DX, LOLK_PANEL_AY + DY)`（**pos = 图心**，见 §2）|
| 可见块 192×32 / 条 | 判据矩形按 `pos ± (96,16)` 现算（`panel_rect()`）|
| 关面板：条 10 帧（脚本）/ 字 20 帧（父 VM 的 alpha）| 条仍是脚本里那 10 帧（照抄）；**字没有父 VM ⇒ C 侧打 20 帧**`LOLK_PANEL_FADE_FRAMES` |
| 出现：`scaleTime(10,0,1,1)`（无 alpha 淡入）| 照抄（脚本 107–112/116 一字未改）|
| "靠近就变淡" | **原版没有这个行为**（卡 115 自定，owner 口径）；过渡帧数借 §3 的 `alphaTime(20,0,0)` |

## 6. 还没钉死的（🟡）

1. **`alphaTime(t, mode, target)` 在 t 帧里的第 0 帧取值**：本文按"从当前值线性、t 帧后到位
   （每帧步长 = Δ/t）"实现（`panel_dim_tick()`）；引擎侧只核到 `mode 0 = 线性`（`engine/anm/th16/07-general.md`），
   没逐帧对过插值器的取整。
2. **`gui+0x1b4` 的单位**：本文按帧（290 / 220）用；若它其实是 640 空间的时间刻度，数字要重算。
3. **面板显示时长与卡 115 的 `LOLK_HUD_HOLD`（300 帧）**：一手值 290（mode 0）更接近原版，
   但**没改**（不在 owner 这三条的口径内），登记在 `mods/th18.v1.00a/card-expand/TUNING.md` §7.5。
