# TH10 输入面 —— 四个输入字、位掩码与「按键 8 帧 → 派生一个位」

> **版本**：TH10 v1.00a（`th10.exe`，487,936 B，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th11:0x…`。
> **方法**：一手平坦反汇编（产物 `local/_scratch/th10_full.asm`）+ 对 `0x474e5c` 等全局做 disp32 字节穷举
> （**只当候选发现器**；任何判定回到指令边界复核）。
> **可信度**：输入字/快照/位掩码/「按住或上帧按住」形状/8 帧派生结构 ✅；
> **「没有双击方向键」是穷举出来的否定结论** ✅；派生位对应的**按钮身份** ❓（§3 末）。

## 0. 一句话结论

TH10 每帧有**四个**输入字和三个快照，全部是 16 位：

| 地址 | 语义 | 一手 |
| --- | --- | --- |
| `0x474e5c` | **游戏输入位（派生后）** | `test BYTE PTR ds:0x474e5c,0x2`（灵击 `0x4259b5`）、`test …,0x4`（低速 `0x4251a5`） |
| `0x474e5e` | 上一帧的 `0x474e5c` | `0x40a4a4: mov ds:0x474e5e,ax`（同段 `0x40a4a0` 先写 `0x474e5c`） |
| `0x474e36` | **原始/已边沿处理的输入** | `0x40a4b8: test al,0x8`；菜单里 `test [0x474e36],bit` |
| `0x474e34` | 上一帧的 `0x474e36` | `0x4238ad`、`0x42c04b` 等 |
| `0x474e30` | 原始输入的当前值（`0x474e36` 的来源） | `0x40a570` / `0x40a58a` 一对 |
| `0x474e62` / `0x474e64` | 键盘路径写出的输入字与其上帧 | `0x429809: mov WORD PTR ds:0x474e5c,cx`（cx = `0x474e30 & 0x1f7`）、`0x4298b2` |
| `0x474e5a` | **「某键按住」计数器（上限 8）** | `0x429818`–`0x429837` |

**位掩码与 TH11 完全一致**（方向解码 `0x4250b3`–`0x425163`，与 `th11:0x430310`–`0x430340` 逐条同形）：
↑`0x10` ↓`0x20` ←`0x40` →`0x80`、低速 `0x4`、灵击 `0x2`、射击 `0x200`。

**两条结论**：

1. TH10 的**边沿/重复键**形状是「现帧 `test` + 上帧 `test`」（`0x4238a4`/`0x4238ad` → `push 0xffffffff` 当重复键），
   **不是**下降沿检测；真正的边沿只在菜单/文字输入那一对（`0x40a570`/`0x40a58a`）。
2. **TH10 没有「双击方向键」判定**（§4 的六条穷举）；但它有**「某键按住 8 帧 ⇒ 派生一个位」**这一形状（§3）。

## 1. 方向位掩码与「松开」判据

```
4250b3: mov al,ds:0x474e5c
4250c0: and cl,0x50 ; cmp cl,0x50 → 5（上+左）      4250e5: and dl,0x60 ; cmp dl,0x60 → 7（上+右）
4250fb: and cl,0x90 ; cmp cl,0x90 → 6（下+左）      425111: and dl,0xa0 ; cmp dl,0xa0 → 8（下+右）
425127: test al,0x20 → 2（下）   425137: test al,0x10 → 1（上）
425143: test al,0x40 → 3（左）   425153: test al,al ; jns → 4（右 = bit 0x80）
```

「松开」不是独立事件，而是**同一个 `test` 在现帧与上帧上的组合**：

```
4238a4: test BYTE PTR ds:0x474e36,0x10   ; 现帧：上
4238ad: test BYTE PTR ds:0x474e34,0x10   ; 上帧：上
4238b4: je 0x4238bf                      ; 两帧都没按 → 跳过
4238b6: push 0xffffffff                  ; 否则当「按住/重复」处理
```

## 2. 唯一的「派生一个位」结构（`ReplayManager::on_tick_0b__record_or_playback_replay` `0x4297d0`）

```
4297ea: mov eax,ds:0x474e5c          ; 当前派生输入
4297ef: mov ecx,DWORD PTR ds:0x474e30 ; 原始输入
4297f5: mov ds:0x474e5e,ax           ; 存上帧快照
429800: and ecx,0x1f7                ; 屏蔽 bit3 / bit11
429806: test ah,0x2 ; je 0x429849    ; bit9（X = 灵击）没按 → 跳过整段
429812: mov al,cl ; 429814: test al,0x1 ; je 0x429842    ; ★ bit0 松开 → 计数器清零
429818: mov ax,WORD PTR ds:0x474e5a ; 42981e: inc ax ; 429820: cmp ax,0x8 ; mov ds:0x474e5a,ax
42982a: jb 0x429849                  ; 未到 8 帧 → 继续
42982c: or cx,0x4 ; 429830: mov ds:0x474e5c,cx          ; ★ 派生位 = 低速（0x4）
429837: mov WORD PTR ds:0x474e5a,0x8                    ; 钳在 8
429842: mov ds:0x474e5a,dx                              ; 清零
```

⇒ **「某键按住到 8 帧 → 把一个派生位打进输入字」**。TH11 的同形结构（`th11:0x436000`–`0x43607b`）派生的是
**组合位 `0x400`（射击+↑）**，见 [th11/01 §3](../th11/01-special-detection.md)。

## 3. ❌ TH10 没有「双击左/右方向键」判定

穷举过的形状（可复核）：

| # | 查法 | 结果 |
| --- | --- | --- |
| A | `0x474e5c` 的全部读点（disp32 穷举） | **20 处**；与方向位配对的只有 `0x4250b3`–`0x425163`（纯电平、无计时）与低速位 `0x41b74e`。**没有一处是左/右的上升沿** |
| B | `0x474e30`/`34`/`36` 与方向位配对处 | 全部是「现帧或上帧按住」的重复键模式（后跟 `push 0xffffffff`/`0x1`/`0xd`），**没有跟随窗口倒计时** |
| C | `0x474e34`（上帧）的全部读点 | 全是上/下（`0x10`/`0x20`）的重复键，**没有左/右配对** |
| D | TH10 的 Player 区（`0x4246c0`–`0x428280`，含 `Player::move` `0x4250b0`） | 除 A 的两处外**没有任何输入读取** |
| E | 重放系统的输入派生（`0x4297e0` 一带） | 只有「补 combo / 连发」逻辑（§2），**没有窗口计时器** |
| F | 与方向位配对的计时器字段 | 搜不到「`cmp …,8/0xa` 之后 `dec` 同一字段」的形状 |

⇒ **TH10 没有双击**。TH10 里与「边沿/时序」有关的只有三样：① 菜单/文字的现帧+上帧对照（`0x474e30`/`0x34`）；
② `0x40a570`/`0x40a58a` 的「按住或上帧按住」；③ §2 的「按住 8 帧 → 派生位」。
**TH11 的缺口瞬移是把 ③ 的「8 帧」复用成「两次方向输入之间的窗口」**，TH10 里没有对应实现
（见 [player/th11/02 §1](../../player/th11/02-support-special-effects.md)）。

## 4. 结论表 / 还缺什么

| # | 断言 | 可信度 |
| --- | --- | --- |
| 1 | 四个输入字/快照的地址与关系 | ✅ 一手 |
| 2 | 方向位与功能位掩码（↑`0x10` ↓`0x20` ←`0x40` →`0x80`、低速 `0x4`、灵击 `0x2`、射击 `0x200`） | ✅ 一手（解码器逐条） |
| 3 | 「按住或上帧按住」= 重复键形状，不是边沿检测 | ✅ 一手 |
| 4 | 存在「按键 8 帧 → 派生位」结构（计数器 `0x474e5a`，钳 8；TH10 派生 `0x4`） | ✅ 一手 |
| 5 | **不存在双击方向键判定** | ✅ 一手（六路穷举 + 20/20 读点） |
| 6 | 派生位对应哪个**按钮** | ❓（`test al,0x1` 与方向解码的低位映射对不上，位表未从 `.rdata` 挖出） |
| 7 | 手柄按钮配置表（`0x4c93de` 一族的 TH10 对应物）未查 | — |
