# TH11 输入面与六个支援特技的判据 —— 含组合位 `0x400`

> **版本**：TH11 v1.00a（`th11.exe`，688,128 B，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th10:0x…`。
> **方法**：一手平坦反汇编（产物 `local/_scratch/th11_full.asm`）+ disp32 字节穷举 +
> **按指令边界重读复核**（本仓纪律：字节穷举只当候选发现器）。
> **可信度**：输入字/位掩码/组合位的两个产生点/六条判据 ✅；`0x4c92b0`/`0x4c92b4` 的来源 ❓。
> **效果侧**（缺口状态机、形态切换、子机数组）见 [`../../player/th11/02-support-special-effects.md`](../../player/th11/02-support-special-effects.md)。

## 0. 输入面（后面全部引用这一段）

| 地址 | 语义 |
| --- | --- |
| `0x4c93c0` | **游戏输入位掩码**（`INPUT`）；`Player::move`、射击、灵击、菜单全读它 |
| `0x4c93c2` | 上一帧的 `INPUT`（同一 DWORD 的高 16 位；写入见 `0x436008`） |
| `0x4c92a8` | `HARDWARE_INPUT`（回放录制/回放的输入源；键盘路径的低 16 位由 `0x457a05` 写） |
| `0x4c92ac` | `HARDWARE_INPUT` 的上一帧 |
| `0x4c93cc` | **「组合位」输入字**（含 `0x400` = 射击+↑）；生产者见 §3 |
| `0x4c93c4` | 录制回放时保存的旧 `INPUT`（`0x40d653` / `0x436008`） |
| `0x4c92b0` / `0x4c92b4` | 菜单「现帧 or 上帧」重复键判定的一对 ❓（来源未找到） |

**位掩码**（方向解码 `0x430310`–`0x430340` 与 `0x4302b4`/`0x4302c8`/`0x4302de`/`0x4302f7`）：

| 位 | 含义 | 一手 |
| --- | --- | --- |
| `0x10` / `0x20` / `0x40` / `0x80` | 上 / 下 / 左 / 右 | `0x430320` / `0x430310` / `0x430330` / `0x430340`（组合位 `0x50`/`0x60`/`0x90`/`0xa0` 定对角） |
| `0x4` | 低速 / Focus | `0x43036d: shr eax,3; and eax,1` → `zPlayer.is_focused` |
| `0x1` | 射击（Z） | `0x4343a7`、`0x436029` |
| `0x2` | 灵击（X） | `0x4311dd` / `0x431279` |
| `0x100` / `0x200` / `0x800` | 手柄按钮 2 / 3 / 5（配置表 `0x4c93de`/`0x4c93e2`/`0x4c93ec`）；**机体逻辑里没用** | `0x457314`–`0x457382` |
| **`0x400`** | ★ **组合位：射击 + ↑ 同帧按住** | 见 §3 |

**边沿工具**：`0x40de10` —— 用 `[+0x118]`(当前) 与 `[+0x11c]`(上帧) 同时算出「本帧新按下」`[+0x124]`
与「本帧新松开」`[+0x128]` 两个掩码。**这是 TH11 唯一的通用边沿工具**（没有 TH18 那种一次性 `INPUT_PRESSED` 数组）。

## 1. 六个支援特技的判据（组合号 = `3×CHARACTER(0x4a5710) + SUBSHOT(0x4a5714)`）

| 组合 | 角色 | 判据（一手） | 计数器字段 |
| --- | --- | --- | --- |
| 0 | 霊夢×紫 | **贴边**（x 已被钳到 ±`0x5c00`）后按该方向置状态 1/3；**8 帧内**再按同方向 ⇒ 触发 | `+0x920`（state）/ `+0x924`（frames） |
| 1 | 霊夢×萃香 | `attempted_direction == 0` 且 `INPUT & 0x9 == 0` 连续 **> 10 帧** | `+0x8ba4` |
| 2 | 霊夢×文 | `INPUT & 0x9 == 0` 连续 **> 10 帧**（**不读射击位**） | `+0x8ba8` |
| 3 | 魔理沙×爱丽丝 | **无输入检测**（被动） | — |
| 4 | 魔理沙×帕秋莉 | `INPUT_B(0x4c93cc) & 0x400`（射击+↑ 同帧） | `+0x8bac`（formation） |
| 5 | 魔理沙×荷取 | **无输入检测**（在 Bomb 状态机里） | — |

分派点：`0x43075c`（组合 0）、`0x43077a`（1）、`0x430651`（2）、`0x4308e3`（4）；组合 1/2 还额外要求
`player+0x948 == 3`（可操作状态）。

**缺口瞬移的窗口（`0x430e50` 状态机）**：state 2/4 时 `cmp DWORD PTR [ebx+0x924],0x8` / `jg` 超时归零
⇒ **二次窗口 = 8 帧**；state 99/100 的演出 45 帧（`0x43104d`）。触发门另要求 GUI 对话 VM 为空、
`[ENEMY_MANAGER+0x70] == 0`，且**按到上/下（`INPUT & 0x9`）会取消**（`0x430e79`）。
⇒ 用户口径的「**松开射击键**后双击」**证伪**：全函数唯一的输入读点是 `&0x9`。

## 2. 组合 4 的组合位 `0x400` 是怎么来的

```
436003: mov eax,ds:0x4c93c0 ; 436008: mov ds:0x4c93c4,eax        ; 存旧值
43600d: movzx eax,WORD PTR ds:0x4c92a8 ; 436014: mov ds:0x4c93c0,eax   ; 本帧 INPUT = HARDWARE_INPUT 低 16 位
436019: je 0x43605a                    ; （来自上一条 test，配置位 0x4c3480 & 0x200）
43601b: test al,0x8 ; 43601d: je 0x436029
43601f: or eax,0x400 ; 436024: mov ds:0x4c93c0,eax   ; ★ 产生点 1（↑ 已按）
43605a: test al,0x1 ; 43605c: je 0x436080            ; 射击
43605e: mov ecx,ds:0x4c933c ; cmp ecx,5 ; jae 0x436080
436069: test al,0x8 ; 43606b: je 0x436080            ; ↑
43606d: cmp DWORD PTR ds:0x4c9348,5 ; jae 0x436080
436076: or eax,0x400 ; 43607b: mov ds:0x4c93c0,eax   ; ★ 产生点 2
```

⇒ `0x400` 的语义 = **「射击(bit0) 与 ↑(bit3) 在同一帧都处于按住状态」**（电平，无计时器、无快照比较），
两个产生点**都在每帧执行的键盘输入函数里**。

`0x4c93cc` 的写入者（穷举）：`0x40d663`（= `HARDWARE_INPUT`，录制/回放路径）、`0x436229`（回放）、
`0x43629c` / `0x4362d1`（回放结束清零）—— 都在 `0x435fe0`/`0x436190` 的 ReplayManager 实现里；
键盘路径下它与 `0x4c93c0` 同源（`0x43600d`）。

> ⚠ **`0x400` 是 TH11 特有**：TH18 的输入面是 `0x4ca428` + `INPUT_PRESSED`。要复刻「射击+↑ 切形态」，
> 必须在 TH18 侧自己按这个语义合成；用「射击+低速」**不符原版**（`0x4` 与 `0x400` 无构造关系）。
>
> ⚠ **方法论**：本文第一稿曾把「键盘路径不产出 `0x400`」写成结论，错因是**用字节子串穷举**
> （`0x436022` 落在 `or eax,0x400` 的立即数里、`0x436025` 的首字节是前一条指令的尾巴）。
> 改用 `objdump --start-address/--stop-address` 逐条重读后结论反转。

## 3. 与 TH10 的差别

| 项 | th10 | th11 |
| --- | --- | --- |
| 输入字 / 上帧 | `th10:0x474e5c` / `th10:0x474e5e` | `th11:0x4c93c0` / `th11:0x4c93c2` |
| 「按键 N 帧 → 派生位」 | ✅ 射击按住 **8 帧** ⇒ 低速 `0x4`（`th10:0x4297d0`，计数器 `th10:0x474e5a`） | ✅ 射击+↑ 同帧 ⇒ 组合位 `0x400`（`th11:0x436000`–`0x43607b`） |
| 双击方向键 | ❌ **不存在**（六路穷举，见 [th10/01 §3](../th10/01-input-face.md)） | ✅ 缺口瞬移的 8 帧窗口 |
| 通用边沿工具 | 无（菜单用现帧/上帧两次 `test`） | ✅ `th11:0x40de10` |

## 4. 结论表 / 还缺什么

| # | 断言 | 可信度 |
| --- | --- | --- |
| 1 | 三个输入全局 + 组合位字 + 上帧快照的地址与关系 | ✅ 一手 |
| 2 | 位掩码（方向 4 位、低速 `0x4`、射击 `0x1`、灵击 `0x2`、手柄 `0x100`/`0x200`/`0x800`） | ✅ 一手 |
| 3 | 组合位 `0x400` = 射击+↑ 同帧；两个产生点都在每帧键盘路径 | ✅ 一手（指令边界复核） |
| 4 | 六个特技的判据与计数器字段；缺口窗口 8 帧；萃香/文阈值 >10 帧 | ✅ 一手 |
| 5 | 缺口**不要求松射击键**；萃香/文的判据**不含**射击位 | ✅ 一手否定 |
| 6 | `0x4c92b0`/`0x4c92b4` 的写入者 | ❓ |

**还缺什么**

- ❓ `0x4c92b0`/`0x4c92b4` 的真实来源（菜单/暂停的重复键判定用；字节子串穷举在这里会假命中，
  需要按操作数位置扫或读 Ghidra 交叉引用表）。
- ❓ 组合 4 长按（射击+↑）的实际切换速率：判据是电平，理论上会每帧切一档，但没找到冷却字段、也没实测。
- ❓ 组合 5（荷取）的状态机细节在 Bomb 侧（`th11:0x407720`），见 [player/th11/02 §6](../../player/th11/02-support-special-effects.md)。

