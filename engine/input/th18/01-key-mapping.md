# th18 输入系统 —— 键盘配置、掩码位、replay 读写点、以及哪些位空着

> **版本**：TH18 v1.00a（`th18.exe`，md5 `9969cac756098c1da05a81de45437a70`，imagebase `0x400000`）。
> 本文裸地址默认属该版本；引用其他版本写成 `th16:0x…`。
> **方法**：一手反汇编（capstone 直读 exe，逐条指令带地址）+ 直读 `.data` 配置表 + IAT 名字解析
> （`GetKeyboardState` = `0x4ad1d0`、`XInputGetState` = `0x4ad280`、`joyGetPosEx` = `0x4ad278`）+
> 逐位写了一个**逐条转写 `0x401c50` 的仿真**（§2.4）+ 对三份掩码的全部字面引用做穷举（§3.2）。
> 社区（ExpHP `th-re-data`）只提供函数**词汇**，不给结论。
> **可信度**：配置表、位→键表、replay 读/写点、播放标志、C/D 消费者 = ✅ 一手；
> 「某位没人置 / 没人读」= ✅（穷举 + 逐条复核指令边界）；`[th18:0x4cf2e4+0xb0]` 的位义 = 🟡。

## 0. 一句话

TH18 每帧的输入是**一条装配线**：

```
GetKeyboardState(栈上 256 字节，VK 索引)  ┐
XInput 1_3 (XInputGetState)              ├─► 原始掩码 zInput+0x00 (th18:0x4ca210) ─► 边沿/连按 (0x42abc0)
DirectInput 手柄 (joyGetPosEx + 配置表)   ┘                                        │
                                                                                  ▼
                            游戏读的掩码：INPUT_HELD th18:0x4ca428（+0x0c = 按下沿 0x4ca434）
```

**只有 `0x4ca428` 的低 16 位进 replay**（录制 = `movzx eax,WORD PTR ds:0x4ca210` → 写 6 字节/帧）。
⇒ 「能不能进 replay」= 「这个位在不在低 16 位里」，而且**必须是引擎自己会置的位**（见 §3）。

## 1. 键盘配置表（一手：直读 exe + 菜单代码）

三个设备各一份 profile，间距 `0x14`（= 5 条 × 4 字节）：

| 设备 | 基址 | 每条的含义（出厂值）|
| --- | --- | --- |
| 1 DirectInput 手柄 | `th18:0x4ca448` | 按钮号：`0`/`1`、`2`/`5`、空、空、`3`/`4` |
| 0 XInput 手柄 | `th18:0x4ca45c` | 表索引：`0`/`1`、`5`/`10`、空、空、`2`/`3`（表见下）|
| 2 **键盘** | `th18:0x4ca470` | VK：`Z`(0x5a)/`X`(0x58)、`Shift`(0x10)/`Esc`(0x1b)、空、空、`C`(0x43)/`D`(0x44) |

- 每条 = 两个 16 位值（低 word / 高 word）= 动作对 `Shot/Bomb`、`Slow/Pause`、…、`Item/Change`；
  `0xffff` = 未绑定（读的地方都先 `test ax,ax` / `js` 跳过）。
- XInput 的那一列不是按钮位本身，而是**表索引**：`th18:0x4b4320` = A(0x1000) / B(0x2000) / X(0x4000) /
  Y(0x8000) / LB(0x100) / RB(0x200) / LT(0x10000) / RT(0x20000) / Back(0x40) / Start(0x80) /
  LThumb(0x10) / RThumb(0x20)（`0x4ca45c` 出厂 = Shot→A、Bomb→B、Slow→RB、Pause→LThumb、Item→X、Change→Y）。
- **方向键（←↑→↓）与小键盘 1..9 不在表里** —— 它们由装配里写死的 VK 直接读（§2.1）。
- 键位设置菜单的五个可改项 = `Shot / Bomb / Slow / Item / Change`（串在 `th18:0x4b66a0` 起），加 `Pause` 与 `Default`。
- 设备探测结果写 `th18:0x4ca444`（`0x401df4`–`0x401dfb`：键盘掩码相对手柄掩码**有变化**就置 `2` = 键盘）。

## 2. 掩码位：逐位（一手：`0x401c50` 的移位链逐键解出）

### 2.1 键盘路径（`th18:0x401c50`）

`th18:0x401c83` `GetKeyboardState(lea eax,[esp+0x10])` ⇒ 栈上 `esp+0x10` 起 256 字节 VK 索引表
（所以「VK `0x23`」读的是 `[esp+0x33]`）。之后是一串**换位装配**：先把 `Shot/Bomb/Slow` 塞进高位，
再每加一个键就 `shr esi,k` 把它挪到最终位。逐条转写（`+0x10` 是缓冲区基址）：

| 指令 | 读的键（VK）| 落到哪一位 |
| --- | --- | --- |
| `0x401ca6` / `0x401cb1` / `0x401cb3` | `Z`（表 `0x4ca470`）、`X`（表 `0x4ca472`）| `Z→bit0`、`X→bit1` |
| `0x401cc4` / `0x401cc9` | `Shift`（表 `0x4ca474`）| `bit3` |
| `0x401cb5` + `0x401cd5` / `0x401cd9` | `↑`(0x26) + 小键盘 `8`(0x68) / 小键盘 `2`(0x62) | `↑ → bit4` |
| `0x401ce6` + `0x401cef` | `↓`(0x28) / 小键盘 `4`(0x64) | `↓ → bit5` |
| `0x401cfc` + `0x401d01` | `←`(0x25) | `← → bit6` |
| `0x401d48` + `0x401d87` | `→`(0x27) / 小键盘 `6`(0x66) | `→ → bit7` |
| `0x401d71` / `0x401d7b` | `Esc`（表 `0x4ca476`）| `Pause → bit8` |
| `0x401d5c` / `0x401d65` | `C`（表 `0x4ca480`）| `Item → bit10` |
| `0x401d39` / `0x401d50` | `D`（表 `0x4ca482`）| `Change → bit11` |
| `0x401d1f` / `0x401d30` | `Home`(0x24) / `P`(0x50) | `bit18`（`0x40000`）|
| `0x401d14` / `0x401d24` | `Enter`(0x0d) | `bit19`（`0x80000`）|
| `0x401c9c` / `0x401d05` | `End`(0x23) / `R`(0x52) | `bit21`（`0x200000`）|
| `0x401da4`–`0x401ded` | 小键盘 `3`/`9`/`1`/`7` | **对角**：`0xa0` / `0x90` / `0x60` / `0x50`（两个方向位一起置）|

> 小键盘 `1/3/7/9` 是对角（同时置两个方向位），`2/4/6/8` 走上面的直线位；
> 小键盘 `0` / `5` **没有读**（缓冲区偏移里找不到 `0x70`/`0x75`）⇒ 按了不进掩码。
> `P`(0x50) 与 `R`(0x52) 是**写死的键**（不在配置表里），分别与 `Home`、`End` 共用一位。

### 2.2 手柄两条路径

- **DirectInput**（`th18:0x401650`，读 profile `0x4ca448` 的按钮号 + `joyGetPosEx` 的轴）：
  按钮 → `bit0/bit1/bit3/bit8/bit10/bit11`；轴过阈值（`0x4cd004`/`0x4cd006`）→ `bit6/bit4/bit7/bit5`。
- **XInput**（`th18:0x401860`，`XInputGetState` `0x4ad280`）：扳机 `≥ 0x1e` → **临时标志字** bit16/bit17
  （只用于查表 `0x4b4320`，**不是掩码位**）；左摇杆 `y ≥ 0x1ea9` → 标志 bit0（= 射击）、`y ≤ -7849` → bit1
  （= 炸弹）；`x ≥ 0x1ea9` → bit3、`x ≤ -7849` → bit2（这两个只喂给方向映射）；方向映射与六个动作
  走 `0x4ca45c` 那份 profile 查表 → 掩码 `bit0/bit1/bit3/bit8/bit10/bit11` + `bit4..bit7`。

**手柄两条路都不置 `bit2`（`0x004`）、`bit9`（`0x200`）、`bit12..bit15`、`bit18/19/21`**（§3.1）。

### 2.4 三条独立对账（这就是为什么上表可以当结论用）

1. **仿真复现**：把 `0x401c50` 逐条转写成脚本、单键按下逐键跑，得到 {`Z→0x1`、`X→0x2`、`Shift→0x8`、
   `↑→0x10`、`↓→0x20`、`←→0x40`、`→→0x80`、`Esc→0x100`、`C→0x400`、`D→0x800`、`Enter→0x80000`、
   `Home/P→0x40000`、`End/R→0x200000`、小键盘 1/3/7/9 → 对角两位} —— 与 §2.1 的逐条表一致。
2. **引擎自己的掩码反查**（最硬的一条）：仿真给出的 `Enter + Z` = `0x80001` **正是** `th18:0x440a6b`
   的立即数；`Esc + Z + X + Enter` = `0x80103` **正是** `th18:0x4439f7` 的立即数。两个掩码都是 ZUN
   自己写的 ⇒ 位分配被引擎侧独立证实。
3. **量纲/常识关**：小键盘 3/9/1/7 = 右下/右上/左下/左上（对角两位）与键盘布局一致；
   `Shift` 落在 `bit3`，而 `th18:0x45b3fa` 正是 `INPUT_HELD >> 3 & 1`。

## 3. 空位：哪些位没有任何设备会置 / 哪些位没人读

### 3.1 从没被任何设备置的位（✅ 三条装配路径逐条核过）

**`0x004`(bit2)、`0x200`(bit9)、`0x1000`(bit12)、`0x2000`(bit13)、`0x4000`(bit14)、`0x8000`(bit15)**。

> 注意 `0x40000`/`0x200000`（Home|P、End|R）虽然**有键置它**，但落在**低 16 位之外** ⇒
> 录制时被 `movzx … WORD` 截掉、回放时也不会被喂回来 ⇒ 对 replay 而言等于不存在（§4.1）。

### 3.2 其中哪些位**没人读**（= 可以借）

穷举口径：把 `0x4ca428`（29 处）、`0x4ca434`（13 处）、`0x4ca210` 的全部**字面引用**逐条打开看掩码
（本文件已确认这三处没有「取地址当结构体用」的读者 —— 那样会漏），得到所有被读的位 = §2.3 第 4 列。

| 位 | 有人读吗 | 能不能借 |
| --- | --- | --- |
| `0x004` `0x1000` `0x2000` `0x4000` `0x8000` | **没有** | ✅ **可借**（五选一）|
| `0x200` | 有（三条读者，见 §2.3）| ❌ **不可借**：置上它 = 对话/Ending 立刻快进、回放被快进 |
| `0x40000` `0x200000` | 没有 | ❌ 借了也没用（低 16 位之外 ⇒ **不进 replay**）|

> 「没人读」的旁证：`Input__compute_edges` `th18:0x42abc0` 是**32 位逐位**循环（`cmp eax,0x80` 前 `eax += 4`），
> 它会为任何被置的位维护按住计数器（`0x4ca2a4 + bit*4` / `0x4ca3a4 + bit*4`）——
> 这些计数器**只有 bit0（`0x4ca3a4`）与 bit9（`0x4ca3c8`）**被别人读过（`0x462982`、`0x43e5be`、`0x440ab3`）⇒
> 借 `0x1000` 这类位不会顺带触发任何判定。

### 3.3 借位的写法（含「播放回放时不覆盖」）

1. **借哪一位**：推荐 `0x1000`（bit12），备选 `0x2000` / `0x4000`。**选哪一位是任意选择**
   （❓ 自定，登记 `TUNING.md`）；「这几位是空的」是 ✅ 一手。
2. **物理键**：用游戏不认识的键（`A` `0x41` / `S` `0x53`，一手：不在配置表、不是方向键），
   自己调 `GetKeyboardState`（SDK 的 `ce_key_down()`）。
3. **写在哪一个点上**（两条都已过 `sitecheck` W1–W4 + 落点栈中性，帧内顺序见 §4.4）：

   | 站点窗口 | 字节 | 写谁 | 为什么能进 replay |
   | --- | --- | --- | --- |
   | `th18:0x462966`（5 B）| `e8 55 82 fc ff` | `INPUT_HELD`（`0x4ca428`）| 在 `0x462961`（`INPUT_HELD = (uint16)raw`）**之后**、录制 `0x462a0d` **之前** |
   | `th18:0x46295a`（7 B）| `0f b7 05 10 a2 4c 00` | 原始掩码（`0x4ca210`）| 在 `movzx …WORD` **那一条之前** ⇒ 随后被搬进 `INPUT_HELD` 并录下 |

4. **只 OR、从不清位** ⇒ 下一帧引擎自己重写（`0x462961`），不会「按住不放」。
5. **播放回放时不覆盖 = 天然成立**：这两条都在 `ReplayManager__on_tick__record_replay`（`0x462940`）里，
   而**回放走的是另一个节点**的 `0x462a50`（注册点 `th18:0x461a2a`）⇒ 站点根本不命中
   （先例：`mods/th18.v1.00a/mouse-control` 的 hook 2 就挂 `0x462966`）。
6. **边沿**：写在 `0x462966`（= `call Input__compute_edges`）之前 ⇒ **引擎自己会为这个位算出**
   `INPUT_PRESSED` / `INPUT_RELEASED` ⇒ 卡侧直接读 `0x4ca434` 就有干净的「刚按下」，不用自己存 prev。

## 4. replay：写入点 / 读取点 / 播放标志

### 4.1 录制（写）—— `ReplayManager__on_tick__record_replay` `th18:0x462940`

```c
/* 0x462950 */ INPUT_HELD_PREV(0x4ca42c) = INPUT_HELD(0x4ca428);
/* 0x46295a */ INPUT_HELD = (uint16)RAW(0x4ca210);      // ★ movzx WORD —— 高 16 位被截掉
/* 0x462966 */ Input__compute_edges();                   // PRESSED/RELEASED/REPEAT 都在这算
/* 0x46296b */ if (SUPERVISOR.config & 0x200 && (INPUT_HELD & 1) && Z 按住 ≥10 帧) INPUT_HELD |= 0x8;
/* 0x4629f7 */ held16 = (uint16)INPUT_HELD;              // ← 录制读点（本帧的全部输入就这三个 16 位）
/* 0x462a05 */ pressed16 = (uint16)INPUT_PRESSED;  released16 = (uint16)INPUT_RELEASED;
/* 0x462a19 */ FUN_00463060(chunk, held16, pressed16, released16);   // 写 6 字节/帧
```

- `FUN_00463060`（`th18:0x463060`）逐条：`mov word [cursor],ax` / `[cursor+2]` / `[cursor+4]`、
  `cursor += 6`，超过 `0x1518` 字节返回 1 ⇒ `ReplayManager__new_replay_chunk`（`th18:0x4630e0`）换块。
- 同一函数每 30 帧还往另一条缓冲写**一个字节**（`0x4629bd`–`0x4629f1`，取 `[0x4cf2dc]+0x30` 的 float
  钳到 0..255）—— 那不是输入，别和输入流混为一谈。

### 4.2 回放（读）—— `ReplayManager__on_tick__playback_replay` `th18:0x462a50`

```c
/* 0x462a60 */ if (!(*(uint32_t*)(REPLAY_MGR+0x218) & 2)) return;   // ★ 播放标志
/* 0x462b3b */ INPUT_HELD     = *(uint16*)cursor;                    // ← 回放读点（每帧 6 字节）
/* 0x462b55 */ INPUT_PRESSED  = cursor[+2];
/* 0x462b6d */ INPUT_RELEASED = cursor[+4];
/* 0x462b72 */ Input__compute_edges();   /* 0x462b8f */ cursor += 6;
```

- 结束标记 = 三个 `0xffff`（`0x462af3`–`0x462b05`）⇒ 清三个掩码 + 调 `th18:0x4588f0` + 块索引置 `-1`。
- 回放期间**录制那条 tick 不跑**（两条节点各走各的门），所以回放时 `INPUT_HELD` 只有 file 这一个来源。

### 4.3 播放标志（三个，任取一个用）

| 判据 | 一手出处 | 可信度 |
| --- | --- | --- |
| `*(uint32_t*)(th18:0x4cf418) + 0x218` 的 **bit1**（`0x4cf418` = ReplayManager 单例）| 置 `th18:0x458a16`、清 `th18:0x463045`、读 `th18:0x462a60` | ✅ |
| `ReplayManager + 0x0c == 1` | `th18:0x461dc3`（回放加速那条 tick 的门）| ✅ |
| `zGameThread + 0xd0 != 0`（`CE_GT_REPLAY_PLAYING`，`engine.h` 已有）| 商店侧 `th18:0x417cd8` 等 | ✅（本仓既有）|
| `[th18:0x4cf2e4 + 0xb0]` 的位 | 置 `th18:0x45894e`（`or …,0x10`）；读 `th18:0x462c35`（`& 4`，另一位）| 🟡 位义未定 |

### 4.4 帧内顺序（注册优先级，一手；机制见 `engine/_shared/frame-loop.md` §4）

| 顺序 | 子系统 / 节点 | 优先级 | 注册点 |
| --- | --- | --- | --- |
| 0 | 输入装配（`0x401c50` 等，帧驱动里先于一切 tick）| — | `th18:0x401e19` 写 raw |
| 1 | ReplayManager 录制 / 回放 | `0x11` | `th18:0x46181e`+`0x461825` / `th18:0x461a2a`+`0x461a42` |
| 2 | AbilityManager（**卡侧 `on_tick_2` = `vtable+0x2c`**）| `0x16` | `th18:0x408475` push `0x16` → `0x408a90` → `0x408640` 的 `call [eax+0x2c]` |
| 3 | Player（**C/D 的消费者在这里**）| `0x17` | `th18:0x45a8aa` push `0x17` → `0x45caa0` → `jmp 0x45be90` |

注册表按节点 `+0x00` **升序**插入（`th18:0x4011d5`）⇒ 顺序 = `0x11 → 0x16 → 0x17`。
**这一条是三处结论的共同前提**：① 卡里写掩码能进 replay（写点在 1 之后、录制之前）；
② 卡里抹 `INPUT_PRESSED` 能阻断 C/D（卡在 2、消费者在 3，见 §5）；③ 鼠标 mod 看回放时自动失效。

### 4a. 「卡自己往掩码写空闲位、再读」的顺序 —— **已验：进得了 replay** ✅

原文这里标「顺序未验 🟡」，现在补齐（一手，逐条）：

- **录制读点 = `th18:0x46295a`**（`movzx eax,WORD PTR ds:0x4ca210`）→ `0x462961` 写进 `INPUT_HELD`
  → `0x4629f7` / `0x462a0d` 交给 `th18:0x463060` 落盘（§4.1）。
- **我们的帧钩子**挂不到「`0x46295a` 之前」（能挂的节点优先级都 `> 0x11`，而 `0x11` 是 ReplayManager 自己，
  见 §4.4 表）—— **但不需要**：挂在 `0x462940` **函数体内**的两个窗口就够（§3.3 第 3 条表）：
  `th18:0x46295a`（在那条 `movzx` **之前**，写 raw）或 `th18:0x462966`（在那条 `movzx` **之后**、
  录制 `0x462a0d` **之前**，写 `INPUT_HELD`）。
- ⇒ **写入会被录进 replay**（`0x463060` 拿到的就是我们写过的值），回放时由 `0x462b3d` 原样喂回
  `INPUT_HELD`；**且因为写在 `compute_edges` 之前，`INPUT_PRESSED` / `INPUT_RELEASED` 也带这个位**。
- **播放回放时不覆盖**：回放走 `0x462a50` 那条节点（§3.3 第 5 条），这两个窗口根本不命中。
- 先例（同款手法、已实跑）：`mods/th18.v1.00a/mouse-control` 的 hook 2 = `0x462966`，其 `AUDIT.md` §B 记
  「记录 replay 的 `0x463060` 在注入点之后 → 鼠标输入会一致地录进录像；且这是**录制**那条 on_tick，
  回放走 `0x462a50`，我们碰不到 ⇒ 看录像时自动失效」。

## 5. C / D 的消费者，以及「按住 Shift 让它们不生效」

### 5.1 两个动作实际做什么（一手）

| 键 | 掩码位 | 唯一消费者 | 动作 |
| --- | --- | --- | --- |
| `C`（配置名 **Item**）| `0x400` | `th18:0x45c084`（在 `Player__on_tick__body` `0x45be90`–`0x45ca8b` 内）| 发动**选中的主动卡**：`0x45c090 mov ecx,[mgr+0x38]` → `0x45c099 call [eax+8]`（= 卡虚表 `+0x08`）|
| `D`（配置名 **Change**）| `0x800` | `th18:0x45c09c`（同函数内）| `0x45c0b0 call th18:0x408b00` = `set_selected_active_card(mgr,-1)`（切到下一张 `flags&8` 的卡）+ 成功播 SE `0x4e` |

两条门控链（同一段）：`mgr(0x4cf298) != 0` → GUI 无对话（`0x4cf2e0`，`+0x1b0 == 0`）→ 关卡在跑
（`0x4cf2d0`，`+0x198 != 0`）。**读的都是 `INPUT_PRESSED`（`0x4ca434`）的上升沿**，不是电平、也不是原始键盘。

- 「唯一消费者」= 穷举：`0x4ca434` 的全部 13 处字面引用里，只有这 2 处读 C/D 位。
- **没有任何 mod 站点覆盖它们**：`sites.py` 的声明表里 `0x45c084` / `0x45c09c` 都空着
  （附近只有已 park 的 `ce_bomb_gate` `th18:0x45c048` 与 `ce_death_result` `th18:0x45c127`）。
- SDK 侧**只覆盖 C 的一半**：`sdk.h` 顶注 + `CE_CARD` 宏把卡虚表 `+0x08` 换成 `ce_s_c_press` →
  `ce_sdk_c_press`（`sdk.c`）—— 那是**被调用方**，只有我们自己的卡走它；
  **原生 57 张卡的 `c_press` 不受它管**，而 **D 完全不在 SDK 面里**
  （`engine.h` 的 `CE_FN_SET_SELECTED_ACTIVE` 只是「可以调它」，没有任何钩子）。

### 5.2 结论：阻断**可以只在 mod 侧做**，且**不需要新站点** ✅

利用 §4.4 的帧内顺序（卡 `0x16` < 消费者 `0x17`）：**在卡的 `on_tick_2` 里把 D 的上升沿位抹掉**：

```c
if (CE_INPUT_HELD() & CE_INPUT_FOCUS)                        /* Shift = INPUT_HELD bit3 */
    *(volatile uint32_t *)CE_ADDR_INPUT_PRESSED &= ~0x800u;  /* 0x4ca434 的 D 位清零 */
```

- 玩家 tick 的 `0x45c09c` 读到 0 ⇒ 不切卡、不播 SE `0x4e`。
- **只抹 `0x800`**：`INPUT_PRESSED` 的其他读者用 `0x201` / `0x80001` / `0x2` 三个掩码，位不相交 ⇒ 零误伤。
- **replay 一致**：录制（节点 `0x11`）在我们之前，流里存的是**真值**；回放时同一帧我们**同样再抹一次**
  ⇒ 录/放行为逐帧一致。（这也是「不能靠改 `INPUT_HELD` 阻断」的原因：那会把真值改掉、录进去就是假的。）
- ⚠ 只在**这张卡在卡组里**时生效（它的 `on_tick_2` 才会跑）—— 正是需要它的场合；
  卡被删 / 不在卡组 ⇒ 一个字节都不碰，D 恢复原生行为。
- ⚠ 商店里两边 tick 都不跑（同一个 `0x4cf2a4` 闸）⇒ 不会出现「只抹了半边」的错配。

### 5.3 如果非要引擎侧拦（**不建议**，仅备查）

| 站点 | 窗口字节 | 落点 | sitecheck |
| --- | --- | --- | --- |
| `th18:0x45c084`（C）| `f7 05 34 a4 4c 00 00 04 00 00`（10 B）| `0x45c09c` | W1 ✅ 10≥5 / W2 ✅ 1 条整指令 / W3 ✅ 窗内无分支（**不需要 `no_replay`**）/ W4 ✅ 零重叠 / L1 ✅ 跳过区净 esp=0 |
| `th18:0x45c09c`（D）| `f7 05 34 a4 4c 00 00 08 00 00`（10 B）| `0x45c0c1` | 同上 ✅ |

**不建议**的理由（供 owner 拍）：① 站点预算现实 = **我们 27 条 / `SITE_BUDGET` 24（记账线）、
进程级 47 / 42（42 已知崩过）**；② §5.2 的 mod 侧做法已达成同一效果且 replay 一致；
③ §BE-EQ / §BE-ER 的教训：近相对分支窗口的接管与回放都出过事故，能不加站点就不加。
