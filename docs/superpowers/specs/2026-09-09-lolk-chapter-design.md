## 0. 一句话 + 用户定案

**被动卡「绀珠传」**：把 boss 战按「**一个非符 + 一张符卡 = 一波**」切章；
每波统计**擦弹数**与**击破率**，波末按 TH15 原式结算**章节奖**（分数，够高再给碎片）；
同时复刻 TH15 的**擦弹 → 场上掉落物减速**。UI 是本卡的重点（用户点名），
用一块常驻面板 + 三行数字。

用户 2026-09-09 的两条定案：

1. 擦弹时**场上掉落物速度减慢**，并有一层（用户记忆里偏橙的）视觉；
2. 波次划分用**最简单的那条**：boss 的非符 + 符卡算一波，**重点在 UI**；
   并预期 TH15 的残留代码可以复用。

## 2. 波次边界（TH18 判据）

用户定案（2026-09-09，**三次**）：**一段攻击 = 一波** —— 一个非符是一波、一张符卡也是一波；
**进入关底 boss / 道中 boss 也算一波**；道中按 ECL 524 切章，一章一波。

边界因此有**三类信号**（全部只读，[`engine/chapter/th18/02`](../../../engine/chapter/th18/02-wave-signals.md)）：

| 信号 | 判据 | 用在哪 |
| --- | --- | --- |
| boss 出现 / 消失 | `ENEMY_MGR.boss_ids[4]` 里有没有活敌人 | 进 boss = 新波；boss 没了 = 结算并关波 |
| **相位指纹** | 敌机中断槽（`zEnemy+0x6374`，8 个 `{hp_value, time, sub_life}`）里**活动槽**变了 | boss 战内部：换相位 = 换波 |
| 章号 | `GLOBALS.inner+0x24`（`0x4ccce4`，ECL 524 写）跳变 | 道中切章 = 换波 |

- 指纹**只在有活动槽时更新**：槽被清空那一帧（`hp_value = -1`）不算边界，
  于是「清空 → 新槽」只报一次，且报到的是新相位；
- 相位切换后 3 帧内不再报边界（去抖：槽清空与符卡位翻转会连报两下）；
- 空波（擦弹/刷出/击破全为 0）不产出，只清计数（TH15 的「没刷怪不结算」同义）。

**为什么道中不用符卡位**：符卡位（`SPELLCARD_PTR(0x4cf2c0)+0x78` bit0）在道中恒 0，
切不出道中的波；而 ECL 524 在零售脚本里正好按「道中段 / 道中 boss / 关底 boss」分段
（0/22/41/43/81/2，[`engine/chapter/th18/01`](../../../engine/chapter/th18/01-chapter-residuals.md) §3）。

### 3.1 擦弹数

用**引擎自己的 `GRAZE` 全局** `0x4ccd0c`（`GLOBALS.inner+0x30`，`Player__do_graze` `0x45e160` 每次 +1），
每帧在 `on_tick_2` 取差分累加。旁边的 `GRAZE_IN_CHAPTER` `0x4ccd10` 是**死字段**
（只写不读、永不归零）→ 不用它（[`engine/chapter/th18/01`](../../../engine/chapter/th18/01-chapter-residuals.md) §2）。

### 3.2 击破率（用户 2026-09-09 三次定案：**三种来源**）

| 波种 | 击破率 | 判据 |
| --- | --- | --- |
| 道中章 | 击破数 / 本章刷出总数 | 分母 0 → **100％**（用户点名的边缘情况）|
| boss 非符 | 击破 → 100％ / 超时 → 0％ | 中断槽 `life.current <= hp_value`（击破）/ `slot.time <= time_in_ecl`（超时）|
| boss 符卡 | 同上 | 另可读 `SPELLCARD+0x78` bit7（已超时）|
| **时符**（耐久符卡） | **恒 100％** | `SPELLCARD+0x78` bit3（ECL 542 置）|

- 「击破 / 超时」**不用本卡猜**：TH18 引擎每帧就在拿敌机的 `life.current` 与中断槽比，
  两条路分别跳不同子程序，超时还会置 `zEnemyData.flags_lo` bit24 与符卡位 bit7
  （[`engine/chapter/th18/02`](../../../engine/chapter/th18/02-wave-signals.md) §2）；
- 本波「见过」任一条件就锁定结果（相位本地条件只在收尾那帧成立；边界帧也要采样）；
- 道中的分子分母仍用 `enemy_count_real` 差分：TH15 的 `DESTROYED` 也是在敌人被移除时加的
  （`th15:0x428b70`），所以「消失」当分子与 TH15 同义（离场也算）；
- 击破率钳在 `0..100`，两个数都进日志。

### 3.3 结算

```
rate  = 分母 ? min(100, 分子 × 100 / 分母) : 100
bonus = (graze × rate × 50 / 10) × 10          # 整数，TH15 原式（= 擦弹 × 击破率% × 5000，取整到十位）
score += bonus / 10                             # TH15 的分数增量
bonus ≥ 1_000_000 → 额外给 1 个碎片：★ 固定「残机碎片」（type 0x10 = 零售 EXTEND2 卡道具）
```

**★ 碎片口径（用户 2026-09-12 定案，覆盖原文的「每 5 波循环」）**：本卡对应的是**绀珠传「传统 / legacy」模式**的掉残
⇒ **固定掉残机碎片、没有循环**（原写成「4 符卡碎 : 1 命碎」是错的；代码一直就是恒命碎，属文档错、代码对）。
TH15 原作规则（用户一手口径）：
- `bonus ≥ 100 万`（⇔ **擦弹数 × 击破率 ≥ 200**，注意「等于也可以」）给资源奖励：
  **完美模式 = bomb 碎片 / 传统模式 = 残机碎片** ⇒ 本卡取**传统模式**。
- **bomb 碎片 5 个 = 1 bomb；残机碎片 3 个 = 1 残机（Extra 5 个）**
  —— ⚠ 与 TH18 原生「3 碎 = 1 残机」**同制** ⇒ 直接撒零售卡道具让引擎自己进位。
- ★ **残机上限 8**：已有 8 残机时，之后拿到的残机碎片**要变成 bomb 碎片**（TH15 原规则；**本卡要实装**）。

碎片走 `ce_spawn_item(type, pos, angle, speed)` 从自机上方弹出（辉针城同款；
type `0x10` = EXTEND2 卡道具 → 命碎、`0x11` = BOMB2 → 符卡碎，AUDIT §Z12），
不直接写全局——这样 HUD、音效、上限全由引擎自己管。

## 4. 擦弹 → 场上掉落物减速

用户定案：**只要擦弹判定框里有敌方子弹，场上掉落物就一直慢**（不是「擦弹那一刻」才慢）。

### 4.1 擦弹判定有**两种模式**（一手，两作同一套）

| 模式 | 用它的子弹 | 擦弹条件 | TH15 | TH18 |
| --- | --- | --- | --- | --- |
| **圆形** | `flags & 0x10` | 弹心 vs 自机判定**圆**：`d² < (r + max(br/2.5, **40.0**))² + br²` | `th15:0x455d00`（`th15:0x4cff28`=2.5、`th15:0x4cffb8`=40.0） | `0x45cd90`（`0x4b921c`=2.5、`0x4b92c4`=40.0） |
| **矩形** | 其余子弹 | 弹**中心** vs 自机判定框外扩 **24.0** | `th15:0x455be0`（`th15:0x4cffa0`） | `0x45cc20`（`0x4b92a4`） |

- 选路在子弹分派器（TH18 `0x4248a0`）：`flags & 0x2` 才参与碰撞、`& 0x10` 走圆、`& 0x40` 先按
  `bullet+0xf38` 缩放半径；自机判定圆半径 = `player+0x4799c`/`+0x479a0`（零售都 3.0），
  矩形半宽高 = `player+0x479a4`/`+0x479a8`（零售 1.5）。
- **这就是用户说的「额外圈」**：圆形判定的边距是 `max(br/2.5, 40)` —— 比矩形的 24 px 大得多
  （常见圆弹 br≈4–8 → 有效擦弹半径 ≈ 43–50 px）。**两作完全相同**，不是 TH15 独有。
- 用户猜的「TH18 擦弹半径更大」不成立；真正的差别在下一节。

### 4.2 为什么「擦弹事件触发」不够

| | TH15 | TH18 |
| --- | --- | --- |
| 同一颗弹能否重复擦 | **能**：per-bullet 计时器 `bullet+0x1464`（擦后置 30 帧，`idiv` 余数门） | **不能**：擦后置 `bullet+0x20 \|= 4`（`0x42496f` 判、`0x424984` 置），一生一次 |

→ TH18 里一颗弹只在**刚进框**那一帧算一次擦弹，之后引擎的 `+0.1/帧` 把速度拉回满速，
观感就成了「只在擦弹那一刻触发」。

### 4.3 落地：每帧扫弹池，按子弹自己的模式判

每帧（`on_tick_2`）扫敌方弹池（`BULLET_MGR(0x4cf2bc)+0xec`，2000 槽，stride `0xfa0`，
状态 `+0xf68`，位置 `+0x638`，半径 `+0x658`，flags `+0x20`），**按上面两种模式原样判**：

- `flags & 0x10` → 圆判定（`max(br/2.5, 40) + r`）；
- 否则 → 矩形判定（24 px 外扩）；
- 任一命中即返回（密集弹幕里通常前几十槽就命中）。

纯读 + 一个写，**无新断点**；写入时机固定（每帧）→ replay 安全。
数值照 TH15：因子 **0.3**，恢复由引擎自己每帧 `+0.1`（`0x446807`–`0x446821`）到 1.0。

### 4.4 擦弹圈（视觉，用户 2026-09-09 定案）

TH15 的「圈」有现成美术：`effect.anm` 的 **`eff_sloweffect.png`**（128×64 = 两个 64×64 sprite：
左半是实心小爆点、右半是**空心环**），由脚本 **25/26/27** 使用（`script27` 用右半那个环：
layer 6 / blendMode 2 / 淡入 30 帧 / 4.3→2.0 缩放 / 慢自转），
起 VM 的是 `Player::on_tick` 里的 `th15:0x4540e0`（条件 = 场上有敌 && 自机动画帧 ≥4 && 低速位）。

本卡的做法：

- **抽图**：`assets/ability/make_lolk_ring_art.py` 把右半 64×64 LANCZOS 放大到 128×128 →
  `ability/lolk/RING.png`（零售字节只在 `local/`，构建时取，不入库——与青眼光束同款做法）。
  放大后亮环半径 ≈ **44 px**，正好接近圆形擦弹判定的有效半径（≈43 px），脚本 scale 1.0 即可。
- **脚本**：`assets/ability/scripts/106_lolk_ring.anm.txt` —— **TH15 `script27` 的 1:1 复刻**：
  `blendMode(2)`（反向减算 `dst − src×alpha`，暗环不发光，见 [`anm/th15/01`](../../../engine/anm/th15/01-blend-modes.md)）、
  `alpha(0) → alphaTime(30,0,96)`（30 帧淡入）、`scale(2.15) → scaleTime(12,4,1.0,1.0)`（12 帧由大变小）、慢自转。
  **缩放取 TH15 原值（4.3→2.0）的一半**：贴图放大到 128×128 后亮环半径 44 px，
  scale 1.0 的落定半径才等于圆形擦弹判定的有效半径（≈43 px）；照抄原值会画成 88 px（实跑纠偏 2026-09-09）。
- **接线**：`lolk.c` 的 `ring_sync()` —— 判定区里有弹 → 起 VM 并每帧钉在自机（`ce_anm_set_pos`）；
  弹离开 → `ce_anm_interrupt(id, 1)`，脚本自己 12 帧渐隐后自删（**不**再每帧改 alpha）；
  过关 / 局末 / 卡被删时删 VM。

## 5. UI（本卡重点）

TH15 的面板是 `front.anm` script 241（父 VM，常驻）+ 五条**标签条** + 两条**碎片标签**，
文字由 `Gui::on_draw_2e` 的 AsciiManager 画（**五**行，不是四行）。
TH18 没有这块板 → 我们自己在 `ability.anm` 追加：

| 元素 | 做法 | 备注 |
| --- | --- | --- |
| 标签条 ×5 | TH15 `front.anm` script241 的 `front02.png` sprite145/146/147/149/148 各切一条，**256×32 画布、内容居中 192**（贴图尺寸必须是 2 的幂），脚本 107–111 | 中心锚 + 内容偏左 = 整条推左 32 px（实机「偏左」的真因）|
| 碎片标签 | sprite150（**B 碎片**，普通模式用）/ sprite151（命碎），脚本 112 | TH15 里它由 script241 起出来但默认禁用，`bonus ≥ 1e6` 才留；本卡只在 `frag_type != 0` 时起 |
| 面板父 VM | 不需要：本卡直接把六条按 TH15 的绝对偏移摆（(448,402) + (0,0)/(−64,50)/(−64,90)/(−64,130)/(−64,170)/(0,240)）| 与 TH15 同坐标、同 `resolutionMode(2)`（640×480 下 ×0.5）|
| 第 1 行 | `ce_hud_text` 擦弹数 `"%d"` | 只在 `on_draw`（`+0x48`）里画 |
| 第 2 行 | `ce_hud_text` 击破率 `"%3.1f%%"` | 跳动时印**倒数中的值**（TH15 就是这样）|
| 第 3 行 | `ce_hud_text` 本波击破数 `"%3d"` | TH15 这一行是 Pointdevice 重开数；本卡没有 PD |
| 第 4 行 | `ce_hud_text` 章节奖 `"%6d"`（从 0 滚到 bonus）| TH15 `gui+0x130` |
| 第 5 行 | `ce_hud_text` 分数增量 `"  +%d"`（色 RGB 128,128,255）| TH15 是 PIV 增量；本卡没有 PIV → 印 `bonus/10` |

位置**逐条照抄 TH15**：AsciiManager 空间（640×480）、右对齐（`align_h = 2`）、行距 20、
x = 300 / **308** / 300 / 300 / 300、y = 226 / 246 / 266 / 286 / **296**、font 2 / group 2。
标签文字在美术里（TH15 的 `front02.png`），本卡只画数值 —— 所以**标签的日文/英文内容不影响实现**。

## 6. 数值（初版，实跑调）

| 量 | 值 | 来源 |
| --- | --- | --- |
| 减速因子 | 0.3 → +0.1/帧 | TH15 原值 |
| 章节奖系数 | 50 | TH15 原值 |
| 分数增量 | `bonus / 10` | TH15 原值 |

TH18 零售分数在百万量级，这个量级不会破坏体感；要更保守就把系数降到 20。

## 8. 明确不做

- 全屏橙色滤镜（TH15 没有，负结论）；
- PIV / 点道具身价（TH18 的 PIV 语义与 TH15 不同）；
- 擦弹变色（TH15 是逐弹染色状态机，与 TH18 的弹对象布局不同，另开卡）；
- Pointdevice 快照 / 重开点（那是 TH15 的模式，TH18 没有）。

## 9. TH18 接缝（2026-09-09 一手定案）

| 需要的东西 | TH18 现状 | 落地方式 |
| --- | --- | --- |
| 擦弹计数 | `GRAZE` `0x4ccd0c` 每次 +1 ✅ | `on_tick_2` 差分（§3.1） |
| 章内擦弹 | `GRAZE_IN_CHAPTER` `0x4ccd10` **死字段** ❌ | 自建差分 |
| 符卡边界 | `SPELLCARD_PTR+0x78` bit0 ✅ | 下降沿（§2） |
