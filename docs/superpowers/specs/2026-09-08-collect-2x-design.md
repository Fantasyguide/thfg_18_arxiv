> **版本**：TH18 v1.00a（`th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本；引用其他版本须写成 `th16:0x…`。

> 上游参考（th15but14 逆向 + TH18 锚点判定）：`local/_scratch/TH15BUT14-REPORT.md`、`local/_scratch/TH18-REPRO-VERDICT.md`。

## 0. 一句话

一张**被动卡**，两个被动：
1. **收点系统**（辉针城 TH14 1:1 复刻）：一次性收点按同时收集量走档位表——≥20 起给碎片
   （按 4 符卡碎 : 1 命碎循环）、≥60 稳定给命碎，**且该批收点所得分数 × 档位倍率（最高 ×2.0）**；
   碎片用 TH18 原生等价物，倍率只作用于分数。
2. **高速射击掉钱**：非聚焦射击命中敌人时，按当前火力掉落一定量【金钱】道具。

用户已定（2026-09-08）：**同一张卡两个被动** / **计数道具 = 金钱(2) + 小分(9–0xe) + P(1)** /
碎片 = TH18 等价物（命碎 / 符卡碎）/ **2.0 是分数倍率，只考虑分数** / 批次语义 1:1
（含「等飞行道具收完才结算」与「上线 / bomb / 对话等时机收取都算同批」）。

## 1. 复刻对象：辉针城收点系统（THBWiki 原文规格）

| 同时回收数 | 碎片奖励 | 分数倍率 |
|---|---|---|
| 0–19 | 无 | 0 |
| 20–29 | 碎片循环 | ×0.5 |
| 30–39 | 碎片循环 | ×0.8 |
| 40–49 | 碎片循环 | ×1.2 |
| 50–59 | 碎片循环 | ×1.6 |
| ≥60 | 残机碎片 | ×2.0 |

- 碎片循环 = 4 个 bomb 碎 : 1 个命碎循环发放；≥60 稳定给命碎，不计入循环。
- 一次性收点 = 一次性上线收取的点 + bomb 启动、对话等时机收取的点。
- **若收点时屏幕上仍有正在飞的「点」，会等它们全部被收取后才算一次收点**
  （⇒ 梦A 御币式持续击杀可把一次收点拉得很长、收到大量道具）。
- 只计 红点(P) 与 蓝点(得点)；碎片等其它道具不计入档位。

**TH18 等价映射**（用户拍板）：

| DDC | TH18 | 依据 |
|---|---|---|
| 红点 = P 点 | 火力道具 type 1 | `0x445A80` case 1 → `ItemManager__collect_power_item` |
| 蓝点 = 得点 | 小分道具 type 9–0xe（分数随 MONEY 涨）| case 9–0xe：`SCORE += (MONEY/10*10)/10` |
| —（DDC 无金钱）| **金钱道具 type 2**（身价兼计分）| case 2 → `collect_money_item` `0x446B00` |
| bomb 碎片 / 残机碎片 | **卡道具 type 0x11 BOMB2 / 0x10 EXTEND2**（收集 → 即时卡 CardBombFragment id 4 / CardLifeFragment id 3，各自走原生进位链）| `0x4b4020` 表一手 dump（type 0x10–0x13 行第一 dword = card_id 3/4/5/6）+ `0x445A80` case 0x10–0x13 → `allocate_new_card(mgr, card_id, 0)`；05-shop §8 |
| 碎片从场上弹出 | 自机位上方 spawn 原生卡道具（卡外观 + 收集走原生分配链喂库存/HUD）| ★ 2026-09-08 实跑纠偏：**虹龙洞原生碎片 = 卡道具**（type 4/6 宝石是旧引擎血统残留，已弃）—— 落点细则见 §5 |

## 2. 锚点（一手，2026-09-08 Ghidra 反编译；进 AUDIT 前 🟡）

道具系统每帧一条主链，全收口在单函数——比 th15but14 的宿主更规整：

```
GAME_THREAD 帧循环
  └─ ItemManager__on_tick 0x446ec0      ← 每帧门卫（GAME_THREAD+0xb0 状态 & 0x4cf2a4）
       └─ ItemManager__on_tick__body 0x445A80   ← 每帧一次，整池 0x1258 槽逐道具
            ├─ 收集判定（半径/收集线/状态 [0x31d]∈{3,4}）
            └─ switch([0x31e] = type)   ← ★ 收集完成分派：type 1/2/4/5/6/7/8/9–0xe/0x10–0x13
                收尾统一 LAB_0044658a（音效 0x25、清 ANM、摘链）
```

| 锚点 | 地址 | 角色 |
|---|---|---|
| 帧 tick | `ItemManager__on_tick` `0x446ec0` 入口 | 批次空闲倒计时 / 「池内无飞行道具 → 结算」判定 |
| 收集事件 | `0x445A80` 的 type switch（`switch(piVar15[0x31e])`）前 | type ∈ {1,2,9–0xe} 的收集 = 计入本批 |
| 在飞判定 | 批次边界谓词（2026-09-08 spawn/body 一手补订初稿）：**计数集 type ∈ {1,2,9–0xe} 且 slot state ∈ {1,3,4}** 的道具存在 → 不结算（初稿漏 state 1 = 出生即飞行，见 plan §分数补差/批次口径）| 有在飞道具不结算 |
| 碎片道具 spawn | `ItemManager__spawn_item`（type、位置、角度、速度）| 奖励落点（§4.3 核对签名）|

> 结构彩蛋：TH18 道具池上限 0x1258 与 TH15（th15but14 钩点宿主循环 `cmp eax,0x1258`）
> 同源——ZUN 复用的是「道具池框架」，档位结算逻辑两作都没有，需自建（本卡）。

## 3. 被动一：收点系统（状态机）

### 3.1 状态机（与 th15but14 `0x100011c0` 同构，C 实现，SDK 卡）

| 状态 | 语义 |
|---|---|
| `batch_count` | 本批已收 type∈{1,2,9–0xe} 的道具数 |
| `batch_score` | 本批小分/钱道具的分值累计（倍率乘在它上面）|
| `batch_open` | 本批进行中（自首个收集事件起）|
| `fragment_cycle` | 4:1 循环游标（0..4；第 5 次给命碎后归 0）|

事件 → 动作：

1. **收集事件**（断点，type∈{1,2,9–0xe}）：`batch_count++`、`batch_score += 该道具分值`、
   `batch_open = true`。
2. **帧 tick**（断点 `0x446ec0`）：若 `batch_open` 且**池内无「计数集 type ∧ state∈{1,3,4}」道具**
   （批次边界谓词，见 §2；state 1 = 出生即飞行，须计入）
   → **结算**（档位表 → 碎片 + 分数补差）→ 状态清零。
   池内仍有在飞 → 什么都不做（这就是「等飞行道具收完」1:1）。
   - 特殊应用天然成立：持续击杀让道具一直飞 → 批次无限延长、一次收 60+。
   - 上线收 / bomb / 对话自动收：全部走同一条收集事件，自动并入同一批。

### 3.2 结算（1:1 档位表）

| count | 动作 |
|---|---|
| <20 | 无 |
| 20–29 | `SCORE += batch_score × 0.5 差量`；碎片：循环位 |
| 30–39 | ×0.8；碎片：循环位 |
| 40–49 | ×1.2；碎片：循环位 |
| 50–59 | ×1.6；碎片：循环位 |
| ≥60 | ×2.0；**碎片：命碎（不计循环）** |

- **倍率只作用于分数**：`SCORE(DAT_004cccfc)` 补上 `batch_score × (倍率−1)`（1:1 原义 =
  收点所得分数 × 倍率；batch_score 只累计计入档位的那批道具的分值，钱道具以
  `MONEY_ITEM_SCORE_VALUE` 口径计入）。**金钱入账不变**（钱道具本身照常）。
- 碎片循环 4:1：第 1–4 次给符卡碎、第 5 次给命碎（`fragment_cycle` 游标）；
  ≥60 给命碎且**不入循环游标**（DDC 原语）。NMNB 共享循环：TH18 无此语义，不做。

### 3.3 分数倍率弹字

每档弹一次浮字（th15but14 原版逐档变色）。**2026-09-08 定案：原生复制**
（TH14 原生结算 → 弹字机的调用面在 TH18 同族保留）：

- TH14 地面真值：档位色 = `0xffffff00 / 0xe0ffff60 / 0xd0c0ff80 / 0xc0a0ffa0 / 0xb040ffff`
  （×2.0→×0.5 降序），经倍率弹字加法器 `0x458000` 入 5 槽环（`[0x4db694]+0x98c`）。
- TH18 原生弹字管理器 `[0x4cf420]` 含 **18 槽环 @+0x624**：k0–12 数字槽（加法器
  `0x4645f0`）+ **k13–17 ×倍率槽 @+0x9cc**；槽字段与 TH14 同构（busy@`+0x3c`、
  color@`+0x1c`、scale@`+0x18`、pos@`+0xc`、值 int@`+0x40`、倍率 float@`+0x44`），
  tick `0x464020` + draw `0x464180` 原生渲染 → **无需 ANM 资产/文字途径决策**。
- ✅ **首验定案（2026-09-08 一手反汇编 draw `0x464180`）**：第二环每槽两次文本调用
  `0x419cb0`（this 显式压 `[0x4cf2ac]`）：格式串 `0x4b71f8` = `"BONUS %.1f"`（值≥0 分支，
  mult float@`+0x44` cvtps2pd 传入）、`0x4b61a4` = `"%d"`（值 int@`+0x40`，y 另偏 +0x4b9278
  低一行）；值 <0 分支 = 格式串 `0x4b7204` `"NO BONUS"`。槽色@`+0x1c` 先抄进文本对象
  +0x19228（0x4644c2）。**格式串不带 × 字符** → 屏显为数值行 + `BONUS 1.6`（×1.6 档）。
  原生 tick 从 busy=1 起接管：age@`+0x24` 每帧 +1，>60 起每帧 color alpha −4（≤0 清 busy
  @`+0x3c`）→ 生命周期与淡出全原生。结论：主案达标（原生视觉语言），垫底不启用。

## 4. 被动二：高速射击掉钱

### 4.1 规格（用户定：THBWiki「高速射击敌人掉落 P 点、与命中火力成正比」的 TH18 金钱版）

- 非聚焦（不按 Shift）射击**命中**敌人时掉落【火力道具 P，type 1】；
- ★ 2026-09-08 设计变更（用户实跑拍板）：原「掉落金钱道具 type 2」在实跑中未出现（链路未明，未深挖），
  用户决定「还是掉 P 吧」——掉落物改 P，与引擎「打人掉 P」同语言；节奏/门控不变：
- 节奏 ∝ 当前火力（`CURRENT_POWER 0x4ccd38`，0.00–4.00）：间隔 = 96 − power×16 帧（4.00 时 32 帧）；
- 聚焦（低速）时不触发；1:1 原句里「魔理沙 B 低速也拥有」是机体特例，TH18 无对应机体 → 不实现。
- 附注：P（type 1）∈ 计数批集 {1,2,9–0xe}——命中掉 P 被吃会拉长收点批（梦A式持续击杀语义）；
  P 满 4.00 后引擎把多余 P 转分，无碍。

### 4.2 命中口径（🟡 待实现期 RE 选定）

候选锚点：`enm_compute_damage_sources` `0x45f0f0`（自机侧伤害结算，蓝眼/炎魔已用）
或自机弹命中路径；掉落节奏需限速（防数值爆炸）：每帧/每 X 点伤害累积阈值 → 掉 1 枚，
阈值随 `CURRENT_POWER` 缩放的实现细节在实现计划中定，进 AUDIT。

## 5. 碎片奖励的落点（TH18 等价物）

| DDC | TH18 复刻 |
|---|---|
| 从场上弹出 bomb 碎 | 自机位上方 spawn **卡道具 type 0x11（BOMB2）** → 原生收集：`allocate_new_card(card_id 4 CardBombFragment)` → 符卡碎进位链、HUD 全免费 |
| 弹出命碎 | 自机位上方 spawn **卡道具 type 0x10（EXTEND2）** → `allocate_new_card(card_id 3 CardLifeFragment)` → 命碎链 |

> spawn 而不是直写计数器 = 1:1 视觉（碎片真的弹出来、要收），且下一批的「等飞行道具」
> 语义自动把刚 spawn 的碎片纳入窗口。碎片 type **不在计数集 {1,2,9–0xe}** 内，不回喂档位、
> 在飞不挡批闭。
>
> ★ 2026-09-08 实跑纠偏（用户定义）：虹龙洞**原生碎片就是卡**——资源碎片以卡掉落呈现，
> 不是 TH14/TH16 那套宝石道具（type 4/6 仍在引擎里、却没有任何 TH18 内容喂它）。因此本表
> 落点用卡道具 0x10/0x11，而非早期 mapping 里的 type 4/6（§2 表已同步改）；卡外观 + 收集走
> 0x445A80 case 0x10–0x13 → `allocate_new_card(…,0)`（ctor 型即时卡）原链喂库存。
> 弹点细则（锚点/初速，弹道半径门一手）在实现计划进 AUDIT §Z12。

## 7. 不做 / 边界

- NMNB 碎片共享循环：TH18 无对应，不做。
- 「4 符卡碎 : 1 命碎」是**奖励循环节奏**，与 TH18 原生「3 符卡碎进位 1 符卡」互不冲突
  （循环决定给哪种碎片，进位交给原生）。
- 不影响 `scoreth18.dat` / side-car 存档（碎片走原生计数器与道具系统）。
- 只做非 Steam / 非汉化 v1.00a。
