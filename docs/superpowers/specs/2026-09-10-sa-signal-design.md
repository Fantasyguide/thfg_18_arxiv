## 0.4 ★ 信号强度的上限定案（用户 2026-09-12）

> **原话**：「111 信号槽实际上有 0~130 的数值，100 以上在屏幕上均会显示为 1.00。100 以上蓝点的价值也都相同。」

⇒ 卡侧现实现**正确**：`signal_core_strength()` 把 0..130 的信号换算成 **0..1000‰（1.00 封顶）**，
100 点与 130 点在**显示**与**蓝点分值**上完全相同；130 只体现在**信号格数**（HUD 5 格）上。
`sdk_core.h` 的乘数附加通道（`ce_score_mul_declare`）声明的也正是这个 **0..1000** 的值，不要再乘 1.3。


## 0. 一句话 + 用户定案

**被动卡「地灵殿」**：复刻 SA 的**信号槽 + 绿点信仰**。

1. **信号槽 0–130**（左下角手机信号样式）：回收线上涨、擦弹涨、线下衰减、被弹归零；
   **满（≥100）→ 像上线回收一样自动收道具**；
2. **绿点信仰**：初值随难度、上限 = 初值 ×2；大 / 中 / 小绿点供养；
3. **蓝点分 = 信仰 × (擦弹倍率 + 信号强度)** → 作用在**金钱道具的分数**上（**不改金钱数量**）；
4. **B 双选**：与 110 同规则（**当且仅当没有炸弹库存且火力 ≥1.00** → 地灵殿 ver B）。

**用户 2026-09-10 定案**：
- ① **伙伴主动技能 = 保留为「可能的未来方向」**（原版没有主动技能，不现在做）；
- ② **B 双选 = 当且仅当没有 B**（与 110 同）；
- ③ **蓝点载体**：取「**金钱道具 = 蓝点**」（用户原话「TH18 在系统上金钱几乎完全替代蓝点」）；
  另一选项「自建蓝点道具」记在 §6 备选。

## 2. 机制

### 2.1 信号槽（0–130）

| 条件 | 效果 |
| --- | --- |
| 回收线上（<100 时） | **+50/f**（不会超过 100） |
| 回收线上（≥100 时） | **+0.09/f** |
| 擦弹 | **+8 / graze**（激光每 3 帧算 1 擦弹） |
| 回收线以下 | **−0.3/f** |
| 被弹（含河童 bomb） / 关卡结束 | **归 0** |
| **满（≥100）** | **像上线回收一样自动收道具** |

- 回收线 = `player+0x47998`；显示上 ≥100 一律显示 1.00。
- ★ **单槽**（用户 2026-09-11 定案）：**不做两个子槽**。原设计的「擦弹槽 / 回收线槽」唯一消费者是
  111 × 114 协同，而**跨卡耦合已砍**（同日本案）。两个来源（擦弹 +8 / 线上 +50 每帧）
  **直接喂同一个槽**，照 SA 原版。
- **全收** ❌ **没有现成原语**（2026-09-11 一手订正）：`0x445ffc` 是 `comiss` 指令、不是函数入口；
  `player+0x47988/8c/90/94` 只是吸引半径。要全收得**自己遍历道具槽**（`mgr+0x14` × `0xc94`）把 `state` 置 3，
  或临时抬高 `player+0x47998`（会牵动原生计分与其他卡）。⏳ 待定。

### 2.2 绿点信仰

- 初值随难度：E **25000** / N **50000** / H **100000** / L **200000** / EX **200000**；**上限 = 初值 ×2**。
- 供养：**大绿点**（敌机掉落）+100；**中绿点**（满 power 后红点转换）+10；
  **小绿点**（boss 击破消弹 / bomb 消弹）每 **100 个** +10（每个 +10 分）。

### 2.3 蓝点分（作用在金钱道具上）

- 公式：**`bonus = 信仰 × (擦弹倍率 + 信号强度)`**，其中
  **擦弹倍率 = graze × 0.0001**（上限 **8.99**）、**信号强度 = 0.00–1.00**。
- 落地：金钱道具收取时（`on_item_score` / `on_item_commit`，辉针城同路径）**加一笔分数**；
  **不改 `MONEY` 数量** → 不碰经济。
- ⚠ 这条是**本卡与 TH18 的适配**（TH18 无蓝点），不是 SA 原义；备选自建蓝点见 §6。

### 2.4 B 双选（与 110 同规则）

- 炸弹库存 **> 0** → 原生 B；库存 **== 0 且火力 ≥1.00** → **地灵殿 ver B**（扣 1.00 火力）。
- 不需要新键 / 设置项 → 回放安全。

### 2.6 残机碎片（照抄 SA）

- **No-Miss 通过 boss 的一个阶段**（**符卡 / 非符都算**，**含道中 boss**）→ **+1 残机碎片**。
- 落地：boss 阶段边界（G6：`SPELLCARD+0x78` 下降沿 / 中断槽切换）+ **该阶段内无 miss 标志**
  → 越过边界时调 `ce_add_life_fragment()`（满命碎自动进整命，自带刷 HUD）。
- **5 碎片 = 1 残机**（TH18 原生规则）。

### 2.5 HUD

- 左下角：**手机信号样式的格子**（3–5 格）+ **信仰 / 蓝点分读数**。
- 同槽位类卡共享 HUD 区（IDEAS §4）。

### 9.1 结构观察（对落地的意义）

1. **「支援特技」是一套独立机制**：触发方式五花八门 —— **松键**（文 / 萃香）、**松键+双击方向**（紫）、
   **同时按两键**（帕秋莉）、**被动**（荷取 / 爱丽丝）。⚠ 其中「松键」「双击」**在 TH18 的输入位上不存在**
   （TH18 只认 `Z/X/Shift/C/D` 与方向键），落地要另想办法（或改触发方式）。
2. **「远程灵击」= SA 的 bomb 位**（按 X 消耗火力）⇒ 已由本 spec §2.4 的「B 双选」覆盖，
   **不必为每个组合再做一套灵击**（否则就是八套炸弹系统）。
3. **子机层的六种形态**（滚动 / 左右 / 可指定方向 / 人偶 / 五配置 / 后方）—— 按 §1 的判断，
   子机**位置与贴图**是 TH18 原生字段（零成本）、**子机弹**走 shooterset（数据驱动），
   ⇒ **这一层是唯一「便宜且能体现组合差异」的层**。
4. **每组合的差异 = 「子机位置 + 子机弹 + 一个支援特技」** ⇒ 落地的现实范围建议定为
   **子机层 + 支援特技**，灵击层不做。

### ⚠ 2026-09-12 追加：低速子机要走「声明层」，不要自己直接写字段

- 一手研究定案（用户拍板）：108（永夜抄）与 111（本卡）的**低速子机最终会落到同一批子机对象**
  （原生聚焦偏移 `+0x6c/+0x70`、贴图脚本、数量）⇒ 两卡各自每帧写 = **同一帧谁后写谁赢**，
  覆盖关系会隐式依赖 tick 顺序。
- ⇒ 改为**「低速子机声明层」**（与仓里既有**伤害层**同形：卡片只声明 → SDK 选举**落笔者**（**id 最小者**）→

- **对 111 的直接影响**：本卡「子机层」的**位置 / 贴图 / 数量**三项改成**向该层声明**，不要直接写 option 字段；
  ⇒ 与 108 同装时按 id 规则**108 胜**（用户已定「108 低速子机覆盖 111 低速子机，高速互不影响」）。
