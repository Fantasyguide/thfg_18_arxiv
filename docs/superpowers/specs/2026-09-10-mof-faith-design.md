## 0. 一句话 + 用户定案

**被动卡「风神录」**：复刻 MoF 的**火力经济 + 信仰 + 连击条**。

1. **灵击**：按 B（**当且仅当没有炸弹库存时**）花 **1.00 火力** → 全屏消弹 + 全场伤害 + 震屏；
2. **信仰**（左下角数字，初始 50000）：由**消弹 / 击破 / 擦弹**供养，**连击条**维持；
   **miss / 非决死灵击 / 全避**扣信仰；下限 50000；
3. **蓝点**（**自建道具**）：满 P 时 **P 点掉落 → 蓝点**；蓝点分值 = **信仰 × 高度系数**；
4. **卡内分数奖残**：蓝点分只进**卡内独立计数** `mof_bonus`，过阈值 → `ce_add_life()` 发残。

**用户 2026-09-10 定案**：
- ① 信仰 = **完整版**（信仰值 + 连击条 + 全套增减）；
- ② **满 P 转化不搁置** → 改成**自建蓝点**（**不 spawn 钱**，否则经济崩）；
- ③ **B 双选 = 当且仅当没有 B**（库存 0 且火力 ≥1.00 才走火力版）；
- ④ **蓝点运动学 = P 点 = 金钱**（不自造一套，照原生道具运动学）；
- ⑤ **不做全局分数奖残**（其他卡的系统自身有意义）→ 只在卡内计数 + 自发残。

## 2. 机制

### 2.1 火力与灵击

- 火力三重身份：**子机 DPS** ／ **灵击资源（−1 档）** ／ **miss 代价（−1 档）**。
- ⚠ **火力单位订正（2026-09-11 一手）**：火力是 `int`，**一档 = `CE_ADDR_POWER_PER_LEVEL` `0x4ccd40` = 100**
  （`Player__initialize` `0x45a98b` 把一档设成 `sht+0x24`；显示 1.00 = 100）。
  所以**不是** `ce_spend_power(1.00)` 而是 `ce_spend_power(CE_POWER_PER_LEVEL())`。
  ✅ **用户 2026-09-11 定：接受原生钳位** —— 灵击**扣到本作允许的最低火力（= 1 档 / 1.00）为止**，
  **不写自写扣法**。即：`GlobalsInner__spend_power` `0x457480` 在 `0x4574a3` 判 `CURRENT_POWER <= 一档`
  就拒绝（返回 0、不扣）—— 直接用它的原生行为：**能一路花到 1.00，但花不到 0**。
  ⇒ 门槛相应写成「**火力 > 1 档**」（不是 ≥ 1.00；恰好 1.00 时放不出灵击）。
  ⚠ 扣完**必须** `ce_repopulate_options()`（Tsukasa / 商店先例）。
- **B 双选**（用户定案 ③）：读炸弹库存——
  - 库存 **> 0** → 走**原生 B**（本卡不动）；
  - 库存 **== 0** → 走**本卡灵击**：`ce_spend_power(...)` + 消弹 + `ce_damage_rect(...)` + `ce_screen_shake(...)`。
- ⚠ **判定点订正（2026-09-11 一手）**：**不能用 `on_bomb_spent`** —— 它在 `0x4203bc`，
  即**炸弹成功花掉之后**才触发，承载不了「库存 == 0」这条分支。
  改用 **`on_tick_2` 读 `INPUT_HELD/INPUT_PRESSED & 0x2`（炸弹键上升沿）**（`04-active-cards.md` §1 表）：
  库存 == 0 时自干、> 0 时交给原生 `do_bomb`。
- 不需要新键 / 设置项 → **回放安全**。

### 2.2 信仰

- **初始 50000**，**下限 50000**（不会被扣穿）。
- **增**：
  - **大信仰点**（击破固定敌人）：E/N **+5000**、H **+8000**、L **+10000**；
  - **小信仰点**（满 P 击破道中带 P 敌人）：**+100**；
  - **微信仰点**（消弹）：**+10**（同时每个 +10 分）。
    ⚠ **计数订正（2026-09-11 一手）**：`ce_cancel_all_bullets()` **返回 `void`**，
    而 `CE_BM_CANCEL_COUNTER` `0x7a41e8` **只被 `ce_cancel_radius` 写**
    ⇒「每个消弹 +10 信仰」**数不出来**。两条出路：① 改用**大半径 `ce_cancel_radius`**
    （`0x429370`，**返回消掉的弹数**，先清零 counter 再读）；② 消弹前后**扫弹池求差**。
- **微信仰点的 4 个来源**：道中 / boss 非符**灵击消弹**；击破 boss 非符与符卡的消弹；
  全避 boss 非符的消弹；2·3·5 面中 boss 登场消弹。
- **减**：miss **−(信仰−50000)/3**；连击槽空时无敌人 **−10800/s**、有敌人 **−600/s**；
  **非决死灵击 −3000**；全避 boss 非符 / 符卡 **−30000**（时符必减）。

### 2.3 连击条（信仰槽）

- 完整槽 = **130f**（60f = 1s）。
- 充能：大信仰点 **+130f**；蓝点 **+100f**；小 P / 小信仰点 **+60f**；大 P / 击杀非 boss **+20f**；
  微信仰点 **+3f**；1UP / 击杀 boss **+0f**。
- **boss 战中连击槽不衰减**。

### 2.4 蓝点（自建道具）

- **来源**：`on_enemy_drop_pre` —— 玩家**满 P** 且掉落是 **P 点（原生 type 1）** → **替换成蓝点**。
- **运动学 = P 点 = 金钱**（用户定案 ④）：不自造，照 116 季节点那套——**逐条照抄原生道具运动学**
  （spawn `0x446f40` + `ItemManager__on_tick__body` `0x445a80` 的出生 / 飞散 / 飘落 / 吸附）。
- **分值** = `信仰 × 高度系数`：
  - 高度系数按**到收点线**（`player+0x47998`）的高度线性打折：线上 = **1.0**，板底 ≈ **0.54**（初版，实跑调）。
- **收集**：不加钱、不走原生 type → `mof_bonus += value`（§2.6）。

### 2.5 视觉 / HUD

- 左下角 HUD：**信仰数字** + **连击条**（同槽位类卡共享 HUD 区，见 IDEAS §4）。
- 蓝点外观：借道具贴图表里蓝点那格（`0x4b4020`，现被金钱用）或自绘。

### 2.6 卡内分数奖残（定案 ⑤）

- 蓝点分**只进卡内计数** `mof_bonus`，**不写全局 score**、**不引入全局分数奖残**。
- 阈值（照 MoF 原版）：**20m / 40m / 80m / 150m** → 每次越过 → **`ce_add_life()`**
  （或 `ce_add_life_fragment()` +1 命碎；[`SDK.md`](../../../mods/th18.v1.00a/card-expand/SDK.md)）。

## 8. TH10 信仰点掉落：一手反编译（2026-09-11）

> 一手：`local/th10.v1.00a/th10.exe`（v1.00a，487936 字节）+ `thecl -d 10` 解 `th10.dat` 的 ECL。
> 结论：**THBWiki 转抄的三个数值全部属实**，而且**「绿色妖精掉大信仰点」得到一手确认**。

### 8.1 妖精颜色 ↔ `dropMain` 参数（七关一致）

### 8.3 ★ 结构发现：小信仰点不是敌人掉的

**type 9（小信仰点）在整个 ECL 的 `dropMain` 里一次都没出现**（出现的只有 0/1/2/3/7）
⇒ 它是**引擎自己转换出来的** —— 印证「**满 P 时 P 点被替换成小信仰点**」。

### 8.4 对本卡的落地意义（比原估简单）

| 档 | 来源 | 落地 |
| --- | --- | --- |
| **大信仰点** | ECL `dropMain(3)` = 绿色妖精一族 | 需要一份「哪些敌人算」的名单（TH18 侧自定）|
| **小信仰点** | **引擎状态转换**（满 P 时 P 点 → type 9）| **不需要敌人名单** —— `on_item_frame` 扫池时把「满 P 时生成的 P 点」改判即可 |

⇒ **「敌人白名单」只需覆盖大信仰点这一档。**
