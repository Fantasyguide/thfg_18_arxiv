## 1. 实装期新结论（原稿里没有的）

### 1.1 ★ 击破 → 神灵：`on_enemy_death` 是**事件钩子**，直接注册即可（**已接线**）

- 口径订正（SDK owner 2026-09-12）：`on_enemy_death` 是 `ce_hooks_t` 的**字段**（`sdk/public.h`），
  由 `sdk.c` 的 `BP_ce_enemy_death`（断点 `0x430240`）沿卡链表**直接** `h->on_enemy_death(card, &ev)` 派发
  —— **不经过 21 槽虚表**。所以 `CE_CARD` 里没有它的桩是**正常的**（与 `on_item_score` /
  `on_enemy_drop_pre` / `on_bomb_gate` 同一类），卡侧写 `.on_enemy_death = fn` 就会被调到。
  ⚠ 我先前从 `CE_CARD` 只展开 21 槽推出「接线不了」是**错的**（把事件钩子当成了虚表槽）。
- 真正卡住它的是**另两处**（已由 SDK owner 当日修好，故现在可用）：
  1. `sites.py` 生成 `sites_gen.h` 时用**下标** `SDK_SITES[10]` ⇒ 插入 `ce_enemy_death` 后
     `CE_BP_SHOT_SET_INDEX_RVA` 被写成 `0x030240`（串位）；已改成**按名字**取址；
  2. `th18_card_expand.def` **漏导出 `BP_ce_enemy_death`** ⇒ thcrap `GetProcAddress` 拿不到 handler、
     游戏里**静默不生效**；已补（`@25`，导出 24 → 25），`patch/th18.v1.00a.js` 已重生成
     （`ce_enemy_death`，cavesize 6，期望 `558bec83ec14`），`sites.py check` 现做
     「patch 声明断点 ↔ `.def` 的 `BP_*`」双向对账。
- ⇒ 113 **已接线**：`static void on_enemy_death(ce_card_t *, const ce_enemy_death_t *)` +
  `CE_CARD(113, …, .on_enemy_death = on_enemy_death)`。判据 = `kind == CE_EDEATH_KILLED`
  且 `flags & CE_EDEATH_F_REAL`（⇒ 自动排除 `KILL_ALL` / `BOMB_KILL` / `ECL_DIE` / `OTHER`）。
  实证（i686 目标文件）：`_on_enemy_death` 已进 `ce_hooks_113`，重定位 `00000080`
  = `offsetof(ce_hooks_t, on_enemy_death)`（`sizeof(ce_hooks_t) = 272`，实测 256 之前我算错了表项）。
- **回调纪律**（`DEATH` §2.4 / §4.1）：**只做 O(1) 入队**（一次数组写 + 计数 ++）、
  **禁止**析构敌人 / 缓存 `ev->enemy`（同帧 sweep 就删）⇒ 队列里**只放标量**（`ev->x / ev->y` 快照），
  帧末 `trance_kill_take()` 一次取走。清场帧一次 100–300 次回调（`DEATH` §1.7）也扛得住。
- ⚠ 队列容量 **16**（不是 64）：每格要存 x/y 两个 float ⇒ 64 格 = 512 B，实测
  `sizeof(trance_card_t)` 变 **600 B** ⇒ 撞穿 `ce_state` 的 **496 字节硬上限**
  （`_Static_assert` 直接红；真跑起来 `ce_state_user` 会**静默返回 NULL**）。
  16 格 = 128 B 位置 + 其余字段，稳在限内；溢出**丢尾**并记 `trance_kill_queue_dropped`。

### 1.2 计分层：`ce_score_applier` 在 `sdk_core.h`（**不在** `sdk.c`）+ 广播形状是故意的

- 口径订正（SDK owner 2026-09-12）：`ce_score_declare` / `ce_score_aggregate` / **`ce_score_applier`**
  都在 `sdk_core.h`/`sdk_core.c`（我先前在 `sdk.c` 里 grep 不到 ⇒ **搜错了文件**）。
- `BP_ce_item_score` 的「逐张广播 `on_item_score(&value)`」是**故意保留**的形状：各卡只**声明**，
  **被选举的落笔者**（id 最小）在广播里自守 `if (ce_score_applier() != 我的 id) return;` 再落笔
  （110/111 都是这么写的）⇒ 不是「层没接上」，**不是缺陷**。
- ⇒ 113 现在**只声明**（`trance_declare_score()`），**故意不注册 `.on_item_score`** ——
  因为 SPEC §9 #5 的**载体**（原生 `0x4ccd24` / 改写 `on_item_score` / 卡内计数）还没拍；
  注册了也只是把已有的声明值再写一遍，没有载体语义。等拍板再接，届时不改 core。

### 1.3 ★ 最大得点的单位：`0x4ccd24` 是 **×100 定点**（一手复核，地址与 SPEC 差 `0x2000`）

- 一手（本次实测，Capstone 反汇编本机 `local/th18.v1.00a/th18.exe`）：
  `max_point = (MONEY × K + K) × 100`，`K = 0x4b93ac`（EASY 500）/ `0x4b93d4`（其余 1000）、
  `×0x4b9304 = 100`；结果 `cvttss2si` 后写 `0x4ccd24`，并按下限 `0x4ccd28` / 上限 `0x4ccd2c` 夹取。
  `MONEY` = `0x4ccd34`（计分乘数，`engine/card/th18/05-shop-and-money.md` §2）。
- ⚠ **地址差**：本机文件里这段的偏移算出来是 **`0x468d1`**（写 `0x4ccd24` 的那条 `mov`），
  而 `REVIEW` §7.7 记的是 `0x446918` —— 差 **`0x2000`**且**整段一致**。同一方法复核 `th13.v1.00c`
  也差 `0x2000`（一手链 `imul [0x4be7dc] / sar edx,5 / idiv 10` 在文件里落在 `0x2ea1a`）。
  ⇒ 这是**工具/文件口径**的差（不是文档写错语义：指令内容逐条对上），**登记为待核**，
  实装用**相对语义**（"字段是 ×100 定点"）而不是绝对地址，所以不受影响。
- ⇒ 113 的 type 1 奖励 +10 / +100 走 `trance_max_point_field_addends(display, unit)`，
  卡侧传 `TRANCE_MAXPOINT_FIELD_UNIT = 100`，**不写死**、**不直接写全局**（会牵动原生最大得分显示）。

### 1.4 一手 type-3 弹窗分的**整数链**（`th13:0x438c3d`）已逐条复核

```
mov eax,0x51eb851f ; imul DWORD PTR ds:0x4be7dc ; sar edx,5 ; (shr ecx,0x1f / add)
mov ecx,0xa ; idiv ecx          ⇒ 商 = (PIV/100)/10、余数 = (PIV/100)%10
⇒ popup = (PIV/100) − ((PIV/100)%10)          （「向下取整到 10 的倍数」，SPIRIT:84 口径）
  实际入账 = popup/10（一手 `th13:0x413bf0`）
```
⇒ 落在 `trance_type3_popup_from_piv()`，单测钉了 11 个点（含 `piv = 30000 → popup 300 → 入账 30`）。

## N. 神灵实体层已落地（2026-09-12，用户裁决 + 实装）

**用户裁决**：「神灵实体 ≈ P 点、蓝点等下落道具，但 ① **不会下落** ② **不会被全屏收集，必须跟过去吃** ③ **随时间不断变小而消失**；**它不是敌人**。」
⇒ 实装 = **自建 VM 池**（文件级 static `s_spirit[128]`，每颗 {VM id, 出生 x/y, life, age, type, dying}），链路：
**击破 → `trance_kill_note()` O(1) 入队 → 帧末 `take` → `trance_spirit_spawn()` 建 VM → 静止（只写 `y+bob`，无速度/重力/出界删）→ 每帧按 core 的千分点写 `scale`（越缩越小）→ 到期 `ce_anm_interrupt(id,1)` 播 20 帧消失段 → 玩家**走到 24 px 内**才入账（槽 +2）**。

- **不再有帧末自动入账那条兜底**（`TRANCE_KILL_AUTOCOLLECT` 宏与分支整段删除）；
- **全屏收点天然无效**：本文件对 `ce_item_collect_all` / `ce_cancel_all_bullets` / `ce_cancel_radius` 的**代码引用 = 0**（结构性事实，不是用 `if` 挡的 —— 我们的池不在引擎道具池里）；
- 载体（借，标 `❓ 自定`）：脚本 `129_season_bullet_summer`（主路径 `0: stop()`、无 `scaleTime` ⇒ 卡侧写 scale 不会被插值器盖掉；`interruptLabel(1)` 正好是 20 帧消失段）、贴图 `SPRITE_SOUL_0`（零售 16×16 魂图）、染色用一手 TH13 `color()` 内芯值（type 0–3）；
- **一手照抄、非自定**：寿命 **480 帧**（`th13:0x438a61`）、缩小 `1.5 → 0.4` / 200 帧（`astral.anm` script1）、染色值；
- `❓ 自定`：池 128（一手 TH13 是 256）、吃取半径 **24 px**（一手 20，但原作会飞向自机，我们不飞 ⇒ 放宽）、bob 1 px / 32 帧（方波）、**层 13**（世界层 —— 场上实体，与 `faith.c` 的 `FAITH_LAYER` 一致；**不是 HUD，所以不走 24/25**；世界层 3–19 本来就在暂停模糊的游玩区 surface 上 ⇒ 同样会被模糊）；
- 收尾：`trance_clear()`（`on_delete` / `on_run_reset` / `on_stage_start` 共用）里 `trance_spirit_clear_all()` **放在 `if (!s) return;` 之前**，含正在播消失段的 `dying` 那批；`ctor` 刻意不清池（每关会被重调）。
