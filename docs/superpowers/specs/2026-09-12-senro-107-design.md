## 0. 一句话

**被动卡「妖妖梦」**：收道具 / **结界中擦弹** / 自机弹命中 → **樱点**与 **+C** 一起涨；
**+C 到 50000 自动开森罗结界**（**7 s**，用户定案）。结界中：**每帧全屏收点**、**擦弹同时涨樱点与最大樱点**、
+C 按剩余计时比例**持续下降**。**中弹或按 B ⇒ 灵击**：结界中断 + **全屏弹转小樱点** + **0.67 s 无敌**（40 帧）；
**自然到期** ⇒ 樱点与最大樱点各 **+10000** + **樱点分**的 Border Bonus。
**Miss / Bomb 扣樱点**（**不动 +C、不动最大樱点** —— 用户口径与一手一致）。
**樱点 = 本卡的「最大得点」**：吃一颗点道具（TH18 金钱）的得分 = 樱点（`on_item_score` 改写身价）。

### 3.2 无敌：走声明层，不写计时器

`ce_invuln_request(107, 剩余帧)` 每帧声明 + 灵击当帧 `ce_invuln_apply()` 补一笔；
SDK 在 `ce_item_frame`（`sdk.c:836`–`848`）每帧 reset 闩锁并落笔。⇒ 与 117 的 40 帧**取最大值、互不截短**
（review §9.7 尾段的结论）。先例 = `cards/pofv.c:161`、`cards/mof.c` 的灵击段。

### 3.3 计分：`on_item_score` 落笔（断点 `0x446cf6`）

- 本卡**声明** `ce_score_declare(107, senro_point_item_value(&st))`（粘性；`on_tick_2` 每帧刷新）。
- 落笔者 = **声明者里 id 最小**（`ce_score_applier()`，`sdk_core.h:103`）⇒ 107 在场时由 107 落笔。
- 落笔写法 = `*value = PV × 10` ⇒ 引擎随后 `SCORE += value / 10` ⇒ **精确得到 PV 分、天然不双计分**
  （review §7.8）。落笔时读的是 **`ce_score_aggregate()`**（Σ 各卡的「最大得点」载体），不读别的卡的状态。
- ⚠ 现行 `sdk.c:631` 的 `BP_ce_item_score` 还是「逐个写指针」的旧形态 ⇒ 落笔者直接写 `*value`
  （层改成聚合式之后这一行**仍然正确**，不需要跟着改）。
- ⚠ **绕过了原生高度系数**：`on_item_score` 在 `collect_money_item` 内、身价**已按收取高度算过**
  （review §7.6 的 `coeff_06`），改写它等于把「线下打折」抹平 ⇒ 登记为未定项（§9 第 4 条）。

## 5. 「7 s」的依据与冲突（必读）

- **用户定案 = 7 s**（420 帧 @60fps），本卡按它实现（`SENRO_BORDER_FRAMES = 420`）。
- **反汇编里有两个数并存**：开结界时写进计时的是 **`0x21c = 540`**（`th07:0x4419fa`，
  `edx = player+0x16a00` ⇒ 即 `[player+0x16a08] = 540`），而 **`0x1a4 = 420`** 出现在 `th07:0x40dbdc`。
- 另有两条未解把「实际帧数」留在了 🟡：
  ① `[player+0x16a08]`（结界计时）的**递减写点全 exe 找不到**（research §6.1，13 处引用全是读）；
  ② `[player+0x16a14]`（计时闸门 = `th07:0x4414cf` 的分母）在 exe 里**没有任何写点**。
- ⇒ 结论：**7 s 是用户口径**，不是反汇编结论。若将来实测出 540 帧（9 s），改一个常量即可。
- ⚠ 本卡的「开结界那一帧就算第 1 帧」（`senro_tick` 里开完门当帧就减 1）是 ±1 帧的判定，
  与 420/540 的量级差相比可以忽略，登记在此以备实跑对账。

## 6. 状态机

### 6.1 每帧顺序（`cards/senro.c` 的 `on_tick_2`）

```
⓿ 中弹灵击的补做（上帧在死亡栈里记下的 pending）→ 消弹 + 小樱点入账
① 无敌声明（剩余帧数 → 层取 max → 自己 apply 一笔）
② 对话中冻结，否则 senro_tick()（计时 / +C 比例 / 自然结束）+ 结界中全屏收点
③ 擦弹差分 → senro_graze()（只在结界中）
④ X 上升沿且结界中 → 灵击（B 路：当场消弹）
⑤ 符卡奖励次数（收掉一张符卡 +1，供樱点（大）道具的 ×100 项）
⑥ 计分声明刷新（粘性）
⑦ 每 600 游玩帧一条诊断日志
```

- 帧源 = `on_tick_2`（管理器侧每帧，菜单 / 商店不跑）；先例 `cards/pofv.c` / `cards/mof.c`。
- **对话中冻结结界计时**（`CE_GUI_MSG_ACTIVE()`，`engine.h:210`）：th07 的结界更新挂在 Player tick 上，
  对话里引擎同样不推进游玩 —— 口径写在这里，实跑看一眼体感。

### 6.2 开门 / 排队 / +C 的重写

| 情形 | 行为 | 一手 |
| --- | --- | --- |
| 加法器把 +C 顶到 `≥ 50000`，且**不在结界中、没在放炸弹** | 夹到满值 + **开门**（计时 = 420） | `th07:0x42f647` / `0x42f652` |
| 顶满时**正在放炸弹** | 只置「排队」，炸弹结束那一帧开门 | `th07:0x44196c` → `0x441983` |
| 顶满时**已经在结界里** | +C 停在满值（下一帧被计时比例重写），**不重开、不排队** | `0x4419b2`/`0x4419df` 的门是主状态 ∈ {1,3}（≠ 展开中的 4）⇒ 见下 |
| 结界中每帧 | `+C = 剩余计时 × 50000 / 总时长`（= 「持续下降」） | `th07:0x4414db`–`0x44150e` |

⚠ 第三行是本卡的**收窄判定**：th07 的另两处排队写点（`0x4419b2` / `0x4419df`）门的是
「Miss 待复活 / 结界收尾动画」，不是「结界展开中」⇒ 展开中再攒满没有明确的一手归宿 ⇒
本卡选「不重开」（`cards/senro_core.c` 的加法器注释里记了这条）。

### 6.3 灵击（含「不在死亡栈里扫弹池」的一手依据）

- **按 B 路**（tick 上下文）：`ce_cancel_latch_claim` → `ce_cancel_radius` → `senro_libyou(n)`
  → 无敌声明 + SE + 震屏；**原生炸弹照放**（本卡只做结界那一半，不碰 `on_bomb_gate` 的代价归属）。
- **中弹路**：`+0x10` 回调里**只做「不收尾就会丢」的事** —— 结束结界（`senro_libyou(0)`）、
  40 帧无敌、`cancel_impending_death()`（`0x45d590`）救命；**全屏消弹推迟到下一帧**。
- **为什么不能当场消弹**（TH18 一手链条）：中弹发生在**弹自己的更新函数**里 ——
  `FUN_004248a0`（同函数在 `0x42497a` 调 `Player__do_graze`）→ `0x42490b` / `0x42493f` `call 0x45cc20`
  （自机受击判定）→ `Player__die` `0x45d3a0` → `0x45d574 call [vt+0x10]`（我们的回调）。
  即回调跑在**某颗弹的更新中途**（`esi` = 那颗弹，返回后同函数还在用它），此时扫整池弹并标删除 =
  和调用方抢同一块状态。⇒ 推迟一帧（≈16 ms）到管理器 tick，先例 = `mof.c` / `pofv.c` / `animal.c`
  的消弹全都在 tick 里做。**实跑要点见 §10 第 3 条。**
- **`107 拿这笔账`**：117 的消弹发生在霊撃的**后续帧**（`cards/animal.c` 的 `hyper_frame` 每帧调
  `ce_cancel_radius`），它 `+0x10` 那一帧不 claim ⇒ 现况下 107 天然拿到。若将来有卡在 `+0x10` 就消弹，
  就需要 SDK 提供**层内顺序**（EVENTS-CONTRACT §5.2 细则 1「107 → 117」目前没有机制）——已登记为跨卡缺口。

### 6.4 两条收尾

| 收尾 | 樱点 | 最大樱点 | +C | 其它 |
| --- | --- | --- | --- | --- |
| 自然结束（计时 ≤ 0） | `+10000` | `+10000` | → 0 | 分数 `+= round10(樱点)`、SE、Bonus 飘字 |
| 灵击（中弹 / 按 B） | 每颗小樱点 `+100` | 不动 | → 0 后按每颗 `+30` 回填 | 40 帧无敌（声明层）、救援时取消死亡 |
| Miss（真死 `+0x14`） | `−round10(min(樱点/2, 100000))` | 不动 | 不动 | 不夹回基准 |
| Bomb（`on_bomb_spent`） | `−round10(樱点/4)` | 不动 | 不动 | 夹回基准（不会变负） |

## 10. 实跑清单

1. **开结界**：收 ~50 颗金钱（`1000/颗`）→ +C 满 50000 → 结界开、+C 变成**逐渐下降**的读数（HUD 三行）。
2. **结界中**：道具**自动全收**（日志 `结界全收`）；擦弹时樱点**与**最大樱点同涨（日志差值）。
3. **中弹**：撞弹 → **不死**、结界中断、日志出现「灵击（中弹）消弹 N 颗」与下一帧的「补做消弹 N 颗」、
   约 0.67 s 无伤；确认**没有崩溃 / 弹幕没有残留诡异状态**（这是 §9 第 3 条的判定点）。
4. **按 B**：结界中按 X → 同一个灵击（当场消弹）、原生炸弹照放、Bomb 再扣一次樱点。
5. **自然结束**：不动 7 s → 樱点与最大樱点各 +10000、飘一条金色 Bonus 数字、分数上涨
   `round10(樱点)`（对账 SCORE 差值）。
6. **Miss / Bomb**：Miss 后樱点减半（上限 10 万）、放炸弹减 1/4；两者都**不掉 +C、不掉最大樱点**。
7. **点道具分值**：吃一颗金钱，弹窗数字 ≈ `PV×10`、SCORE 增量 = `PV`（与 110/111 同装时看聚合）。
8. **符号/边界**：樱点到最大樱点时数字变金黄、+C 满值变亮青。
9. **同装**：与 117 咆哮 / 113 灵界同装各跑一局 —— 一次中弹**两份代价都付**、无敌**不互相截短**、
   消弹**只发生一次**（EVENTS-CONTRACT §5.2）。
10. **删卡**：买倒吊人删掉 107 → HUD 三行消失、无敌/计分声明退掉、日志无残留（商店里 tick 停着也不漏）。
11. **回放**：录一段「开结界 + 灵击」的回放，重放行为一致（只读 `0x4ca428` 的掩码，不用随机数）。
