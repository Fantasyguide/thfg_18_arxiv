# Card Expand Foundation Hardening Design

> **版本**：TH18 v1.00a。本文定义 `mods/th18.v1.00a/card-expand/` 的地基修复；不改变现有卡牌的玩法数值或效果。

## 目标

让扩容初始化真正满足“任何失败都关闭新 ID”，让行为登记、数据登记和卡牌类别在进入游戏前完成一致性校验，并把新增卡牌所依赖的公共接口从 TH18 地址与 ABI 实现中分开。完成后，开发者应能用一个明确的检查入口发现重复 ID、主动卡配置错配、资源生成物漂移和 DLL 构建问题。

## 范围

本轮包含五组改动：初始化失败回退；行为注册与数据契约；安全的发卡接口；JSON 两阶段装载；SDK/build/docs 边界整理。现有 `CE_CARD(id, ...)` 卡牌源码保持兼容，现有卡牌 ID、资源编号、补丁地址和游戏效果不变。

本轮不引入第三方行为 DLL、动态 ABI、符号 ID 分配器，也不把所有 `engine.h` 地址改成多版本 profile。这些需要独立设计，不能混进一次安全修复。

## 初始化与失败语义

`ce_selfcheck()` 使用单一失败出口。只要 module base 可用，任何失败都尝试把分配器上界恢复到零售值；回退函数保持幂等。最终日志必须区分原始失败与回退是否成功。

初始化仍按现有顺序执行，但所有会发布运行时状态的步骤必须先完成自身校验。JSON 装载先解析到固定大小的临时数组，检查全部卡牌、商店容量和全局约束，再统一写入表、文案和注册表。解析失败不得留下已发布的新卡定义；临时名字由固定结构持有，不再逐卡 `malloc`。

## 行为注册与跨层契约

行为注册表增加按 ID 的直接索引和持久错误状态。重复 ID、越界 ID和容量错误即使发生在 DLL constructor 阶段，也会被记录并在 `ce_sdk_setup()` 中令整包失败；不依赖此时尚未初始化的日志。

`ce_sdk_setup()` 对每张 JSON 卡执行以下契约：

- `category == 0` 时必须登记行为，且 `active_recharge > 0`；
- `active_recharge > 0` 时 JSON `category` 必须为 0；
- 行为 ID 必须落在 58–254，并存在于本次成功解析的 JSON 注册表；
- 其他类别继续允许没有行为，以支持纯数据占位卡。

事件回调仍按游戏卡链表顺序执行，因此已有叠加行为不变；行为查找改为 O(1)。私有状态表本轮保持现状。

## 公共 SDK 边界

新增 `native/sdk/public.h`，承载卡作者需要的稳定类型、hook 定义、卡对象访问器和 `CE_CARD` 声明入口。TH18 v1.00a 的地址、对象偏移和内联 ABI 包装继续由 `engine.h` 与平台实现持有。现有 `native/sdk.h` 作为兼容入口包含 public API 与平台 helper，使全部现有卡牌无需批量改写。

会直接改变游戏状态的 helper 使用可检查的结果。`ce_give_card()` 仅在 `allocate_new_card()` 成功后调用 `mark_obtained()`；返回值继续保留引擎的成功值或 `-1`，现有调用方无需改变签名。

## 构建与开发入口

Makefile 提供三层入口：

- `quick`：主机纯逻辑测试与 Python 单测；
- `check`：资源、SHT、音效、站点、文档和 DLL 静态约束；
- `package`：完整生成、验证、DLL 构建与分发目录。

交叉编译器优先使用显式 `TOOLCHAIN`，否则从 `PATH` 查找 `i686-w64-mingw32-gcc` / `objdump`，最后兼容当前本机路径并给出清晰错误。`dllverify` 必须以断言方式检查 PE32、必要导出和依赖，不能只打印。

标准 pytest 收集不得因测试模块 import 时 `sys.exit()` 崩溃。脚本式检查保留直接执行方式，但不再以 `test_*.py` 名称伪装成 pytest 测试，或改为标准 pytest 函数。

## 测试与验收

每个行为变更遵循红绿重构：先加入会在旧实现上失败的测试，再写最小修复。

主机测试覆盖：重复和越界行为登记留下错误；按 ID 查找；主动卡类别契约；分配失败不解锁；JSON 批次只有全部有效时才提交。Windows/补丁侧通过现有站点扫描、DLL 构建、x87 检查和导出检查验证。

最终验收命令从 `native/` 执行：

```bash
make quick
make check
make package
python3 ../../../../tooling/check-docs.py
```

工作区已有的 `patch/files.js` 修改属于用户，不在本轮回退或覆盖；生成命令若刷新该文件，必须核对结果只反映当前资源内容。
