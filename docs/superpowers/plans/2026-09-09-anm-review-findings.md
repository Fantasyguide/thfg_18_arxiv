### C1 · `04-variables.md` §8：`10035` 判成「无固定引擎语义 ✅」是错的

穷举漏掉真消费者 `FUN_00405700`：

```
th16:0x4057cb  MOVSS XMM0, [EBX + 0x4c8]     ← 10035
th16:0x4057d3  ADDSS XMM0, [EBX + 0x40]      ← rotation.z
th16:0x4057dd  CALL th16:0x406470            ← cartesian_from_polar(out, angle, 150.0f)
```

**闭合链的三段本仓三份文档各写了一段，只是没人串起来**：

1. `02-vm-core.md` 已登记 `ANM_ON_TICK_CALLABLES` `th16:0x4919e8` = `{0, 0x407330, 0x405700, …}`，
   由 `AnmVm__run` 按 `vm+0x5c4` 每帧派发
2. `08-child.md` 已确认 `508 createEffect` 把回调下标写进 `vm+0x5c4`，真实数据 `508` ×42 全 kind=1
3. effect 表 `th16:0x4a2250` 的 kind=1 项 → `+0x5c4 = 2` → `th16:0x405700`
4. 而 `04` §8.2 自己列的「用法 3」就是 `effect.anm` #155–196 共 42 个 script 做
   `setF(10035, ±π/4)` 后紧接 `508 createEffect`

⇒ **46 次 `setF(10035)` 里 42 次，下一条指令就在安装那个读它的引擎回调。** ±π/4 = ±45° 正是那个角。
thpages 的 "Is somehow related to rotation?" 对 z 分量是对的。

METHOD 的额外闸门里「一手到底」（穷举漏项）与「对抗证伪」（只在自选的 5 个函数上否掉
「渲染欧拉角缓存」，而真正的渲染消费者就在表外）**两条都断**。

**处置**：`10033`/`10034` 的判定仍成立（独立穷举确认除 helper 外只有假阳性）→ 拆开：
x/y 保留、z 撤销 ✅ 改 ❌，新结论「`10035` = `on_tick` callable #2 读取的、相对 `rotation.z`
的角度偏移；仅在 `+0x5c4 == 2` 的 VM 上生效」给 🟡。§8.4 的「过额外闸门」宣称删掉。

### C2 · `06-settings.md`：`300 sprite` 的「`id` 恒非负、0 次负数 ✅」是假的

实跑 54 个文件：`arg0 == 0xFFFFFFFF`（signed −1）**共 80 条**——`effect.anm` 27 / `front.anm` 21 /

而文档自称与 thpages 逐条比对过）。

### C3 · `07-general.md` §4.1：mode 27–31 的公式写反自变量，且挂在 ✅ 下

文档写 `1 − g_c(u)`，实际是 **`1 − g_c(1 − u)`**：

```
th16:0x4038e7  xmm0 = 1.0 ; xmm1 = xmm0 ; subss xmm1, xmm3   ← 1 − u
               subss xmm1, [th16:0x494460]  (−c) ; mulss ; divss w ; subss s ; divss n
               subss xmm0, xmm1
mode 28–31 同构：th16:0x403922 / 0x40395d / 0x403998 / 0x4039d3
```

**照文档写的公式实现，曲线是 `f(0)=1, f(1)=0` —— 整段动画倒放。** 而文档自己给的峰值
（1.125…1.800）与「越过终点再回落」只在正确公式下成立，说明作者知道形状却把式子抄反了。
这是「公式错不会报错、只会画面不对」的最坏形态：不是微妙，是彻底反向。
