## 1. 一句话结论

**thcrap 的断点入场时刻（"站点"）预算 = 全进程共享的硬上限**（分片实验已证伪 per-patch 假设）：
TH18 实测**安全 ≈22 条、≥24 必崩**。因此「新机制能不能做」的第一问不是"能不能写代码"，
而是**"要几条站点、能不能并进已有站点"**。八个跨作系统原语里 **7 个是 0 站点**（走函数调用 /
声明层 / 数据层），只有「收点(12)」复用一条既有站点。

## 4. 给同僚的硬约束（务必先读）

1. **发布只有一条路**：`MODKIT_DIR=<modkit> python3 native/tools/deploy.py`（构建 → 站点预算 → 双向导出对账 →
   复制 → 回读 md5）。手工拷 patch/DLL 会造出"patch 与 DLL 不同源"的静默失效。
2. **站点余量只有 2**（当前 **22 / 24**：正式 patch 20 条 + 测试归档 2 条，两者共用一个进程预算）。
   要加站点前先在 `COMPAT-MATRIX.md` §1 记账。
3. **共享工作树**：`mods/th18.v1.00a/card-expand/` 可能同时有别的会话在改；动手前看 `git status`，
   只提交自己那批文件。
4. **文档门只扫已跟踪文件**：`python tooling/check-docs.py` 用 `git ls-files *.md`
   ⇒ 新建的 md **先 `git add` 再跑闸**，否则它静默不检查。
5. **实跑判读**：`python3 native/tools/verify.py all --check`（读游戏日志的"本次启动段"）。
   注意**防假绿**：先确认日志里 `integrity[stage N]: card[i] id=…` 列出了全部 12 张系统卡
   （106–117），少一张卡后面全绿也不算数。
