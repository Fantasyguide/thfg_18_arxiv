# mouse-control —— TH06NC 鼠标控制

> **版本**：TH06NC（Steam 2026 重制版，`th06nc.exe`，MD5 `b0cc28ec904e9efce2439ad857c938b5`，
> imagebase `0x140000000`）。本文裸地址默认属该版本。

用鼠标操自机：光标在哪，自机往哪走。**F9** 开关。

移植自 [`th18.v1.00a/mouse-control`](../../th18.v1.00a/mouse-control/README.md)，
思路完全一样，**实现方式不同**——TH18 那个走 thcrap 断点，TH06NC 暂无 thcrap 生态，
所以这个是**单 DLL 代理**，不需要任何加载器。

> ⚠️ **未实机验证。** 开发机是 Linux，跑不了这个游戏。静态审计全过、交叉编译产物
> 格式核验通过，但**没人真的启动过它**。首次使用请按下面「怎么确认成功」逐条看。
> 详见 [`AUDIT.md`](AUDIT.md) §E。

## 原理

**合成输入**——每帧按光标方位算出「该按哪个方向键」，写进 `INPUT_HELD` 的方向位，
剩下全部交给游戏自己的移动代码。所以钳位、低速、倾斜动画、出生无敌
**一个都不用我们操心**，它们本来就在那条路径上。

**玩家对象零写入**：整个 mod 只写 `INPUT_HELD` 一个 dword，玩家对象只读不写。
这条约束换来的好处见 [`AUDIT.md`](AUDIT.md) A 节——checklist 里最容易出错的一整节直接 N/A。

## 装法

**一个文件，拖进游戏目录（和 `th06nc.exe` 同一层）**：

```
<游戏目录>/
  th06nc.exe
  VCRUNTIME140_1.dll     <- 就是它
```

### 为什么是 `VCRUNTIME140_1.dll`

它在 exe 的**静态导入表**里，且只被要走一个函数（`__CxxFrameHandler4`）。
Windows 加载器必须在 exe 入口点**之前**把它加载起来，否则进程根本起不来——
所以这条路**不依赖游戏跑到哪一段代码**。我们把真身从 `System32` 加载进来转发，
游戏的异常处理照常工作。

> **早先的 `xinput1_4.dll` 那条路实测不成立。** 它不在导入表里，是运行时
> `LoadLibraryW` 的，而且那段代码上面有个闸门（`th06nc:0x1400ab7b4` 的 `JNZ`）——
> 前置初始化没成功就整段跳过，连游戏自己的 `XInput DLL の読み込み中...` 都不会打印。
> 完整对比见 [`TARGET.md`](TARGET.md) §3。
> `native/xinput1_4.dll` 仍然会构建出来，留作备选，但**默认别用它**。

**卸载**：删掉 `VCRUNTIME140_1.dll`。没有别的残留（ini 和 log 可以一并删）。

### 自己编译

```sh
cd mods/th06nc/mouse-control/native && bash build.sh
```

需要 clang + lld-link + Windows SDK/CRT 头（本机走 `cargo-xwin` 缓存那套，
见全局笔记的 xwin 环境）。产物 `xinput1_4.dll`。

## 用法

**默认开启**（装上就生效，不用先按键）。

| 操作 | 效果 |
| --- | --- |
| 移动鼠标 | 自机朝光标走；光标移出可动区则停在对应的墙上 |
| **左键** | 射击（等同 Z） |
| **右键** | **低速**（等同 Shift） |
| **中键** | **炸弹**（等同 X） |
| **F9** | 开 / 关鼠标控制。关掉后键盘方向键立即恢复 |
| **F11** | 标定：点关卡区两个角（推荐）——见下 |
| **F10** | 标定：瞄自机（需先按 F9 关掉鼠标控制）——见下 |
| Z / X / Shift / 方向键 | 照常可用（见下） |

- **方向**：开启期间键盘方向键失效（每帧被覆盖）。按 F9 关掉即恢复。
- **按键**：只叠加、不清位，所以键盘 Z/X 与鼠标左右键**同时有效**。
- 只在游戏是前台时接管，alt-tab 出去点别的窗口不会走火。
- 出生动画与死亡期间不接管方向（那时游戏本来也不读方向位）。
- 想改成默认关闭：ini 里 `enabled = 0`。

## 标定（一般**不需要**了）

默认布局已经按实测数据烤进去了，装上直接就是准的：

> 虚拟屏高固定 480、宽随窗口宽高比扩展；关卡区 384×448 **水平居中**、顶边 `y=16`；
> 缩放 = 客户区高 / 480。

已在 **1280×720** 和 **1920×1080** 下验证，误差 ≤ 7px（手点两角的精度量级）。
非 16:9 的窗口没测过——**只有那时才需要标定**。

> ⚠️ 如果你之前跑过标定，`th06nc_mouse.ini` 里会有 `cal_*` 几行，它们**优先级更高**、
> 会盖掉上面的默认值。想用新的默认值就**把 ini 删掉**（或删掉那几行 `cal_*`）。

### 要标的话：先按 F9

> ⚠️ **两种方法都要先按 F9 关掉鼠标控制**——开着的时候光标是隐藏的，看不见就点不准。
> ⚠️ **不要点鼠标左键**——左键是射击。标定只按功能键，**不用点击**。

**方法 A：点关卡区两个角**（推荐）

1. **F9** 关掉鼠标控制
2. 光标移到关卡区（弹幕区）**可见边框左上角**，按 **F11**
3. 光标移到**右下角**，按 **F11**
4. **F9** 开回来

**方法 B：瞄自机**（备用）——F9 关掉后，光标压在自机上按 **F10**，
把自机挪远（x、y 各至少差 40）再压上去按一次 **F10**。

两种方式都会解出仿射映射并写进 ini，之后自动读取。窗口尺寸变了会按比例缩放。

## 配置

可选。游戏目录下的 `th06nc_mouse.ini`（标定会自动写这个文件）：

```ini
[mouse]
enabled   = 1      ; 1 = 启动即开启鼠标控制（默认），0 = 默认关闭
toggle_vk = 120    ; 开关键虚拟键码，120 = 0x78 = F9
calib_vk  = 121    ; 瞄自机标定键，121 = 0x79 = F10
corner_vk = 122    ; 点角标定键，122 = 0x7a = F11

; 以下四项由 F10 标定自动写入，一般不用手改
cal_scale_x  = 2.000000
cal_off_x    = 232.000000
cal_scale_y  = 2.000000
cal_off_y    = 32.000000
cal_client_w = 1280
cal_client_h = 960

; 默认布局的两个可调量（虚拟单位，虚拟屏高 = 480）
origin_x = -1     ; <0 = 关卡区水平居中（NC 的实际布局）；填 >=0 则当作左边界
origin_y = 16     ; 关卡区顶边
```

关系是 `客户区像素 = cal_off + cal_scale × 自机坐标`。想手动微调就直接改 `cal_off_*`。

## 怎么确认成功

先看 `<游戏目录>/th06nc_mouse.log`（目录只读时退到 `%TEMP%`）。

**如果一个文件都没有**，用 [DebugView](https://learn.microsoft.com/sysinternals/downloads/debugview)
（以管理员运行，勾上 Capture Win32）看——每行日志同时走 `OutputDebugStringA`，
不依赖任何文件写权限。两边都没有，才说明 DLL 真的没被加载。

日志开头应该是：

```
th06nc mouse-control —— imagebase=00007FF7XXXXXXXX
[who] 代理 = VCRUNTIME140_1.dll
[who] 本 DLL  = ...\VCRUNTIME140_1.dll
[who] 游戏目录 = ...
[ini] origin=(32,16) toggle_vk=0x78
[guard] 序言签名匹配，跳板就绪（F9 开关鼠标控制）
[diag] 首次生效 [已标定] client=1280x960 cursor=(700,500) ...
```

进关卡按 F9，四条验收：

| # | 看什么 | 通过说明 | 不通过说明什么 |
| --- | --- | --- | --- |
| 1 | 自机朝光标移动并停在光标附近 | 坐标变换正确 | 见下「偏了怎么办」 |
| 2 | 按住 Shift 时定位明显更准 | 死区随合法步长缩小，速度读对了 | `+0x7860/64` 读错 |
| 3 | 自机有左右倾斜动画 | 合成输入路线成立（动画是游戏自己做的） | 说明我们其实没走输入路径 |
| 4 | 光标移出关卡区时自机贴墙不抖 | 目标钳位生效 | 目标没被钳到 `[0,384] × [0,448]` |

## 没反应？按这张表查

| 日志情况 | 说明 | 怎么办 |
| --- | --- | --- |
| **log 文件和 DebugView 都没有输出** | 代理根本没被加载 | 确认文件名正好是 `VCRUNTIME140_1.dll`、和 `th06nc.exe` 同一层 |
| 游戏启动就弹 `0xc0000142` | 我们接不上 System32 的真身，**刻意**让它响亮失败 | 确认 `C:\Windows\System32\VCRUNTIME140_1.dll` 存在；不存在就装 VC++ 运行库 |
| `[guard] …序言与预期不符，永久停用` | **不是这个 build**。后面那行打出了实际字节 | 换回记录在案的版本，或重做逆向（[`TARGET.md`](TARGET.md) §7） |
| `[hook] VirtualAlloc 失败` / `VirtualProtect 失败` | 系统层面拒绝 | 看 `err=` 的错误码 |
| 只有 `[guard] …跳板就绪`，之后没有任何 `[diag]` | hook 装上了但**没被触发** | 说明没进到玩家 tick——先进关卡再按 F9 |
| 有 `[diag] mouse_tick 首次触发` 但 F9 无效 | 触发了。看下一条 `[diag]` 说停在哪 | 按那行打出的实际值排查 |
| `[diag] playerState=… 本帧不接管` | 出生/死亡期间，正常 | 等动画结束 |
| `[diag] 取光标/客户区失败` | 窗口 API 出错 | 看 `err=` |
| 有 `[diag] 首次生效 …` 但手感不对 | 链路全通 | 那行给出 client 尺寸 / scale / 光标 / 目标 / 当前位置 / 死区，对着看 |

## 偏了怎么办

**先做上面的标定。** 没标定时用的是 TH06 的布局猜测，实测偏右约 200px，这是已知的。

标定完还偏：

| 现象 | 说明 | 怎么办 |
| --- | --- | --- |
| 整体平移一个固定量 | `cal_off_*` 差一点 | 直接改 ini 的 `cal_off_x/y`（单位是客户区像素） |
| 靠近一角准、离得越远越偏 | `cal_scale_*` 不准 | 重标，两点取得更靠近对角、离得更远 |
| 换了窗口尺寸后偏 | 自动按比例缩放失效（例如切了全屏改变了黑边比例） | 在当前尺寸下重标一次 |

日志里 `[diag] 首次生效` 那行会写明当前是 `[已标定]` 还是 `[未标定]`，先看这个。
