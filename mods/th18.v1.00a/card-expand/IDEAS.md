### 1.1 弹幕归属（「这颗弹是谁发的？」2026-09-10 结构复核）

- **zBullet 没有 owner 字段**（ExpHP th18 一手结构，stride `0xfa0`）：字段是 pos / velocity / speed /
  angle / hitbox / ex 状态 / scale / timer / **state** / **bullet_def_ptr** / **type** / **color**；
  唯一的指针 = `next_bullet_in_layer`（链表）与 `bullet_def_ptr`（贴图表项）——**没有 enemy / parent / owner 回指**。
- **绑定在敌人一侧**：`zEnemyData` 有 `bullet_props[0x10]`（0x598，`zEnemyBulletShooter`）、
  `bullet_mgr_offsets[0x10]`（0x4e58）、`bullet_mgr_origins[0x10]`（0x4f18，`zBulletOffset` = float2 xy + float）
  ——**敌人持有发射器 / 炮口定义**，弹生成后不带回指。
- **想拿 owner 只有两条路**：① hook 弹生成路径（ECL et* → 发射器 → `bullet_pool_spawn`）把 owner
  记进 side table（按 `index_in_bullet_array` `0x660` 索引）；② **空间启发式**（「在某敌人半径内的弹」）。
- **对卡的影响**：109 的蓝圈 / 红圈本来就是**半径消弹**（`ce_cancel_radius`），108 的「使魔周围」也是空间的
  → **都不需要 owner**；只有「只消某个 boss / 敌人发的弹」才需要 ① 的 spawn hook。

### 1.2 使魔 = 实体化的发射口？（th08 vs th18，2026-09-10 结构复核）

- **th08（永夜抄）**：使魔**不是独立类**，而是**带使魔 flag 的 `zEnemy` 实体**——
  `zEnemy` 有 `+0x2e0c __flag_field_used_by_familiars__see_0x41b246`、
  `+0x3380 __familiar_count__but_not_total`、`+0x53c8 familiar_circle_effect`；
  管理器侧 `zAsciiManager.familiar_popups[0x80]` / `zEffectManager.familiar_effects[0x80]`。
  每个 `zEnemy` 只有**一个** `bullet_props`（发射口）+ `bullet_offset`
  → **想要多个发射口就得召多个实体（使魔）**；发射口**随实体生灭，不常驻**。
- **th18**：**没有任何使魔字段**；发射口是 `zEnemyData` 内部的**常驻槽**——
  `bullet_props[0x10]`（`zEnemyBulletShooter`×16）+ `bullet_mgr_offsets[0x10]` / `bullet_mgr_origins[0x10]`
  / `et_ex_index[0x10]`。**一个敌人自带 16 个发射口，跟着敌人一生都在**，由 ECL et* 反复改写 / 启用。
- **想法（用户 2026-09-10）：把「活跃且远离敌人」的发射口实体化成使魔** ——
  多炮口 boss 本来就用**远偏移发射口**打弹，所以「使魔」只缺一层实体皮：
  ① 读 `bullet_props[16]`（`offset_final` = 相对发射点）+ `bullet_mgr_origins[16]`（世界原点）；
  ② 判「活跃」（候选 `type != 0` / `et_ex_index`，**待一手**）；
  ③ 用 `EnemyManager__allocate_new_enemy` **`th18:0x42d7d0`**（按 ECL 子程序名建**真 zEnemy**，
     原生 `CardLilyWhite` 在用）spawn 真敌机当身体 —— 天然可打 / 有 HP / 死亡掉落；
  ④ 击破 → `ce_cancel_radius` 按**位置**消弹转分（不需要 owner）。
  → 这是把 108「使魔原义」**部分救活**的一条路（需新增 `ce_spawn_enemy`，可能还要自定义 ECL 子程序）。
- **降级方案（用户 2026-09-10）：不折腾「停发射口」，改用「比例扣血」** ——
  使魔（= 远发射口实体化）被打 / 被击破时，**按比例扣本体 HP**（永夜抄人类形态原义 = **1/2 伤害转嫁 boss**）：
  - HP 结构：`zEnemyData.life` @ **`+0x4ff4`**（`zEnemyLife`：`+0x0 current` / `+0x4 maximum` /
    `+0x8 remaining_for_cur_attack` / `+0xc current_scaled_by_seven` / `+0x18 is_spell`）
  - ⚠ **别直接写 `current`**：`current_scaled_by_seven` / `remaining_for_cur_attack` / `is_spell`
    会与符卡进度 / 血条脱同步
  - 更稳：**往玩家伤害源池** `player+0x20574`（1024 槽 × `0x9c`）放一条源（先例：主动卡 Miko / Remilia，
    见 [`engine/player/th18/02`](../../../engine/player/th18/02-damage-sources.md)），让引擎自己结算
  - 闭环 = **远发射口实体化 → 打它按比例扣本体血 → 击破时空间消弹转分**
- **结论**：th18 的「使魔」= **敌人的 16 个发射口槽**（有发射口、没有实体）；
  「杀掉使魔消弹」在 TH18 **没有可击杀的载体**。要复刻只能：① `ecl_enm_create` 生成子敌人当载体；
  ② 自建 VM 池做伪使魔（照 116 / 119）＋ hook 弹生成把弹绑上去；③ 纯空间近似。

### 1.3 发射口预研（2026-09-10 一手反汇编，th18 v1.00a）

**et* 家族**（ExpHP labels 已命名；`bullet_props[i]` = `enemy + 0x598 + i*0x488`，16 个）

| op | 地址 | 作用 |
| --- | --- | --- |
| 600 etNew | `0x433dde` | `memset(bullet_props[i], 0, 0x488)` + 默认值；同清 `offsets[i]` / `origins[i]` / `et_ex_index[i]` |
| 602 etSprite | `0x434032` | 写 `bullet_props[i].type` / `.color` —— **`type != 0` = 已配置** |
| 603 etOffset | `0x434066` | 写**相对偏移** `bullet_mgr_offsets[i].x/.y`（`enemy+0x4e58 + i*0xc`） |
| 628 etOffsetAbs | `0x43414e` | 写**绝对原点** `bullet_mgr_origins[i].x/.y`（`enemy+0x4f18 + i*0xc`）；把 `origins[i].z` 置 **1.0（绝对）/ 0（相对）**（判据 `x ≥ −990`） |
| 601 etOn | `0x433f34` | 算**发射点世界坐标** → `bullet_props[i].offset_final`（`enemy+0x5a0 + i*0x488`），再 `CALL 0x427810`（BulletManager, `&bullet_props[i]`）开火 |
| 613 etClearAll | `0x434d46` | 全屏取消（`BulletManager` `0x4297a0` = 已知 cancel_all） |
| 615/616 etCancel/etClear | `0x4359b0`/`0x435a74` | **按「敌人位置」半径取消**（`0x42d1e0` = `enemy+0x44` → `0x429250` 半径消弹）；etCancel 额外清激光/特效 |

**etOn 的发射点算法**（`offset_final`）：
- **绝对模式**（`origins[i].z > 0.9`）→ `offset_final = origins[i].xy + offsets[i].xy`（z = 0）
- **相对模式** → `offset_final = enemy.pos + offsets[i]`
- 常量：`0x4b916c = 0.9`（模式阈值）、`0x4b9178 = 1.0`（绝对标志）、`0x4b947c = −990.0`（绝对原点哨兵）

**结论（回答「活跃 / 在哪 / 能不能停」）**
1. **活跃** = `bullet_props[i].type != 0`（etSprite 写、etNew 清零）；要「最近开火」另外 hook etOn 打时间戳
2. **发射点世界坐标** = `bullet_props[i].offset_final`（`enemy + 0x5a0 + i*0x488`），etOn 时算好
3. **「远离敌人」** = `|offset_final − enemy.pos|` > 阈值 → **「实体化使魔」的候选**
4. **停发射口：没有 per-emitter 关闭指令** —— etClear/etCancel 是「敌人周围半径消弹」，不是关槽；
   写 `type = 0` 会被下一发 etSprite 写回来 → **用户判断正确（困难）**
5. **现成弹药**：`0x429370` = **按位置半径消弹 + 转点道具**（`ce_cancel_radius` 的底层，stdcall 四参 + XMM2 半径，`SDK.md` §；AUDIT O29a）。
   ⚠ 别和 `0x429250` 混：那是 **2 参、不转道具**的另一版，全 EXE 只有 etCancel/etClear（`0x4359d9` / `0x435a9d`）在用

**问题**：110 的信仰想复刻「蓝点分 = 信仰 × 吃黄系数」，TH18 底层还剩多少？

**道具类型分发**（`ItemManager__on_tick__body` `0x445a80`）：type `1..0x13`（19 种），

| 15 | `0x446584` | … |
| 16–19 | `0x446531` | … |

**关键事实**
- **TH18 没有「最大得点」全局**。`[0x4ccd34]` = **MONEY**（`engine/card/th18/05-shop-and-money.md` §1：
  「关卡内赚、关卡末花的循环货币，**而且同时是计分乘数**」）。
- `0x446547`（type 9–14）就是 `SCORE += f(MONEY)`，clamp 999999999 —— 即
  「**道具 → 按全局乘数加分**」的**形状还在，但乘数是钱、不是最大得点**。
- 道具贴图表 `ITEM_TYPE_TABLE_sprite_and_card @0x4b4020`（stride 8）：
  **type 1–19 每种都有 sprite 号** → ⚠️ 2026-09-10 纠偏：那个号是 **`bullet.anm` 的脚本号**
  （`script112..125`），**不是** `bullet1.png` 的图元号 —— 脚本 112/113/115/117 分别画
  `bullet/item.png`（entry3）的 `sprite500/502/506/510`：**火力 = 红色方点、金钱 = 金色方点**（16×16）。
  「蓝点」是**道具灵**（TH17 `beast1.png` 的鱼）那一侧的叫法，别和 TH18 的金钱图元混。

**结论**
1. **贴图在** ✅ · **type 槽在**（type 2） · **「蓝点 = 最大得点 = 吃黄线」的计分语义：不存在** ❌
   ⚠ **订正（2026-09-11 一手）**：TH18 **有**「最大得点」这个派生值 —— `0x4ccd24`，
   由 `(MONEY+1) × 难度常量 × 100` 算出（`0x446918` 起；EASY 用 `0x4b93ac` = 500、其余 `0x4b93d4` = 1000，
   `0x4b9304` = 100 是 ×100 定点），下限 `0x4ccd28`、上限 `0x4ccd2c`（`0x44286e` / `0x442898` 初始化）。
   ⇒ 「不存在」只对**独立可写的计数器**成立；派生值一直在，**写 `MONEY` 就等于写它**。
   但写 `MONEY` 会污染商店经济（钱能买卡、花钱会反掉）⇒ 卡内仍应自建计数器。
2. 想原样复活蓝点 = 自己造一个点道具 type + 最大得点全局 → **等于重写一条道具逻辑**，与原生池冲突
3. **便宜的替代**：TH18 的 **type 9–14（分数转换点）本来就是「按全局乘数加分」的通道** →
   110 可以不复活蓝点，而是**把信仰接进这条通道**（信仰当乘数 / 用 9–14 当信仰点载体）

**TH18 侧的 rank 接口（对 106 最关键）**
- TH18 有**同一组** ECL opcode **529–534**（`rankF3/F5/F2/I3/I5/I2`，`0x435b4f`…）
- 它们读 **`GlobalsInner+0x2c` = `0x4ccd08`**（getter `0x439ea0` = `mov eax,[ecx+0x2c]`）
- `0x4ccd08` 的 xref **只有 2 个 READ**（`Enemy__ecl_get_int/float_global` `0x437515`/`0x438183`），
  **没有 WRITE** → TH18 **没有原生动态 rank 写入者**
- **2026-09-10 复核：TH18 的 rank 是彻底死代码**（负结论）
  1. **从不写**：全程序 **185231 条指令**扫描，只有 **2 条**碰 `0x4ccd08`，**都是读**
     （`Enemy__ecl_get_int/float_global` `0x437515`/`0x438183`）；`GameThread` 里那几条 `[reg+0x2c]=0`
     是 **MSVC 异常帧**（magic `0xfff0bdc1`），不是 GlobalsInner。初值 = **0**（`.data`）。
  2. **从不用**：`thecl -d 18` dump 全部 **22 个 ECL**，`ins_529`–`ins_534`（= `rankF3/F5/F2/I3/I5/I2`）
     出现 **0 次**（对照：`ins_527` 42 次、`ins_535` 101 次 → dump 正常）
- **对 106 的意义**：**不能搭车**——写 `0x4ccd08` 也没人响应（没 ECL 调那 6 个 opcode）。
  PlayRank 的「整蛊影响面」**必须自己接**：① **改 ECL** 在关卡里插 `rankF*/rankI*` 选弹幕参数；
  ② 自定效果（用户提的「缩短 boss 符卡两波间隔」/ 调全局弹速密度）；③ 只做数值层 + 显示

### 1.7 可借技术：th15 Attack Randomizer（纯 ECL 随机派发）

**来源**：`D:\Downloads\th15randomAttack.zip`（v1.1；thcrap 上叫 `RandomAttack`）。
**只换 `th15.dat`，纯数据、无 exe 改动。**

**做法（一手 dump 对比 orig vs mod）**
1. **攻击集中**：把各关 ECL 的攻击子程序（`Xxx_at`）**搬进 `default.ecl`**，改名带来源后缀
   （`GirlA01_at_ST1` / `BCir01_BS4`…）→ `default.ecl` **5.8KB → 312KB**；各关 `st*.ecl` 相应缩小
2. **派发器**（default.ecl）：

   - `RandBossAt(A)`：同样，`% 109`
   - **`-10000` = ECL 的 `RAND`**（eclmap `-10000 RAND` 坐实）；`A` 透传给攻击子程序
3. **关卡 ECL 打补丁**：原来的 `@GirlA03_at() async;` → **换成 `@RandStageAt(0) async;`**
4. **随机初速**：`ins_23((1 + [-10000]) & 7)` = 随机等 1–8 帧；`-9982` 当标志位：
   `unless ([-9982] != 1234569) goto 跳过等待`，`RandDeadAt` 置 `1234569` → 死亡攻击立刻起
5. **死亡 / 复仇攻击**：`RandDead()` → `ins_300("RandDeadAt", …)`；

6. **`enemy.anm` 扩容**（986KB → 1052KB）：别的关的攻击贴图要一起带
7. 调时长 / 减重叠以压崩溃（changelog 一长串）

**风险**：跨攻击的子弹属性重叠 → **崩溃**（README 明说无法根除）。

### 1.8 「波次」与 TH18 的难度旋钮（2026-09-10，为 106 简单版 rank 铺路）

**mod 的「波次」怎么认定**：**它不认定** —— 替换的是 **ECL 的攻击调用点**（`@Xxx_at() async;`），
每个调用点换成一个随机攻击。波次边界由 **ECL 自己的调度**决定。**例**：`GirlA03()` 里一句
`@GirlA03_at() async;` → `@RandStageAt(0) async;`。

**ECL 内部真正的「波」**（th15 与 TH18 同构，一手 dump）：
```c
ins_535($A, 1, 1, 4, 20);   // $A = diffI(E,N,H,L) ← 波数（按难度）
...（etNew/etSprite/etAngle/etSpeed 配发射口）...
LOOP:
    ins_601(0);             // etOn = 开火 ← 一波
    ins_23(N);              // 波间隔
    if ($A--) goto LOOP;
```
TH18 实例：`ins_535($D, 10, 20, 26, 32)` + `ins_601(0)` + `ins_23(9)`。

**TH18 的难度旋钮（= 简单版 rank 的天然接口）**
- `ins_535 diffI` / `ins_536 diffF` 读 **`0x42aa20` → `GLOBALS+0x40` = `0x4ccd00`（难度）**，
  按 0/1/2/3 跳表在 **E/N/H/L 四个常量里挑一个**（>3 用第 4 个）
- `0x42aa20` **只被 ECL 派发器 `FUN_00430d30` 调用** → **hook 它只会影响 ECL**
- ⚠ `0x4ccd00` 本身还被 `EnemyManager__allocate_new_enemy` / `GameThread__end_stage` /
  `ScoreFileShotData::add_to_top10_if_worthy` 等读 → **直接写它会波及结算 / 分数 / 刷敌**
- ⚠ ECL 的 `rank_mask` 门控走的是 **per-context `difficulty_mask`**（非 `0x42aa20`）→ hook 它**不动门控**

**简单版 rank 路线（106）**：hook `0x42aa20` 返回 `f(真难度, 我们的 PlayRank)`
→ 所有 `diffI/diffF`（波数 / 间隔 / 速度）整体偏移，**不改一句 ECL**。
（与 th06 `rank→插值弹数弹速` 的效果方向一致；门控那半要另找。）

- **蓝色消弹圈（爆风）**：**击破妖精 / 幽灵**时产生，**有攻击力**；消掉圈内**白弹**；
  被消的白弹**以同样速度投到对手场地**；按**连爆质量回复己方气槽**
- **红色消弹圈**：**使用蓄力攻击**时产生；消掉圈内**所有弹幕**（含不可消）；
  被消的白弹**直接消失**（不投给对手）且**不回复气**

**固灵（吸灵）**
- 按**低速键（Shift）** → 低速移动 + 展开暗色**吸灵领域** → 这个动作称为**固灵**
- 进入领域的**幽灵** → 变圆形、**HP 减半**、**缓慢上浮** → 此时称为**活化灵**
- 活化灵**一段时间内没被击破会自爆**，生成 **3 颗自机狙小玉**
- 活化灵很脆、**击破有爆风**；**普通幽灵很硬（3 枪打不掉）、只有被连爆波及时才爆**

**键位（用户 2026-09-10 定）**：基本语义与普通作一致，选定花映塚系统即整体受影响 ——
**Shift = 低速 / 固灵（吸灵领域）**；**Z 点一下 = 发一发**（可给攻击力补偿）；**长按 Z = 蓄力**；
**B = QCA**（基本意图与 B 一致，不另设专用键）。
**白弹映射（用户 2026-09-10 暂定）**：**非 boss** 的、**贴图半径小于阈值 T** 的弹幕算白弹（T 待定）。

**Charge Mode（原版设置项，默认 Slow；本卡按上述键位）**
- **Slow（默认）**：按住 Shift = 低速 + 吸灵领域；按住射击 = 蓄力（**不射击就不能蓄力**）
- **Charge**：按住射击 = 低速 + 吸灵领域；按住 Shift = 蓄力（此时不能射击）（**不射击就不能展开吸灵领域**）

**蓄力 / 气槽**
- 按住射击 → 自机上方显示 `charge a/b`（a = 当前等级，b = 当前可蓄最高等级）；每升一级「叮」一声
- 松开射击键 → 发动 a 级**蓄力攻击**；**AI 能边蓄力边射击，玩家不能**
- **蓄力槽 / 气槽** = 场地底部横槽，**共 4 级**；「气」= 槽里的实心部分，用来发动蓄力攻击

**蓄力攻击 CA / QCA**：基础 = 释放一波随角色各异的强化射击；等级越高 → 无敌越长、消弹圈越大、附加攻击越强。

| --- | --- | --- | --- | --- |

**SC Level**
- 游戏区**左下角的数字，最高 16**，**Lunatic 难度初始为 8**
