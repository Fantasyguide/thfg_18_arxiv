## 0. 量法（可复现）

- **分频段**：Welch PSD 积分（44.1 kHz 用 `nperseg=32768`、22.05 kHz 用 `16384`，Δf 都 ≈1.35 Hz），
  频段 `sub<60 / 60–120 / 120–250 / 250–500 / 500–2k / 2k–8k / >8k`。
- **带宽统一**：我们的素材 22050 Hz（Nyquist 11 kHz）⇒ **所有**统计都先统一到 **11 kHz 以内**
  （原曲 8 阶 Butterworth 低通 10.8 kHz），表里的「原曲@11k」就是这个口径；原曲 11–22 kHz 的能量单独报
  （th18_14：−33.8 dBFS，不进对比）。
- **响度统一**：三方各自乘增益使积分响度（BS.1770-4 / EBU R128）都 = **−14.0 LUFS**，再比每段 dBFS。
  「占比」= 该段能量 / 全带（0–11 kHz）能量，**与响度无关**。
- **低频包络**：<120 Hz 低通后的峰值 / RMS / crest（峰−RMS）/ 包络 99.9 百分位 / 包络中位 /
  占空比（包络 ≥ p99.9−10 dB 的时间占比）/ 每秒重击数（`find_peaks`，间距 ≥0.1 s）。
- 复现：`python3 tools/measure_band_energy.py --stems th18_14 th18_12 th18_13 th18_18 --md /tmp/lowfreq_4.md`

## 2. 结论（一句）

**原曲本来就少？ ✗ 不成立 —— 是我们丢了。**

证据链：

1. **原曲的低频占比不低**：sub<60 占总能量 **10.6%**（−9.76 dB），60–120 再 **11.0%**（−9.58 dB）⇒ 原曲是
   低频很足的曲子，不存在"ZUN 这首本来就没低音"。
2. **同响度下我们低 5 dB**（表 1a：−32.81 vs −27.85 dBFS）；占比也低 4 dB。
3. **编排里本来就有低音**：本曲 MIDI（`th18_13.mid`，内部 `th18_14`）的贝斯轨 `Trilian (Hardcore Finger)`
   → GM **36 Slap Bass 1**，1610 个音里 **834 个（52%）在 65 Hz 以下**，最低 **E1 = 41 Hz**，
   最常见的音是 A1(55 Hz, 248 个)/D2(73 Hz, 206)/C#2(69 Hz, 163)/E2(82 Hz, 132)，G1(49 Hz) 也有 128 个
   ⇒ **低音写在 sub 区**，不是没写。
4. **换音色就能把差额补回来**（表 4）：同一个 MIDI、同一个 kit，只把贝斯 program 36 → 38（Synth Bass 1），
   sub<60 立刻从 −5.01 变 **+1.84 dB（+6.9 dB）** ⇒ 丢的是**音源/音色的下潜**，不是编曲。
5. **限幅不是主因**：响度匹配的限幅只让 sub 再掉 **0.05 dB**（−4.96 → −5.01）。

原因定位（按贡献）：**① 贝斯音色在 41–55 Hz 基频太薄**（主因，可造成 ≥6 dB 差额）
> **② 底鼓 kit**：owner 2026-10-19 定的 **kit 25 = `TR-909 [SC-55]`** 比原 MIDI 的 **kit 16 `POWER`** 在
> sub<60 少 **3.9 dB**（实测：`--no-program-override` 的 sub −1.04 vs 现在 −4.96；A/B 见 §4）
> **③ 演奏密度**（同人 MIDI 的转录差异）：<120 Hz 重击 3.6/s vs 原曲 5.3/s、占空比 8.8% vs 29%
> **④ 限幅**：−0.05 dB（可忽略）。

⇒ 这不是 `th18_14` 的 bug，是**整条 SF2 重编曲链的下潜不足**在本曲最明显（见 §3）。

## 3. 4 首对照（同曲型 boss 曲，都归一到 −14 LUFS）

| 曲 | Δsub<60 | Δ60–120 | Δ120–250 | Δ<120 占比 | 本曲低频包络（占空比 / crest） |
|---|---|---|---|---|---|
| `th18_12`（5 面 boss） | −2.60 | **+10.83** | +6.56 | −2.48 | 60.7% / 8.8（低频过载、被压扁） |
| `th18_13`（6 面道中） | **−7.63** | **−7.10** | −4.60 | −2.27 | 33.4% / 14.3 |
| **`th18_14`（6 面 boss）** | **−4.96** | −1.26 | +0.91 | −2.61 | 8.3% / 17.8 |
| `th18_18`（Ex boss） | −6.65 | +3.02 | +5.33 | −4.23 | 31.7% / 14.3 |

**结论：14 不是特例** —— 4 首的 **sub<60 全部低于原曲**（−2.6 … −7.6 dB），而 **<120 Hz 的占比差
高度一致（−2.3 … −4.2 dB）**，是**系统性问题**（贝斯 patch + kit 的下潜），不是某一首的渲染 bug。

**但 14 为什么最容易被耳朵抓到**（这条解释 owner 的听感）：
- 14 的贝斯线**大部分写在 sub 区**（52% 的音 <65 Hz，最低 E1），正好踩在我们最薄的那一段；
  而它的 60–120 只差 1.3 dB ⇒ 低频是"上面有、下面没有"的**空心**，听感上就是"低音少"。
- 对比：`th18_12` 的贝斯**只有 9% 在 65 Hz 以下**（多数 D2–A2），所以它是**低频过多**（+10.8 dB 在 60–120）；
  `th18_18` 的贝斯**一个音都不在 65 Hz 以下**，sub 全靠底鼓 ⇒ 差 6.7 dB。
- 14 还额外偏暗：2k–8k −2.7 dB、>8k −6.2 dB（SF2 的镲/空气声不足）⇒ "薄"是低频塌 + 高频暗叠加。

## 5. 方案（2 选 1）+ 试点文件

**推荐 ②（低架 EQ）**：不动音色、不重渲、一行母带处理，补的量正好对上差额。

- ② **低架 low shelf**：`f0 = 100 Hz`、`S = 1`、**+4 dB**。实测传递：30 Hz +3.97 / 50 Hz +3.76 /
  60 Hz +3.53 / 100 Hz +2.00 / 150 Hz +0.67 / 300 Hz +0.05 ⇒ 就是"100 Hz 以下 +4 dB 的斜坡"。
- ① **换贝斯音色**（若 owner 愿意改音色）：`36 → 37 Slap Bass 2` **只补 1.4 dB**（但把 sustain 修回来）；
  `36 → 38 Synth Bass 1` 补 6.9 dB 但 60–120 也 +5.5 dB（要么配一个 60–120 的小切，要么别用）。
  ⇒ **单靠①不到位，单靠②不改音色**；两个都做的组合（37 + 低架 +2）才是"最贴原曲"的，需 owner 点头再做。

**建议值**：先用 **+4 dB @100 Hz** 试听（把差 5 dB 补到差 1.5 dB，60–120 只多 1 dB）；
若 owner 觉得"还是不够"，再上 +6 dB；若觉得"糊了"，退 +2 dB。
**别用 `>8k` 的 −6 dB 当理由去提高频**——那是 SF2 镲片的问题，另一件事。

## 6. 顺带发现（不在本任务范围，但会影响 owner 听感，建议另开一轮）

1. **`th18_12`（5 面 boss）低频过量**：同响度下 60–120 **+10.8 dB**、120–250 +6.6、500–2k **−8.8**、
   2k–8k −5.2 ⇒ 贝斯把中频压住了；`_rearr` 的 LUFS 是 **−8.44**（比原曲 −10.11 还响 1.7 LU）。
   它自己的低频 crest 只有 8.8 dB（原曲 12.7）⇒ **低频被压扁**。
2. **`th18_13`（6 面道中）**：`_rearr` LUFS **−7.04**（比原曲 −11.58 响 4.5 LU）、低频 crest 8.8 dB、
   并且有**直流偏移**：均值 **−0.0272**、<20 Hz 能量 −16.4 dB（其余三首 −28…−35）⇒ 吃 headroom、
   可能有咔哒。建议加 20 Hz 高通 + 查一下这个 render 为什么这么热。
3. **`th18_18`（Ex boss）**：sub<60 −6.65 且贝斯全在 60 Hz 以上 ⇒ 它的 sub 全来自底鼓，同样受 kit 影响。
