## 0. 一句话结论

1. **TH13 的「灵界攻击变化」在 TH18 有**一个**近乎一一对应的落点**：TH13 是「把主炮组号换成常量 10」（`th13:0x446006`→`th13:0x446036`），
   TH18 是同一段代码骨架（`th18:0x45ea00`），**而本 mod 已经在那里挂了 `ce_shot_set_index`**（`th18:0x45ebfb`，卡回调 `on_shot_set_index`）。
   ⇒ **不需要新 hook、不需要新 cave**；113 只要在灵界期间从这个回调返回一个组号即可（117 咆哮就是这么做的）。
2. **真正的成本是数据与槽位**：TH18 的 `+0xe0` 偏移数组只有 **40 格**，原生占 `0x00`–`0x16`、本 mod 已占 `0x17`–`0x27`
   ⇒ **一格都不剩**。要么 `REPLACE` 一个没人映射的原生槽，要么把头部 `+0x02` 从 40 抬到 41（要挪数据区）。
   **一个槽就够**：四个角色各读自己的 `pl0X.sht`，同一个索引在四个文件里放四套不同的 row。
3. **「增伤」不用另外做**：TH13 灵界的伤害高是**写在那组 row 的 `dmg`/`rate` 里**（魔理沙 22×2/2 帧），
   子弹创建路径上**没有任何倍率**（`th13:0x445c93` 直接取 `row->dmg`）。
   ⇒ **现有的魔理沙 `bullet_damage_permille = 1250` 是自定值，换了 shot 组之后会重复计一遍**（§7）。
4. **「移速 ↑」是一手 ×3/2**（`th13:0x442be5`–`th13:0x442bf8`）⇒ 现有的 `×1.15f` 应改成 **`×1.5f`**（仍走 `CE_PLAYER_SPEED_MULT`，用 `*=`）。
5. **妖梦没有对应自机**（TH18 是 灵梦/魔理沙/咲夜/早苗）⇒ 那一行只能**丢**或**映射到咲夜**；本文把问题清楚地摆出来（§4.3），不替用户拍板。

### 1.3 ★ 硬约束：shooterset 槽位已经用满

`local/th18.v1.00a/dat/pl0X.sht` 与 `native/build/sht/pl0X.sht` 逐字节解析（`+0x02` = 40）：

| 索引 | 用途 | 状态 |
| --- | --- | --- |
| `0x00`–`0x04` | 非聚焦火力档 0–4 | 原生 |
| `0x05`–`0x09` | 聚焦火力档 0–4 | 原生 |
| `0x0a`–`0x15` | 装备卡子机组（12 格，逐卡见 `engine/sht/th18/01` §4）| 原生 |
| `0x16` | 108 妖侧（`REPLACE` 覆盖**原生无卡映射**的那一格）| 本 mod |
| `0x17`–`0x1d` | PEA×2 / SEASON×5 | 本 mod |
| `0x1e`–`0x27` | WOLF×5 / EAGLE×5（117）| 本 mod |
| **空位** | — | **0 格** |

⇒ **要加灵界组，只有两条路**（都不新增 hook，只动数据）：

| 路 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| **D1 REPLACE 一个原生槽** | 选一个「没有卡映射且引擎不会自己取」的槽（候选 `0x16` 已被占；其余要先做 xref 普查），把偏移指到文件尾的新记录 | 与原生卡/别的卡**抢槽**；`append_shooterset.py` 已支持 `REPLACE`，但**必须先证「没人用」** |
| **D2 抬高头部 `+0x02`（40 → 41）** | 偏移数组多一格：数组落在 `+0xe0..+0x183`，与数据区起点 `+0x180` 重叠 4 字节 ⇒ 必须把**所有**组偏移 +4（数据整体后移）| 解析器上界来自头部 ✅ 可扩；但 `+0x180` 是**硬编码常量**（`th18:0x45a830`），且 `sht-verify` 的「前 23 组逐字节不变」不变式要重写；**未经实跑验证，风险最高** |
| **D3 运行时改 sht 影像** | 不动文件：在 `on_load` 里把 `*(zPlayer*)(…+0x47940)` 的某一组 row 就地改写成灵界值（开机解析后到关底前都有效）| 零数据工程；但要处理「换机体 / 读档 / 跨局缓存 `th18:0x570920`」的时机，且**改的是共享影像**，得保证别的卡不用那一组 |

> **推荐 D1**（与 108/109 同款、已有工具与校验），**备选 D3**（不动文件、风险局部）。D2 只在 D1 找不到空槽时考虑。

### 4.2 「已实装」与「本文建议」的差异（需要用户拍板的只有一处）

- 现有 `HANDOVER-113.md` 的机体特技表里：**魔理沙 = 灵界伤害 ↑ + 移速 ↑**。
  一手：**伤害↑ 不是倍率**，是 shot 组的 `dmg`；**移速↑ 是 ×1.5**（不是 1.15）。
- 因此 §7 的两条建议（去掉 1250‰ / 改成 1.5f）是**一把动两个既有实装点**，必须先定案。

### 4.3 ★ 妖梦 ↔ 咲夜：本报告只提出问题

事实（一手）：TH13 第 4 机体是**妖梦**（`CHARACTER == 3`），她的灵界是**免蓄力连斩**
（`th13:0x4460ec` 起整套蓄力逻辑只对妖梦生效；灵界组 = 2 row、rate 30、`anm=1/2` 与普通聚焦斩**同一对脚本**）。
TH18 的四机体是 灵梦 / 魔理沙 / **咲夜** / 早苗 —— **没有妖梦**（`local/th18.v1.00a/dat/pl02.sht` 是咲夜的飞刀）。

| 选项 | 内容 | 代价 / 问题 |
| --- | --- | --- |
| **丢** | 只做灵梦/魔理沙/早苗三行；咲夜灵界 = 无 shot 变化（或保留现有的「时间×2」）| 少一个手感；但**零发明** |
| **映射到咲夜** | 把「免蓄力连斩」几何搬到咲夜：TH18 的咲夜主炮 `dx ±10` + 飞刀子机；灵界组可做成「高速多刀」| **这是我们在发明 ZUN 没写过的行为**（TH13 没有咲夜，TH18 没有灵界）⇒ 必须标 `❓ 自定` + 进 `TUNING.md`，不能写「复刻」|
| **映射到早苗** | 把妖梦的斩击并给早苗（TH18 早苗已是「多子机扇」）| 会覆盖掉早苗自己那条（§4.1）|

> **我的建议（🟡，仅建议）**：走「**丢** + 在 `TUNING.md` 登记咲夜行为待定」。
> 理由是 CLAUDE.md 的六问第 5 条：**能复刻就不要自己写**；把斩击塞给咲夜是本报告里唯一
> 无法给出「原版出处」的一行。若用户要「四机体每台都有灵界变化」，那第二条才有意义，
> 但**必须写清是自定**。
