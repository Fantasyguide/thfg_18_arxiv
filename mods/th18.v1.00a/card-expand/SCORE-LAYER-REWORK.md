## 0. 一句话

**计分层从「各卡抢落笔权、id 最小者独占」改成「各卡只声明自己那一族的加数，SDK 一次合成」**：
`G = G_0 + Σ未耦合 + coupling‰ × Σ耦合 / 1000`，落笔 = **站点 `th18:0x446bf9` 的 `ecx = 1000 × G`**
（引擎随后自己乘高度系数、弹窗、`SCORE += floor(ecx/1000)`）。
⇒ 107 / 110 / 111 从「互相吞」变成「叠加」；**没有卡声明时 SDK 一个字都不写**（§6）。
★ 2026-09-13 第二次修订：落笔点原来在**引擎算完身价之后**（`0x446cf6`/`0x446caa`），
写 `regs->esi` 会把引擎刚做的高度系数整个丢掉 ⇒ 实际结构退化成 `coeff_06 × G_0 + ΣG_i`；
搬到输入侧（`ecx`）之后才是规格要的 **`coeff_06 × (G_0 + ΣG_i)`**（§2、§4）。

**单位链（★ 2026-09-13 第二次修订；这条原先写错了两处，逐条对着 exe 改）**：

| 量 | 单位 | 一手换算 | 谁用 |
| --- | --- | --- | --- |
| `ecx`（站点 `0x446bf9`） | **1/1000 点** | `ecx = clamp((1+MONEY) × k × 100, 1e6, 表值×100)` | 引擎的系数两段；**我们的落笔点** |
| `esi`（弹窗值 / 身价） | **点 × 10** | 满额支：`esi = 10 × floor(ecx/1000)`；线下支再乘 §2⑦ 的系数 | `0x446cfc` 弹窗（`0x4645f0` 直接把十进制位画出来）；`0x446d0d mul esi` 的被除数 |
| `SCORE` 增量 | **点** | `SCORE += esi/10` ⇒ 满额支 `= floor(ecx/1000)`；线下支 `= floor(esi/10)` | `0x4cccfc`（封顶 `0x3b9ac9ff`） |

⇒ **`G_0`（点）= `ecx/1000`**，层要的桥值 = **身价** = `ecx/100`（= `G_0 × 10`）；
上下限常数（`CE_SCORE_BASE_MIN_PTS` / `..._MAX_*`）正是**身价**单位的 `[10000, 表值]`
（= `0x4ccd28`/`0x4ccd2c` ÷ 100），所以 `ce_score_base_points()` 必须**先钳身价、再 ÷10**。
引擎自己已经把 `ecx` 钳在同一个区间 ⇒ **现场这次钳是恒等**，`G_0 ≡ ecx/1000`（单测 `test_score_base_unit_identity`）。
**字节等价论证（没有卡声明时）**：SDK 连 `regs->ecx` 都不写 ⇒ 引擎走原样的 `ecx`：
原生钳位已发生、原生系数照乘、原生弹窗值与 `SCORE += floor(ecx/1000)` 全部不变 ⇒ 逐字节相同。
我们写进去的值也**永远是 1000 的倍数**（`1000 × G`）⇒ 与原生 `ecx`（`(1+MONEY)×k×100`，k∈{500,1000}）同类，
引擎「量化到 10 的倍数」那一步对两边都是恒等，不引入额外舍入。

**★ 曾经错在哪、怎么发现的（保留历史，别抹掉）**：
初版的落笔点挂在 `0x446cf6` / `0x446caa` —— 那两条都在**引擎算完身价之后**，handler 却把 `regs->esi`
整个覆盖掉 ⇒ 引擎刚做的高度系数被**静默丢弃**，实际结构是 `coeff × G_0 + ΣG_i`
（甚至 `G_0` 只是「碰巧」相等：层的上下限钳方向与引擎一致时才不动）。
`SCORE-LAYER-REWORK.md` 初稿 §2 里写的「钳在断点之前 ⇒ 结构是
`SCORE += floor(coeff × (clamp(G_0) + 我们的加数) / 100)`」是**意图**、不是当时**实装**的行为 ——
本次按「单一汇合点 `0x446bf9` 只改 `ecx`」重做后才真正成立。
发现路径：重读 `0x446b00`–`0x446d3e` 全部指令 + 逐条模拟整数链（§2④–⑦），
再对 `sdk.c` 的旧 handler 一比就看出「写 `esi` 等于把系数丢掉」。

## 3. 新接口（`native/sdk_core.h`）

| 类别 | 接口 | 语义 |
| --- | --- | --- |
| 桥 | `ce_score_bridge(raw_value, difficulty)` | 每颗道具、在卡回调**之前**由 `sdk.c` 填：`raw_value` = **身价** = 站点 `0x446bf9` 的 `ecx / 100`，`difficulty` = `0x4ccd00` |
| 桥 | `ce_score_set_coeff(permille)` / `ce_score_coeff_permille()` | `coeff_06` **只读标记**（1000 = 线上 / 真空飞行；0 = 线下） |
| 加数 | `ce_score_declare_delta(id, points)` | **未耦合**加数（107 的「最大得点」走这条） |
| 加数 | `ce_score_declare_coupled(id, points)` | **耦合**加数（110/111 的「Δ」走这条，会被 `coupling` 缩放） |
| 耦合 | `ce_score_mul_declare(id, permille)` / `ce_score_signal_strength()` | 各卡的信号强度（千分点，0..1000），求和 |
| 耦合 | `ce_score_graze_mult(graze)` | `min(graze × 1, 8990)`（千分点；`1 graze = 0.0001`） |
| 耦合 | `ce_score_coupling_permille()` | `1000 + Σ信号`（没人声明信号时 = 1000 = ×1.0，对应规格里的 `else 1`） |
| 读值 | `ce_score_base_points()` / `ce_score_total()` | `G_0`（点，= `ecx/1000`）/ `G`（点） |
| 读值 | `ce_score_apply()` | 「引擎单位」旧读法 = `G × 10` = 身价；★ **不再是落笔路径**（落笔是 `sdk.c` 写 `ecx`），留给单测 / 旧读法 |
| 读值 | `ce_score_participants()` / `ce_score_aggregate()` / `ce_score_applier()` | 诊断：参与者数 / Σ加数（原始和，不乘耦合）/ 最小 id |
| 旧接口 | `ce_score_declare(id, v)` = `ce_score_declare_legacy(id, v)` | **旧语义**（该卡自己的得分值，非增量），折成加数后进同一条算式 |

**合成规则**（`ce_score_total()` 的全部内容）：

```
G = G_0（= 桥值/10 = 站点 ecx/1000，见 §2 单位表；上下限先钳在**身价**上再 ÷10）
  + Σ ce_score_declare_delta   （原样）
  + coupling_permille × Σ ce_score_declare_coupled / 1000
  + Σ legacy（max(v, 10) 折成点）
coupled 那一项 64 位中间量；总和与 G_0 都钳在 int32；落笔 = `regs->ecx = 1000 × G`（溢出饱和 + 报一次）
```

**为什么分成两条加数通道**：用户规格里**唯一带乘数**的只有 `(Δ_10 + Δ_11)` 这一项
（110 与 111 是同一个「信仰」量纲）。107 的「最大得点」是 TH07 自己的数（公式里已是点），
**不该**再被擦弹倍率缩放 ⇒ 它是未耦合族。⇒「谁该被乘」这件事由**通道**表达，
不再依赖「谁是 id 最小的落笔者」——那正是重做前 107 在场就让 110/111 静默失效的根因。

## 4. `coeff_06`：**没有新建**，而且它本来就在运作（这条待验项的结论）

**结论：引擎自己在我们的落笔点之后施加高度系数**，所以三张卡声明 `G_i` **不会**绕过它
（旧审计 §5.5 的「绕过嫌疑」到此证伪）；而且★ 2026-09-13 第二次修订后它乘的是**整笔 `G_0 + ΣG_i`**
（旧写法覆盖 `esi`，结果是 `coeff × G_0 + ΣG_i`，已修）。

| 步 | 地址（`th18:`） | 做什么 |
| --- | --- | --- |
| 0 | `0x446bf9` 前 | **我们的落笔点**（写 `ecx`）；三条难度支已把钳位结果写进 `[0x4ccd24]`，此处 `ecx` 恒等于它 |
| 1 | `0x446bf9` | 读回收线 `player+0x47998`（`movss`），与 **`esi` = PLAYER 的 `+0x624`（自机的 y）** 比较 —— ★ 不是道具的 `+0x624` |
| 2 | `0x446c01`–`0x446c11` | 自机在线以上（或道具 `state == 3` 真空飞行）⇒ 跳 `0x446cb4`：系数 = 满额（`SCORE += floor(ecx/1000)`） |
| 3 | `0x446c17`–`0x446cf3` | 线下 ⇒ 按自机到回收线的距离 `d` 做一次折扣（整数骨架，形状见下） |
| 4 | `0x446cb4`/`0x446cf3` → `0x446cfc`/`0x446d03` | 系数落在 **`esi`（身价）** 上（弹窗 `0x4645f0` 吃同一个值）→ `SCORE(0x4cccfc) += esi/10` |

⇒ **本层不实现它、也不施加它**（用户原话：「不要新建，它实际上是已经在运作的机制本身」）。
`ce_score_coeff_permille()` 只是「这一颗在线上还是线下」的**诊断标记**（`sdk.c` 用整数搬运
两个 float 的位模式来判，避免引入 x87）。★ `sdk.c` 的两个老出口站点现在**只观察**：
把引擎的最终 `esi` 与我们的预测 `10 × G_total` 比一行（`score-out:`），
满额支应当**完全相等**、线下支应当更低 —— 这就是「系数乘在整笔上」的实跑证据。

**🟡 折扣曲线的形状**（本次重读得到，可信度：骨架 ✅ 一手 / 除数解释 🟡）：

```
线下支（0x446c17–0x446cf3）等价于：
    q = floor(ecx/100) ; F = q − (q mod 10)          # 与满额支同一套 ÷100、÷10
    d = trunc(player_y − poc_line)                  # cvttss2si，单位 px（>0 才会走这一支）
    esi = 10 × floor( (0.9F − 0.9F × d/163.1798…) / 10 )   # ≤10 时被顶到 10（最少 +1 分）
⇒ 系数 = esi/(满额 esi) ≈ 0.9 × (1 − d/163.18)
   · 0.9 来自 9F/10（F = 10·floor(q/10)）；除数来自 0x446c5c 的魔数 0x91a2b3c5 +
     `add edx,ecx` + `sar edx,8`（= 乘 2^40/(0x91a2b3c5+2^32)）：不是整数除法，是**定点倒数乘**，
     2^40/6738035653 = **163.1798**（本节初稿写 163.09，本次改为实测值）。
   · 逐点核过：base=2,000,000（d=1/40/100/140/160）系数 = 0.8945/0.6790/0.3480/0.1275/0.0175，
     与 0.9×(1−d/163.18) 完全一致（脚本见 AUDIT 本条目）。
   · **对整笔线性**：系数只通过 F（∝ ecx）与 d 进入 ⇒ 我们写 `ecx = 1000 × G_total` 时，
     引擎打折的正是 `G_total` 自己（截断误差 ≤ 整数链那几步，≤ 十分之几分）。
🟡 **仍未钉死**：为什么是 163.18（像 163.2？还是某个 ×k 的换算）、以及为什么线下第一像素就从
0.9 起跳（线上 1.0 → 线下 0.8945 是个**不连续**的跳变，这是引擎自己的形状，我们不复制）。
它**不影响本层算式**（引擎自己乘），因此登记进 §7 待办。

**三条必须讲清的坑**（重做时踩过 / 差点踩）：

1. **基础只能出现一次**。旧口径里 107 与 110/111 **各自**把基础声明进来，落笔者再用
   `mof_core_pv()` 的「两卡同装」支把它们减掉 —— 那套减法一旦遇到第三张卡就崩。
   现在基础只由 `G_0` 出，卡只交 Δ ⇒ **不需要减法**（单卡时两者等值，见 §6）。
2. **自己乘 ≠ 层乘**。111 旧实现自己乘 `(擦弹倍率 + 信号强度)`；重做后必须**撤掉**那一句，
   否则层再乘一次 = 双乘。110/111 的 `*value` 写入也一并撤掉（落笔只由 SDK 做一次）。
3. **`0` = 不参与 是 legacy 的语义**。新通道里 `0` 是「声明了 0」；`ce_score_declare`
   保留旧语义（`0` = 退出），所以 `ce_layer_drop_card()` 四个通道都要退（少退一个 = 被删的卡
   永远留在聚合里）。

**减法之后 110 单装还成立吗**（`mof_core_pv()` 的「只装 110」支说 `PV = 信仰_110`）：
- **卡声明的值一直是「点」**（单位没错）：重做**前**的落笔是卡自己写 `*value = max(PV,10) × 10`，
  引擎 `SCORE += *value/10` ⇒ `SCORE += PV`；重做**后** SDK 写 `ecx = 1000 × (G_0 + ΣG_i)` ⇒
  `SCORE += G_0 + ΣG_i`。⇒ 卡侧声明的量纲**没变**。
- 变的只有**基础由谁出**：旧口径里每张卡把自己的基础（107 的 `SENRO_POINT_BASE` 50000、
  110/111 的 `faith_slot_t.base`）一起声明进来；新口径基础只由 `G_0`（= **TH18 原生身价换算的点值**）出。
  ⇒ NORMAL + 资金力 0 时 `G_0 = 1000` 点（一手：`ecx = 1,000,000`），而 110 的旧声明里那份基础是 50000 点
  ⇒ **单卡 110 的分数会比旧行为低约 49000 点**（`1000 + Δ` 对 `50000 + Δ`）。
- ⚠ 这一条要用户点头：按用户公式（`G_0` = 原生身价）就是上面这样；如果期望「110 单装 ≈ 旧观感」，
  那需要把「各作基础」也当成 `G_i` 的一部分重新定义（不是本层能自行决定的）。见 §7 第 6 条。

## 6. 一致性证明：没有卡声明时逐字节等价 / 单卡时的差异

**命题 A（新增，本次改动的核心承诺）**：**没有卡声明时，SDK 一个字都不写** ⇒ 引擎走原样的
`ecx`（原生钳位、原生高度系数、原生弹窗值与 `SCORE += floor(ecx/1000)` 全不变）⇒ **逐字节等于原生**。
判据就是 `ce_score_participants() == 0`（单测 `test_score_base_unit_identity` 断言它在无声明时为 0）。

**命题 B**：只有一张卡声明时，`SCORE` 增量 = **`G_0 + ΣG_i`（点）**，其中
`G_0` = 原生身价换算的点值（= `ecx/1000`）、`G_i` = 卡声明的点值；引擎随后把 `coeff_06` 乘在**整笔**上。

**旧行为**（`sdk.c` 旧 `ce_item_score_common`，一手）：沿卡链逐张 `h->on_item_score(card, &value)`，
卡自己写 `*value = max(自己的值, 10) × 10`（三张卡都是这个形状），最后 `regs->esi = value`；
引擎随后 `SCORE += value / 10`（**并把 `coeff_06` 丢掉**，因为 `esi` 已被覆盖）。

**新行为**：站点 `0x446bf9` 写 `regs->ecx = ce_score_total() × 1000`。

**证明**（三种单卡情形，逐条对上单测）：

| 情形 | 旧落笔值（写进 `esi`，单位 = 身价） | 新式（点） | 相等条件 |
| --- | --- | --- | --- |
| 107 单装（新通道，未耦合族） | `max(G_07, 10) × 10` | `G_0 + G_07` | 旧式没有基础那一份 ⇒ 新式**多一份 `G_0`** —— 这是规格要的（基础回给引擎那一份） |
| 107 单装（legacy 通道，旧卡不改也走这条） | `max(V, 10) × 10` | `G_0 + max(V,10)` | 单测造 `G_0 = 旧基础` 的桥值 ⇒ 引擎收到的身价**逐字节相同**（`apply()` 那一侧） |
| 110 单装（新通道） | `max(50000+Δ, 10) × 10`（旧基础 = TH10 的 50000 点） | `G_0 + Δ`（`G_0` = TH18 原生 = `ecx/1000`；NORMAL 资金力 0 ⇒ 1000） | 卡侧量纲相同（都是点）⇒ 差的是**基础来源**：`G_0` = 1000 对旧 50000（见上面那段⚠） |
| 111 单装（新通道） | `max(base_111+Δ, 10) × 10` | `G_0 + Δ` | 同上（`base_111` 是 `faith_slot_t.base` 的固定表） |

**两句话把事情说清**：

1. **旧卡一行不改也不会变**：旧卡走 `ce_score_declare`（legacy 通道），层把它按 `max(v,10)` 折成点，
   `apply()` 与旧落笔公式**逐字节相同**（单测 `test_score_rework` ①b 用 `G_0` 恰好等于旧基础值的桥值做全等断言）。

2. **新通道少交一份基础**：三张系统卡现在只交「自己那一族的加数」，基础由 `G_0` 出
   ⇒ 少掉的那一份**正是旧代码多吃的引擎原生身价**；`G_0 = 旧基础` 的档位下数值相同，
   其余档位按用户公式走（见 §7 第 6 条）。

**legacy 通道的等价（真正的「一行不改也等价」）**，单测 `test_score_rework` 逐条钉死：

```
legacy: ce_score_declare(id, V)        →  折成加数 max(V, 10)
新落笔: apply() = (G_0 + max(V,10)) × 10
旧落笔: value   = max(V, 10) × 10        （然后引擎 /10、再按高度打折）
⇒ 两者相差恰好 G_0 × 10 —— 而 G_0 是**引擎本来就要给的那一份**（原生身价），
  旧代码把它吃掉了（因为卡自己声明的是「基础 + Δ」）。所以在「基础由谁出」这一点上，
  新式把引擎的那一份**还了回去**，其余每一位都相同。
```

**为了让「逐字节」这条也有可执行证据**，单测里造了 `G_0` 恰好等于旧基础值的桥值：
`ce_score_bridge(G_0 × 10, NORMAL)` ⇒ `ce_score_apply() == max(V,10) × 10`，**整数全等**
（`tests/test_sdk_core.c` 的 `test_score_rework` ①/①b 两组、共 3 张卡各一遍）。
★ 新增（第二次修订）：`test_score_base_unit_identity` 把 `G_0 == ecx/1000` 在
「5 难度 × 9 资金力档」的网格上逐点断言（含引擎自己那两个钳），并断言无声明时
`ce_score_participants() == 0`（= SDK 不写）。
⚠ 如实说明：`单卡 + 新通道`（卡声明 Δ）与旧式相差的 `G_0` 是**规格要的差异**（基础改成
按用户公式算），不是回归；「逐字节等价」的承诺落在 **legacy 通道**与**无声明**两条上。

## 8. 实跑怎么验（日志与现象）

**A. 逐颗对照（本次新加的两行，最能说明问题）**：`trace` 打开时，每吃一颗金钱会连着两行
（头 30 颗 + 之后每 50 颗，两行永远成对）：

```
score-in:  base=<钳位后 ecx> G0=<ecx/1000> lay=<层的 G_0> sum=<Σ声明> -> ecx=<落笔值> coeff=<1000|0> (#n)
score-out: engine=<引擎最终 esi> ours=<10 × G_total> delta=<ours − engine> (at/above line => must be 0 | below-line => coefficient)
```

- **线上 / 真空飞行**（`coeff=1000`）：`G0 == lay == base/1000` 且 **`delta == 0`**
  ⇒ 引擎的满额支与我们声明的 `G_total` 完全一致（系数 = 1.0）。
- **线下**（`coeff=0`）：`delta > 0`，且 `engine ≈ 10 × 0.9 × (1 − d/163.18) × G_total`
  ⇒ 看见的差额**就是** `coeff_06`（这是把注入点搬到入口之后唯一能看见它的手段；
  想看到具体数值就把自机停在回收线下 40 px 左右吃一颗 —— 预期系数 ≈ 0.68）。
- 若某颗 `delta < 0`（我们比引擎小）⇒ 说明落笔没生效或双重打折，**停下报日志**。

2. **单装**：只带 107（或只带 110 / 只带 111）吃一颗金钱（回收线以上），
   `SCORE` 增量应当 = `G_0 + 卡自己的 Δ`；线下吃时应当**打折**（`score-out:` 的 delta > 0）
   —— 这一条恰好验证「coeff_06 仍在运作」（它由引擎施加，不由本层）。
3. **两卡同装**（110 + 111）：`G = G_0 + (Δ_10 + Δ_11) × (擦弹倍率 + 信号强度)`。
   把信号槽打到满（`1.00`）再吃一颗，`SCORE` 增量应当约等于 `G_0 + (Δ_10+Δ_11) × 2`。
4. **+107**（107 + 110 + 111）：`G_0 + Δ_10×c + Δ_11×c + G_07`。
   验证点：**107 在场不再让 110/111 的公式失效**（重做前这正是静默 bug）。
5. **删卡**（买倒吊人删掉 110；或原版空白卡清空整副牌）：`ce_score_apply()` 应立刻回到
   「只剩 G_0」（日志里不再出现那张卡的声明），**不需要**等下一帧（商店里 tick 停着）。
   全删光时 `sum=0` ⇒ **`ecx` 那一栏应当等于 `base`**（我们没写）。

**★ 无卡基线（本次新增的承诺）**：把三张卡都摘掉吃一颗 ⇒ 日志里 `score-in: … -> ecx=<base>`（与 `base` 同值）
且 `delta == 0`；分值应与原版**逐字节相同**。这一条是「SDK 一个字都不写」的验收。
