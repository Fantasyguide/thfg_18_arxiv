## 1. owner 口径（原话逐字）

### 1.1 杂兵战：四种东西

> **1）一定数量的分**（废话……）。
>
> **2）Power**，就是屏幕上那些**红色的「P」**，它们起到增加自机火力的作用，**小 P 火力加 1，大 P 火力加 8**。
> 当自机火力达到 **128**、即 **MAX** 状态时，有**一次全屏消弹**功能。之后**击破敌人就不再提供 P**。
>
> **3）Point**，就是屏幕上那些**蓝色的「点」**，称为**蓝点**，它们不仅起到**大量加分**的作用，
> 而且在达到**一定数量**之后可以**奖励残余自机数**。
> 特别注意蓝点有两种：**带方框的大蓝点**和**圆形的小蓝点**。**小蓝点的回收不记入 Point 数值**，
> 并且它的分值比大蓝点小，**为大蓝点的 1/10**。Point 奖命上限如下：
> ```
> Start：        100，250，500，800，1100
> Extra Start：200，666
> ```
>
> **4）Time**，就是屏幕上那些**紫色的「永」**，称为**刻符**，它们不仅起到**大量加分**的作用，
> 而且可以**增加人妖逢魔时状态槽中的夜点数**，连带的作用是**提高蓝点的最大分值**。因此刻符数量越多越好。
> **注意：刻符是可以自动吸收的道具，只要屏幕上有刻符，则会自动被自机吸收**
> （**恰好在自机损命时出现的刻符则不能自动吸收**）。

### 1.2 SC 战：多出来的那一块 UI

> 最上面的是 **SC 名称**，下面**左边不断跳动的分值**是在 **NO MISS + NO BOMB**（不中弹 + 不放 B）击破该 SC 时
> 最后应当取得的**奖励分数**；下面**右边**是该 SC 击破的**历史记录：击破次数 / 总挑战次数**。
>
> 注意 SC 战中 BOSS 都会放出一个**巨大的圆环**（图上那个白色的环），环中写的是：
> `Spell Card, Attack of Little Girl.` 这个圆环**随时间推移会逐渐变小**。当时间消耗至 **0 秒**时该圆环**破裂**，
> 本次 SC 挑战**失败**，所以 SC 战时**不要指望拖光时间**来解决战斗，那样是**没有分**的。

### 1.3 魔使（六种）

> 看见图中那些**绿色的六芒星小圆环**了吗？那些东西叫做「**魔使**」，是 BOSS 释放出来辅助 BOSS 攻击的工具。**魔使一共有六种**：

| 魔使 | 人间操术下撞击 | 妖怪操术下 | 人/妖两种状态的弹幕 |
| --- | --- | --- | --- |
| **红色魔使** | 会 MISS（撞弹）| **不可见但可以穿梭其间** | **没有区别** |
| **黄色魔使** | 会 MISS（撞弹）| 不可见但可以穿梭其间 | **有一定区别** |
| **蓝色魔使** | **不会** MISS | 不可见但可以穿梭其间 | 没有区别 |
| **绿色魔使** | **不会** MISS | 不可见但可以穿梭其间 | **有一定区别** |
| **阴阳玉**（4A 面 BOSS 博丽灵梦专有）| 会 MISS（撞弹）| 不可见但可以穿梭其间 | 没有区别 |
| **六芒星**（4B 面 BOSS 雾雨魔理沙专有）| 会 MISS（撞弹）| 不可见但可以穿梭其间 | 没有区别 |

> ★ **owner 已拍：这六种不做，统一成红色** —— 见 §2b。

### 1.4 SC 的成败

> **NO MISS NO BOMB 击破 SC 之后**将取得上方相应**奖励分数**并且获得**一定数量的蓝点与刻符**。
>
> 如果有如下一种情况发生则 SC 战**宣告失败**：
> **MISS** / **放 B** / **MISS 后使用决死结界发动 LSC** / **接关** / **时间耗尽** / 其他不可预料的情况……
>
> SC 失败时，BOSS 放出的**巨大圆环宽度会变细**、上面的**字变的不可见**、屏幕上方的**奖励分数立即变为 0**，
> 这些都是 SC 失败的标志。当然，失败后你还可以继续玩下去。
> （关于 MISS 后使用决死结界发动 LSC 的情况将在后面给出详细说明。）

## 2b. owner 拍板：**魔使六种不做，统一成红色**（2026-09-22 夜）

> **owner 原话**：「**使魔六种不需要做啊，因为原则上得每个符卡调太麻烦了 / 就都统一成红色即可**」

⇒ 落地口径：
- **不做六种分类**（红/黄/蓝/绿/阴阳玉/六芒星）—— 原因是**每种都要按符卡逐个配**，成本不划算；
- **统一按「红色魔使」的语义**：**人间操术下撞击会 MISS**、**妖怪操术下不可见但可穿梭其间**、**人/妖两种状态的弹幕没有区别**；
- **范围（owner 补一句）**：「**我刚才说的都是敌人使魔**」⇒ 这条**只管敌人使魔（魔使）**，与玩家侧那套（我们画的妖侧本体/子机、以及 #23 本体光环）**无关**。
- **记录口径（照 owner 原话字面落地）**：敌人使魔**统一成红色** —— 既指**语义**（红色那一档：人间撞 = MISS、妖怪侧不可见可穿梭、两状态弹幕相同），
  也按字面理解指**外观/染色统一成红**（不再有六种颜色）。
- ⚠⚠ **owner 2026-09-22 二次订正（重要）**：「**它不是一个固定的环，而是在切换时候的一个特效环，只会存在一小段时间 / 你可能扫错了**」
  ⇒ 我们现在那版（环**挂在使魔身上、与使魔同生同死**、按 `focused` 换 `interrupt` 2/1）**很可能是挂错了对象**：
  正确的形态应是「**切换那一刻起一个特效环，短命、自删**」，而不是随使魔常驻。⇒ 已让 108 工单**重扫**：
  （a）切换例程里起的那支环的**一手句柄/模板槽/寿命帧数**；（b）它是**起在自机身上**还是**每只使魔各起一支**；
  （c）有没有「常驻的外观随状态变」**另一套**机制（`enemyType` / `anmFlags` / `IsYoukai()`，那是**可见性/外观**那条，与这支短命环**不是同一件事**）。
  结论落定后再决定我们那版是**改成短命特效**、还是**两套都留**（常驻的按 #12/#23 那条、特效的按本条）。

## 2c. ★★★ 一手核实结果（2026-09-22 夜）：**蓝点（Point）** 与 **刻符（Time）**

### 2c.2 小点的「1/10」与「不记账」（✅ 一手闭合，逐指令）

- **大点** `Item::collect_point_item th08:0x440e40`：线上/线下的分值公式（`th08:0x440e59`–`0x440ec4`，`PIV/2 − trunc(y−pocY)×(PIV/1000)`）
  → `isMaxValue`(`+0x2d8`) 补满 → **trunc10**（`th08:0x440ee2`）→ **極端人間 ×2**（`th08:0x440efa call 0x406d10`）→ 弹窗 + `AddScore`
  → **`pointItemsCollectedInStage(+0x2c) ++`**（`th08:0x440f59`）/ **`pointItemsCollected(+0x30) ++`**（`th08:0x440f6d`）
  → **`IncreaseSubrank`**（+10 满值 / +3，`th08:0x440fa4`/`:0x440fb2 call 0x43bfc3`）→ **奖命梯 while**（`th08:0x440fb7`–`0x440ff9`）
  → hscr 计数（`th08:0x441000`）+ 防篡改（`th08:0x44100d`）。
- **小点** `Item::collect_point_small th08:0x441020`：与大点**逐指令同形**地算完，**再**多四句 `idiv 10`：
  `th08:0x4410c2` → `[ebp-4] = PIV/10`（trunc10）· `th08:0x4410e7` → `[ebp-8] = score/10`（trunc10）·
  極人 ×2 在 **/10 之后**（`th08:0x441109`/`:0x441115`）· `isMaxValue` 闩写在 `th08:0x441161`。
- **那两句到底除以谁**：`PIV` 的除法作用在**局部副本**上（`[ebp-4]`，`th08:0x441030` 载入）；**全程没有 `mov [globals+0x24], …`**
  ⇒ 它只当**比较阈值**用（弹窗颜色 + `isMaxValue` 翻转点）；**`score/10` 才是分值本身** ⇒ **「小点分值 = 大点的 1/10」成立**，
  且**阈值成对 /10**（否则小点永远到不了「满值」）。🟡 唯一细节：大点比 `trunc10(score) vs PIV`、小点比 `trunc10(score/10) vs trunc10(PIV/10)` ⇒ 翻转点可能差 ≤1 档。
- **「不记账」的负证据（地址级）**：`th08:0x441020`–`0x44116d` 函数体内**不存在** ——
  ① `[globals+0x2c]`/`[globals+0x30]` 的读写；② `call 0x43bfc3`（subrank）；③ `call 0x440470` / `call 0x439b29`（奖命梯）；
  ④ `ds:0x164cf9c` 自增（hscr）；⑤ `call 0x406e50`（防篡改）。⇒ owner「**小蓝点不记入 Point 数值**」= 不推进 1UP、不加 subrank、不进 hscr ✅。
- 字段名（一手比较点 `th08:0x440fd3 mov edx,[eax+0x30] / cmp edx,[ecx+0x38]`）：`globals+0x2c` = 本关大点数、
  `+0x30` = **累计**大点数（奖命比它）、`+0x34` = 已奖命次数、`+0x38` = 下一个阈值。

**§2c.3 两行的逐条（表里只留指针）**

- **梯的开关**：门 = `[globals+0x34] ≥ 0`（`th08:0x440fbd jl`）；另外 stage ∈ {6,7,8}（`ds:0x164d2cc`）时
  `th08:0x43511c or DWORD PTR [eax+0x34],0xffffffff` = **把整条奖命梯关掉**（🟡「`0x164d2cc` = stage 号」是从比较值 6/7/8 推的）。
- **奖命动作** `GameManager::CollectExtend th08:0x439b29`：`th08:0x439b3e cmp eax,8 / jge` ⇒ **命上限 8**；
  命 <8 ⇒ `th08:0x439b43 push 1` → `th08:0x439b48 call 0x43c641`，其内 `th08:0x43c66d fadd DWORD PTR [eax+0x74]`
  = **残余自机数 +1**（float `globals+0x74`），并 `th08:0x439b5b push 0xc8`(200) → `call 0x43bfc3` = **subrank +200**；
  命满 ⇒ 炸弹 +1（`globals+0x80`，`th08:0x4398af fadd`，上限 8）。

### 2c.4 刻符的例外「损命时出现的那颗不能自动吸收」（✅ 一手闭合）—— **真身是玩家状态，不是单颗标记**

**三道门**（逐指令）：

1. **抓取盒整段关闭**（决定性）：`Player::CalcItemBoxCollision th08:0x44a5a0`：`th08:0x44a5bc movsx ecx,BYTE PTR [0x17d5ef8]`（playerState）
   → `0`(ALIVE) 放行 / `3`(INVULNERABLE) 放行 / `4`(BORDER) 放行 / **否则 `th08:0x44a5d9 xor eax,eax`** ⇒ **state ∈ {1 SPAWNING, 2 DEAD} 时任何道具都「没碰到」**。
2. **每帧把刻符打回下落**（`ItemManager::on_tick th08:0x440500` 内）：
   - state 1（归航）/ state 0 过线：`th08:0x44085f` 读 playerState → `th08:0x4408e0 vy = −0.7`（`0xbf333333`）+ `th08:0x4408f0 state = 0`；
   - **state 3（击破掉的）连上抛中的也打**：`th08:0x4406eb`–`th08:0x44071e` ⇒ `state=0`、`vx=0`、`vy=−0.7`、`vz=0`；
   - state 5（符卡螺旋 / 擦弹）：上抛中**不动**（`th08:0x4407a5 jmp`），只在 `vy>0` 那帧打（`th08:0x4407aa`–`0x4407dd`）。
3. **损命当帧的批量收尾** `ItemManager::sub_441530 th08:0x441530`（**只动 state 1**，`th08:0x441555 cmp eax,1 / jne`）
   ⇒ `state=0`、`vx=0`、**`vy = −0.9`**（`0xbf666666`，`th08:0x441574`）；调用点全 exe 仅 **2 处**：
   `th08:0x44aeae`（Miss 处理内，上一句就是 `th08:0x44ab84 mov BYTE PTR [ecx],0x2` 置 DEAD）与 `th08:0x44ceaa`。

⇒ **「损命那一刻刚出生/还在上抛的刻符」= 被打回 state 0（vy −0.7）⇒ 没有机会进 state 1 归航；同时抓取盒整段关闭 ⇒ 既不会飞过来也收不到**；
复活（ALIVE / INVULNERABLE / BORDER）后才可能重新归航（还要过收点线与火力/聚焦门 `th08:0x4407fb`–`0x440859`），否则按 state 0 下落，`y > 448+16 = 464` **整颗没了且不给分**。
**没有单颗专用的 Timer 门**：`0x18b89bc`（`g_UnkAutoCollectTimer`）全 exe **只有一条引用**（`th08:0x4406d8 call 0x4066a0`，语义 = `timer < 0` ⇒ **提前**把 state 3 转 1），**无任何写点 ⇒ 在 v1.00d 里是死的**（建议**不复刻**）。

### 2c.5 与卡里 `#19` 的关系（**不是同一处**，两条独立规矩）

### 2c.6 给实现者的口径 + 影响面（**要不要动 TH18 的经济，先说清**）

- ✅ **「小蓝点 = 1/10 分 + 不记账」只要落在给分侧**（例如 `on_item_score`/`on_item_collect` 里按 TH18 自己的类型号只改写这一颗的分值），
