#### §th07-P1 —— 森罗结界五枚 SE 的一手与读法（2026-10-01 独立复核，`WORK-PACKAGES.md` §0 P1/P8）

- **表怎么读**（与 TH18 不同，别照抄 id）：TH07 cfg `th07:0x49ea88`、**stride 8 / 38 行**、字段
  `+0x00` = 名表下标、`+0x04` = i16 音量（÷100 = dB）；名表 `th07:0x49ebb8`（**30 项**，值是字符串 VA）；
  唯一播放入口 `th07:0x44c930`（`ecx` = SoundManager `0x4ba0d8`，id 在 `push`）。
  **行号就是 id**（这是 TH18 与其余各作的分水岭，见 `engine/_shared/th18-sound-table.md` §11）。
- **五枚逐一**（我按指令边界重读，逐行）：

| 时机 | 一手 | TH07 id → wav | 我们的落点 |
| --- | --- | --- | --- |
| 结界展开（第一声） | `0x441b8a push 0x20` → `0x441b91 call` | `0x20` → `se_border.wav`（−3.00 dB；**TH07 独有**） | `CE_VOICE_PCB_BORDER`（扩表 `0x5c`，构建期现取）|
| 结界展开（第二声，同帧） | `0x441b98 push 0x24` → `0x441b9f call` | `0x24` → `se_bonus2.wav` | TH18 `0x30`（md5 `ee39e1df…` 相同）|
| 自然到期结算 | `0x4416f6 push 0x21` → `0x4416fd call` | `0x21` → `se_bonus.wav` | TH18 `0x2f`（md5 `44b82b1d…` 相同）|
| 灵击 / 中弹打断（第一声）| `0x441e3c push 0x07` → `0x441e43 call` | `0x07` → `se_tan00.wav`（**−15 dB**）| TH18 `0x1b`（`se_tan00`，−11 dB；同 md5 `f5409b28…`）|

- **否定结论（过指令边界）**：TH07 全 exe 的 `call 0x44c930` 共 **123** 处，**`0x441000`–`0x442000`

#### §th10-P6 —— 这两条的一手、根因与落笔（2026-09-22，工单 `WORK-PACKAGES.md` §0 P6）

- **#1（音效）**：一手链条 = `th10:0x41b43c mov ebx,0x1d` → `0x41b446 call 0x43dd10`（SE 播放器）
  → **紧接着** `0x41b44b cmp WORD ds:0x474c48,0x64` / `0x41b455 mov [esp+0x14],1`
  ⇒ **同一条代码既播那一声、又置「刚满 P」标志**（后者正是全场转换的触发）。
  ⇒ 「满 P 那一刻」的那一声 = TH10 的 `se_powerup.wav`。
  ⚠ 如实登记：**TH10 的转换循环本身静音**（`th10:0x41ba50` 里只有 `spawn_item` 与建 anm VM 两个 call，
  一次 `play_sound` 都没有）⇒「在**转换那一帧**响一声」是 **❓ 自定**（音色是一手，触发口径是我们的）。
  落地 = `cards/faith.c` 的 `faith_convert_full_p_items()`（`n > 0 && !s_was_full` + `CE_VOICE_MOFPOWERUP`）；
  音频走音效表扩容通道（`assets/voice/ORDER.txt` 一行 → `derive_retail_se.py` 构建期从
  `local/th10.v1.00a/dat/` 现取，**版权字节不入库**）⇒ `patch/th18/voice.js` 与
  `dist/patch-step3/th18/voice/MOFPOWERUP.wav` 都在。
- **#2（队列）**：一手 TH10 全文见 [`engine/faith/th10/02-faith-drop-distribution.md`](../../../engine/faith/th10/02-faith-drop-distribution.md) §3.6 ——

#### §th13-P12 —— #4「被 boss 体术 ⇒ 不能移动」的一手结案（2026-09-22）

> 一手全文：[`engine/player/th18/03-player-hit-gate.md`](../../../engine/player/th18/03-player-hit-gate.md)
> **§1.6**（TH18 体术路径 + 命中链写点穷举）/ **§4.2**（TH13 判定层的灵界闸门）/ **§4.3**（TH13 体术路径）。
> 落地登记：[`AUDIT.md`](AUDIT.md) §BE-FE。

- **体术是什么**：不是 ECL、不是推挤、也不是体术专用代码 —— 就是 `EnemyData__step_game_logic` `0x42ed40`
  里的接触判定：圆分支 `0x42f580 call 0x45cd90`、OBB 分支 `0x42f667 call 0x45cea0`（两处第 3 参传 0 = 可致死）。
  命中后调用侧只对返回值 **2（擦弹）** 做事（`0x42f66c` 起、每 6 帧一次 `Player__do_graze`），
  **返回值 1 什么都不做** ⇒ 体术的全部后果只能来自那两条判定函数体内的 `call 0x45d3a0`。
- **「不能移动」是谁写的**：TH18 里移动只从 `Player__on_tick__body` 的 **case 1** 调
  （`0x45c0c1` 判 `[0x4cf2a4]==0` → `0x45c0cc call 0x45b170`，全 exe 唯一调用者）⇒ 状态 ≠ 1 = 不能移动。
  `player+0x476ac` 全 exe 7 个写点里，**值 4（决死窗口）只有 `0x45d4e4` 一处**（在 `Player__die` 体内 =
  **我们站点之后**）、值 2 只有 `0x45d21c` 一处（`0x45d090`，只能从状态 4 走到）。
  ⇒ **没有「比站点更早的一笔」可以单独掐**：命中链「判中 → `call`」之间，三条判定函数
  **一条玩家字段写都没有**（区间 `0x423e10`–`0x45d588` 62035 条指令按 disp 过滤出 49 条写，判定函数体内 0 条）；
  玩家位置/速度的 26 条写点全部属于玩家自己那一族 ⇒ **TH18 没有体术推挤**。
- **一手对照（判真）**：TH13 的灵界**有两道**拦 —— ① 判定层：`th13:0x444146` / `th13:0x444269` /
  `th13:0x444759` 在入口过灵界旗标就 `xor eax,eax; ret`（**圆弹 / 激光 / 体术**，连判定都不成立）；
  ② on_hit 层：`th13:0x444ca4` 早退到函数尾（矩形弹那条路 = 弹被吃）。两处**之前**都没有玩家字段写
  （四个判定函数 `writes.py` 筛完 = 0 条）⇒ owner 的「TH13 灵界 = 无敌 + 不被体术锁」**判真**。
- **为什么那次会不能动**：owner 的记录写于 **2026-09-18 23:11**，而闸门站点 `ce_player_die`
  **2026-09-19 20:57（`7647511`）才放出**（此前 park 在 `sites.py` 里）⇒ 那次实跑灵界没有任何防护：
  体术命中 ⇒ `Player__die` 跑 ⇒ **状态 4 = 决死窗口 = 停止移动** ⇒ 8 帧后窗口结束、被 113 的 `+0x0c`
  救援取消（state 回 1）⇒ 下一帧再中 ⇒ **「不能移动，持续被体术」的循环**。#3（音效没屏蔽）、
  #6（灵界结束后死亡）与它是**同一个缺闸门**的三种表现。
- **改了什么**：**没有加站点、没有动无敌层**（owner 口径：无敌 = 会删金光）。闸门语义保持不变
  （判定照跑、弹被吃掉、hit 音被拦、状态/决死窗口/停止移动全不写）。卡侧只补了一件**只读**的现场取证：
  灵界期间每帧读 `player+0x476ac`，≠1 就计数并在状态值变化时打一行
  `trance: ★ player LOCKED-in-trance: state a -> b …`，汇总行新增 `player-lock watch: N`（正常恒 0）。
- **实跑判据（单卡 113）**：灵界里贴着 boss 本体站定 ⇒ ① 可以自由移动、不扣命、不记 miss、无中弹音；
  ② 日志每 ~60 帧一行 `no-hit gate: Player__die … skipped (#N, declared by card 113) …` 且 `#N` 增长；
  ③ 汇总行 `player-lock watch: 0`。看到 ② 不出或 ③ 非 0 ⇒ 把日志行发回来（那就是「没被拦住的另一条锁」）。
