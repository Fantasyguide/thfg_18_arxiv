script script262 {
// 灵界**退出擦除幕布** ①/④ —— 逐条搬 TH13 `effect.anm` **script7**
//   一手原文（`thanm -l 13 local/th13.v1.00c/dat/effect.anm`，原文行 107–120）：
//     -1: type(1); sprite(sprite0); scrollMode(0,1); scale(3.0,12.0);
//         rotate(0.0,0.0,1.2217305); pos(160.0,-328.10498,0.0);
//         posTime(30,1,-1024.0,96.0,0.0); color(32,16,96);
//     40: delete();
//
// ## 这是什么（用户口径「灵界退出时那张 astral 图被一个**有形状的**不透明 mask 盖掉」）
//   TH13 灵界的进/出**不是淡入淡出**，而是 4 块**巨大的斜置幕布**扫过屏幕：
//     · 贴图 `effect/eff_switch.png` = **纯 alpha 形状**（RGB 全白、alpha 沿斜向笔触渐变，
//       64×64 逐像素导出核对过）⇒ 配上 `color(32,16,96)` = **深蓝紫的"笔触状"遮罩**。
//       ⚠ **染色不是自定**：贴图 RGB 全是 `ffffff`、没有颜色信息 ⇒ 颜色**必须**由 `color()` 给。
//     · `scale(3.0,12.0)` × 128×128 = **384×1536** 的一块，再 `rotate` 70° 横着扫过屏幕；
//     · 四条同一套配方错开 0/5/10/15 帧出发、40/45/50/55 帧各自自灭。
//
// ## ★★ 两处**一手订正**（2026-09-13 第七轮；上一版这两处都错了，实跑表现 = "两个蓝矩形"）
//   ① **位置要加 effect 宿主的 `entity_pos = (320,240)`**：这 4 台子 VM 由 effect 回调
//      `th13:0x4032d0` 即时画，而 `0x402ff0` 尾段 / `0x4035e0` 的三个 case 都把它们的
//      `entity_pos` 写成 **(320,240,0)**（一手：`fld [0x4aea3c]=320` / `[0x4aea38]=240` →
//      `mov [eax+0x574]/[eax+0x578]`）。⇒ 屏幕位置 = 脚本 `pos` **+ (320,240)**。
//      上一版漏了它 ⇒ 整块幕布**高了 240 px**，露在游玩区里的只剩"被 CLAMP 拉实的那半边"、
//      即用户看到的**蓝矩形**。
//   ② **`posTime` 的 (x,y,z) 是绝对目标，不是增量**（一手：thpages `interpolation.md`
//      "the current value of the field is copied to `initial`, the argument is stored in `goal`"；
//      第二参是**缓动曲线**，1 = `easeIn2(x) = x²`）。上一版注释写"增量 ⇒ 不动"也是错的
//      ⇒ 目标值同样要 +(320,240)。
//   ⇒ 本作世界层坐标 = **TH13 屏幕坐标 − (320,16)**（游玩区 x∈[−192,192]、y∈[0,448]，
//      1 世界单位 = 1 屏幕 px ⇒ 尺寸不换）⇒ 两条合起来：**世界值 = 一手字面量 + (0, 224)**。
//
// ## 另外两条必须声明的偏差
//   ③ **`scrollMode(0,1)` 不写**：那条管采样器寻址（U=WRAP 平铺 2 次 / V 从第 1 行起、
//      越过第 63 行 CLAMP；一手 `engine/anm/th16/09-drawing.md` §4.2(c)(d)）。本仓贴图并进图集、
//      不能越界 UV ⇒ **由 `make_trance_art.py::make_switch()` 把这套寻址逐像素烘进
//      `SWITCH.png`（128×128）**，连 CLAMP 造成的"实心半边"也一并烘进去（那是原版画面的一部分）。
//   ④ **层**：一手这 4 台由 EffectManager 回调画，宿主层由状态机在 **6 / 20 / 26** 之间切
//      （`0x4035e0` 的 case 7/8/9 = `state 0/1/2` + `layer 26/20/6`；`begin` = 中断 9 ⇒ 灵界中 = 6）。
//      **转场那两档（20/26）是"盖在最上面"的意思**（TH13 的 HUD 用 17/19/23/25，26 比 HUD 还高）
//      ⇒ 本卡取 **19 = TH18 游玩区最上层**（❓ 自定，`TUNING.md` §2.0）。
// ★★ 2026-09-13 第八轮订正（**染色**）：`color(32,16,96)` → **`color(64,64,56)`**。
//   一手 TH13 是 (32,16,96)（蓝紫）；但 **TH18 自己那份一模一样的配方**
//   （`local/th18.v1.00a/anm/effect/effect.anm.txt` 的 script3..10 —— 与 TH13 script3..10 同形，
//   只多了 `resolutionMode(1)`）写的是 **`color(64,64,56)`**：一个**近中性**的暗色。
//   用户实跑看到的"两个蓝色的矩形 / 神秘蓝色块"就是 (32,16,96) 在**不透明叠加**时带来的蓝紫。
//   本轮真正的修法是「**目的地 alpha 遮罩**」（脚本 271 清零 → 本幕布写笔触 alpha → 底色填满 →
//   astral 用 `blendMode(7)` 读）⇒ 幕布 RGB 只在笔触边缘露一点；取 TH18 自己的中性值即
//   **同时**去掉蓝色调、又与 TH18 的现成配方一致（`AUDIT` §CN-9）。
// ★★ 第八轮（追加订正）：**层 19 → 3**。这一批幕布**必须**和 astral 同层（层 3）：它们写的
//   是**目的地 alpha**，而 astral（`blendMode(7)`）只认**同一个 surface 里、且在自己之前**写下的 Da。
//   层 19 画在 astral **之后**（渲染阶段表 `engine/anm/th18/02-render-stages.md` §1）⇒ 遮罩读不到。
//   同层内的前后 = **生成顺序**（尾插）⇒ 卡侧在"下落沿"里**先起幕布、再重起 astral**（`trance.c`）。
// ★★★ 2026-09-13 第十轮：**层 3 → 5**（`AUDIT` §CT-8）。
//   TH18 的 boss 符卡背景 = `st0Xenm.anm` script10–14（`stgenm/stageXX/cardbg0/1.png`），
//   它们全部写 **`layer(4)`**（一手：`thanm -l 18 st01enm.anm`，script10/11/12/13/14 的 `ins_304(4)`）
//   ⇒ 层 4 那一趟（优先级 `0xb`）画在层 3（`0xa`）**之后** ⇒ 会把我们的灵界幕布整块盖掉
//   ＝ 用户口径「**灵界幕布被 boss 符卡幕布取代**」。
//   **一手的相对关系**：TH13 自己的符卡背景是 **`layer(3)`**（`thanm -l 13 st01enm.anm` script11–14
//   的 `ins_304(3)`），而 TH13 的灵界 astral 由 effect 宿主画在 **层 6**（`0x4035e0` case 9）
//   ⇒ **原版里 astral 在符卡背景之上（灵界幕布赢）** ✓。
//   TH18 把符卡背景从 3 挪到了 4 ⇒ 我们要保持同一相对关系就得挪到 **5**（= 世界层背景组 3–5 的顶，
//   仍在子弹/敌机层 6–19 之下；层 3–5 同相机 3、同 surface 0 ⇒ 几何/尺寸不变）。
