//   -m local/vendor/thpages/static/mapfile/v4.anmm`；v4 mapfile 自注「for version 4: StB, Mof」
//   ⇒ TH10 用的就是它，`ins_N` 名对表也在那份 mapfile 的 `!ins_names` 段）：
//     script377 { sprite(sprite346); type(1); angleVel(0.0f, 0.0f, 0.7853982f);
//                 scale(0.5f, 0.5f); scaleTime(16, 0, 1.0f, 1.0f);
//               +32: angleVel(0.0f, 0.0f, 0.0f); type(0); stop(); }
//
// 为什么搬这条（三条一手链，逐条可复跑，完整推导见 `assets/ability/make_mof_art.py` 文件头 §定案）：
//   ① 类型 → 信仰值：`ItemManager::on_tick__body` th10:0x41b3ce 的 11 项跳转表
//      （`0x41b8a0`）里 **idx2 = 类型 3 → `0x41b57f`**：难度表 E/N 5000 · H 8000 · L/EX 10000、
//      弹窗色 `0xff00ff00` ⇒ 类型 3 = **大信仰点**。
//   ② 类型 → 脚本号：`ItemManager::spawn_item` th10:0x41bca8 `lea eax,[ebp+0x176]`
//      ⇒ **脚本 = 类型 + 374** ⇒ 类型 3 → **script377**。
//   ③ 脚本 → sprite：`sprite(sprite346)`，而 `on_draw__body` th10:0x41b8e0 的
//      `lea edx,[eax+0x157]`（eax = `item+0x3e4` = 视觉类型）也落在 **343 + 类型** ⇒ 两条独立对上。
//   ⇒ 贴图 = `@FAITH_DOT_BIG@` = `ability/mof/FAITH_DOT_BIG.png`（16×16 = 源 sprite346 `(32,208)` 原样切）。
//
// 逐条对应（v4 号 → 真名，`v4.anmm` 逐行可查）：
//     ins_3  → sprite      ins_67 → type        ins_53 → angleVel    ins_50 → scale
//     ins_60 → scaleTime   ins_63 → stop
//   ⚠️ **`angleVel` 不是 `rotate`**：ins_53 是角速度（ωz = π/4 /帧 自转），`rotate` 是 ins_49。
//      32 帧 × π/4 = 8π = **整整 4 圈** ⇒ 原文在 `+32:` 把角速度归零时视觉上正好回正（自带自洽）。
//   ⚠️ `+32:` 段末尾是 **`stop()`（只停脚本，VM 与贴图留在场上）**，**不是 `delete()`**

//
// ── 三档共用本脚本（与 TH10 逐条对照后的事实，不是偷懒）───────────────────────
//   · 大 = 类型 3 → script377（本条）；小 = 类型 9 → `script383`：**两条正文逐字相同**，
//     只差 `sprite()` 引用的那一格（`sprite346` vs `sprite352`）；
//   · 微 = 类型 8 → `script382`：多 `blendMode(1)` + `alpha(16)`，且 `scale(0.0f,0.0f)`

//   · sprite 由卡侧 `faith_sprite_for()` 按档 `ce_anm_set_sprite()` 换（脚本里的

//
// ── ★★ 2026-09-16：**收集时没有任何收尾动画**（原来那段 ❓ 自定已删）──────────
//   用户实跑：「拾取到大信仰点，吸收那一刻动画是一个放大减淡 …… 和 th18 的吸收 p 点金钱的动画不符」
//   —— 用户是对的，而且**一手连 TH10 都是「引擎直接删 VM」**：
//     · TH18（收集分派共享尾 `th18:0x446584`–`0x4465a5`）：`push 0x25` → `call 0x476c70`
