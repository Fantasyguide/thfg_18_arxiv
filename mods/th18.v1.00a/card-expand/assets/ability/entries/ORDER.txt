# 追加进 ability.anm 的贴图与图集。**只许追加**：行序 = 编号（entry = 原生 7 + 行序，sprite = 原生 109 + 行序）。
# 第 k 个数据行 → entry (7+k)、sprite (109+k)；脚本里写 `@NAME` 引用（收尾 `@` 可省）。
# 源图 `local/` 开头 = 原生贴图（gitignored，构建时取）。
#
# ★★ 2026-09-13「图集合并」（最后一次重排；此后**只许 append**）—— 完整方案见 `ATLAS-MERGE-AUDIT.md`
#   起因：贴图键 = `(anm 槽号 << 8) | entry 下标`，绑贴图时只取**低 8 位**（`th18:0x486d38` 打包 /
#   `th18:0x47e1a4` 解包）⇒ **一个 anm 最多 256 个 entry**，我们已经有 367 ⇒ 后 111 个 entry 全画错图。
#   （sprite 号**不受限**：原生 `bullet.anm entry0` 一个 entry 就有 368 个 sprite。）
#   做法：把同一张卡的几十张小图并进**少数几个 entry**（引擎原生支持一个 entry 多个 sprite）。
#   结果：追加 entry 从 360 压到 41，**总 entry 48 / 上限 256**，给以后的新卡美术留了 208 个 entry。
#
# ■ 语法（v2，本文件是唯一事实来源；由 `assets/build_ability.py` 解析）
#   ① 单图行：  `NAME 源图(相对 assets/) [WxH]`   —— 一行 = 一个 entry = 一个 sprite。
#        不写尺寸 = 卡图（256×320，字段抄 abcard BLANK_max）；写 `WxH` = 整张贴图一个 sprite。
#   ② 图集段：  `ATLAS <图集名> <画布WxH[@列x行]>`   —— 段头，本身不是成员；段内一行一个成员：
#        · 网格段（段头带 `@列x行`）：`成员名 源图 WxH`    —— 矩形 = 画布等分后**行优先**的第 k 格
#        · 显式段（段头不带 `@`）：  `成员名 源图 @x,y,WxH` —— 矩形直接写死（画布坐标，左上角起）
#        整段编译成**一个 entry**：name = `ability/atlas/<图集名>.png`（画布由构建脚本按成员贴出来），
#        成员按**段内顺序**拿**连续** sprite 号。
#   ③ 退役行：  `REF <退役名> <目标名>`   —— 只保 `@退役名` 能解析成目标名的 sprite，**不占 entry**。
#   ④ 成员命名：成员名 → 自己的 sprite 号；`图集名_k` → 段内第 k 个成员；`图集名` → **第 0 个成员**
#        （向后兼容"一行一个 entry"的老写法；`anm_ids.h` 里逐名生成 `CE_ANM_ABILITY_SPRITE_*`）。
#   ⑤ 成员矩形 = **成员原图自己的像素尺寸**（不补边、不缩放、不重采样）。
#        依据：VM 的 `scale.x` 乘的是 **sprite 矩形宽**（`th18:0x481703`：`[vm+0x74] × [vm+0x54]`），
#        矩形一改，脚本里的 `scale()` 与 C 侧的 `ce_anm_set_scale` 就跟着变
#        （旧方案把 48×32 补进 64×64 ⇒ 用户实跑看到"一边横向伸缩一边位移"）。
