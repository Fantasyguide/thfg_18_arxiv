1. 这一轮里，"读一手"反复出错：切错四张贴图（16×14 当 8×8、30×30 当激光、大玉当光束、整格均值当颜色），

2. 根因有三层：
   - **读的是"关于一手的话"**（注释、摘要、均色）而不是 anm/ECL 本身；

     所以 `ins_618` 在 TH19 里的语义**无从查表**，只能反编译。
3. 已立的铁律见 `METHOD.md` 的「读 anm 贴图必须走 entry 表 → sprite → 三元组」（2026-10-18）。
   本文是它的配套：**当 ECL 那端静态不可达时，改走反编译**。

  ins_600($A); ins_607($A, 3); ins_602($A, $B, $C); ins_606($A,1,1)
  ins_604($A, 1.5707964f, 0.034906585f)    // 角度：方向 π/2、角度差 2°  ⇒ 平行（±2°）
  ins_605($A, 2.0f, 1.0f)                  // 速度：max 2.0 / min 1.0
  ins_611($A, 0, 2, 1, ...) x3
  ins_571(%E, 2.0,2.0,2.0,2.4,2.8,3.0,3.0,3.2)   // 8 档速度表
  ins_620($A, 0.0f, 96.0f)                 // 位置 (0,96)
  ins_618($A, (rand×π/2) − π/2, 192.0f)    // ★ 语义未知（TH19 无公开表）
  每帧 ins_601($A) 发 + ins_23([-1]) 等 1 帧；按档颗数 8/8/8/6/5/4/5/4

**结论**：
- 角度只有 `ins_604(dir=π/2, dif=2°)` 一个来源 ⇒ **平行**（与 owner 一致 ✅）；
- `ins_605(maxspd, minspd)` 与 `ins_618` 都可能给速度 ⇒ **`ins_618` 不可能是"角度"**；
- `ins_618` 的第三参 `192.0` 与场地半宽 **192** 数值相同 ⇒ 疑似"x 散布"，但**无依据** ❓。

## 4. 反编译研究计划（"最硬的路"）

**目标**：把 TH19 的 ECL 指令表**从 exe 里解出来**，从此 `ins_XXX` 的语义不再靠猜。

### 阶段 A：定位 ECL 虚拟机

1. 在 `local/th19.v1.10c/ghidra_projects` 里打开工程（或用 `tooling/ghidra/run.sh` 新起）。
2. 找 **opcode 分派**：典型形态是一个大 `switch`／跳转表，`ins_23`（等待）、`ins_1`（删单位）等是高频入口，
   可从字符串/常量反推（如 `ins_700` 的 `512.0f`、`ins_704` 的 `1.5707964f` 这类**字面量常量**是很好的锚）。
3. 产出：`(opcode_number → handler 地址)` 的完整表。

### 阶段 B：解 `ins_618`（与 600/601/602/604/605/607/608/611/620/621）

4. 对每个目标 opcode，读 handler 里**从栈上取几个参数、写进目标对象的哪个字段**。
5. 关键验证：`ins_618` 若写的是"速度"字段 ⇒ 与 `ins_605` 重复，需看谁覆盖谁；
   若写"散布/偏移"字段 ⇒ 验证 `192` 与场地半宽的关系。

### 阶段 C：重建 TH19 eclmap

6. 把 `(opcode → 名字)` 落成 `local/vendor/.../th19.eclmap`（或 `engine/ecl/th19/eclmap.txt`），
   **入库**（这是本次缺口的根因：map 没留下来）。
7. 用 `thecl -d <map> th19.dat` 重出一遍 `_ext/ecl/*.txt`，与现有文本**逐字对比** —— 这一步能顺带验证：
   现有 `_ext` 用的 map 与我们重建的是否同一个。

### 阶段 D：回流文档

8. `engine/ecl/OVERVIEW.md` 加一节「第五世代（TH19/TH20）」；`engine/ecl/th19/` 放：
   - `00-opcode-table.md`（完整 opcode 表）
   - `01-et-family-args.md`（`ins_600/601/602/604/605/607/608/611/618/620/621` 的逐参语义）
9. 在 `HANDOFF-109-C34-SANAE.md` / `-MARISA.md` 里把相关 ❓ 更新为"已由反编译解决"。

## 6. 一点方法论（写给下一个接手的人）

- **别信注释、别信均值、别抽样**：注释会与实物同源同错；均值会掩盖"切多一圈"；抽样会掩盖"选错行"。
- **三元组**（文件 : entry : sprite）是"读到了"的唯一证据；给不出就是没读到。
- **静态不可达就写"不可达"并问 owner**，不要拿"最像的那个"顶替 —— 这一轮所有的错都出在这句上。
- 反编译出来的结论也要过同一道关：**写清 handler 地址 + 取参个数 + 写哪个字段**，否则同样是"推测"。
