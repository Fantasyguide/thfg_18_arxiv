## 1. 为什么这些代码是 C3–C4（引擎侧绑定）

### 1.1 引擎用**字符串**指定 ECL 子程序；两个入口在 vtable 里**相邻**

| 事实 | 地址（TH19 v1.10c，裸地址属本版） |
| --- | --- |
| `push 0x599b0c`（= `"ExtraAttack"`） | `0x50d91f`，函数起点 **`0x50d8a0`**，函数尾 `push 0x3` |
| `push 0x599b18`（= `"BossAttack"`） | `0x50d87f`，函数起点 **`0x50d800`**，函数尾 `push 0x4` |
| 二者都 `call 0x50d410`（按名字 spawn ECL 子程序） | `0x50d926` / `0x50d886` |
| 二者在 **20 个 vtable** 里是**相邻两槽**（例：`.rdata` `0x5a8a2c` = `0x50d8a0`、`0x5a8a30` = `0x50d800`） | 卡类对象虚表 |

⇒ ★ **卡 3 的 vtable 槽 = `0x50d8a0`（spawn `ExtraAttack`，并 `push 3`）；卡 4 的槽 = `0x50d800`（spawn `BossAttack`，并 `push 4`）**。
★ 所以"**C3 = `ExtraAttack()`、C4 = `BossAttack()` 起头**"不是按名字猜的，而是**常量 3/4 与槽位邻接**两路对上。

### 1.2 C4 为什么最终跑到 `Boss00BossCard1()`

`BossAttack()` 只做一件事：`ins_300("Boss00", 0.0f, 128.0f, 100, 100, -1)` 再 `ins_1()`。
⇒ 它 spawn 的是**整棵 boss 攻击树**（`Boss00` → `Boss00Boss` → `Boss00Boss1` / `Boss00BossCard1`），
符卡体的名字靠**"卡名 = 拼出来的"**，所以 exe 里**没有** `Boss00BossCard1` 字面量（实测 `strings` 0 命中）——只有
`ExtraAttack` / `ExtraAttack00` / `ExAttack` / `BossAttack` / `BossDead` / `BossEscape` 这些**固定名字**在 exe 里。

### 1.3 用"符卡名"反查坐实 C4 与低/高档

`ins_522(0, 1800, 0, "…")` 设的符卡名是**唯一的、可外部对照的标识**：

| 函数 | 设的名字 | 判定 |
| --- | --- | --- |
| `pl01 Boss00BossCard1()` `:248` | 星符「シュート・ザ・ビースト」 | **魔理沙 C4 低档** ✅ |
| `pl01 Boss00BossCard1H()` `:287` | 星符「シュート・ザ・ビーストキング」 | **魔理沙 C4 高档** ✅ |
| `pl02 Boss00BossCard1()` `:146` | 風符「ウィンドライダー」 | **早苗 C4 低档** ✅ |
| `pl02 Boss00BossCard1()` `:148` | 風符「ウィンドマスター」 | **早苗 C4 高档** ✅（与低档**同函数**，靠 `!012345` / `!67` 的 rank 门切）|

### 1.4 排除法：这些**不是** C3–C4

| 函数 | 依据 | 结论 |

## 3.0 ★★ ECL 派发机制（一手，TH19 v1.10c）—— S1 的地基

解释器 = `0x4fecc0`（全 exe 最大函数，25 994 B，1 个 xref）。入口处的取指-派发：

```
0x4fecf6  movzx edx, WORD PTR [esi+0x4]      ; opcode = 当前指令 +0x4（u16）
0x4feceb  call 0x56bef0                       ; esi = 当前指令指针（由 [ctx+0x55c8]+0xc 取）
0x4fecff  add ecx, 0xfffffed4                 ; ecx = opcode − 300
0x4fed09  cmp ecx, 0x2e6                      ; 范围闸：0..742 ⇒ 覆盖 opcode 300..1042
0x4fed15  movzx eax, BYTE PTR [ecx+0x505560]  ; ★ 一级：字节表（0x505560 起，743 项）
0x4fed1c  jmp DWORD PTR [eax*4+0x50524c]      ; ★ 二级：指针表（0x50524c 起，197 个入口）
```

⇒ **`handler(opcode) = dword[0x50524c + 4 × byte[0x505560 + (opcode−300)]]`**（`opcode` 必须在 300..1042）。
★ 系统码（<300）走 `0x4fed0f` 的 `ja 0x505234` 分支，不在这一层。

> ★ 这也解释了为什么"扫跳转表"扫不到：一级表是**字节**索引、二级表只有 **197** 项。

### 取参助手

* `0x50c1b0` = `get_int_arg(N)`（`push N; mov ecx, ctx; call`）
* `0x50c1d0` = `get_float_arg(N)`
* `0x40ee10` / `0x40ee00` = 取"某结构体 + 槽号"的**元素地址**（两个不同的结构体基址）
* `0x404010` = **vec3 相加**（`out = a + b`，逐分量 `addss`）

### ★★ `618` 结案：**发射位置偏移**（极坐标 → 向量），不是速度、不是位置

`ins_618` handler = `0x502432`（`th19_fmts`：`Sff`），逐指令：

| 地址 | 动作 |
| --- | --- |
| `0x502436` | `A = get_int_arg(0)`（槽号） |
| `0x502445` / `0x502454` | `θ = get_float_arg(1)`、`r = get_float_arg(2)` |
| `0x502463` | `0x402780(&vec)`：`vec = (0,0,0)`（3 float 清零） |
| `0x502478` | `fsincos(θ)` ⇒ `st0 = cos θ`、`st1 = sin θ` |
| `0x50247e` / `0x502484` | `vec[0] = r·cos θ`、`vec[1] = r·sin θ` |
| `0x50248e` / `0x5024a4` | 写进 **`this+0x4e6c`** 的槽 A：`[eax] = vec[0]`、`[eax+4] = vec[1]` |

★ 对比 `ins_620` handler = `0x502511`：把 `(x, y)` 写进 **`this+0x4f2c`**，并把 `[eax+8] = 1.0f`（有效标志）。
★ 消费点 `ins_601`（发射）handler = `0x50221b`：
`if (pos_flag[+8] > 0x5aa224) pos = this+0x4f2c[A] else pos = 0x401a50(this+0x48)`；
再 `0x404010(out, pos, off)` ⇒ **`out = 基准位置 + 偏移`**，写进出生的弹（`+0x8/+0xc/+0x10`）。

⇒ **`618(A, θ, r)` = 给发射器槽 A 设"出生点偏移向量" `(r·cos θ, r·sin θ)`** ✅✅ 一手；
★ `ins_601(A)` 的出生点 = **`620` 设的基准位置 ＋ `618` 设的偏移**（基准未设时用默认点 `0x401a50(this+0x48)`）。

### ★ 由此直接坐实 owner「早苗 C4 发弹点遍布整个 x 轴」

`pl02 Boss00BossCard1_at` 每帧：`ins_620($A, 0.0f, 96.0f)` ＋ `ins_618($A, [-9987]×π/2 − π/2, 192.0f)`。

* `[-9987]` 是**对称随机 `[−1,1]`**（旁证：`pl01` C4 用 `[-9989] + [-9987]×0.08726646` 做 ±5° 抖动）；
* ⇒ `θ ∈ [−π, 0]` ⇒ `cos θ ∈ [−1, 1]` ⇒ **`x = 192·cos θ ∈ [−192, +192]`** = **整个 x 轴** ✅✓✓
* `y = 96 + 192·sin θ ∈ [−96, 96]`（靠上/屏外）⇒ 从顶边往下洒 ✅

★ 这一条把 §2.4 的 🟡 升级为 ✅。

### 4.3 卡外壳 opcode 的**结构归属**（只到"动哪个结构体"，不是语义）

★ 做法：对每个 handler 取 `lea ecx/eax,[edi+0xNNN]` 的立即数 + `get_int_arg`/`get_float_arg` 的调用计数。
★ **这只证明"动哪个结构体"，不证明"字段语义"** —— 所以这些行仍是 🟡。

| 子系统 | opcode | 结构基址 |
| --- | --- | --- |
| **A**（`this+0x134`） | `306`／`313`／`316`／`502` | **16 槽 dword 表**（`0x40ee30` 的越界闸是 `idx < 0x10`）；与子弹类型表 `0x5ac` **无关** |
| **B**（位置/速度） | `401`／`404`／`405`／`412`／`504`／`505` | `+0x90`／`+0xd8`（两个 vec3）＋ `+0x3dc`/`+0x40c`/`+0x43c`/`+0x46c`（一组四元） |
| **C** | `513` | `+0x14`／`+0x2cc`／`+0x55e8` |
| **D** | `523` | `+0x5008` |
| **未识别** | `302`／`500`／`516` | 没有直接 `[edi+…]` 基址（走别的助手），❓ |


#### A 组细节（本轮新读，仍不冒充语义）

* `0x40ee30(base, idx)`：**通用数组取址**，`idx < 0x10` 才合法（否则 `0x4027a0` 断言）⇒ `this+0x134` 是**16 槽 dword 表**。
* `0x50d380(sel)`：**id → 全局对象**的查表（`sel==0x1d` → `[0x5d1a3c]+0x35fc`；`sel==0` → `[[ctx+0x4c84]]+0x81570c`；`sel==1` → 下一项…）。
* 于是 `306(a,b)` 的形态是：取 `a`（槽）、`b`（id） → `0x50d380(b)` 得全局对象 → `0x40ee30(this+0x134, a)` 取槽 → 写入。
  ★ 只到"**把某个全局对象登记/绑定进 16 槽表**"这一层；**没有**证明槽里存的是指针还是 id ⇒ 仍 🟡。
* `401/404/405/412/504/505` 那一组用 `0x40fe70(ctx)` = `(ctx[0x5170] >> 3) & 1`（**位标志测试**），
  说明这组的第一步是"看某个标志位"，再看 `+0x90`/`+0xd8` 两个 vec3 ⇒ 位置/速度语义的**方向**是对的，
  但字段名仍未定 ⇒ 仍 🟡。


★ 由此可以给"外壳"一个**有依据的分组**（而不是把 15 条笼统标"阶段/子状态"）：
`306/313/316/502` 是一组、`401/404/405/412/504/505` 是一组 —— 这与 ECL 里的用法也吻合
（卡开头连用 `306/404/405/401/504`，卡中反复 `316/307`，卡尾 `412`）。


### 4.4 `604` 第三参（`dif`）的**全语料分布**（判它到底像不像"散布"）

脚本对 43 份转储统计 `ins_604(a, dir, dif)` 的第三参：

| `dif` 取值 | 次数 | 折算 |
| --- | ---: | --- |
| `0.0f` | 110 | 无 |
| `0.17453292f` | 26 | 10° |
| `0.34906584f` | 19 | 20° |
| `0.55850536f` | 17 | 32° |
| `0.2617994f` | 8 | 15° |
| `0.034906585f` | 8 | 2° |
| `0.05235988f` | 5 | 3° |
| `0.5235988f` | 5 | 30° |
| `0.7853982f` | 5 | 45° |
| `-1.5707964f + rand×0.17453292f` | 5 | ★ 全在 `pl01`（`ExtraAttack00`）|

★ 结论（只到这一步）：`dif` 在**绝大多数**调用点上取 `0` 或 **2°–45° 的小正角** ⇒ 形态上像"角散布/角增量"；
★ 但 **魔理沙 C3（`ExtraAttack`）用的是 −90°（=−π/2）**，与"散布"完全不相容 ⇒
它在本处只能是**另一种用法**（例如 `(dir, dif)` 当作"从 dir 到 dif 的角度区间"，两值相等 ⇒ 单方向），
**不能**把 −π/2 当成"散布 90°"——那是本仓最容易再犯的一次误读。
