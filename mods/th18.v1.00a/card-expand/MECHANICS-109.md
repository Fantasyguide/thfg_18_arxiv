## 2. 消弹场（「圈」）——**机制核心**

一手：TH09 把消弹做成**玩家身上的节点**（场），字段 = **`r0` 起点 / `dr` 每帧增量 / 寿命**，
逐帧扩张、到寿命释放；**圈碰到敌弹就消、碰到敌人就伤**。**不是一次性按终点半径消一圈** ✅。

### 2.1 各节点的**一手数值**（都逐指令核过）

| 节点 | 一手出处 | r0 / dr / 寿命 | 终点半径 |
| --- | --- | --- | --- |
| ★ **「自机弹命中」（= 暴风/連爆）** | `th09:0x41fe93` | **0 / 1.6→实际 ×0.5 = 0.8 / 70** | **56** |
| 「松手那一下」 | `th09:0x41e875` | 16 / 20 / 8 | 176 |
| CA 档 1 | `th09:0x403c30` 一族 | 0 / 4.0 / 48 | 192 |
| CA 档 2 | 同上 | 0 / 4.0 / 64 | 256 |
| CA 档 3·4 | 同上 | 0 / 3.5 / 128 | 448 |
| BOSS 大场（kind 4）| `th19:0x41d0d0` | 500 / 0 / 30000（永久）| 500 |

★ **「×0.5」别漏**：节点构造函数 `th09:0x41d050` 里 `fmuls [0x490f54]`，而 **`[0x490f54] = 0.5f`**
⇒ 存进去的 `dr = 1.6 × 0.5 = **0.8**` ✓（我先前漏了它，导致暴风大了一倍、速度快一倍 ✗）。

### 2.2 红圈（蓄力攻击的消弹圈）——**TH09 的贴图卷环**

| 项 | 一手 |
| --- | --- |
| 脚本 | **`etama.anm` script91 / 92 / 93**（三个蓄力档，**一条律**）|
| 贴图 | **`sprite224`** = `etama3.png` 里 **左起第三条**竖带（x=32，**16 宽 × 128 高**）|
| 画法 | `sprite(sprite224)` + **`blendAdditiveSet(1)`（加算）** + `rotate(0,0,%RANDRAD)`（随机自转）+ `posTime(48/64/128, 0, 192/256/448)`（从 16 扩到终点）|
| ★ 关键 | sprite 表声明 **16×768**，而图集只有 128 高 ⇒ **768 = 6 × 128**：引擎把带子**沿周向平铺 6 圈**贴到环上 ✓（所以**摊开看图集怎么看都不像** ✓）|

**实现（owner 已定：方案 A）**：把「卷环」**离线做掉** —— 径向 ← 带子的 x、周向 ← 带子的 y
（按一手 6 圈平铺取样）⇒ 一张环形贴图，卡里当普通 sprite 用 ✓。**纹理仍是一手的** ✓。
❓ 径向拉伸倍数（`THICK_MUL`）一手那个卷环回调 `0x40dc70` 的映射**没读出来** ⇒ 现在 3×，可调。

### 2.3 暴风（連爆）的**画面**——TH19 `ghost.anm`

★ **半径（owner 口径）**：**小怪**的暴风半径**不大**；而**纯净灵 + 三种动物灵（+ 幽灵）**的暴风半径

★ **观感（owner 口径）**：**最外侧深色（大约黑色）→ 中间红褐色 → 芯部透明** ✓
（⚠ owner 注：「**一手不一定对**」⇒ 我先前那套「照一手 script20 的 `color/color2` 抄」**以实跑观感为准** ✓）。

| 项 | 一手 |

## 3.5 固灵结界（除霊オーラ）★ 本卡主机制

★ **owner 批注：固灵结界 TH09 和 TH19 都有** ✓ —— 但**被固灵之后的后果两作不同**：

| 原作 | 灵被固灵（沈静化）之后 |
| --- | --- |
| **TH09 的幽灵** | **从鸟形变成火焰形** ✓ → **慢慢往上移动** ✓ → 若**没有及时打死**，会变成 **三发自机狙** ✓（★ owner：「秉承着**除 th06 不变难**的原则，自机狙得做，但**最终应该会去掉**」）|
| **TH19 的四种灵** | **只会过一段时间消失** ✓（不发弹）|

⇒ 本卡：**两种都要做** ✓ —— TH09 幽灵走「鸟→火焰→上飘→(超时)三发自机狙」✓；
TH19 四种灵走「停住→到点自然成佛」✓（第 4 节）。★ **自机狙最终会去掉**是 owner 已定方向 ⇒ 做成**可一键关掉**的一档 ✓。

> 「Charge ボタンを押しっぱなしにすると、**除霊オーラを展開**します。＊**オーラの形はキャラによって様々**です。
> 　オーラに触れた**敵と敵弾は遅くなり**、**霊力アイテムを放出**します。…また、**ピュア霊、動物霊**に
> 　オーラを当てると、霊達は**沈静化**します。沈静化すると**その場に留まり**、**耐久力も格段と低く**なり…
> 　一定時間経つと**自然成仏**します。」

| 机制 | 一手 | 实现要点 |

### 6.1 ★ 核心抽象：「**送到对面去**」（owner 提出，本节给出定义）

owner 口径：

> 「关键的部分在于，**送到对方场地的弹幕**，在普通 STG 作 = **轰到本侧的敌人身上**。
> 　可以一定意义上**虚拟出一个敌人**，因为 **TH19 的灵一开始只生成纯净灵，动物灵是送给对面才有的**。
> 　我建议是**抽象出来什么叫做「送到对面去」**。」

**本卡的定义（供审核）**——「送到对面」= 一个**统一事件**，三种落地：

| 场景 | versus 原作 | 本卡（单人）如何落地 |
| --- | --- | --- |
| **弹幕被送到对面** | 对面场地里出现这些弹（打对面的自机）| ★ = **打在本侧的敌人身上** ✓（owner 口径）⇒ 直接对这些敌人结算伤害/消弹 |
| **灵被送到对面** | 对面场地里出现这只灵 | = **在本侧场地生成这只灵**（从版内顶边出场 ✓，因为场外会被引擎瞬删 ✗）|
| **BOSS 态被送到对面** | 对面出现「BOSS 态的我」放符卡 | = **在本侧生成那个假 BOSS 载体**，它放的弹**打本侧敌人** ✓（并可按 owner 口径把场地拉过来 180° 反转）|

★ **派生规则（一手）**：TH19 里**一开始只生成「ピュア霊」** ✓；**動物霊只会因为「被送到对面」才存在** ✓
⇒ 本卡：**ピュア霊（纯灵）在场内生成 → 被击破 ⇒「送到对面」⇒ 变成動物霊回来** ✓
（单人时「对面」= 本侧 ⇒ 就是**再来一只動物霊** ✓）—— 这条正好把「召唤量」的来源讲通了 ✓。

★ **`虚拟敌人`**（owner 提到）：需要「对面有一侧」的机制（如符卡瞄准、场地反转）时，
用一个**不可见的虚拟对手位**占位即可 ✓（不影响本侧敌人 ✓）。

## 8. 重做时**务必避开的坑**（都是这轮踩出来的）

1. **TH19 专有的 anm 图元号，TH18 不认** ✗（`ins_617`、`anchor` …）——
   写新脚本后**必须**拿一个「实跑确认能画」的脚本**比对 op 号**（`thanm -l18`）✓。
2. **别照抄带 `scriptNew` 的脚本** ✗（它是启动器，引用的是**原作的脚本号** ⇒ 会召唤到本卡别人的特效）。
3. **脚本与卡侧别抢同一个属性** ✗（`scale`/`alpha` —— 要么脚本管、要么卡侧管）。
4. **`color`/`color2`（内/外）两作语义相反** ✗ —— 抄数值时要按**实际观感**决定放哪个槽。
5. **位置直接写世界坐标** ✓（别自己加/减换算 ✗）。
6. **SDK 注释要按「它修饰的是哪个名词」读** ✓；有疑义找**跑得通的同类卡**当实证 ✓。
7. **「看着不对」时先怀疑自己对格式的理解** ✓（例：sprite 表的高度可能是**平铺后的**高度 ✓）。
