## C2. ★★★★ 已解（2026-10-12）：灵梦 C1「四颗转不起来」= **脚本漏抄 `type(1)`** ✗

**owner 原话**：「109 灵梦 C1 的四颗弹幕死活转不起来」（一级证据 ✓）。

**真根因（一手，本机 TH18 逐函数点数 ✓）**：
* TH18 `AnmManager__draw_vm`（`th18:0x481210`）按 renderMode 分派：**0/2 → `th18:0x47e8f0`**、
  **1/3 → `th18:0x47ed50`**（`engine/anm/th18/01-vm-instantiate.md` §3b ✓）；
* `0x47e8f0` **`fsincos` = 0 条**（不旋转 ✗）、`0x47ed50` **有 `fsincos`（`th18:0x47ed8c`）** ✓；
* ⇒ **不写 `type()` = 默认 mode 0 ⇒ 引擎不读该 VM 的 rotation** ✗
  ⇒ 卡侧 `ce_anm_set_rotation` / 脚本 `rotate(...)` 全部无效 ✗ —— **这就是"死活"二字的来源** ✓。

**修法（已落 ✓）**：`assets/ability/scripts/427_pofv109_c1_bullet.anm.txt` 补回**一手本来就有的两句** ✓：
`type(1);` ＋ `angleVel(0.4712389f, 0.0f, 0.4712389f);`（逐字同值 ✓ 27°/帧）。
先例 `149_otter_orb` 证明「`type(1)` + `angleVel` + `stop()`」三者共存时引擎自己积分角速度 ✓
（脚本停了自转照跑 ✓）⇒ **卡侧再写 rotation 就是双倍转速** ✗。

**教训（写下来防复发）**：转写一手脚本时，**渲染模式类指令（`type()`）必须逐条对抄** ✓ ——
它管的是"引擎走哪条绘制路径"，漏了以后**下游怎么调 API 都白费** ✗，而且现象是"完全没反应"，
极易被误诊成"参数写错/插值器覆盖/引擎拿不到向量" ✗（这次三连误诊 ✓）。
