# DEV-INPUT-SYNTH —— 调试件「逐帧合成方向输入」（挂在调试键上）

> **版本**：TH18 v1.00a（`th18.exe`，imagebase `0x400000`）。本文裸地址默认属该版本。

## 0. 这是什么、为什么有它

用户 2026-09-13 口径：
> 「写一个脚本**挂在调试键上**，**按照帧操作进行移动**，**松开方向键**，然后**平均意义上不要移动**」
> 起因是一个小测试：「**原生一张文文的卡或许能刷出来永久无敌？**」

⇒ 一个**开发用**的输入合成器：按住调试键时**逐帧替玩家写方向位**，一个周期里**含"不按方向"的帧**，
整周期**净位移精确为 0**（自机在原地抖、不漂走）。**默认不按键时一个字节都不写。**

## 1. 用法

| 项 | 值 |
| --- | --- |
| **调试键** | **`Ctrl + A`**（`CE_VK_CONTROL` + `CE_VK_A`）。⚠ **`Ctrl+Space` 已被 112/117 占用**，别用那个。`A` 不在 TH18 键盘配置表里、不是方向键、全仓零引用 ⇒ 零撞车 |
| **模式** | `[左 N 帧][全松 M 帧][右 N 帧][全松 M 帧]`，宏 `CE_INPUT_SYNTH_{LEFT,RIGHT,RELEASE}_FRAMES`；**默认 N=1, M=1**（周期 4 帧） |
| **写什么** | `INPUT_HELD`（`0x4ca428`）与 `INPUT_PRESSED`（`0x4ca434`）的**四个方向位**（`0x010/0x020/0x040/0x080`），**先抹后写**；`Z(0x001)/X(0x002)/Shift(0x008)/C(0x400)/D(0x800)` **一个都不碰** |
| **怎么读效果** | 每 **30 帧**一行日志：相位/方向记号、自机 `x,y`、**定点累计 Δx（1/128 px，整数无误差）**、**峰值 \|Δx\|**、以及 **`player+0x47778`（无敌计时器 cur）**；按下/松开各一行总结 |
| **验收判据** | ① `peak` 停在 **≤ 8 px**（普通 4 px/帧、原生卡 29 超速 8 px/帧）；② 累计 `dx` **每 4 帧回到 0**；③ 无敌 `inv` **单调上升**（这就是"刷永久无敌"的直接证据） |

**关闭**：松开 `Ctrl+A` 即停写（`if (!down) return;`）。`CE_INPUT_SYNTH_ENABLED = 0` 时整件是**编译期空壳**
（发布版建议置 0；置 0 后连调用点都被优化掉，一个字节都不写）。

## 2. ★ 一手依据（为什么「平均不移动」是**结构性**的，而不是近似的）

- **调试键这条路不进游戏输入流**：`ce_key_down` 走 `GetKeyboardState`（user32）；
  空格/Ctrl/Shift 之类不在 TH18 键盘配置表里（先例：`cards/animal.c:233` 的注释、`ufo.c` / `trance.c`）。
- **方向位**：`engine/input/th18/01-key-mapping.md` §2.3 的位表（`0x010` 上 / `0x020` 下 / `0x040` 左 / `0x080` 右）。
- **同帧生效**：卡链 tick（节点 `0x16`）在 **Player tick（`0x17`）之前**
  （`0x461825 push 0x11` / `0x408475 push 0x16`）⇒ 在 `BP_ce_item_frame` 里写 HELD，同帧 Player 读得到。
- ★★ **订正一条旧口径：TH18 自机没有加速度/惯性**。`Player__sub_45b170` `0x45b170` 的积分段
  `0x45b5a2`–`0x45b608` 逐条是 `dx = (int)(dirX * speed * mult)` —— **`speed` 每帧只由当帧输入选表**，
  公式里**没有"上一帧速度"项**；松方向那一帧 `dirX = 0` ⇒ `dx = 0` ⇒ 当帧速度就归零。
  （`player+0x47934` = 上一帧 dx，但只在 `0x45b618`/`0x45b658`/`0x45b750`/`0x45b799` 被读，用途是**转身特效**。）
  ⇒ 「左 1 帧 / 右 1 帧」本来**就是**净零，不需要靠 N/M 去抵消惯性。
- **更强的理由（半周期镜像）**：模式满足 `u(t + P/2) = -u(t)`（`P = 2(N+M)`），
  而动力学对 `x → -x` **等变**（`0x4b7058 左 = (-1,0)` 正是 `0x4b7060 右 = (1,0)` 的取反 —— 一手）
  ⇒ 周期解满足 `z(t + P/2) = -z(t)` ⇒ **每周期末尾位置精确回到原点，对任意 N/M 都成立**。
  单测逐相位验了这条不变量；离线复算（定点 1/128 px）：

| N/M | 周期 | Δx(600 帧) | 峰值 \|Δx\|（普通 4 px/帧） | 峰值（原生卡 29 = 8 px/帧） |
| --- | --- | --- | --- | --- |
| **1/1** | **4** | **0** | **4.00 px** | **8.00 px** |
| 1/2 | 6 | 0 | 4.00 px | 8.00 px |
| 2/2 | 8 | 0 | 8.00 px | 16.00 px |
| 4/4 | 16 | 0 | 16.00 px | 32.00 px |

⇒ 峰值 ∝ N ⇒ **N=1 是唯一最小解**；M=1 把「起步」触发率拉满。
（反事实惯性模型下 `Δx(1200) == Δx(600)`、且最后一个整周期增量 = 0 ⇒ 只有一次性瞬态、**不累积**。）

## 3. ★★ 它要测的那张卡：TH18 原生卡 29「SPEEDQUEEN（疾風の下駄，射命丸文）」

⚠ **订正**：先前「TH18 原生能力卡里没有文/AYA」是**看错表**了 ——
`REIMU_OP / MARISA_OP / …` 那张是 **`pl0X.sht` 的 shooterset 索引槽**（卡 8–18 用），不是能力卡名表。
**能力卡 29 = `SPEEDQUEEN` / Aya 确实存在**，三条独立证据：
`engine/card/th18/08-catalog.md` §C 第 29 行 = `SPEEDQUEEN / Aya`；
ExpHP 符号库（`games/th18.v1.00a/symbols.json`）独立命名了 `struct zCardAya` 并给 `0x40c7f0` 标了方法；
逐条反汇编 `0x40c7f0` 确认。

**一手（`engine/card/th18/12-card29-aya-speedqueen.md` 已记，本工具实测又独立复核过一遍）**：
- 卡片 tick = `CardAya__on_tick` `0x40c7f0`。触发条件（`0x40ca95`–`0x40cab2`）：
  **`上一帧方向 == 0` ∧ `这一帧方向 != 0` ∧ `!聚焦`**，且**本帧不能按 Z**
  （Z 门 `0x40c80a test [player+0x4779c],0x200`；按 Z 的那支会把缓存钉 0 后返回）。
  方向 = `player+0x4793c`（0..8 八向）、聚焦 = `player+0x476cc`、上一帧方向缓存 = `card+0x58`。
- **量 = `0x40cb16 addss xmm1,[0x4b9248]`，`0x4b9248 = 4.0f`；整段没有任何"计时器 vs 常数"的比较/钳位**
  ⇒ **只要反复满足条件，`player+0x47778` 就单调上升**（判据读取 `0x45cd1c`/`0x45ce78`/`0x45d055`；
  每帧衰减 `0x45c5bc`）。
- ⇒ **结论：能刷成事实上的永久无敌**。本工具的模式每 4 帧制造 **2 次**「0→非 0」跳变
  ⇒ 毛 **+2 帧/帧**、减 −1 帧/帧衰减 = **净 +1 无敌帧/帧**。
  ⚠ 顺手订正文档 §4 的口径：那里写的"净 +2 帧/帧"把**毛/净**混了（量级不影响结论）。
- ⚠ **我们自己的卡刷不了**：它们走 SDK 的无敌**声明层**（`ce_invuln_request` / `ce_invuln_apply`，
  聚合 = **取 max / 置值**语义）⇒ 这条口子被**结构性堵住**（`12-card29-aya-speedqueen.md` §6）。
  所以要测必须用**原生卡 29**，工具也就必须**不依赖我们任何卡**（见 §4 的落地理由）。

## 5. ❓ 未闭合 / 注意事项

1. ⚠ **合成输入不进 replay 录像**：录制读点在 `0x4629f7`（节点 `0x11`，**早于**卡链 `0x16`）
   ⇒ 卡侧写 `INPUT_HELD` 不会被录进去。**带这个工具录出来的回放不忠实** ⇒ 别留这类录像。
   （想让合成输入进录像，唯一路是挂进 `0x462940` 体内 = **新站点**；预算已超，不建议。）
2. ❓ `player+0x477f0..f8` 每帧从全局 `0x5217dc..e4` 整块拷（`0x45c717 movq`），而那一格在文件镜像里
   还在 `.data` 的 BSS 尾巴（未初始化）⇒ **运行期常态值未闭合**。它在 `dx` 里是**与方向无关的同一常数**
   （左右两半加同样的量）⇒ 不破坏左右对称，但若常态非 0 会叠加一个恒定漂移。
   **实跑时看日志**：`dx` 是否每 4 帧回 0 即可判定（判据见 §1）。
3. 本件**只在实跑里验证**过"能不能刷无敌"这件事（工具本身未实跑）⇒ 首次使用请先看日志三行：
   峰值、`dx` 回零、`inv` 走势。
