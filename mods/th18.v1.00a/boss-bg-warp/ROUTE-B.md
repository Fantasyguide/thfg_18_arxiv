# 路线 B —— 「我们自己画」的自包含实现（`native/route_b.c`）

> 为什么要单独一个文件：本 mod 的主文件 `native/th18_bgwarp.c` 由**另一个并行 agent** 维护；
> 路线 B 放在**自己的文件**里（自装桩、自己的日志/ini），只在 `Makefile` 的 `SRC` 里加一行，
> **不改对方的任何代码**（连插件的 `thcrap_plugin_init` 都不动 —— 用 GCC 的
> `__attribute__((constructor))` 在 DLL 加载时装桩）。

## 它做什么

| 环节 | 做法（全部一手，见 [`AUDIT.md`](AUDIT.md) §O） |
| --- | --- |
| 插入点 | **层 6 绘制桩 `0x487780`**（叶子函数 `6A 06 E8 rel32 C3`，被调 `render_layer=0x488260`）——背景已合成、精灵层尚未绘制 ⇒ 采到的是背景 |
| 装桩方式 | **替换型桩**：整个桩被替换；桩尾用 `mov eax,imm32; call eax` **绝对调用**复刻原动作 ⇒ **不搬任何含相对寻址的字节** |
| 绘制 | 复刻引擎那条路：`SetTexture[vt+0x104]`、`SetFVF(0x144)[vt+0x164]`、`[vt+0x10c](0,6,0)`、`DrawPrimitiveUP[vt+0x14c]`；顶点 28 B `{x,y,z=0,rhw=1,color,u,v}` |
| 状态 | 画前关 `ZENABLE`/`ZWRITEENABLE`（画后恢复）；画后把引擎的"当前贴图/FVF"缓存置成不可能值逼它重设 |
| 采样源 | 离屏面 `[0x4ccfa0]`（默认）或 `[0x4ccf9c]`，`GetContainer`（vtable +0x2C）取纹理 |
| 坐标 | 世界 x∈[−192,192]、y∈[0,448]；**实测视口** `GetViewport`(+0xC0) ⇒ playfield 中心 = 视口中心 |
| **敌方圆心/半径** | ★ **不碰引擎内部结构**：网格段 VM 的 `+0x5c8` 缓冲里就是它这一帧的顶点（前两个 float = 位置，网格空间 = 世界 + (640,256)）⇒ 全部扫一遍取包围盒 ⇒ 得到敌方那个圆盘的中心与半径 |
| 光晕贴图 | ★ 把「精灵序号」解成纹理：`[vm+0x20]`(组)/`[vm+0x24]`(索引) → `[[0x51f65c]+组*4+0x312072c]+0x11c` 的条目（步长 68，`+8` = handle）→ `handle>>8`/`&0xff` → `[[…]+0x124]+索引*0x18` = `IDirect3DTexture9*` |

## 模式（游戏里按 `8` 循环）

| 模式 | 内容 |
| --- | --- |
| 0 | 关（`rb_draw` 第一行就返回 ⇒ 什么都不碰） |
| 1 | **M1**：整屏平移采样（只覆盖平移后的那块，避免"露馅"） |
| 2 | **M2**：`N×N` 扭曲网格（`N` 可调，33~65），圆心跟自机，圆外裁掉 + 外圈羽化 |
| 3 | **光晕贴图测试**：用解出来的**光晕 sprite 纹理**画同一份网格（验证"光晕能不能自己画"） |

按 `9`：**第二份** —— 优先画在**敌方那个圆盘**上（圆心/半径由 VM 缓冲反推）⇒ 这就是"移走的那份，敌人的也重画一份"。

## 不撕裂的两条结构性保证

1. **位移乘边缘窗**：最终位移（无论有没有混别人的场）都乘 `(R²−r²)/R²` ⇒ **圆盘边缘位移必然→0**；
2. **alpha 外圈羽化**：`fade`（默认 0.15）⇒ 透明度也连续。

## 血案：对着"过期设备"调 vtable ⇒ 跳进堆地址（2026-10-17，dump `th18.exe.37324.dmp`）

**dump 一手**：`Eip=0x90a66dc`（不在任何模块、堆区）、`Ebp=mod_th18_bgwarp.dll+0x3321`、
栈上有 **`0x00487780`（层 6 桩）** 与 `d3d9.dll`/`nvd3dum.dll` ⇒ **崩在我们桩的调用链里、跳到了堆地址** ✓

**根因**（我的错，且是同一类错误的**第四次**）：
当时 ini 的 `mode` 被我设成 **2** ⇒ **加载/标题阶段就在画**，那时 `[0x4ccdf8]` 里的设备指针是**过期/无效**的；
我只校验了"vtable 内存可读"，**没校验 vtable 里那一项是不是可执行代码** ⇒ `call vt[0x3a]` 直接跳进堆 ⇒ 闪退 ✓

**两条修法**：

1. ini `mode` 默认回到 **0**（加载/标题阶段**一个字节都不碰 D3D**）；
2. ★ 新增 `rb_code()`：调用前要求目标**属于已映射模块（`MEM_IMAGE`）且是可执行页** ——
   每次绘制校验设备侧的 9 个槽 + 面侧 2 个槽；任何一项不过 ⇒ **不画**并写
   `[设备] ★ 设备 … 的 vtable 里有非代码项（多半是加载/标题阶段的过期指针）⇒ 本次及后续不画` ✓

> 同一类错误的四次记录：① trampoline 漏 XMM；② 拿运行时量当身份判据；③ 走引擎链表不封顶 / `wrap_pi` 用 while；
> ④ **拿游戏指针当 vtable 调**。统一教训：**用游戏给的东西之前，先验证"它是我想的那种东西"**。
